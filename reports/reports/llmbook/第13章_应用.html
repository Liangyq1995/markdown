1. LLM 应用范式转变

LLM 的出现从根本上改变了 NLP 应用的开发模式：将任务特定知识从模型参数转移到提示中，使应用开发从"训练模型"转变为"设计提示"。

特征传统 NLP 方法LLM 方法
开发方式每任务独立设计模型统一模型 + 提示工程
数据需求大量标注数据少量示例甚至零样本
部署成本多个专用模型单一 LLM 服务多任务
泛化能力局限于训练分布强泛化到新任务
更新方式重新训练修改提示即可
低资源语言专项数据采集 + 训练仍面临挑战，需微调
推理能力依赖特征工程CoT 等提示策略激发
应用建议（书中原文）：大语言模型和传统小模型各有优点。大语言模型可为各种 NLP 任务提供统一解决方案，在零样本/少样本场景下具有竞争力；小模型能够部署在资源受限条件下，在充足高质量标注数据下可获得不错性能。实践中应综合考虑标注数据可用性、计算效率、部署成本等多方面因素。

2. 传统 NLP 任务中的 LLM

2.1 序列标注（NER / POS）

传统方法：CNN/LSTM/BERT + CRF，BIO 标注格式（Beginning / Inside / Outside），需大量标注数据。

LLM 方法：通过上下文学习或特殊提示直接抽取实体，无须 BIO 标记。只需给予提示（如"请识别出句子中包含的实体"）或任务示例即可。

挑战：对于罕见或歧义名称的特殊实体，LLM 可能误解其含义，将其与常见非实体词混淆，难以准确识别。

2.2 关系抽取

LLM 借助特定提示方法（如上下文学习）完成关系抽取，在涉及复杂推理的场景中相较小模型更具优势。当关系标签规模较大时，可采用大小模型协作范式：

  • 小模型进行候选关系初筛 → 大模型从初筛结果中推理最合适关系
  • 大语言模型对数据进行初步标注 → 丰富小模型训练数据

现代信息检索系统采用检索-重排序流水线框架：检索模型从大规模语料库中检索候选信息，重排序模型对候选信息进行精细排序。LLM 可用于：

  • 稠密检索：以 Mistral-7B 等规模相对较小的语言模型作为检索基座，通过微调提升文本表示质量
  • 重排序：三种方法——逐点评测法（Pointwise）、成对比较法（Pairwise）、列表排序法（Listwise）
  • 数据增强：引导 LLM 为文档生成候选查询，扩充训练数据

3.4 RAG 三种改进策略

输入优化策略

在文档层面：使用相关度排序模型过滤相关程度较低的候选文档。在词元层面：采用压缩/摘要方法实现更细粒度的内容优化，预先抽取并保留关键实体（如人名中的姓氏）以防信息丢失。

指令微调策略

构造面向检索文档利用的指令数据，通过微调提升 LLM 对文档信息的处理能力。关键点：(1) 确保模型平等关注输入不同位置（开头/中间/结尾）的内容，缓解"中间位置信息丢失"问题；(2) 包含不相关文档的指令数据，提升模型的抗干扰能力。

预训练策略

若 LLM 主要用于信息检索任务，可在预训练阶段针对性加强检索生成能力：将文档标题/首段作为查询，其余内容作为期望生成结果；或将每段话分为等长两部分，前半作查询，后半作目标。还可基于聚类方法构造相关文档集合，通过拼接关联文档得到预训练数据。

5. 多模态大语言模型

5.1 架构与训练

多模态 LLM（MLLM）通常由视觉编码器 + 连接模块 + 大语言模型三部分组成：图像首先被分割成 Patch，通过图像编码器和连接模块转换成图像块嵌入，与文本嵌入拼接后输入 LLM 自回归生成文本。

训练分两阶段：

  • 视觉-语言对齐预训练：利用大规模图文对进行端到端训练，对齐两种语义空间。数据量 <1M 只更新连接模块；较大规模可微调 LLM；1B 规模可进一步微调视觉编码器。
  • 视觉指令微调：提高模型遵循指令和解决任务的能力，可用 GPT-4 基于图像描述自动合成视觉指令。

    assert reverse_string("hello") == "olleh"
    assert reverse_string("") == ""
    assert reverse_string("a") == "a"
    assert reverse_string("ab") == "ba"

# 步骤2：生成通过上述测试的实现
def reverse_string(s: str) -> str:
    return s[::-1]

8.4 Text-to-SQL 示例

-- 问题：找出每个部门薪资最高的员工姓名和薪资
-- Schema: employees(id, name, department_id, salary, hire_date)
--         departments(id, name, manager_id)

SELECT e.name, e.salary, d.name AS dept_name
FROM employees e
JOIN departments d ON e.department_id = d.id
WHERE e.salary = (
    SELECT MAX(salary)
    FROM employees
    WHERE department_id = e.department_id
)
ORDER BY d.name;

10.2 OpenAI Assistants API 代码示例

OpenAI Assistants API 提供了构建 Agent 的标准化接口，集成了代码解释器、文件检索和自定义工具：

from openai import OpenAI
client = OpenAI()

# 1. 创建 Assistant（定义角色和工具）
assistant = client.beta.assistants.create(
    name="数据分析助手",
    instructions="你是专业的数据分析师，擅长 Python 数据分析",
    tools=[
        {"type": "code_interpreter"},   # 代码执行沙箱
        {"type": "file_search"},        # 文件语义检索
        {
            "type": "function",         # 自定义工具
            "function": {
                "name": "query_database",
                "description": "查询业务数据库",
                "parameters": {
                    "type": "object",
                    "properties": {
                        "sql": {"type": "string", "description": "SQL 查询语句"}
                    },
                    "required": ["sql"]
                }
            }
        }
    ],
    model="gpt-4-turbo"
)

# 2. 创建 Thread（独立对话会话）
thread = client.beta.threads.create()

# 3. 添加用户消息
message = client.beta.threads.messages.create(
    thread_id=thread.id,
    role="user",
    content="分析这份销售数据并生成可视化报告"
)

# 4. 运行 Assistant（异步执行）
run = client.beta.threads.runs.create(
    thread_id=thread.id,
    assistant_id=assistant.id
)

# 5. 轮询等待完成
import time
while run.status in ["queued", "in_progress"]:
    run = client.beta.threads.runs.retrieve(
        thread_id=thread.id,
        run_id=run.id
    )
    time.sleep(1)

# 6. 获取最终回答
messages = client.beta.threads.messages.list(thread_id=thread.id)
print(messages.data[0].content[0].text.value)

14. 小结

LLM 的应用版图已从传统 NLP 任务扩展到代码智能、科学研究、企业自动化等广泛领域。核心的技术架构模式是：

架构模式解决问题适用场景关键组件
RAG 模式知识边界 + 幻觉问题知识密集型问答向量数据库 + 重排序 + LLM
Agent 模式复杂多步骤任务需要工具调用和规划的场景任务规划 + 工具调用 + 反思
RAG + Agent覆盖最广泛需求企业级综合应用意图分类 + RAG + Agent + 安全过滤
微调 + 领域数据垂直领域专业性医疗/法律/金融等继续预训练 + 指令微调 + 领域数据
LLM 应用开发核心能力的转变：从"训练模型"转变为"系统设计"——如何设计提示、如何构建检索管道、如何编排 Agent 工作流，成为新的核心竞争力。大语言模型的兴起为通用人工智能的探索带来了新的研究曙光，同时研究人员也应关注 AI 的安全发展，使其真正为人类造福。
