一、注意力机制变体全景图

原文：A Visual Guide to Attention Variants in Modern LLMs | 2026

注意力机制是 Transformer 的核心，但原始的多头注意力（MHA）在长序列推理时面临 KV Cache 内存爆炸问题。从 MHA 到 GQA 再到 MLA，本质上是一场"如何在保持建模质量的同时压缩 KV Cache"的工程与算法创新竞赛。

1.1 多头注意力（MHA）

是什么：原始 Transformer 注意力机制，每个注意力头都有独立的 Q、K、V 投影矩阵。

为什么：多头并行让模型能同时关注不同位置、不同语义子空间，增强表达能力。

问题：推理时 K/V 矩阵随序列长度线性增长，大模型长上下文下显存占用极高。

代表架构：GPT-2 OLMo 2 7B OLMo 3 7B

1.2 分组查询注意力（GQA）

是什么：将多个 Query 头分组共享同一对 K/V，介于 MHA（每头独立KV）和 MQA（所有头共享一对KV）之间。

为什么：显著降低 KV Cache 占用，同时建模性能退化比 MQA 少得多。K/V 组数是可调超参数。

效果：在大多数任务上接近 MHA 质量，但推理内存减少 4–8 倍，是目前最主流的注意力方案。

代表架构：Llama 2/3 Mistral Qwen2

1.3 多头潜在注意力（MLA）

是什么：DeepSeek-V2 提出的创新方案——不共享 K/V，而是将 K/V 联合压缩为一个低维潜向量 $c$，推理时只缓存这个压缩表示，需要时再解压。

为什么：GQA 通过"共享"降低内存，MLA 通过"压缩"降低内存。在相同内存压缩比下，MLA 能维持更好的建模性能（DeepSeek-V2 消融实验证实）。

代价：实现复杂，serving 栈需要专门适配；对小模型/短上下文优势不明显。

代表架构：DeepSeek V3 Kimi K2 GLM-5 Ling 2.5 Mistral Large 3

1.4 滑动窗口注意力与稀疏注意力

对于超长上下文，全局注意力的 $O(n^2)$ 复杂度是硬瓶颈。滑动窗口注意力让每个 token 只关注固定大小的局部窗口；稀疏注意力通过学习或固定模式选择性计算。现代架构通常采用混合策略——大部分层用局部/稀疏注意力，少数关键层用全局注意力。

1.5 线性注意力与混合架构（2025趋势）

Gated DeltaNet 等线性注意力机制用快权重记忆更新替代 Softmax，实现 $O(n)$ 复杂度。Qwen3.5 将混合架构（Transformer + 线性注意力）纳入旗舰系列，标志着混合策略的成熟。

二、从 GPT-2 到 gpt-oss：架构演进分析

原文：From GPT-2 to gpt-oss: Analyzing the Architectural Advances | 2025

OpenAI 时隔多年发布 gpt-oss（20B 和 120B）开放权重模型，这是自 GPT-2 以来首次大规模开放权重分享。通过对比两代架构，可以清晰看到 LLM 工程从学术到工业的演进轨迹。

2.2 关键技术点

MXFP4 量化：gpt-oss 采用 MXFP4（Microscaling Float 4-bit）格式，在大幅压缩模型大小的同时保持推理质量，使 120B 模型在单 GPU 上成为可能。

宽度 vs 深度权衡：gpt-oss 相比 Qwen3 选择了更宽（hidden_dim 更大）但更浅（层数更少）的设计，这对推理延迟有正面影响（并行度更高），但对某些需要深度推理的任务可能不如深层架构。

注意力偏置与注意力 Sink：gpt-oss 保留了 attention bias，相关研究表明注意力 sink（某些 token 集中获得大量注意力权重）是长上下文稳定性的关键，attention bias 有助于控制这一现象。

三、KV Cache：从原理到从零实现

原文：Understanding and Coding the KV Cache in LLMs from Scratch | Jun 2025

KV Cache 是 LLM 生产推理中最重要的优化技术之一。没有 KV Cache，每生成一个新 token 都需要重新计算所有历史 token 的 K/V，导致推理延迟随序列长度平方增长。

3.1 为什么需要 KV Cache

在自回归生成中，第 $t$ 步生成的 token 的注意力计算需要用到所有前序 token 的 K 和 V。由于这些值不会变化（历史上下文固定），重新计算是纯粹的浪费。KV Cache 将它们缓存起来，每步只计算新 token 的 K/V 并追加到缓存。

sequenceDiagram
    participant T as Token生成循环
    participant M as LLM模型
    participant C as KV Cache

    Note over T,C: 无KV Cache（低效）
    T->>M: 输入[t₁,t₂,...,tₙ]
    M->>M: 计算所有token的K,V,Q (O(n²))
    M-->>T: 输出 tₙ₊₁

    Note over T,C: 有KV Cache（高效）
    T->>C: 读取已缓存的K₁..Kₙ, V₁..Vₙ
    T->>M: 只输入新token tₙ
    M->>M: 只计算tₙ的K,V,Q (O(1))
    M->>C: 追加 Kₙ₊₁, Vₙ₊₁
    M-->>T: 输出 tₙ₊₁

3.2 PyTorch 核心实现

# 带 KV Cache 的注意力层（简化版）
class CachedAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.cache_k = None  # KV Cache
        self.cache_v = None

    def forward(self, x, use_cache=True):
        q = self.W_q(x)   # 只需要当前token的Q
        k = self.W_k(x)
        v = self.W_v(x)

        if use_cache and self.cache_k is not None:
            # 追加到已有缓存
            k = torch.cat([self.cache_k, k], dim=1)
            v = torch.cat([self.cache_v, v], dim=1)

        if use_cache:
            self.cache_k = k  # 更新缓存
            self.cache_v = v

        # 标准注意力计算（Q只有1个token，K/V有全部历史）
        attn = torch.softmax(q @ k.transpose(-2,-1) / k.size(-1)**0.5, dim=-1)
        return attn @ v

3.3 KV Cache 的内存成本

KV Cache 并非免费的午餐——它将时间成本转换为空间成本。对于一个 70B 参数模型，32k 上下文长度的 KV Cache 可能需要超过 100GB 显存，这正是为什么 GQA/MLA 等压缩注意力成为必需品。

四、多模态 LLM：融合视觉与语言

原文：Understanding Multimodal LLMs

多模态 LLM 让语言模型能够理解图像、音频、视频等非文本模态，是从"语言助手"到"通用助手"的关键跨越。核心挑战是如何将不同模态的信息统一编码并送入 Transformer。

4.2 典型模型技术亮点

  • Aria（2024）：24.9B 参数的多模态原生 MoE 模型，每个文本 token 激活 3.5B 参数，视觉编码器为 SigLIP（438M）。
  • NVLM（NVIDIA）：在建模性能和响应质量之间做了系统性 ablation，为方法选择提供了实验依据。

五、编码器与解码器架构的本质区别

原文：Understanding Encoder And Decoder LLMs

LLM 领域的"架构之争"本质上是三种 Transformer 变体的适用场景之争，理解它们的差异是选择正确工具的基础。

5.1 三类架构对比

架构类型预训练任务注意力方向擅长任务代表模型
纯编码器掩码语言模型（MLM）双向（看全文）分类、NER、句子表示BERT, RoBERTa
纯解码器下一词预测（CLM）因果单向（只看左侧）文本生成、对话、代码GPT系列, Llama, Qwen
编解码器序列到序列编码器双向+解码器单向翻译、摘要T5, BART, mT5

5.2 为什么解码器架构主导了大模型时代

  • 涌现能力：仅通过下一词预测，大参数解码器模型展现出摘要、翻译、推理等未被显式训练的能力。
  • In-context 学习：无需更新参数，通过示例即可完成新任务，这在双向编码器中不自然。
  • 统一框架：生成范式可以表达几乎所有 NLP 任务（分类→生成标签字符串，翻译→直接生成译文）。

5.3 MLM vs CLM 预训练对比

MLM（BERT式）：
输入: "The [MASK] sat on the [MASK]"
目标: 预测 "cat" 和 "mat"
优势: 能看到完整上下文，表示质量高

CLM（GPT式）：
输入: "The cat sat on the"
目标: 预测下一词 "mat"
优势: 自然支持生成，可扩展到任意长度
