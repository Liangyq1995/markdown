二、MLA：多头潜在注意力（完整推导）

2.1 KV Cache 内存瓶颈

标准 MHA 每层 KV Cache：

$$\text{KV Cache}_\text{per layer} = 2 \times n_h \times d_h \times T \times B \times \text{sizeof}(\text{float})$$

DeepSeek-V3 配置（$n_h=128$，$d_h=128$，$T=128000$，fp16）：单层 $= 2\times128\times128\times128000\times1\times2\text{B} \approx 8.4\text{GB}$，80 层约 $672\text{GB}$，完全无法实际部署。

2.2 MLA 低秩联合压缩

KV 压缩（下投影）— 推理时只缓存此向量

$$\mathbf{c}_t^{KV} = W^{DKV} \mathbf{h}_t \in \mathbb{R}^{d_c}, \quad W^{DKV} \in \mathbb{R}^{d_c \times d}, \quad d_c = 512 \ll n_h d_h = 16384$$

Key/Value 解压（上投影）

$$\mathbf{k}_t^C = W^{UK} \mathbf{c}_t^{KV}, \quad W^{UK} \in \mathbb{R}^{n_h d_h \times d_c}$$ $$\mathbf{v}_t^C = W^{UV} \mathbf{c}_t^{KV}, \quad W^{UV} \in \mathbb{R}^{n_h d_h \times d_c}$$

解耦 RoPE（解决位置编码与低秩压缩的冲突）

低秩压缩后的 Key 无法直接附加 RoPE（旋转操作与矩阵乘法不可交换），因此额外引入携带位置信息的 Key 分量：

$$\mathbf{k}_t^R = \text{RoPE}(W^{KR} \mathbf{h}_t) \in \mathbb{R}^{d_h^R}, \quad d_h^R = 64$$ $$\mathbf{k}_t = [\mathbf{k}_t^C;\, \mathbf{k}_t^R], \quad \mathbf{q}_t = [\mathbf{q}_t^C;\, \mathbf{q}_t^R]$$

注意力计算

$$\mathbf{o}_t = \sum_{j=1}^{t} \text{softmax}\!\left(\frac{\mathbf{q}_t^T \mathbf{k}_j}{\sqrt{d_h + d_h^R}}\right) \mathbf{v}_j^C$$

权重吸收技巧（推理时零额外开销）

注意力内积中 $W^{UK}$ 可吸收进 Query 投影，使计算在压缩空间内完成：

$$\mathbf{q}_t^T \mathbf{k}_j^C = \mathbf{q}_t^T W^{UK} \mathbf{c}_j^{KV} = \underbrace{(W^{UK\top} \mathbf{q}_t)}_{\boldsymbol{\kappa}_t}{}^T \mathbf{c}_j^{KV}$$

内积维度从 $n_h d_h = 16384$ 降至 $d_c = 512$，进一步提升推理速度。

2.3 压缩比量化对比

方法每层 KV 缓存维度相对 MHA表达力
MHA$2 \times 128 \times 128 = 32768$1×基准
MQA$2 \times 128 = 256$1/128×明显下降
GQA（g=8）$2 \times 8 \times 128 = 2048$1/16×接近 MHA
MLA$512 + 64 = 576$（仅 $\mathbf{c}_{KV}$）约 1/57×超越 MHA

MLA 的 KV Cache 与 GQA 相近（均约 576 维），但因低秩分解保留了全部 $n_h$ 个注意力头的独立性，表达力反而超越 MHA。DeepSeek-V2 实测相比 67B Dense 模型节省 KV Cache 93.3%。

三、DeepSeek MoE：细粒度专家 + 共享专家

3.1 细粒度专家分割

传统 MoE 专家粒度粗，每次激活的专家组合数 $= \binom{N}{K}$，特化受限。DeepSeekMoE 将每个标准专家拆分为 $m$ 份，同时激活数扩大 $m$ 倍：

$$N_\text{routed} = m \times N_\text{orig}, \quad K_\text{active} = m \times K_\text{orig}, \quad d_\text{expert} = d_\text{orig}/m$$

组合空间从 $\binom{N}{K}$ 扩展到 $\binom{mN}{mK}$（指数级增长），有利于更精细的知识分解与专家特化。

DeepSeek-V3 配置：$N_r = 256$ 个路由专家，每 token 激活 Top-8，总计算量不变。

3.2 共享专家机制

$$\mathbf{h}_t' = \underbrace{\sum_{i=1}^{N_s} \text{FFN}_i^{(s)}(\mathbf{h}_t)}_{\text{共享专家（始终激活）}} + \underbrace{\sum_{i \in \text{TopK}(\mathbf{s}_t, K_r)} g_{i,t} \cdot \text{FFN}_i^{(r)}(\mathbf{h}_t)}_{\text{路由专家（Top-K 激活）}}$$

V3 使用 1 个共享专家：负责跨任务的通用知识（基础句法、高频词汇），路由专家则专注特定领域知识，两者分工明确，避免路由专家浪费容量学习通用知识。

3.3 Auxiliary-Free 负载均衡（核心创新）

传统 MoE 使用辅助损失 $\mathcal{L}_\text{balance} = \alpha N \sum f_i P_i$ 防止专家崩溃，但辅助损失系数 $\alpha$ 难以调节——过大损害主任务质量，过小无法防止崩溃。

DeepSeek 解决方案：可学习偏置 $b_i$

$$s'_{i,t} = s_{i,t} + b_i = \text{Sigmoid}(\mathbf{h}_t^T \mathbf{e}_i) + b_i \quad \text{（TopK 选择基于 } s'_{i,t}\text{）}$$

归一化门控值时不使用 $b_i$：$g_{i,t} = s_{i,t}/\sum_{j\in\mathcal{T}} s_{j,t}$（确保偏置只影响路由决策，不影响专家输出加权）。

训练中动态调整偏置：过载专家 $b_i \leftarrow b_i - \gamma$，欠载专家 $b_i \leftarrow b_i + \gamma$。完全无需辅助损失。

四、FP8 混合精度训练

4.1 FP8 格式

格式符号位指数位尾数位动态范围典型用途
E4M3143较小（$\pm 448$）权重、激活值
E5M2152较大（$\pm 57344$）梯度（范围更宽）

相比 BF16（1+8+7 位），FP8 存储量减半，矩阵乘法吞吐量最高翻倍（H100 FP8 TFLOPS = 2× BF16）。

4.2 动态量化策略

粗粒度量化会因少数极大值拉低整体精度。DeepSeek-V3 采用精细粒度在线量化：

$$\hat{\mathbf{X}}_{i,j} = \text{round}\!\left(\frac{\mathbf{X}_{i,j}}{s_{i,\lfloor j/128 \rfloor}}\right), \quad s = \frac{\max|\mathbf{X}_\text{tile}|}{\text{E4M3}_\text{max}}$$
  • 激活矩阵：按 $1\times128$ 的 tile 分块量化（每行独立缩放）
  • 权重矩阵：按 $128\times128$ 的 block 分块量化

4.3 混合精度策略

FP8 计算（高吞吐）
  • 矩阵乘法（GEMM 核心计算）
  • 前向/反向权重矩阵运算
BF16/FP32 保留（高精度）
  • Embedding 层
  • RMSNorm 归一化
  • 注意力 Softmax
  • 输出投影
  • Master 权重副本（BF16）
  • 梯度累加器（FP32）

V3 是首个在超大规模模型（671B）上验证 FP8 训练可行性的工作，整个预训练过程未出现不可恢复的 Loss 尖峰。

五、多 Token 预测（MTP）

动机：密集化训练信号

标准自回归训练在位置 $t$ 只预测 $t+1$ 处的 token，每个位置仅贡献一个梯度信号。MTP 在每个位置同时预测未来 $D$ 个 token，训练信号密度提升 $D$ 倍。

V3 的 MTP 结构（D=1）

  • 一个共享的 Embedding 层（与主模型共享权重）
  • 一个独立参数的 Transformer 层
  • 一个与主模型共享的输出头

训练损失

$$\mathcal{L}_\text{total} = \mathcal{L}_\text{main} + \lambda \sum_{d=1}^{D} \mathcal{L}_\text{MTP}^{(d)}$$ $$\mathcal{L}_\text{main} = -\sum_t \log P(x_{t+1}|x_{\leq t}), \quad \mathcal{L}_\text{MTP}^{(d)} = -\sum_t \log P_\theta^{(d)}(x_{t+d+1}|x_{\leq t})$$

推理时复用为投机解码草稿模型

  1. MTP 模块（轻量）生成候选 token 序列
  2. 主模型并行验证候选序列
  3. 接受符合主模型分布的候选，拒绝不符合的

实测加速比约 1.4~1.8×，接受率约 85~90%。

六、DeepSeek R1：GRPO 推理训练

6.1 为什么选 GRPO 而非 PPO

PPO（传统方案）
  • 需要与 Actor 同等规模的 Critic 网络
  • 671B 模型：Critic 同样 671B，内存×2
  • Critic 训练需要额外稳定性处理
  • 4 个模型同时占用 GPU：Actor、Critic、Reference、Reward
  • 优势估计用 GAE（Generalized Advantage Estimation），需要 $\lambda$ 系数调优
  • KL 惩罚以 per-token 密集奖励形式加入，隐式抑制响应长度增长
GRPO（DeepSeek 方案）
  • 用组内相对排名替代价值函数
  • 无需 Critic 网络，节省 50%+ 内存
  • 组内归一化自然提供优势基线
  • 仅 Actor + Reference 两个模型
  • KL 散度作为无偏估计直接加入损失（非 per-token 密集奖励），不抑制长度
  • 每 400 步将 Reference 更新为最新策略，平衡探索范围与稳定性

PPO vs GRPO 详细对比（来自论文 Background 章节）

维度PPOGRPO
需要的模型数4 个（Actor + Critic + Reference + Reward）2 个（Actor + Reference）
优势估计GAE，需要 Critic 网络，需调 $\lambda$（默认 0.95，敏感）组内均值/标准差归一化，无需额外参数
KL 惩罚方式per-token 密集奖励，隐式压缩响应长度无偏估计直接加入损失，允许长推理链
长 CoT 适配性差：Critic 难以预测长序列末端奖励；KL 抑制长度好：无 Critic；KL 不抑制长度
超参调优难度高：$\lambda$ 敏感，$\lambda=0.95$ 时性能显著劣于 GRPO低：$\lambda=1.0$ 时 PPO 接近 GRPO，但 GRPO 无需调
DeepSeek-Coder-V2-Lite 实验$\lambda=0.95$ 时明显差；$\lambda=1.0$ 时接近 GRPO最优基线，无额外调参

论文结论：PPO 可以在精细调参后接近 GRPO，但额外的计算开销（Critic 模型）和调参负担使其在大规模训练中不如 GRPO 实用。

6.2 完整 GRPO 推导

步骤一：组采样

对每个问题 $q$，从旧策略 $\pi_{\theta_\text{old}}$ 采样 $G=16$ 个输出 $\{o_1,\ldots,o_G\}$，由奖励函数计算分数 $\{r_1,\ldots,r_G\}$。

步骤二：组内相对优势

$$\hat{A}_i = \frac{r_i - \text{mean}(\{r_j\}_{j=1}^G)}{\text{std}(\{r_j\}_{j=1}^G)}$$

直觉：组内奖励高于平均 → 正优势（值得强化）；低于平均 → 负优势（值得抑制）。无需绝对价值基线。

步骤三：完整目标函数

$$\mathcal{J}_\text{GRPO}(\theta) = \mathbb{E}\!\left[\sum_{i=1}^{G}\!\left(\min\!\left(\frac{\pi_\theta(o_i)}{\pi_{\theta_\text{old}}(o_i)}\hat{A}_i,\;\text{clip}\!\left(\frac{\pi_\theta(o_i)}{\pi_{\theta_\text{old}}(o_i)},1-\varepsilon,1+\varepsilon\right)\hat{A}_i\right) - \beta\,D_\text{KL}(\pi_\theta\|\pi_\text{ref})\right)\right]$$ $$\varepsilon = 0.2, \quad \beta = 0.001$$

6.4 RL 基础设施：四模块解耦架构

DeepSeek 的 RL 训练框架将流水线分为四个解耦模块，各模块执行完毕后自动将模型从 VRAM 卸载到内存/磁盘，为下一模块腾出空间：

模块功能关键优化
Rollout 模块从训练集加载 Prompt，通过多个 vLLM worker（搭载 Actor 模型）采样多个响应MoE 专家并行；MTP 自推测解码加速；热点专家冗余副本均衡负载
Inference 模块加载 Reward Model 和 Reference Model，对 Rollout 生成的样本做前向推理，获取模型奖励和 KL 信息与 Rollout 模块解耦，可独立扩展
Rule-based Reward 模块计算规则奖励（代码执行器、答案匹配器、格式检查器）异步调度，与 Rollout/Inference 重叠执行，隐藏延迟
Training 模块加载 Actor（+可选 Critic），计算损失并更新参数；支持 PPO/GRPO/DPO 等多种算法全局 batch 按长度排序 + Best-Fit 打包，消除 padding 浪费；集成 DualPipe 流水线

十、DeepSeek-V3.2：高效注意力与可扩展 RL

10.1 DSA：DeepSeek Sparse Attention

DeepSeek-V3.2 在 DeepSeek-V3.1-Terminus 基础上，通过继续训练引入 DSA（DeepSeek Sparse Attention）——这是该版本唯一的架构改动，足见其分量。DSA 是一种细粒度、内容驱动的动态稀疏注意力，由两个组件构成：Lightning Indexer（极轻量打分器）与 Top-k Token Selector（细粒度 token 选择器）。核心思想：不再对全部历史 token 做二次方全注意力，而是先廉价地打分，再只对每个 query 最相关的 $k$ 个 token 做完整注意力，从而将主注意力复杂度从 $O(L^{2})$ 降至 $O(Lk)$（$k \ll L$），在长上下文场景下几乎不损失性能，部分长程基准甚至反超稠密注意力。

动机：从固定稀疏到学习型稀疏

传统稀疏注意力多采用固定模式：滑动窗口（如 Gemma 3、Olmo 3 只看局部窗口）、跨步（strided）或块状稀疏。这类方法实现简单，但稀疏模式与内容无关——它们无法根据"当前 query 真正需要回看哪些历史 token"动态选择，长程依赖任务下质量受损。DSA 的关键区别在于：稀疏模式是学出来的，而非硬编码。Lightning Indexer 学习一个内容相关的重要性函数，让模型自己决定每个 query 应关注哪些历史位置，从而在大幅削减计算的同时保持稠密注意力的质量。这正是 DSA 难点所在：稀疏注意力不新鲜，"在不掉点的前提下做稀疏"才是真正难的事。

Lightning Indexer：极轻量打分器

Lightning Indexer 计算 query token $h_t$ 与每个前序 token $h_s$ 之间的相关性得分 $I_{t,s}$，作为"该不该回看 $h_s$"的依据：

$$I_{t,s} = \sum_{j=1}^{H^{I}} w_{t,j}^{I} \cdot \mathrm{ReLU}\left(q_{t,j}^{I} \cdot k_{s}^{I}\right)$$
符号含义来源
$H^{I}$Indexer 头数（$\ll$ 主注意力头数 $H$）超参
$q_{t,j}^{I} \in \mathbb{R}^{d^{I}}$第 $j$ 个 Indexer 头的 query 向量由 query token $h_t$ 经低秩投影得到
$k_{s}^{I} \in \mathbb{R}^{d^{I}}$Indexer 的 key 向量（各头共享）由前序 token $h_s$ 经低秩投影得到
$w_{t,j}^{I} \in \mathbb{R}$第 $j$ 个头的可学习混合权重由 query token $h_t$ 决定（query 相关的门控）
$d^{I}$Indexer 的低维投影维度远小于主注意力头维度

设计要点：

  • 用 ReLU 而非 Softmax：Softmax 需对整条序列做全局归一化，开销大且不利于后续 Top-k 选择；ReLU 直接把负的点积得分归零，无需全局归一化，且在 FP8 下吞吐极高。论文明确指出选 ReLU 是 "for throughput consideration（出于吞吐考虑）"。
  • Indexer 只在 query 端打分：key 侧的 $k_s^{I}$ 来自 MLA 已经压缩并缓存的表示，无需在各头上重复压缩或打分，进一步省算力。
  • 头数少 + 低秩 + FP8：$H^{I}$ 远小于主注意力头数、$d^{I}$ 很小、整体以 FP8 实现并融合进单次 kernel launch，因此其名义上的 $O(L^{2})$ 开销相对 MLA 几乎可忽略。
  • 稀疏性来自选择器而非 ReLU 本身：由于存在跨头求和，单个得分 $I_{t,s}$ 通常不会恰好为 0；真正的稀疏截断由后续 Top-k 选择器完成，ReLU 主要起"压负值 + 提速"作用。

Top-k 选择与核心注意力

基于得分 $I_{t,:}$，对每个 query token $t$ 选出得分最高的 $k$ 个前序 token，构成选中集合：

$$\mathcal{S}_{t} = \left\{s \;\middle|\; I_{t,s} \in \text{Top-k}(I_{t,:})\right\}$$

核心注意力仅在这 $k$ 个 token 上执行（而非全序列）：

$$u_t = \mathrm{Attn}\left(h_t,\;\{c_s \mid s \in \mathcal{S}_{t}\}\right)$$

其中 $c_s$ 是 MLA 已压缩的 KV 表示。关键超参 $k = 2048$：即无论上下文多长，每个 query token 只对 2048 个 KV 条目做完整注意力。在 128K 上下文下，主注意力操作量约为稠密注意力的 1.6%（对比：固定模式稀疏约 0.4% 但质量下降）。主注意力复杂度由 $O(L^{2})$ 降至 $O(Lk)$；Indexer 自身仍是 $O(L^{2})$，但因低秩 + FP8 + 少头，相对 MLA 的开销可忽略，端到端仍获显著提速。

与 MLA 的集成：DSA 实例化于 MLA 之下

DSA 并非独立注意力，而是实例化在 MLA 之上，复用 MLA 的压缩 KV 表示 $c_s$ 同时用于打分与稀疏注意力。其数据流（对应论文 Figure 2）如下：

单层 DSA 伪代码

Algorithm 1: DSA 前向（单层，给定 query 与前序压缩 KV 缓存）

Input: query 隐状态 ht; 缓存 {cs, ksI} for s < t; 超参 k = 2048

// 1. Lightning Indexer 打分（FP8，单次 kernel launch）

qt,jI, wt,jI ← indexer_proj(ht) // 低秩投影到 HI 头

It,s ← Σj wt,jI · ReLU(qt,jI · ksI)

// 2. Top-k 细粒度选择（GPU partial sort）

St ← { s | It,s ∈ Top-k(It,:, k) }

// 3. 核心注意力仅作用于选中 KV（自定义 CUDA gather kernel）

ut ← MQA_Attn(ht, { cs | s ∈ St })

return ut

实现与系统优化

  • FP8 单 kernel 打分：Indexer 以 FP8 批量矩阵乘实现，$L \times L$ 得分矩阵在单次 kernel launch 内完成，避免逐 token 循环。
  • Top-k 用 GPU 部分排序：对每个 query 的得分向量做 partial sort 取前 $k$，避免对整条序列全排序的开销。
  • 变长稀疏 gather：每个 query 选中的集合不同（逐 query 变长稀疏），核心注意力用自定义 CUDA kernel 处理，并配合 FlashMLA / FlashAttention-3 Sparse 做 kernel 复用。
  • 分页缓存不一致：Indexer 的 key & key_scale 缓存用 page size = 64（适配 DeepSeek 提供的 kernel），而 token 级稀疏前向算子用 page size = 1，需在统一 attention backend 内支持不同 page size。
  • 短上下文回退：短序列下 DSA 退化为掩码多头注意力（masked MHA）以省去选择开销；MLA 内偏好 MQA 模式，以最大化共享 KV 的 GPU 数据复用。

10.2 可扩展 GRPO：四项稳定技术

V3.2 在 GRPO 大规模强化学习中发现并修复了若干数值不稳定问题，提出四项关键改进。关键数字：后训练 FLOPs 超过预训练成本的 10%，是开源模型中首次在此规模上稳定扩展 RL。

① 无偏 KL 估计（Unbiased KL Estimation）

原始 K3 估计量在策略 $\pi_\theta \ll \pi_\mathrm{ref}$ 时梯度爆炸。替换为以下无偏形式：

$$D_\mathrm{KL}(\pi_\theta \| \pi_\mathrm{ref}) = \frac{\pi_\theta(o_{i,t})}{\pi_\mathrm{old}(o_{i,t})} \cdot \frac{\pi_\mathrm{ref}(o_{i,t})}{\pi_\theta(o_{i,t})} - \log\frac{\pi_\mathrm{ref}(o_{i,t})}{\pi_\theta(o_{i,t})} - 1$$

该形式在任意分布比值下均有界，消除训练初期的梯度爆炸风险。实践中发现不同领域对 KL 正则化强度需求不同：数学任务可使用较弱的 KL 惩罚（$\beta$ 接近 0），甚至完全省略。

② Off-Policy Sequence Masking（阈值 $\delta$ 控制）

对高度 off-policy 的负优势序列引入二进制掩码 $M_{i,t}$：

$$M_{i,t} = \begin{cases} 0 & \hat{A}_{i,t} \lt 0 \;\text{且}\; \frac{1}{|o_i|}\sum_t \log\frac{\pi_\mathrm{old}(o_{i,t})}{\pi_\theta(o_{i,t})} \gt \delta \\ 1 & \text{otherwise} \end{cases}$$

阈值 $\delta$ 控制 off-policy 程度的容忍上限（论文未公开具体数值，需针对任务调优）。仅对负优势序列做掩码——模型最需要从自身错误中学习，而高度 off-policy 的负样本会误导优化。$\pi_\mathrm{old}$ 直接使用推理框架返回的采样概率，同时覆盖训练-推理框架不一致和多步更新两种 off-policy 来源。

③ Keep Routing（保存推理路由）

在推理阶段记录每个 token 的 MoE 路由路径，训练时强制复用相同路由，确保训练与推理的 MoE 激活一致，避免路由漂移导致的分布偏差。该技术自 DeepSeek-V3-0324 起纳入标准 RL 流水线，被证明对 MoE 模型 RL 稳定性至关重要。

④ Keep Sampling Mask（保存采样截断掩码）

保存采样时的截断掩码（top-p/top-k 截断位置），在训练策略评估时应用相同掩码，保证策略梯度估计中分子分母使用一致的采样空间。top-p 采样 + Keep Sampling Mask 的组合可有效保留样本质量同时维持训练稳定性。

Thinking Context Management：精确规则

DeepSeek-V3.2 在多轮工具调用中采用以下上下文保留策略（与 R1 的"第二轮消息到来时丢弃推理"不同）：

  • 保留推理内容：当对话中仅追加工具相关消息（工具调用结果）时，历史 <think> 块全程保留，避免重复推理
  • 清空推理内容：当新的用户消息到来时，历史推理内容被丢弃，但工具调用历史及其结果仍保留在上下文中

注意：Roo Code、Terminus 等通过"用户消息"模拟工具交互的框架，会触发推理清空规则，无法充分受益于此机制，建议改用 non-thinking 模式。

效果：BrowseComp 评测中，使用上下文管理（Discard-all 策略）得分从 51.4 提升至 67.6；SWE-Verified 等代码 Agent 任务稳定在 73-74 区间。

11.1 CSA：Compressed Sparse Attention

CSA 在 MLA 低秩压缩基础上进一步引入 跨 token 压缩，将相邻 $m$ 个 token 的 KV 表示合并为一个压缩单元，大幅降低长序列下的 KV Cache 占用。

KV 压缩公式（双向 look-ahead / look-back 各 m 个 token）

$$C_i^\mathrm{Comp} = \sum_{j=mi}^{m(i+1)-1} S_j^a \odot C_j^a + \sum_{j=m(i-1)}^{mi-1} S_j^b \odot C_j^b$$

$S_j^a$、$S_j^b$ 为可学习的标量门控权重，$C_j^a$、$C_j^b$ 分别为前向和后向的 KV 潜在向量。双向融合使压缩单元同时感知局部上下文。

稀疏选择策略

  • Top-k 稀疏选择：对压缩后的 KV 单元做重要性打分，只保留最相关的 $k$ 个
  • 滑动窗口近邻保留：无论打分如何，始终保留最近 $w$ 个 token 的精确 KV，防止近邻信息丢失
  • MQA 核心注意力：压缩单元部分采用 Multi-Query Attention，进一步减少 KV 头数

11.2 HCA：Heavily Compressed Attention

HCA 采用更大压缩比 $m' \gg m$，将更长范围的历史 token 压缩为极少数的 KV 单元，无需稀疏选择，直接对所有压缩单元做密集注意力。CSA 和 HCA 层交错排列：

  • CSA 层负责中程精确稀疏注意力
  • HCA 层负责超长程粗粒度全局注意力
  • 两者配合实现 1M 上下文的高效覆盖

11.4 mHC：流形约束超连接

mHC（manifold-constrained HyperConnection）将层间残差连接的混合矩阵 $B_l$ 约束在双随机矩阵流形上，保证谱范数有界，使残差变换非扩张。

流形约束定义

$$B_l \in \mathcal{M} \triangleq \{M \mid M\mathbf{1}=\mathbf{1},\;\mathbf{1}^TM=\mathbf{1}^T,\;M\geq 0\}$$

双随机矩阵满足行和与列和均为 1，由 Birkhoff 定理可知其谱范数 $\|B_l\|_2 \leq 1$，从而保证梯度在深层网络中不爆炸。

投影算法

使用 Sinkhorn-Knopp 算法在每步优化后将 $B_l$ 投影回流形 $\mathcal{M}$，计算开销极小（仅需交替行/列归一化）。

11.5 Muon 优化器

V4 采用 Muon 优化器替代 AdamW，通过 Newton-Schulz 迭代将梯度矩阵正交化，使参数更新具有等向性，加速收敛并提升训练稳定性。

Newton-Schulz 正交化更新

$$O_t = \mathrm{HybridNewtonSchulz}(\mu M_t + G_t) \cdot \sqrt{\max(n,m)} \cdot \gamma$$ $$W_t = W_t(1-\eta\lambda) - \eta O_t$$

$M_t$ 为动量累积，$G_t$ 为当前梯度，$\gamma$ 为缩放因子，$\eta$ 为学习率，$\lambda$ 为权重衰减系数。正交化步骤确保更新矩阵的 Frobenius 范数与维度无关。

Hybrid Newton-Schulz 迭代细节（10 步两阶段）

给定矩阵 $M$（SVD 为 $M = U\Sigma V^T$），目标是将 $M$ 正交化为 $UV^T$。先归一化 $M_0 = M / \|M\|_F$，然后执行 10 步迭代：

$$M_k = aM_{k-1} + b(M_{k-1}M_{k-1}^T)M_{k-1} + c(M_{k-1}M_{k-1}^T)^2 M_{k-1}$$
阶段步数系数 $(a, b, c)$作用
快速收敛阶段前 8 步$(3.4445, -4.7750, 2.0315)$驱动奇异值快速趋近 1
精确稳定阶段后 2 步$(2, -1.5, 0.5)$将奇异值精确稳定在 1

注意：由于 V4 的注意力架构对 query 和 KV 直接应用 RMSNorm，有效防止注意力 logit 爆炸，因此不需要 QK-Clip 技术。

11.6 On-Policy Distillation（OPD）

OPD 替代混合 RL 阶段，通过多教师反向 KL 蒸馏将多个专家模型的推理能力融合到学生模型。超过 10 个教师模型覆盖各任务域，蒸馏到单一学生模型。

训练流程

1
专家训练：10+ 个独立专家模型并行训练，每个专家专注于特定任务域（数学、编程、Agent 等），使用 GRPO 算法，超参数与 V3.2 保持一致
2
OPD 蒸馏：学生模型在线生成样本（on-policy），与各教师的分布做加权反向 KL 散度。采用全词表 logit 蒸馏（而非 token 级 KL 估计），获得更稳定的梯度估计

目标函数

$$\mathcal{L}_\mathrm{OPD}(\theta) = \sum_{i=1}^N w_i \cdot D_\mathrm{KL}(\pi_\theta \| \pi_{E_i})$$

$\pi_{E_i}$ 为第 $i$ 个教师专家，$w_i$ 为任务权重，反向 KL 使学生模型的输出分布覆盖各教师的众数区域。反向 KL 的梯度等价于以 $\log\frac{\pi_{E_i}(y_t|x,y_{\lt t})}{\pi_\theta(y_t|x,y_{\lt t})}$ 为 per-token 优势估计的策略梯度（stop gradient 操作）。

V4 的 Interleaved Thinking（对比 V3.2）

V3.2 在新用户消息到来时会清空推理内容。V4 凭借 1M 上下文窗口，进一步优化：

  • 工具调用场景：所有推理内容在整个对话中完全保留，包括跨用户消息边界——模型可在长 Agent 任务中维持连贯的累积思维链
  • 普通对话场景：保持原有策略，新用户消息到来时丢弃推理内容，保持上下文简洁

技术机制

Anticipatory Routing 详细机制

核心思想：将主干网络的参数更新与路由网络的参数更新解耦，避免两者同步变化引起的训练不稳定。

  • 具体做法：在步骤 $t$ 时，特征计算使用当前参数 $\theta_t$，但路由索引使用历史参数 $\theta_{t-\Delta t}$ 提前（anticipatorily）计算并缓存
  • 工程优化：提前计算路由仅需一次前向传播，通过流水线编排与 EP 通信重叠，额外墙钟时间开销控制在约 20%
  • 动态激活：引入自动检测机制——仅在检测到 loss spike 时激活 Anticipatory Routing，运行一段时间后自动回归标准训练，整体额外开销可忽略
  • 效果：成功规避了训练过程中的 loss spike，无需人工干预且不损失模型性能

SwiGLU Clamping 参数选择

在 DeepSeek-V4-Flash 和 V4-Pro 的全程训练中均使用以下 clamping 配置：

  • 线性分量（linear component）：clamp 至 $[-10, 10]$（双向限制）
  • 门控分量（gate component）：仅限制上界为 10（单向限制）

参考文献：Bello et al. (2017) 和 Riviere et al. (2024) 均使用 clamping 约束数值范围；OpenAI (2025) 也采用 SwiGLU clamping。实验验证：该设置有效消除激活值异常点（outliers），显著稳定训练过程，且不损害模型性能。
