概述

科学进步的本质是一个反复的循环：探索假设、设计实验、解读证据、将洞见带入下一轮尝试。人类研究者能够在数周乃至数月的时间跨度内维持这一过程，因为他们拥有持久的记忆——知道哪些方向已被证伪、哪些发现可以复用、哪些失败包含了下一步的线索。然而，现有 LLM Agent 系统（如 Codex、Claude Code）虽然能够长时间运行代码编辑和实验，但其本质仍是"持久的任务执行"而非"累积性研究"——每次尝试基本上是独立的，缺乏将过去证据系统化纳入未来决策的机制。

本文提出 Arbor，一个面向自主优化（Autonomous Optimization, AO）的通用研究框架。其核心创新是 Hypothesis Tree Refinement（HTR）——一种持久化的树形数据结构，将假设、制品版本、实验证据和蒸馏洞见有机绑定在每个节点上。框架由两类 Agent 构成：

  • 长生命周期协调器（Coordinator）：拥有并维护全局假设树，负责战略层面的探索——观察当前前沿、生成子假设、选择待执行节点、整合返回证据、向上传播洞见、决定合并/剪枝/继续。
  • 短生命周期执行器（Executor）：每个执行器接受一个树节点（假设），在隔离的 git worktree 中实现并评估该假设，返回结构化报告（dev 分数、事实结果、蒸馏洞见、分支引用），然后退出。

关键机制在于 held-out 合并门控：只有当候选制品在 held-out 测试集上真正超越当前最优时，才被合并进主干。这将探索性 dev 反馈与已验证的制品级进步严格分离，防止对开发集的过拟合伪装成真实进展。

在六个真实研究任务（模型训练、harness 工程、数据合成）上，Arbor 在所有任务上取得最佳 held-out 结果，平均相对增益超过 Codex 和 Claude Code 的 2.5 倍。在 MLE-Bench Lite 上，配合 GPT-5.5 骨干，Arbor 达到 86.36% Any Medal，创下该榜单最高纪录。

假设树节点结构

假设树 $T = (V, E)$ 是一棵有根树，根节点 $n_0$ 代表初始研究目标。每个节点 $n \in V$ 是一个三元组：

$$n = \langle h_n,\ \iota_n,\ \mu_n \rangle$$

  • 假设 $h_n$：描述如何修改制品以改进目标的可验证/可证伪声明。靠近根的节点描述宽泛研究方向，深层节点指定可被执行器实现的具体干预。
  • 洞见 $\iota_n$：存储与该假设相关联的可复用证据解释。对已执行叶节点，总结"尝试了什么、发生了什么、为何支持或削弱假设"；对内部节点，抽象其所有子节点的洞见，形成方向级理解。
  • 元数据 $\mu_n$：连接语义假设与可执行证据，包括节点状态、dev 分数、事实结果记录、实现引用（git 分支/commit）、可选背景证据。

三种角色同时扮演

假设树在 Arbor 运行中同时扮演三个角色：

  • 搜索前沿：记录哪些方向处于活跃、已验证或已剪枝状态
  • 长期记忆：存储成功与失败的可复用证据
  • 可审计研究记录：将每次制品变更链接到驱动它的假设和证据

Hypothesis Tree Refinement（HTR）

HTR 算法伪代码

Algorithm 1   Hypothesis Tree Refinement (HTR)

Input:   P = (M0, O, Edev, Etest), budget B, branching factor k

Output: best artifact M* and hypothesis tree Tree

 

// 初始化：单根节点树，最优制品为初始制品

init Tree = ({n0}, ∅),   bn0 ← M0,   Mbest ← M0

 

while B left and pending leaves exist do

// Step 1: Observe — 从树中读取前沿状态、根洞见、剪枝/验证教训

V ← Observe(Tree, Mbest)

 

// Step 2: Ideate — 在选定父节点下附加 k 个子假设

p ← choose parent under V

attach k pending children {n(i) : h(i)} ← Ideate(p, V)

 

// Step 3: Select — 前沿控制，选择最有价值的待执行叶节点

L ← pending leaves under Select(V)

 

// Step 4: Dispatch — 并行执行器，每个执行器测试一个假设

{(sn, rn, ιn, bn)}n∈L ← parallel Executor(hn, ιanc(n), Mbest)

 

// Step 5: Backpropagate — 写回证据，向上抽象洞见

foreach n ∈ L, a ∈ path(n0 → n) do

write back (sn, rn, ιn, bn)

ιa ← Abstract({ιc}c∈ch(a))   // 子节点洞见抽象为方向级洞见

end foreach

 

// Step 6: Decide — held-out 合并门控 + 剪枝

n† ← arg maxn∈L sn

if O(Etest(bn†)) > O(Etest(Mbest)) then Mbest ← merge(bn†)

prune subtrees falsified by {ιn}n∈L;   persist Tree

end while

return M* ← Mbest, Tree

 

Procedure Executor(hn, ιanc(n), Mbest):

// 在隔离 worktree 中实现假设，直到成功或达到上限

fresh worktree Wn ← Mbest

repeat

Δ ← Implement(hn, ιanc(n), Wn)

(sn, rn) ← Edev(apply(Δ, Wn))

until run ok ∧ hn-path exercised, or cap reached   // 仅修复 Δ，假设 hn 固定不变

return (sn, rn, Distill(hn, Δ, rn), commit(Wn))

协调器六步骤详解

步骤操作关键设计
Observe 读取树的结构化投影：活跃前沿节点、最近返回证据、祖先洞见、当前最优制品 树作为权威状态，防止协调器依赖有损的对话历史；上下文压缩后重新接地
Ideate 选择父节点，在其下提出一组子假设（精炼、替代或修正） 以累积树证据为条件：已验证洞见提供构建基础，已剪枝节点提供负约束，最近报告提示可行干预
Select 选择待执行的 pending 节点 不仅是分数最大化；在部分和延迟反馈下的前沿控制——方向可因强先验、兄弟歧义或失败能澄清假设而被选中
Dispatch 并行派发执行器，每个执行器在独立 worktree 中实现一个假设 兄弟假设的并行执行在同一研究方向内提供对比证据，便于后续剪枝和抽象
Backpropagate 将执行器证据写入叶节点，沿路径向上更新洞见 传播的不只是标量分数，还包括因果归因、适用条件、可复用教训；叶级观察可成为方向级约束，最终成为全局先验
Decide 继续扩展 / 剪枝 / 停止 / 申请合并 held-out 合并门控：候选在 fresh worktree 上运行 Etest，仅当超越当前最优时合并；高 dev 低 test 被视为过拟合信号

Dev/Test 分离揭示自主搜索中的过拟合

Terminal-Bench 任务上出现了一个典型案例：Claude Code 取得最高 dev 分数（75.00），但 held-out 分数下降至 71.70；Arbor dev 分数较低（72.22），但 held-out 分数达到最佳（77.36）。这正是 Arbor 合并门控的价值体现——高 dev 低 test 的候选被识别为"利用反馈信号而非产生可迁移改进"的证据。

消融实验关键发现

  • HTR 提升精炼质量而非可执行性：所有变体均获得 100% 有效提交，说明消融差距不是由基本执行失败导致的。差距出现在结果质量上——Full Arbor 81.82% vs w/o tree 63.64% vs w/o insight feedback 54.54%。
  • 去掉洞见传播比去掉树本身更有害：这是反直觉但深刻的发现。仅有层级结构而无传播洞见的树，只能在语法上组织实验，无法提供后续决策所需的语义记忆。树的价值在于其上能够累积证据。
  • 树结构与洞见传播相辅相成：树定义了竞争假设的存储和比较位置，洞见传播决定了什么可复用信息被携带向前。二者结合才能将局部实验结果转化为对未来搜索的持久约束。

局限性

  • 标量目标的局限：Arbor 当前评估的 AO 任务均使用单一标量指标（loss、pass rate、accuracy）。对于多目标、定性评估或需要人类判断的研究任务，HTR 的假设精炼机制能否有效工作尚待验证。
  • 高层问题表述依赖人工：Arbor 在目标可通过具体精炼序列改进时表现最强，但当进展需要弱连接于现有树的全新高层表述时可靠性下降。Architecture Design 任务最终发现单旋钮调整已到边际收益递减，需要更大的算法变动，但识别这一变动仍依赖先验判断而非树的自动生成能力。
  • 搜索成本：Arbor 使用 20.12M–43.19M tokens，与单轨迹基线规模相当，但对于资源受限场景，树的维护和洞见传播仍有额外开销。
  • 骨干模型依赖：HTR 提供模型无关的框架结构，但实证上限受任务-骨干匹配影响。Claude Opus 4.6 在 BrowseComp 上最优，GPT-5.5 在 MLE-Bench 上最优，说明框架无法完全解耦模型能力与任务需求。
  • 评估范围：当前 AO 任务套件覆盖三类研究制品，但仍属于 ML 工程范畴。将 Arbor 推广至更广泛的科学研究场景（实验科学、理论推导、跨学科发现）需要进一步的评估和可能的架构调整。
  • 活跃技术报告：论文明确声明这是一份持续演进的技术报告，评估范围将随项目发展更新，当前结果代表特定时间点的快照。

总结与启发

核心贡献回顾

Arbor 的贡献可以从三个层次理解：

问题层次：将自主研究形式化为"自主优化（AO）"——Agent 从初始制品出发，通过迭代实验改进制品，无需逐步人工监督。这一形式化的价值在于它清晰地分离了探索性 dev 反馈（可自由使用）与验证性 test 评估（仅用于准入），从而将"研究进展"与"过拟合"区分开来。

机制层次：HTR 是核心创新。它将假设树作为持久化研究状态，每个节点绑定假设、制品版本、实验证据和蒸馏洞见。关键不在于树的存在本身，而在于洞见的双向流动：执行结果向上抽象为方向级教训，方向级约束向下影响子假设生成。这使得"失败"不再是浪费的尝试，而是压缩进树节点的可复用信息。

系统层次：协调器-执行器的架构分离解决了长时间自主研究的核心张力——战略决策需要全局视野，而实现单个假设需要短视野的工程工作。通过将两者分离，Arbor 避免了低级执行追踪模糊全局研究状态，同时保持了实验结果对假设的可归因性。

对自主 AI 研究范式的深度思考

Arbor 代表了自主研究 Agent 从"持久任务执行"向"累积性学习"的范式转变。这一转变的本质是：研究的价值不在于单次实验的结果，而在于实验序列如何重塑后续搜索空间。人类研究者的核心优势正是这种跨时间的认识论积累——每次失败都在压缩可能性空间，每次成功都在建立新的构建基础。

消融实验揭示了一个深刻洞见：去掉洞见传播比去掉树结构本身更有害。这说明层级组织只是必要条件，而非充分条件。树的价值来自其上积累的语义记忆，而非其拓扑结构。这与认知科学中"图式"（schema）的概念高度呼应——专家的优势不在于记住更多事实，而在于拥有能将新信息快速整合进现有知识结构的抽象模式。

从更宏观的视角看，Arbor 的设计哲学指向了一个关于 AI 研究能力的根本问题：自主研究需要的不是更强的单次推理，而是更好的证据组织机制。当前 LLM 的上下文窗口虽然越来越大，但线性增长的上下文无法替代树形的知识组织——前者是信息的堆积，后者是知识的精炼。

跨任务迁移实验（BrowseComp 优化的 harness 在 HLE 和 DeepSearchQA 上同样有效）进一步表明，HTR 发现的不是任务特定的技巧，而是具有更广泛适用性的设计原则。这与人类研究者在一个领域积累的方法论能迁移到相关领域的现象类似。

然而，Arbor 也揭示了当前 AI 研究的边界：当问题需要全新的高层概念框架时，树形精炼的能力受限。这暗示下一代自主研究系统可能需要某种"元认知"能力——不仅能在已有框架内精炼，还能识别何时需要跳出框架、重新定义问题。这或许是通向真正"通才自主研究"的最后一公里。

对实践者的启示

  • 设计研究系统时，持久化研究状态比更大的上下文窗口更重要：树形结构将证据压缩为可复用洞见，而非简单堆积原始信息。
  • Dev/Test 分离是自主搜索的必要条件，而非可选项：没有 held-out 门控，迭代优化几乎必然导致对反馈信号的过拟合。
  • 失败的实验应被设计为一等公民：HTR 的洞见传播机制使失败节点成为约束未来搜索的宝贵信息，而非被丢弃的噪声。
  • 协调器-执行器分离是可扩展性的关键：战略决策与局部实现的分离允许并行探索，同时保持全局研究状态的一致性。
