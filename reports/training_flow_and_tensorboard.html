Rollout · Reward · 参数更新 · TensorBoard 指标 — 基于 Qwen3.5-35B-A3B 实际配置

0. 总体架构

┌──────────────────────────────────────────────────────────────────────┐ │ Fully Async RL Training │ │ Rollouter Node(s) Trainer Node(s) │ │ ───────────────── ────────────── │ │ sglang async engine ──batch──▶ Megatron actor │ │ rl_factory_agent_loop ──batch──▶ GRPO advantage │ │ HTTP tool calls ──batch──▶ GSPO actor update │ │ judge API reward ──batch──▶ weight sync back to rollouter │ └──────────────────────────────────────────────────────────────────────┘ 关键特性： adv_estimator = grpo # 无 critic 模型，不需要价值函数 loss_mode = gspo # 双边裁剪策略梯度 rollout_mode = async # 异步多轮工具调用 use_kl_in_reward = False # KL 作为 loss term，不加入 reward use_kl_loss = True # kl_loss_coef = 0.02 staleness_threshold = 0.5 # 允许最多半版本参数延迟
ℹ️
无 Critic 模型 本项目使用 GRPO（Group Relative Policy Optimization）而非 PPO，没有独立的 critic value network。 优势估计通过同一 prompt 的多个响应组内归一化得到，不需要 V(s) 估计。 TensorBoard 中 critic/ 前缀的指标仅是代码命名惯例，指 score/reward/advantage 统计，并非 critic 模型输出。

训练步骤顺序

fit_step(): 1. _fit_generate # 从 rollouter queue 取 rollout batch 2. _fit_compute_reward # 提取 reward_tensor（judge API 已在 rollout 阶段完成） 3. _fit_compute_log_prob # 计算 old_log_probs（decoupled mode） 4. _fit_compute_ref_log_prob # ref policy log_probs（KL loss 用） 5. _fit_compute_critic # GRPO 模式：空操作（use_critic=False） 6. _fit_compute_advantage # GRPO 组内归一化，得到 advantages & returns 7. _fit_update_critic # GRPO 模式：空操作（use_critic=False） 8. _fit_update_actor # GSPO loss + KL loss → 梯度更新 9. _fit_update_weights # trigger_parameter_sync_step=4 时同步到 rollouter 10. _fit_collect_metrics # compute_data_metrics + compute_timing_metrics → TensorBoard

2.3 KL 惩罚配置

⚠️
KL 不加入 Reward，作为 Loss 项 use_kl_in_reward=False，所以 token_level_rewards = token_level_scores（不扣 KL）。 KL 散度通过 use_kl_loss=True（kl_loss_coef=0.02）加入 actor loss，在参数更新阶段约束策略漂移。

3. 参数更新（GRPO + GSPO）

3.1 优势估计：GRPO（无 Critic）

# 每个 prompt 采样 n=8 个响应，构成一个 group scores = token_level_rewards.sum(dim=-1) # shape (bs,) for prompt_idx in group: group_mean = mean(scores[group]) group_std = std(scores[group]) if norm_adv_by_std_in_grpo: advantage_i = (score_i - group_mean) / (group_std + ε) # 标准 GRPO else: advantage_i = score_i - group_mean # Dr.GRPO # advantage 广播到 response_mask=1 的所有 token advantages = advantage_i.unsqueeze(-1) * response_mask # shape (bs, seq_len) returns = advantages # GRPO: returns == advantages（无 bootstrapped value）
✅
GRPO 核心思想 高于组均值的响应获得正优势（被强化），低于均值的获得负优势（被抑制）。 不需要 critic 模型估计 V(s)，完全由 reward 信号驱动。 组内归一化天然控制了 reward scale，比 PPO 更稳定。

3.2 策略损失：GSPO（双边裁剪）

# loss_mode = "gspo" # clip_ratio_low = 0.2, clip_ratio_high = 0.28, clip_ratio_c = 10.0 ratio = exp(log_prob_new - log_prob_old) # 重要性权重 π_θ / π_old # GSPO：双边不对称裁剪 if advantage > 0: clipped = clip(ratio, 1 - clip_ratio_low, 1 + clip_ratio_high) else: clipped = clip(ratio, 1 - clip_ratio_high, 1 + clip_ratio_low) pg_loss = -min(ratio * adv, clipped * adv) # 取悲观估计 pg_loss = agg_loss(pg_loss, response_mask, loss_agg_mode="seq-mean-token-mean") # KL loss（约束策略与 ref policy 之间的散度） kl_loss = kl_penalty(log_prob_new, ref_log_prob) * response_mask kl_loss = agg_loss(kl_loss, response_mask) total_loss = pg_loss + kl_loss_coef * kl_loss # kl_loss_coef = 0.02

本节说明：若把 adv_estimator=grpo 改为 adv_estimator=gae，训练流程中哪些环节会发生变化。

3b.1 fit_step 步骤对比

3b.2 GAE 优势计算（逐 token）

代码入口：compute_gae_advantage_return()，core_algos.py:215

# Step 1：critic_wg.compute_values(batch) # critic 模型对每个 token 位置做前向推理，输出 V(s_t) values: shape (bs, response_length) # 每个 response token 有独立 V(s_t) values = values * response_mask # tool response token 位置置 0 # Step 2：GAE 逆向递推（从最后一个 token 往前） nextvalues = 0 lastgaelam = 0 for t in reversed(range(response_length)): # TD-error：当前 reward + 折扣下一步价值 - 当前价值 delta = token_level_rewards[:, t] + gamma * nextvalues - values[:, t] # GAE 递推（指数加权 TD-error 序列） lastgaelam = delta + gamma * lam * lastgaelam # tool response token 不参与 GAE 递推（mask=0 保持上一步值） nextvalues = values[:, t] * response_mask[:, t] + (1 - response_mask[:, t]) * nextvalues lastgaelam = lastgaelam * response_mask[:, t] + (1 - response_mask[:, t]) * lastgaelam advantages = stack(reversed(advantages_reversed)) # shape (bs, response_length) returns = advantages + values # critic 训练目标 advantages = masked_whiten(advantages, response_mask) # 全局白化归一化
ℹ️
GAE 与 GRPO 的核心区别 GAE 中 A_t 通过逐步 TD-error 加权得到，序列中每个 token 的 advantage 不同，前期 token 受后续多个 TD-error 影响。 gamma（折扣因子）和 lam（GAE λ）控制远近 reward 的权重。 GRPO 中没有这两个概念——它直接把 outcome reward 标量广播给整条轨迹。

3b.3 Critic 更新（Value Function Training）

# critic_wg.update_critic(batch) → dp_critic.update_critic() → core_algos.compute_value_loss() for epoch in ppo_epochs: for mini_batch in mini_batches: vpreds = critic_model.forward(input_ids) # 重新前向推理得到当前 V(s_t) # value loss with clipping（防止 critic 更新过猛） vpred_clipped = clip(vpreds, values - cliprange_value, values + cliprange_value) vf_loss1 = (vpreds - returns) ** 2 # 原始 MSE vf_loss2 = (vpred_clipped - returns) ** 2 # 裁剪后 MSE vf_loss = 0.5 * mean(max(vf_loss1, vf_loss2), response_mask) # 取悲观估计 # 记录指标（会写入 TensorBoard） metrics["critic/vf_loss"] += vf_loss metrics["critic/vf_clipfrac"] = fraction(vf_loss2 > vf_loss1) metrics["critic/vpred_mean"] = masked_mean(vpreds, response_mask) vf_loss.backward() grad_norm = clip_grad_norm_(critic_params, max_norm=grad_clip) metrics["critic/grad_norm"] = grad_norm

⚠️
PPO 的额外资源开销 PPO 需要额外维护一个 critic 模型（通常与 actor 同尺寸或更小）， 每步需要额外进行 critic forward（compute_values）和 critic backward（update_critic）。 对于 Qwen3.5-35B-A3B 这样的大模型，critic 会显著增加显存和计算量。 这是 GRPO 相比 PPO 的核心优势之一——无需 critic，训练资源减半。

Critic 指标如何解读（实际输出的 12 个）

问题看哪个指标期望趋势
模型总体效果是否在提升？ critic/score/mean 稳步上升（奖励增加）
模型是否在区分好坏响应？ critic/advantages/max - critic/advantages/min 差值适中；过小说明组内无差异（学习信号弱）
KL 惩罚是否有效（use_kl_in_reward=True 场景）？ critic/rewards vs critic/score 本项目两者相同；若开 KL，rewards 应低于 score
训练是否稳定，没有 reward hacking？ critic/score/max 不应出现爆炸式增长
响应长度是否合理？ response_length/* + critic/score/mean CoT 长度增加不应带来 score 等比例增加
