第6章 模型预训练

大语言模型 · 预训练目标 · 分布式训练 · 训练稳定性 · 效率分析 · 代码实践

本章系统介绍大语言模型预训练的全流程：从自监督预训练目标的设计，到分布式训练技术（3D并行、ZeRO优化），再到混合精度训练与激活重计算，最后给出完整的参数量/运算量/显存估算公式与代码实践。

6.1 预训练任务

大规模预训练的核心在于设计合适的自监督任务，使模型从海量无标注文本中学习语义知识与世界知识。目前常用的预训练任务分为三大类：语言建模（LM）、去噪自编码（DAE）以及混合去噪器（MoD）。

任务类型 子类型 代表模型 输入形式 优化目标 适用架构
语言建模 (LM) 因果语言模型 (CLM) GPT-3, PaLM, LLaMA 完整序列 u $\sum_{t=1}^{T}\log P(u_t|u_{<t})$ Decoder-only
前缀语言建模 (Prefix LM) T5, GLM 前缀 + 后缀 $\sum_{t=k+1}^{T}\log P(u_t|u_{<t})$ Prefix Decoder

去噪自编码 (DAE) 掩码语言建模 BERT, T5, FLAN-T5 损坏文本 $u \setminus \tilde{u}$ $\log P(\tilde{u}|u \setminus \tilde{u})$ Encoder-Decoder

6.1.1 因果语言模型（CLM）

CLM 是目前绝大多数大语言模型（GPT-3、PaLM、LLaMA 等）采用的预训练任务，核心思想是自回归地预测下一个词元。给定词元序列 $\mathbf{u} = \{u_1, \ldots, u_T\}$，训练目标为最大化如下对数似然：

$$\mathcal{L}_{\text{LM}}(\mathbf{u}) = \sum_{t=1}^{T} \log P(u_t \mid \mathbf{u}_{<t}) \tag{6.1}$$

其中 $\mathbf{u}_{<t} = \{u_1, \ldots, u_{t-1}\}$ 为当前位置之前的所有词元。该损失本质上是一个多任务学习过程——预测"好看"时模型在做情感分析，预测"一块糖"时在做算术推理。

Ilya Sutskever 的解释：通过对词元更精准的预测，模型就可以更好地理解文本、建模世界语义知识。GPT-4 predicts the next word better.

前缀语言建模（Prefix LM）

Prefix LM 专为前缀解码器架构设计。训练时将序列按随机位置 $k$ 切分为前缀 $\mathbf{u}_{\text{prefix}}$ 和后缀 $\mathbf{u}_{\text{suffix}}$，仅对后缀词元计算损失：

$$\mathcal{L}_{\text{Prefix}}(\mathbf{u}) = \log P(\mathbf{u}_{\text{suffix}} \mid \mathbf{u}_{\text{prefix}}) = \sum_{t=k+1}^{T} \log P(u_t \mid \mathbf{u}_{<t}) \tag{6.2}$$

由于未将所有词元损失纳入计算，相同数据规模下 Prefix LM 训练的模型性能通常稍逊于标准 CLM。

中间填充（Fill-In-the-Middle，FIM）

FIM 将序列划分为前缀、中间、后缀三部分，将中间部分移至序列末尾，训练模型恢复中间缺失内容的能力：

$$\mathcal{L}_{\text{FIM}}(\mathbf{u}) = \log P(\mathbf{u}_{\text{prefix}}) + \log P(\mathbf{u}_{\text{suffix}} \mid \mathbf{u}_{\text{prefix}}) + \log P(\mathbf{u}_{\text{middle}} \mid \mathbf{u}_{\text{prefix}}, \mathbf{u}_{\text{suffix}}) \tag{6.3}$$

FIM 常作为标准 CLM 的辅助任务，广泛用于代码预训练（如 Code LLaMA、StarCoder），提升代码补全能力。

6.1.2 去噪自编码（DAE）

DAE 通过随机替换/删除操作生成损坏文本 $\mathbf{u} \setminus \tilde{\mathbf{u}}$，训练模型恢复被替换/删除的片段 $\tilde{\mathbf{u}}$：

$$\mathcal{L}_{\text{DAE}}(\mathbf{u}) = \log P(\tilde{\mathbf{u}} \mid \mathbf{u} \setminus \tilde{\mathbf{u}}) \tag{6.4}$$

代表模型：BERT（掩码比例15%）、T5（掩码整个片段）、FLAN-T5。相比 CLM，DAE 实现更复杂，需设定词元替换策略、片段长度、替换比例等额外超参数。

6.1.3 混合去噪器（MoD / UL2 Loss）

MoD 将 LM 和 DAE 统一建模为不同类型的去噪任务，通过特殊前缀词元（[S]、[R]、[X]）引导模型选择对应去噪器：

[S] S-去噪器

等同前缀语言建模，训练模型基于前缀生成后缀

掩码比例：0%

[R] R-去噪器

短片段掩码，每片段3-5个词元，约15%掩码比例

掩码比例：~15%

[X] X-去噪器

长片段（12+词元）或高比例（~50%）掩码，任务难度最高

掩码比例：~50%

代表模型：UL2、PaLM 2。

LLaMA CausalLM 损失计算代码

以 Transformers 库中 LlamaForCausalLM 为例，展示 CLM 损失的完整计算流程：

class LlamaForCausalLM(LlamaPreTrainedModel):
    def __init__(self, config):
        super().__init__(config)
        self.model = LlamaModel(config)
        self.vocab_size = config.vocab_size
        # 将最后一层隐状态映射为词汇表中每个词元的 logit
        self.lm_head = nn.Linear(config.hidden_size, config.vocab_size, bias=False)

    def forward(
        self,
        input_ids: torch.LongTensor = None,
        attention_mask: Optional[torch.Tensor] = None,
        position_ids: Optional[torch.LongTensor] = None,
        labels: Optional[torch.LongTensor] = None,
        **kwargs,
    ) -> Union[Tuple, CausalLMOutputWithPast]:
        # Step 1: 通过 LlamaModel 获取最后一层隐状态
        outputs = self.model(
            input_ids=input_ids,
            attention_mask=attention_mask,
            position_ids=position_ids,
        )
        hidden_states = outputs[0]

        # Step 2: 映射头将隐状态转化为词汇表 logits
        logits = self.lm_head(hidden_states).float()

        loss = None
        if labels is not None:
            # Step 3: 移位对齐 —— 预测位置 t 的词元，标签为位置 t+1
            # shift_logits: [B, T-1, V]，shift_labels: [B, T-1]
            shift_logits = logits[..., :-1, :].contiguous()
            shift_labels = labels[..., 1:].contiguous()

            # Step 4: 展平后计算交叉熵损失（等价于 -log P(u_t | u_{<t}) 的均值）
            loss_fct = CrossEntropyLoss()
            shift_logits = shift_logits.view(-1, self.config.vocab_size)
            shift_labels = shift_labels.view(-1)
            shift_labels = shift_labels.to(shift_logits.device)
            loss = loss_fct(shift_logits, shift_labels)

        return CausalLMOutputWithPast(loss=loss, logits=logits)
关键设计：移位（Shift）对齐
shift_logits = logits[..., :-1, :] 取位置 0~T-2 的预测，shift_labels = labels[..., 1:] 取位置 1~T-1 的真实词元，实现"用前 t 个词预测第 t+1 个词"的自回归训练目标。

6.2 优化参数设置

大语言模型预训练的优化设置与传统神经网络有所不同，需要在批次大小、学习率调度、优化器选择和稳定化技术等方面进行精心设计。

6.2.1 批次大小

大模型预训练通常将批次大小设置为 1M 到 4M 个词元，并采用动态批次调整策略——训练过程中逐渐增大批次大小：

  • GPT-3：32K → 3.2M 词元
  • PaLM-540B：1M → 4M 词元

小批次在训练早期加速损失下降（高频更新），大批次在后期使损失下降更稳定（低噪声梯度）。

6.2.2 学习率调度：Warmup + Cosine

大模型预训练通常采用两阶段学习率调度策略：

预热阶段（Warmup）

占总训练步数的 0.1% ~ 0.5%，学习率从极小值（如 $10^{-8}$）线性增加到峰值。

目的：参数随机初始化时梯度较大，小学习率防止训练初期震荡。

衰减阶段（Decay）

学习率从峰值衰减至 峰值的 10%，防止在最优点附近震荡。

常见策略：余弦衰减（Cosine）、线性衰减、平方根倒数衰减。

三种衰减策略对比：

  • 余弦衰减（Cosine Decay）：$\eta_t = \eta_{\min} + \frac{1}{2}(\eta_{\max} - \eta_{\min})(1 + \cos(\pi t / T))$，最常用，绝大多数模型采用（GPT-3、LLaMA、BLOOM 等）
  • 线性衰减：学习率线性降低，OPT 等模型使用
  • 平方根倒数衰减：$\eta_t \propto 1/\sqrt{t}$，PaLM、T5 使用 Adafactor 时采用

6.2.3 优化器

大语言模型训练通常采用 Adam 或其变种 AdamW。Adam 的核心机制：

  • 一阶矩（动量）：使用历史梯度加权平均代替当前梯度，缓解随机性带来的损失震荡
  • 二阶矩（自适应学习率）：用梯度的加权"方差"对梯度归一化，防止梯度过小

大模型训练常用超参数：$\beta_1 = 0.9$，$\beta_2 = 0.95$，$\epsilon = 10^{-8}$。

Adafactor（谷歌提出）：Adam 的显存节省变种，通过矩阵分解存储二阶矩，被 PaLM、T5 使用。超参数：$\beta_1 = 0.9$，$\beta_2 = 1.0 - k^{-0.8}$（$k$ 为训练步数）。

6.2.4 稳定优化技术

梯度裁剪（Gradient Clipping）

当梯度模长超过阈值时按阈值截断，防止损失突增。大模型训练通常设置阈值为 1.0（Baichuan-2 为 0.5）。

权重衰减（Weight Decay）

AdamW 在每次参数更新时引入衰减系数，通常设置为 0.1，防止过拟合并稳定训练。

训练恢复（Checkpointing）

每隔固定步数保存模型存档点。训练异常（损失激增）时回退到前一存档点并跳过问题数据。

Dropout

大模型训练中很少使用。原因：大规模训练数据和归一化结构已提供足够正则化，Dropout 反而影响效率。

6.3 可扩展的训练技术

随着模型参数规模扩展，高效训练面临两大核心挑战：如何提高训练效率（吞吐量）和如何将庞大模型加载到有限 GPU 显存中。本节介绍 3D 并行训练、ZeRO 优化器、激活重计算和混合精度训练四大技术。

6.3.1 3D 并行训练

3D 并行是数据并行（DP）+ 流水线并行（PP）+ 张量并行（TP）三种策略的组合，GPU 总数满足：

$$N_{\text{GPU}} = N_D \times N_P \times N_T$$

其中 $N_D$ 为数据并行数，$N_P$ 为流水线并行数，$N_T$ 为张量并行数。

数据并行（DP）

是什么：模型参数复制到所有 GPU，训练数据平均分配。

怎么做：各 GPU 独立前/反向传播，AllReduce 平均梯度后统一更新。

优点：实现简单，PyTorch/TF 原生支持，扩展性强。

缺点：每 GPU 需存完整模型，显存冗余严重。

流水线并行（PP）

是什么：将模型不同层分配到不同 GPU，按层流水线执行。

怎么做：连续若干层放同一 GPU，配合梯度累积提高 GPU 利用率（GPU1 处理第2批时 GPU2 处理第1批）。

优点：减少层间 GPU 通信量，支持超大模型。

缺点：朴素调度存在"气泡"，需梯度累积优化。

张量并行（TP）

是什么：将参数矩阵按行/列分块，分配到多 GPU 并行计算。

怎么做：矩阵乘 $\mathbf{WH}$ 分解为 $[\mathbf{W}_1\mathbf{H}, \mathbf{W}_2\mathbf{H}]$，两 GPU 并行，最后 AllGather 合并。

分解目标：注意力层 $W_Q, W_K, W_V, W_O$ 和 FFN 层 $W_U, W_D$。

代表实现：Megatron-LM（支持行/列分块张量并行）。

6.3.2 零冗余优化器（ZeRO）

ZeRO（Zero Redundancy Optimizer）由 DeepSpeed 提出，解决数据并行中每 GPU 存储完整模型副本的冗余问题。ZeRO 将优化器状态、梯度、模型参数分级分片到各 GPU 上。

PyTorch 中对应实现称为 FSDP（Fully Sharded Data Parallel）。

ZeRO 级别 分片内容 每 GPU 显存（字节） 相比无 ZeRO 节省 说明
无 ZeRO 无分片 $16P$ 1×（基准） 模型参数2P + 梯度2P + Adam优化器(参数+动量+方差)12P
ZeRO-1 优化器状态分片 $4P + 12P/N_D$ 最多 4× 模型参数和梯度各 GPU 保留，优化器状态均摊
ZeRO-2 优化器状态 + 梯度分片 $2P + 14P/N_D$ 最多 8× 在 ZeRO-1 基础上梯度也均摊
ZeRO-3 优化器状态 + 梯度 + 参数分片 $16P/N_D$ 最多 $N_D$× 所有内容完全均摊，需要时从其他 GPU 获取
显存构成（混合精度训练，Adam 优化器，参数量 P）：
• 模型参数（FP16）：$2P$ 字节
• 模型梯度（FP16）：$2P$ 字节
• Adam 优化器：FP32 参数副本 $4P$ + 动量 $4P$ + 方差 $4P$ = $12P$ 字节
• 合计：$(2+2+4+4+4) \times P = 16P$ 字节

6.3.3 激活重计算（Gradient Checkpointing）

激活重计算（也称梯度检查点）是一种以计算换显存的技术：

  • 问题：反向传播计算 $\mathbf{W}$ 的梯度需要用到前向传播的激活值 $\mathbf{X}$（$\mathbf{Y}=\mathbf{XW}$），保存所有层激活值占用大量显存
  • 解决：前向传播时仅保留每个 Transformer 层的输入，反向传播时按需重新计算层内激活值
  • 代价：增加约 $\frac{1}{3}$ 的额外计算量（相当于额外做了一次前向传播），但显存节省显著
使用激活重计算时的运算量变化：
不使用：$6CP$（前向 $2CP$ + 反向 $4CP$）
使用后：$8CP$（额外一次前向 $2CP$）
激活值显存：从 $(16BTH + 6BTH' + 2BT^2N) \cdot L + 4BTH + 4BTV$ 简化为 $(4 + 2L)BTH + 4BTV$

6.3.4 混合精度训练（BF16/FP16）

混合精度训练同时使用半精度（2字节）和单精度（4字节）浮点数，实现显存减半、效率翻倍。

格式 字节数 符号位 指数位 尾数位 数值范围 精度 典型用途
FP32 4 1 8 23 $\pm 3.4 \times 10^{38}$ 最高 优化器状态、主参数副本
BF16 2 1 8 7 $\pm 3.4 \times 10^{38}$（与FP32相同） 中等 大模型训练首选，A100/H100支持
FP16 2 1 5 10 $\pm 65504$ 中等 早期混合精度训练，需 loss scaling
INT8 1 1 — 7 $-128$ ~ $127$ 低 量化推理（不用于训练）

BF16 vs FP16：为何大模型训练首选 BF16？

  • BF16 指数位与 FP32 相同（8位），数值范围 $\sim 10^{38}$，大模型训练中梯度值域宽，不会溢出
  • FP16 指数位仅 5 位，范围仅 $\pm 65504$，大模型训练中容易发生梯度溢出（overflow），需要 loss scaling 技巧
  • BF16 精度（7位尾数）略低于 FP16（10位尾数），但对模型训练收敛影响可忽略
  • 现代 GPU（A100、H100）原生支持 BF16 计算单元

混合精度训练流程：

  1. 保留 FP32 主参数副本（保证精度）
  2. 训练时将 FP32 参数转换为 BF16/FP16
  3. 用 BF16/FP16 执行前向传播和反向传播（占绝大部分时间）
  4. 参数更新时在 FP32 上进行优化

6.4 模型参数量计算与效率分析

本节以 LLaMA 为例，系统推导参数量、训练运算量、训练时间和显存占用的估算公式，为实际训练资源规划提供理论依据。

6.4.1 参数量计算

设词表大小 $V$，模型层数 $L$，隐层维度 $H$，FFN 中间维度 $H'$，各组件参数量如下：

组件参数量说明
输入嵌入层 $\mathbf{E} \in \mathbb{R}^{V \times H}$$VH$词表映射到 H 维向量
多头注意力（$W_Q, W_K, W_V, W_O$）× L层$4H^2 \times L$每个矩阵 $H \times H$
FFN（$W_U, W_G \in \mathbb{R}^{H \times H'}$，$W_D \in \mathbb{R}^{H' \times H}$）× L层$3HH' \times L$LLaMA 使用 SwiGLU，三个矩阵
RMSNorm（每层2个 + 最后1个）$(2H \times L) + H$归一化参数
输出层 $W_L \in \mathbb{R}^{H \times V}$$VH$映射到词表维度
$$\text{参数量} = 2VH + H + L \cdot (4H^2 + 3HH' + 2H) \tag{6.5}$$

验证（LLaMA-7B）：$V=32000, L=32, H=4096, H'=11008$

$$2 \times 32000 \times 4096 + 4096 + 32 \times (4 \times 4096^2 + 3 \times 4096 \times 11008 + 2 \times 4096) = 6{,}738{,}415{,}616 \approx 6.74 \times 10^9$$

6.4.2 训练运算量估计

设参数量 $P$，训练词元总数 $C = BT$（$B$ 为批次大小，$T$ 为序列长度），$N$ 为注意力头数，$D = H/N$ 为每头维度。

多头注意力运算量（含前向+反向）：

$$\text{运算量}_{\text{Attention}} = 12 \cdot (BT^2ND + BT^2N) \cdot L = 12CTL \cdot (H + N) \tag{6.6}$$

线性变换运算量：

$$\text{运算量}_{\text{Linear}} = 6C \times \text{线性变换参数量} \approx 6CP \tag{6.7}$$

（使用激活重计算时变为 $8CP$）

由于注意力运算量约为线性变换的 $T/(6H)$（序列长度 $T \leq H$），多头注意力运算量最多为线性变换的 $1/6$，可忽略不计。因此：

$$\text{总训练运算量} \approx 6CP \quad \text{（不含激活重计算）} \tag{6.9}$$ $$\text{总训练运算量} \approx 8CP \quad \text{（含激活重计算）}$$

示例（LLaMA-7B，$C = 10^9$ 词元）： $6 \times 6.74 \times 10^9 \times 10^9 \approx 4.04 \times 10^{19}$ FLOP

6.4.3 训练时间估计

$$\text{训练时间} = \frac{\text{运算量}}{\text{GPU 数量} \times \text{GPU 每秒浮点运算数}} \tag{6.10}$$

实际 GPU 利用率通常为理论峰值的 30%~70%。

示例（LLaMA-65B）：$P = 6.5 \times 10^{10}$，$C = 1.4 \times 10^{12}$，使用激活重计算，运算量 $= 8CP = 7.28 \times 10^{23}$ FLOP。使用 2048 张 A100（实际性能 $2 \times 10^{14}$ BF16 FLOP/s）：

$$t = \frac{7.28 \times 10^{23}}{2048 \times 2 \times 10^{14}} \approx 1.78 \times 10^6 \text{ 秒} \approx 20.6 \text{ 天}$$

与论文公布的 21 天基本一致。

6.4.4 训练显存估计

训练显存分为三部分：模型参数与优化器、激活值、其他开销。

激活值显存（不含 FlashAttention，LLaMA 为例）

$$\text{激活值} = (16BTH + 6BTH' + 2BT^2N) \cdot L + 4BTH + 4BTV \tag{6.11}$$

各优化技术下的激活值显存：

优化技术激活值显存公式
无优化$(16BTH + 6BTH' + 2BT^2N) \cdot L + 4BTH + 4BTV$
流水线并行（$N_P$）$(16BTH + 6BTH' + 2BT^2N) \cdot L/N_P + 4BTH + 4BTV$
张量并行（$N_T$）$\left[(8 + \frac{8}{N_T})BTH + \frac{6}{N_T}BTH' + \frac{2}{N_T}BT^2N\right] \times L + 4BTH + 4BTV$
激活重计算$(4 + 2L)BTH + 4BTV$

综合估算公式（ZeRO-3 + FlashAttention + 激活重计算）

$$\text{每张 GPU 显存} \approx \frac{16P}{N_D} + (4 + 2L)BTH + 12BTV + 6 \text{ (GB)} \tag{6.15}$$

训练主程序

from dataclasses import dataclass
from transformers import (
    AutoModelForCausalLM, AutoTokenizer,
    HfArgumentParser, TrainingArguments, Trainer,
)
from transformers.hf_argparser import HfArg

@dataclass
class Arguments(TrainingArguments):
    model_name_or_path: str = HfArg(default=None, help="模型路径，如 meta-llama/Llama-2-7b-hf")
    dataset: str = HfArg(default="", help="预训练数据文件路径")
    model_max_length: int = HfArg(default=2048, help="最大序列长度")
    save_only_model: bool = HfArg(default=True, help="仅保存模型参数，不保存优化器状态")
    bf16: bool = HfArg(default=True, help="使用 BF16 混合精度训练")

def train():
    parser = HfArgumentParser(Arguments)
    args = parser.parse_args_into_dataclasses()[0]

    # 加载分词器
    tokenizer = AutoTokenizer.from_pretrained(
        args.model_name_or_path,
        model_max_length=args.model_max_length,
        padding_side="right",
        add_eos_token=False,
    )

    # 加载模型，启用 FlashAttention-2 加速注意力计算
    model = AutoModelForCausalLM.from_pretrained(
        args.model_name_or_path,
        attn_implementation="flash_attention_2"
    )

    # 初始化 Trainer 并开始训练
    trainer = Trainer(
        model=model,
        args=args,
        tokenizer=tokenizer,
        train_dataset=PTDataset(args, tokenizer),
    )
    trainer.train()
    trainer.save_model(args.output_dir + "/checkpoint-final")
    trainer.save_state()

if __name__ == "__main__":
    train()

预训练数据集类

import torch
from datasets import load_dataset
from itertools import chain

class PTDataset:
    def __init__(self, args, tokenizer):
        self.block_size = args.model_max_length
        self.tokenizer = tokenizer
        self.input_ids = self.group_texts(self.process())
        self.labels = self.input_ids.copy()

    def __len__(self): return len(self.input_ids)
    def __getitem__(self, i): return dict(input_ids=self.input_ids[i], labels=self.labels[i])

    def encode(self, examples):
        """分词，截断到 block_size"""
        return self.tokenizer(examples["text"], truncation=True)

    def group_texts(self, examples):
        """将所有文本拼接后按 block_size 切块，避免填充浪费"""
        concatenated = list(chain(*examples))
        total = (len(concatenated) // self.block_size) * self.block_size
        return [
            torch.stack(concatenated[i:i + self.block_size])
            for i in range(0, total, self.block_size)
        ]

    def process(self):
        """加载数据集、分词、返回 token id 列表"""
        input_ids = []
        dataset = load_dataset('text', data_files=self.args.dataset)['train']
        tokenized = dataset.map(self.encode, batched=True, remove_columns='text')
        for example in tokenized:
            if len(example['input_ids']) > 0:
                input_ids.append(torch.tensor(example['input_ids']))
        return input_ids

DeepSpeed ZeRO-3 关键参数说明：
• stage3_max_live_parameters：控制同时驻留显存的参数量，越小越省显存但通信开销越大
• stage3_max_reuse_distance：控制参数缓存复用距离，越小越省显存
• stage3_gather_16bit_weights_on_model_save：true 则保存时合并分片（保存慢但加载方便），false 则分片保存（需用 DeepSpeed 脚本合并）

适用场景与扩展建议

上述代码（DP + ZeRO）适用于：

  • 模型大小 不超过 30B
  • GPU 数量 少于 16 张

如需在 128~2048 张 GPU 上训练 70B+ 模型，需启用完整 3D 并行（DP + PP + TP），推荐使用 Megatron-LM。硬件上还需要：

  • 单机内：NVLink + NVSwitch（GPU 间高速互联）
  • 跨机器：InfiniBand（高性能网络互联）
