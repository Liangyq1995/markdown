Function-Aware Fill-in-the-Middle as Mid-Training for Coding Agent Foundation Models

1. 概述

标题Function-Aware Fill-in-the-Middle as Mid-Training for Coding Agent Foundation Models
核心问题coding agent 需把外部工具返回值整合进持续推理，而标准从左到右代码预训练只在正向方向暴露该能力——本文在 pretraining 与 post-training 之间补一个 mid-training 阶段，用 function-aware FIM 安装与 agent 循环结构同构的归纳偏置。
作者Yubo Wang, Jiarong Liang (等贡献), Yuxuan Zhang, Xuye Liu, Cong Wei, Yuyu Zhang, Ping Nie, Wenhu Chen
机构University of Waterloo · University of British Columbia · NVIDIA · Verdent AI · Vector Institute
开源地址https://github.com/TIGER-AI-Lab/FIM-Midtraining

coding agent 解决真实软件工程问题的能力，过去几乎完全由 post-training 阶段合成 agent 轨迹数据（SWE-Gym、R2E-Gym、SWE-Smith）驱动，而其底座 code LLM 只用 next-token prediction 与随机 span FIM 在互联网级代码上训练。作者指出在 pretraining 与 post-training 之间存在一个训练时间缺口：底座模型从未被针对「agentic post-training 之后将要求的条件化结构」显式优化过。本文把这个缺口当作机会，设计一个专门的 mid-training 阶段，在引入 agent 专用数据之前先对齐 agent 相关的归纳偏置。

作者的核心观察是：agent 的一步（context → action → 外部计算的 return → continuation）与一个函数调用点（pre-call 绑参 → call → callee 计算的 return → post-return 消费）在结构上同构。这种条件化结构在普通代码中天然以互联网规模存在。据此提出 function-aware FIM mid-training：用程序依赖图（PDG）分析与复杂度-可推断性双准则（complexity–inferability double criterion）挑选被 mask 的函数作为自监督目标，并在 FIM middle span 内嵌入 chain-of-thought rationale，使模型学到「先推理再产出一致代码」的 think-then-act 模式。该方法与 base model 无关（不依赖某个参考模型的预测分数），便于做跨基座泛化分析。

关键数字：968 个去污 GitHub 仓库 → ≈78K 自包含 Python 文件 → ≈400K FIM 样本（320K 单函数 / 60K pair / 20K triple），≈2.6B token（Qwen2.5-Coder tokenizer）。在 Qwen2.5-Coder-Instruct 7B/14B 与 Qwen3-8B 上各做 1 epoch mid-training，随后接现有 agentic post-training 管线不改：

  • SWE-Bench-Verified：+2.8 / +3.0 / +3.2（7B / 14B / Qwen3-8B）；
  • SWE-Bench-Lite：+3.7 / +4.0 / +5.4（同三模型）；
  • SWE-Smith 配对 7B 上 Verified +5.3；
  • 仅含 Python 代码的语料还跨域恢复 τ-bench +3.9、BFCL +2.4、LiveCodeBench +11.1。

2. 研究背景与动机

2.1 coding agent 的训练范式与缺口

coding agent 已从研究演示走向部署系统。其进展几乎完全由 post-training 阶段合成 agent 轨迹数据的扩展驱动：SWE-Gym、R2E-Gym、SWE-Smith 等 pipeline 在 issue-resolution 任务上策划或合成模仿人类/LLM 行为的轨迹。这些 pipeline 起步的底座通常是用 next-token prediction（部分加随机 span FIM）在互联网级代码上训练的 code LLM（Qwen2.5-Coder、DeepSeek-Coder、StarCoder 等）。作者在 pretraining 与 post-training 之间识别出一个「训练时间缺口」：底座模型很少被针对 post-training 之后将要求的条件化结构优化。本文把这个缺口当作机会，设计一个专门的 mid-training 阶段，在引入 agent 专用数据前先对齐 agent 相关的归纳偏置。

2.2 FIM 相关工作与随机 span 的三重不足

fill-in-the-middle 目标并不新；现代 code LLM 把随机 span FIM 混进 pretraining。但作者论证随机 span FIM 与 agentic 条件化对齐不佳，给出三点理由：

  1. span 边界语法上任意：多数被 mask 的 span 切穿表达式或残缺语句，对函数级依赖的信号很弱；
  2. 无推理监督：模型直接填 span，没有镜像 agent「先想再行动」的中间 rationale；
  3. 目标被 pretraining 溶解：到 post-training 开始时，FIM 赋予的结构先验已被数万亿无关 token 摊薄。

本文逐一回应：(i) 用 PDG 分析在函数粒度选 mask 目标；(ii) 在 FIM middle span 内嵌入 CoT rationale；(iii) 把目标放在专门的 mid-training 阶段，把信号集中在 agentic post-training 之前。

2.3 结构同构洞察

agent 在第 $t$ 步采样 $a_t \sim \pi(a_t \mid h_t)$，观察 $o_{t+1} \sim p(o_{t+1} \mid h_t, a_t)$（由外部过程产生），并条件于整条轨迹继续。这一四元分解——context、action、外部计算的 return、continuation——正是函数调用点的分解：建立意图并绑参的 pre-call 代码、调用本身、由当前作用域外代码产生的返回值、消费返回值的下游代码。一个被训练去双向推理函数级依赖的模型，必须学会从 caller 上下文与下游用法重建 callee 行为——这恰是给定 history 与工具返回去预测 agent continuation 所需的同一能力。需强调这是结构对应而非字面对应：FIM 训练条件于给定 suffix，而 agent 推理是生成 suffix，但前者诱导的表示应可迁移到后者（论文用实验验证）。

3. 核心方法

3.3 mask 选择双准则与公式

对每个 $v \in V$ 定义复杂度分数 $\hat{H}(v)$，由三个结构量归一化加权和构成：

$$\hat{H}(v) = w_\ell\, \phi(\mathrm{LoC}(v), c_\ell) + w_c\, \phi(\mathrm{CC}(v), c_c) + w_d\, \phi(D(v), c_d),$$

其中 $\mathrm{LoC}$ 为代码行数、$\mathrm{CC}$ 为 McCabe 圈复杂度、$D$ 为控制流最大嵌套深度，归一化函数 $\phi(x, c) = \min(x/c,\, 2)$（软上限）。默认 caps $(c_\ell, c_c, c_d) = (50, 10, 5)$，weights $(w_\ell, w_c, w_d) = (0.4, 0.4, 0.2)$。

继而定义可推断性分数 $\hat{I}(v)$，聚合五个上下文导出信号，近似 $v$ 的函数体与文件其余部分的互信息：

$$\hat{I}(v) = \alpha\, C_{\mathrm{caller}}(v) + \beta\, C_{\mathrm{callee}}(v) + \gamma\, C_{\mathrm{sig}}(v) + \delta\, C_{\mathrm{doc}}(v) + \varepsilon\, C_{\mathrm{class}}(v).$$

五个分量含义：$C_{\mathrm{caller}}$ 衡量调用点参数特异性、$C_{\mathrm{callee}}$ 统计 $v$ 调用的文件内函数数、$C_{\mathrm{sig}}$ 聚合类型注解与命名描述性、$C_{\mathrm{doc}}$ 标记 docstring 是否存在、$C_{\mathrm{class}}$ 统计类内兄弟方法。默认混合权重 $(\alpha, \beta, \gamma, \delta, \varepsilon) = (0.30, 0.25, 0.20, 0.10, 0.15)$。作者强调每个分量都是手工设计的代理量：一个学习到的可预测性分数会把选择耦合到某个参考模型，从而复杂化跨基座泛化分析。

将 $\hat{H}$ 与 $\hat{I}$ 以调和平均形式结合，并乘以一侧难度惩罚 $\rho(\Delta(v))$，得最终 FIM 分数：

$$\mathrm{FIM}(v) = \frac{\hat{H}(v)\,\hat{I}(v)}{\hat{H}(v) + \hat{I}(v) + \varepsilon} \cdot \rho(\Delta(v)).$$

调和平均迫使 $\hat{H}$ 与 $\hat{I}$ 同时较大、惩罚失衡；$\rho$ 下权重即便给定完整上下文仍困难的目标（否则是不可学噪声）。其中残差难度 $\Delta(v)$ 与惩罚 $\rho(\Delta)$ 定义为：

$$\Delta(v) = \max\left(0,\, \frac{\hat{H}(v) - \hat{I}(v)}{\hat{H}(v) + \varepsilon}\right) \in [0, 1),$$

$$\rho(\Delta) = \begin{cases} 1, & \Delta \le \tau_d, \\ \exp\left(-\,\frac{(\Delta - \tau_d)^2}{2\sigma^2}\right), & \Delta \gt \tau_d. \end{cases}$$

单函数选择用 $\tau_d = 0.50$、$\sigma = 0.20$，阈值 $\tau_{\mathrm{FIM}} = 0.08$、$\tau_{\hat{H}} = 0.15$。该非对称设计反映目标本身的不对称：平凡易目标已被硬过滤移除，故无需额外奖励高可推断性；而即便有完整上下文仍困难的目标则须被下权重。

算例：Calculator.total 的打分走查

目标函数为 Calculator.total，其结构量为 LoC = 10、CC = 5、D = 3。代入式 (1)：

$$w_\ell\,\phi(10,50) = 0.4 \times 0.20 = 0.08,\quad w_c\,\phi(5,10) = 0.4 \times 0.50 = 0.20,\quad w_d\,\phi(3,5) = 0.2 \times 0.60 = 0.12,$$

$$\hat{H}(\mathrm{total}) = 0.08 + 0.20 + 0.12 = 0.40.$$

五个可推断性分量：$C_{\mathrm{caller}} = 0.20$（唯一 in-file caller mean 无参调用，$0.60/3$），$C_{\mathrm{callee}} = 0.50$（调用 is_int 与 add，$2/4$），$C_{\mathrm{sig}} = 0.50$（返回类型 $+0.30$、命名 $+0.20$），$C_{\mathrm{doc}} = 0.5$（有 docstring），$C_{\mathrm{class}} = 0.90$（三个兄弟 $3/5$ 加 __init__ bonus $+0.30$）；加权和 $\hat{I}(\mathrm{total}) = 0.06+0.13+0.10+0.05+0.14 = 0.48$。残差 $\Delta = \max(0,(0.40-0.48)/0.40) = 0$，故 $\rho = 1$，最终

$$\mathrm{FIM}(\mathrm{total}) = \frac{0.40 \times 0.48}{0.40 + 0.48} \approx 0.22 \;\ge\; \tau_{\mathrm{FIM}} = 0.08 \;\Rightarrow\; \text{selected}.$$

3.4 多函数组选择

真实代码补丁常跨多个相关函数。为此扩展到 mask $k=2$ 或 $k=3$ 个结构上相连的函数组。组分数在单函数调和平均之上再乘一个耦合项 $Coup(G)$：

$$\mathrm{FIM}(G) = Coup(G) \cdot \frac{\hat{H}(G)\,\hat{I}(G)}{\hat{H}(G) + \hat{I}(G) + \varepsilon} \cdot \rho_G(\Delta(G)),$$

$$Coup(G) = w_c\,\frac{|E^{\mathrm{call}}_G|}{k(k-1)} + w_s\,\frac{|E^{\mathrm{sib}}_G|}{\binom{k}{2}} + w_{st}\,\mathrm{Jacc}_G,$$

其中 $\hat{H}(G)$ 为组内成员复杂度均值、$\mathrm{Jacc}_G$ 为组内对之间所访问实例属性（self.x）集合的平均 Jaccard 相似度，$(w_c, w_s, w_{st}) = (0.50, 0.20, 0.30)$。关键：$\hat{I}(G)$ 在联合 mask 假设下重算——组内 caller/callee/sibling 贡献被排除、成员 docstring 贡献为零，防止组凭组内引用获得虚高分数。八种拓扑模式：$k=2$ 有 caller-callee、co-callee、sibling-coupled、mutual-call；$k=3$ 有 call-chain、hub、fan-in、class-triad。候选组须在 $E_{\mathrm{call}} \cup E_{\mathrm{sib}}$ 中构成连通子图。

3.5 FIM 训练目标与 CoT 增强

对每个被选中目标运行三阶段 pipeline：Generate，Gemini-3-Flash 仅看被 mask 的文件，逐步产出 rationale 与候选函数体，不接触 ground-truth body；Filter，另一个 Gemini-3-Flash judge 就可行性与五个质量维度给 (rationale, candidate body) 打分，保留得分最高的 ≈400K 样本；Format，把保留的 pair 放入 FIM middle span，rationale 在 body 之前：

<fim_prefix>  prefix
<fim_suffix>  suffix
<fim_middle>  rationale  body

模型因此被训练成「先推理、再产出一致代码」，镜像 agent 一步的 think-then-act 结构。ground-truth body 仅作过滤锚，从不出现在训练目标中。mid-training 用标准 FIM loss 作用于 middle span（rationale + body），pack 到模型原生上下文长度并使用其原生 FIM sentinel token；超参：AdamW、lr $1.0\times10^{-5}$、cosine、warmup ratio 0.1、weight decay 0.05、1 epoch、有效 batch 128、序列长度 32,768、bf16。

论文用 self-CoT 变体（由被训练模型自身生成 rationale）隔离 FIM 结构贡献与 CoT 蒸馏贡献，见消融 4.3。

3.6 训练算法伪代码

Algorithm 1：单函数 FIM 目标选择（per file）

Require: 源文件 s；阈值 τ_d, τ_FIM, τ_Ĥ；文件行数界 [L_min, L_max]；LoC 界 [ℓ_min, ℓ_max]

if Lines(s) ∉ [L_min, L_max] then return ∅   // file-level pre-filter

T ← ParseAST(s)

V, E_call, E_sib ← BuildPDG(T)   // 调用边 + 兄弟边

C ← ∅

for each v ∈ V do

if v is dunder or LoC(v) ∉ [ℓ_min, ℓ_max] then continue

Ĥ(v), Î(v) ← compute complexity, inferability   // Eqs. (1),(2)

if Ĥ(v) < τ_Ĥ then continue

Δ(v) ← max(0, (Ĥ(v) − Î(v)) / (Ĥ(v) + ε))

FIM(v) ← [Ĥ(v)·Î(v)] / [Ĥ(v) + Î(v) + ε] · ρ(Δ(v))

if FIM(v) ≥ τ_FIM then C ← C ∪ {v}

end for

return C   // 按 FIM 降序排序

Algorithm 2：多函数组 FIM 目标选择（per file，节选）

Require: 源文件 s；单函数分数 Ĥ(v), Î(v)；组阈值 τ_coup^G, τ_Ĥ^G, τ_FIM,2^G, τ_FIM,3^G；LoC 比例 cap (θ_2, θ_3)；per-file cap (N_2, N_3)

V, E_call, E_sib ← BuildPDG(ParseAST(s))

G ← ∅

for each 拓扑模式 P ∈ {caller-callee, co-callee, sibling-coupled, mutual-call, call-chain, hub, fan-in, class-triad} do

for each 连通子图 G ⊆ V 匹配 P do

if 任一成员未通过 per-function 过滤、LoC 比例超 θ_|G|、Coup(G) < τ_coup^G 或 Ĥ(G) < τ_Ĥ^G then continue

在联合 mask 假设下重算 Î(G)   // 排除组内引用；C_doc = 0

Δ(G) ← max(0, (Ĥ(G) − Î(G))/(Ĥ(G)+ε))

FIM(G) ← Coup(G) · [Ĥ(G)·Î(G)]/[...] · ρ_G(Δ(G))

if FIM(G) ≥ τ_FIM,|G|^G then G ← G ∪ {(G, P, FIM(G))}

end for

end for

按 FIM(G) 降序排序 G

在非重叠 + per-size cap 下贪心选取，return S

4. 实验结果与分析

4.1 实验设置

基准分三组：coding-agent 基准（SWE-Bench-Verified 500、SWE-Bench-Lite 300，为主 in-domain 目标）；非 agent coding 基准（LiveCodeBench、OJBench、FullStackBench-EN，作回归检查）；工具使用与 OOD agent 基准（Terminal-Bench 2.0、τ-bench、BFCL，后两者不含 Python 代码编辑轨迹，测试函数调用归纳偏置是否跨任务族迁移）。

训练：对 Qwen2.5-Coder-Instruct 7B/14B 与 Qwen3-8B 在所选 FIM 语料上用标准 FIM loss 做 mid-training，随后不改地接现有 agentic post-training pipeline——R2E-Gym 或 SWE-Smith（Qwen2.5-Coder 系列）、SWE-Lego（Qwen3-8B，训 2 epoch 而非官方 4 epoch 以防过拟合）。

评测协议：所有数字为每个 pipeline 最终 checkpoint 上三个独立评测 seed 的均值（表中省略 %，括号内为标准差带）。baseline = base + post-training；ours = base + FIM mid-training + 相同 post-training。FIM-only checkpoint 因指令跟随退化不与 instruction-tuned baseline 公平比较，故每条增益都存活于后续 post-training。agent harness 由 post-training pipeline 固定：R2E-Gym 用 OpenHands fork、SWE-Smith 用 SWE-agent、Qwen3-8B 用 OpenHands 直接（SWE-Lego 数据超 Qwen2.5-Coder 32K 上下文）。

4.5 行为分析：增益从哪里来

在 14B + R2E-Gym 上对比 post-training-only 与 ours。负观察恢复：若任一工具输出匹配错误模式（stack trace、「No replacement was performed」、shell 错误等），该轨迹含负观察。两 checkpoint 含负观察轨迹比例基本一致（88.8% vs 91.8%），但恢复率（含错误轨迹中仍以通过 patch 终止的比例）从 24.8% 升至 28.8%（+4.0 pp，+16% 相对）——正是本文框架预测 mid-training 应支撑的能力：在外部返回与模型先验矛盾后仍能富成效地继续。mid-training 还把 agent 推向iterate-and-verify 策略：每个已解任务的编辑数从 3.3 升至 7.4、轨迹长度从 15.1 升至 23.6 步；search 动作占比 15.3%→11.0%，execute_bash 19.5%→24.6%。

5. 总结与启发

5.1 局限性

论文在 Section 6 明确列出四点局限，框定其主张：

  1. 仅 Python 语料与评测：mid-training 语料与 in-domain agent 基准均仅 Python；跨语言证据仅间接来自 FullStackBench-EN（§4.3），向 Java/C++/Rust 的迁移留待未来。
  2. CoT 依赖 teacher：默认配方依赖 Gemini-3-Flash；CoT 来源消融表明自生成 rationale 可恢复大部分增益，但完全开源复现需一个可比强度的开源 teacher。
  3. 跨基座验证有限：跨基座证据仅来自单一非 Qwen2.5-Coder 配置（Qwen3-8B + SWE-Lego），它同时改变了 post-training pipeline；结论是「不绑定某一 pretraining/post-training 组合」而非「保证跨所有 base 家族迁移」。
  4. 模块化假设：function-aware FIM 预设模块化代码；在单块脚本、生成代码或 notebook 上 pipeline 产出更少合格目标，该区域未被系统研究。

5.2 核心洞见与读后评注

  1. 「结构同构」是廉价且可扩展的自监督信号源。作者没有合成新轨迹，而是把普通源代码里天然存在的函数调用点当作 agent action-observation-continuation 循环的互联网级类比。这把「agent 能力」从一个需要昂贵 post-training 数据的属性，降格为一个可在 mid-training 用自监督安装的结构先验——成本只有 2.6B token、1 epoch、单机 8×H100。
  2. 选择「mask 什么」比「用多强的 teacher」更关键。Block B 表明函数选择算法是主导杠杆：Random 设底 13.95、Gemini-selected 15.05，而 Full 达 15.60。frontier teacher 对「选哪个函数」有判断但不充分；真正起作用的是 PDG 结构 + Ĥ/Î 双准则。这对工业实践意义重大：一个 base-model-agnostic、手工设计的可预测性代理，比调用 frontier 模型选目标更便宜且更可复现。
  3. FIM 结构本身做实质工作，不是蒸馏。Block A 去掉所有 rationale 仍 +1.18（占 Gemini-3 全增益近半），self-CoT 恢复 1.68/2.43。说明增益主要来自「函数级双向条件化」这一结构目标，CoT 只是放大器。这回应了「是不是变相蒸馏 frontier 模型」的质疑。
  4. 能力侵蚀是被低估的 post-training 代价。R2E-Gym 单独在六基准上均值掉 4.81 点，agent 论文很少报告。mid-training 把均值恢复 +3.52，且仅用 Python-only 语料就跨域恢复 τ-bench/BFCL——这是函数调用同构存活过 post-training的最直接证据，也是本文最有说服力的实验之一。
  5. 失效模式分析揭示机制：增益不是「学到了新能力」，而是改变了停止策略。no-patch 失败从约 11 降到约 1，因为 FIM 训练让模型总在 prefix/suffix 间产出非空 span。这把「agent 不再过早放弃」解释为一种训练时安装的生成倾向，而非推理能力提升——更细粒度、也更可信。
  6. 多函数单文件是同构论证的最直接检验。增益在多函数单文件任务上 +9.1 pp（4× 于单函数），恰是 function-aware FIM 直接训练的跨 caller-callee/sibling 依赖结构；多文件不获益则暴露当前粒度局限，自然指向「跨文件函数对」的未来工作。
