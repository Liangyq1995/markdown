第2章 计算基础设施与网络

《Machine Learning Systems at Scale》Vijay Janapa Reddi · MIT Press · Vol.2 · 整合原第 2–3 章 · 2026-07-04

核心主线以 175B 为贯穿算例：硅片→节点→Pod 逐层诊断四座墙 → 节点边界处通信墙 bind → 织物作为 Gradient Bus（α-β、bisection、RDMA）闭合
学习目标用同一模型在解码/训练两种负载下定位绑定墙；将 TP/DP/PP 映射到 NVLink/IB 层级；用 α-β 与 bisection 估算 AllReduce 占比并制定织物验收清单

一、开篇：175B 与四座物理墙

大规模 ML 的参与门槛不在算法公开与否，而在能否建造并持续运营物理系统。本章用同一个锚点模型——175B 参数、FP16 权重 350 GB——从单卡推理追到千卡训练，看绑定约束如何在硅片、节点、Pod 三层切换。

舰队有效吞吐不是峰值 TFLOP/s 的简单加总，而是各层瓶颈的最小值：

$$\text{Effective} = \min(\text{Compute},\ \text{Memory BW},\ \text{Bisection BW},\ \text{Storage Feed},\ \text{Reliability Budget})$$

四座墙对应这一公式在不同规模下的具体项：内存墙（HBM 带宽追不上算术或容量）、功耗墙（机架 70–100 kW 液冷）、通信墙（跨节点 IB 相对 NVLink 的带宽断崖）、可靠性墙（组件数量使 MTBF 坍缩）。算法是软件；基础设施是参与边界。

175B · 推理侧：内存墙首次 bind

自回归解码时，即便 350 GB 权重已分片进 HBM，每 token 仍须把活跃权重片流过算术单元。H100 单路径 HBM 3.35 TB/s 给出带宽地板：

$$T_{\text{decode,floor}} = \frac{350\ \text{GB}}{3.35\ \text{TB/s}} \approx 104\ \text{ms/token}$$

这是用户感知「逐字停顿」的物理下限之一——与 989 TFLOP/s 峰值无关。推理 SLA 必须先算此地板，再谈算力。

训练侧同一 350 GB 将以梯度形态在步末穿越互联——那是通信墙的主战场，下文第五节沿此路径展开。在此之前，须先理解硅片与节点如何把算力「造出来」、又在何处停下。

二、硅片层：加速器谱系与内存墙

现代服务器 CPU 仅 5–10% 晶圆面积用于算术——对 GEMM 主导负载这是通用性税（Generality Tax）。加速器谱系回收面积：GPU（SIMT，~50–60% 算术）、TPU（脉动阵列，~70–80%）、定制 ASIC（>90%）。选型 = 工作负载稳定性 × 可编程性：研究迭代选 GPU；固定 Transformer 量产可评估 TPU/ASIC。

2.1 GPU 代际：算力、NVLink 与功耗不同步

架构峰值 TensorTDPNVLink备注
V100 (2017)125 TFLOP/s FP16300 W300 GB/s首代 Tensor Core
H100 (2022)989 TFLOP/s FP16700 W900 GB/sTransformer Engine / FP8
B200 (2024)4500 TFLOP/s FP81000 W1800 GB/schiplet、NVLink 5

峰值 TFLOP/s 增速快于 TFLOP/W——功耗墙因此与内存墙并列，成为机架与设施设计的一等公民。NVLink 带宽六代间从 300 增至 1800 GB/s，支撑节点内张量并行；跨节点仍受 IB 约束（第三节量化断崖）。

2.2 Roofline：同一 175B，训练 GEMM vs 解码

脊点算术强度 $I_{\text{ridge}} = \pi / \beta_{\text{HBM}}$。H100：$\pi = 989$ TFLOP/s、$\beta = 3.35$ TB/s →

$$I_{\text{ridge}} \approx 295\ \text{FLOP/byte}$$

大 batch 训练 GEMM（$I \gg 295$）算力受限，调 batch/融合核；自回归解码（$I \ll 1$）带宽受限，调 KV cache/量化/投机解码——同一模型、两种负载、两种优化方向。

寄存器文件聚合带宽 >300 TB/s，HBM 仅 3.35 TB/s（~100× 落差）。高 MFU 要求 tiling：权重块载入 SM SRAM，驱逐前尽可能复用。HBM 是「能放几十 GB 的最高带宽层」，永不单独消除内存墙。

2.3 对照：DLRM 10 TB——容量墙先于带宽墙

推荐 Archetype B（DLRM）与 LLM 相反：容量先于带宽。10 TB embedding 无法装入单 H100 80 GB，8 卡节点 640 GB 仍不足——至少 16 个 8-GPU 节点才够容量底线。问题从 HBM 访问升级为跨节点 AllToAll；第八节拓扑选型须同时服务 LLM 大梯度与 DLRM 多对多路由。

三、节点层：NVSwitch 与带宽断崖

8×H100 张量并行要求 all-to-all 交换部分激活/梯度。环形拓扑 8 卡需 4 hop，有效带宽降 4×；全连接 mesh 需 28 链路不可布线。NVSwitch 交叉开关（~800 W）换全 bisection，使节点成为逻辑「超级加速器」——175B 的 TP 切分应锁在此域内。

DGX H100 节点 · 互联契约

  • 8× H100 SXM，NVLink 4.0 聚合 ~900 GB/s/GPU 双向
  • 4× NVSwitch，节点内 all-to-all bisection
  • 8× ConnectX-7 NDR 400 Gb/s（~50 GB/s/端口）——跨节点唯一出口
  • 主机 512 GB–2 TB DRAM：数据管道 staging；训练步中 PCIe 同时承载加载、梯度出口、检查点

3.1 9× 断崖：TP 与 DP 的物理分界

节点内 NVLink ~900 GB/s；跨节点 NDR IB ≈ 50 GB/s/端口——同向对比约 9× 断崖。HBM 3.35 TB/s vs IB 50 GB/s 更大：在同步点，「算得快」可瞬间归零。

并行维消息特征应锁定的互联175B 含义
张量并行 (TP)高频、中块 all-to-allNVLink 域（节点内）永不跨 IB 断崖
流水线 (PP)微批 P2P，延迟敏感同 rack / 邻近节点 IB4 KB 控制消息 α 主导（第七节）
数据并行 (DP)低频、350 GB 级梯度全网 IB + bisection通信墙在此 bind

节点内 NVSwitch 闭合了 TP 交换；一旦 DP 需跨机架同步 350 GB 梯度，绑定项从 HBM/NVLink 切换到 IB 与 bisection——以下各节沿 175B 训练步追踪这一切换。

四、机架与 Pod：设施经济学

单机架 32×700 W GPU ≈ 22 kW 仅芯片，加 NVSwitch/IB/CPU 常达 70–100 kW/机架，风冷失效，必须冷板液冷。Pod 将数百机架织成 WSC：Fat-Tree 换全 bisection（SuperPOD），Torus 换成本与局部性（TPU Pod）。

10,000 H100 峰值 ~9.89 EFLOP/s FP16，但有效吞吐 = min(算力, bisection BW, 存储供料)——第四节公式在 Pod 尺度的实例化。4:1 超额认购 bisection 可砍半，AllReduce 吞吐跌 30–60%。

设施 ~40 MW 上限约束光学比例：机架内 DAC 铜缆（<3 m，~$50/条）vs 脊层光模块（>30 m，~$500+，~20 W/链路）。20,000 GPU 脊层 ~20,000 光链路 → $10M 线缆 + 400 kW 光模块——移动比特与计算争同一 MW 预算（第九节量化互联功耗）。

硅片 lottery：同 bin H100 时钟差 50 MHz 在 BSP AllReduce 中可使整机吞吐降 5–10%。训练池保持同质性，慢卡隔离至推理池——可靠性墙在万卡规模上与通信墙同等可见。

五、Gradient Bus：ML 织物不是传统网络

传统数据中心为百万小鼠流设计：异步、TCP 可丢包重传、优化平均吞吐。ML 训练是少数大象流 + BSP 屏障：一次丢包可 stall 全部 GPU；评价指标从 per-flow 公平变为全局同步完成时间——最慢链路决定 1024 卡步长。

维度传统 DCML Gradient Bus
流量形态异步 many-to-many周期性 AllReduce / AllGather / AllToAll
流大小大量短流175B 单步 350 GB 级梯度象流
丢包容忍TCP 重传可接受RDMA Go-Back-N：晚丢 1 包可重传数百 MB 尾部
拥塞语义局部独立全局 incast + 屏障放大 straggler

175B · 训练侧：通信墙 bind

FP16 梯度 350 GB/步，有效 IB 50 GB/s 给出纯传输下限：

$$T_{\text{sync,floor}} = \frac{350\ \text{GB}}{50\ \text{GB/s}} = 7.0\ \text{s}$$

此期间除非与 backward overlap，否则全员 idle。FP32 梯度 700 GB 加倍——AllReduce 可占单步 10–40%（混合并行与 overlap 前更高）。第一节 104 ms/token 的解码地板与这里 7 s/步的同步地板，是同一 350 GB 在两种负载下的两面。

Straggler · 1024 GPU × 100 ms 尾延迟

$$\text{浪费 GPU·s} = 1024 \times 0.1\ \text{s} = 102.4\ \text{GPU·s/事件}$$

BSP 下 p99 路径延迟不是 outlier KPI，而是绑定约束——须监控尾延迟与 RDMA retry，非平均端口利用率。

单机上内存总线搬权重；集群上织物就是 Gradient Bus。以下三节按因果链设计这条总线：传输（α-β + GPUDirect）→ 拓扑（bisection）→ 行为与集成（PFC、SKU 验收）。

五层是因果链，不是话题清单：350 GB 象流先压 L1–L2（物理 + 传输）；再逼 L3 保证 bisection；L4 暴露拥塞与 pause storm；L5 兑现为可采购的「一台训练机」或 commissioning 失败。第二至四节讨论的硅片/节点/Pod 决策，分别对应 L2 入口、L3 局部性与 L5 功率预算。

七、L1–L2：物理层、RDMA 与 α-β

400G+ 链路用 PAM4 + RS FEC，每 hop 增加 ~100–200 ns 不可替代的 α。DAC 铜缆 <3 m 最低延迟；脊层光模块换距离，付功耗与美元——与第四节光缆经济学同一账本。

7.1 α-β 成本与临界消息大小

$$T(n) = \alpha + \frac{n}{\beta}, \quad n^* = \alpha \cdot \beta$$

NDR IB 典型 $\alpha \approx 1.5\,\mu\text{s}$、$\beta \approx 50\,\text{GB/s}$ → $n^* \approx 75$ KB（工程常记 ~100 KB）。175B 训练步同时出现两类消息：

消息大小 $n$主导项175B 场景优化杠杆
PP 微批 handoff~4 KBα（~95%）流水线阶段边界减 hop、同 rack 放置
DP 梯度分片~350 MBβ8 节点 DP 分片加 rail、分层 AllReduce
全量梯度象流350 GBβ平坦 Ring AllReducebisection、overlap、压缩

算例——4 KB PP 控制：$T \approx 1.5 + 4/50\text{GB/s} \approx 1.58\,\mu\text{s}$，加倍带宽几乎无效。算例——350 MB 分片：$T \approx 7.0\,\text{ms}$，投资带宽直接缩短步长。

7.2 GPUDirect RDMA：消除主机 staging

第三节 DGX 每 GPU 独占 IB HCA。无 GPUDirect 时，350 GB 梯度须经「GPU HBM → 主机 DRAM → NIC」双拷贝；FP32 700 GB/步 × 双路径 ≈ 700 GB 冗余主机流量/步。GPUDirect 使 NIC 直接 DMA GPU HBM，释放 CPU 做 overlap——万卡规模近乎必选，也是 PCIe 争用（加载/检查点/梯度）之外的第二条隐形 stall 来源。

协议：InfiniBand 信用流控原生无损；RoCEv2 需 PFC+ECN，运维负担更高。RDMA 丢包 Go-Back-N 在 BSP 下放大为整机 straggler——要求无损织物，非「尽力而为以太网 + 调参」。

八、L3：拓扑与 Bisection Bandwidth

Bisection bandwidth（$\text{BW}_{\text{bisect}}$）：集群一分为二时穿越分割面的总带宽。350 GB/步 AllReduce 需要接近非阻塞 bisection；ECMP 静态哈希无法把单条象流切到多路径——多象流碰撞可一路饱和、他路空闲。

拓扑Bisection175B LLM（大梯度）DLRM（AllToAll）
3-tier Fat-Tree非阻塞（足额端口）通用 AllReduce；SuperPOD可行，成本高
Rail-optimized每 GPU 独立上行节点内 NVLink + 每轨 IB；减 incast层级并行首选
Dragonfly / Torus$\mathcal{O}(\sqrt{N})$ bisection差全局 AllReduce强局部性时可接受

1024 GPU、350 GB/步需数千条 400G 链路满速；3000 端口 × 25 W ≈ 75 kW 纯互联功耗（可达 IT 负载 10%+）——第四节 MW 预算在此处落地为「比特的瓦特税」。

九、L4–L5：拥塞控制、SKU 与验收

L4 行为层：PFC 暂停、DCQCN/HPCC 主动降速——BSP 下 proactive 拥塞控制是延迟需求，非可选项。推理 mice 与训练 elephant 须流量隔离（SR-IOV、VL），避免共享 PFC 域引发 pause storm。

L5 集成层：NVIDIA SuperPOD（Fat-Tree + NVSwitch）、Meta Grand Teton（rail-optimized）把五层压成可采购 SKU。企业以太网上跑大规模同步训练通常低效——不是配置问题，是协议语义与 ML 同步模型不匹配。

织物 commissioning 检查表（占项目时间线 15–20%）

  1. NCCL-tests：小/大消息 AllReduce，校准有效 $\alpha,\beta$
  2. ibstat / 交换机计数器：RDMA retry、PFC pause 计数
  3. 主动 incast 实验：验证 rail 均衡与 ECMP 哈希碰撞
  4. 硅片同质性：隔离 lottery 慢卡，训练池 bin 一致
  5. 多租户：训练象流与推理鼠流分域

十、章节总结

从 175B 出发的设计链

  1. 诊断顺序：解码查 HBM 地板（~104 ms/token）；多节点训练查 IB 地板（~7 s/步 350 GB）；万卡查 MTBF 与 bisection
  2. 层级映射：TP∈NVLink 域，PP∈邻近 rack，DP∈全网——9× 断崖是物理分界，非软件可配
  3. Gradient Bus：织物 = 集群内存总线；α-β 区分 PP 控制（~4 KB）与 DP 梯度（350 MB–350 GB）
  4. 采购双账：同时算 $\text{BW}_{\text{bisect}}$ 与互联功耗（75 kW+）；Fat-Tree vs rail 须匹配 LLM 与 DLRM 负载
  5. 验收：GPUDirect + 无损 RDMA + NCCL burn-in——「上架即用」在 fleet 尺度不成立
本章闭合 Vol.2 Part I 的第一个问题：硅片与织物能否让 175B 在训练步长内不被通信 bind。第 3 章存储回答第二个问题——加速器再快，燃料线供不上同样空转。
