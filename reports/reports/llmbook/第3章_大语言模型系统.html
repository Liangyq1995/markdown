第3章 大语言模型资源

《大语言模型》赵鑫等著 · 中国人民大学 AI Box · 第46–70页

由于面临着算力、数据、技术等多重挑战，从头研发或复现大语言模型绝非易事。本章介绍可公开使用的大语言模型研发资源，包括模型检查点和API（§3.1）、预训练数据（§3.2）、微调数据（§3.3）以及常用代码库（§3.4）。

3.1 公开可用的模型检查点或API

大模型预训练对计算资源要求极高，经过预训练的公开模型检查点对推动技术发展至关重要。目前开源社区积累了大量模型检查点，商业公司也提供闭源模型的API接口。

3.1.1 开源通用大语言模型

LLaMA 系列（Meta AI）

LLaMA（2023.02） 开源
  • 参数规模：7B / 13B / 30B / 65B
  • 训练数据：超过 1T tokens（Common Crawl、GitHub、Wikipedia、Books、ArXiv、StackExchange）
  • 硬件：65B 版本在 2,048 张 A100 (80G) 上训练约 21 天
  • 关键设计：Pre-Norm（RMSNorm）、SwiGLU 激活函数、RoPE 旋转位置编码
  • 意义：13B 版本在多项 NLP 基准上超越 GPT-3 (175B)，成为开源 LLM 事实标准

LLaMA-2（2023.07） 开源可商用
  • 参数规模：7B / 13B / 34B（未开源）/ 70B
  • 训练数据：扩充至 2T tokens
  • 上下文长度：从 2,048 翻倍至 4,096 tokens
  • 关键改进：引入分组查询注意力（GQA），显著降低推理时 KV Cache 内存占用
  • Chat 版本：通过完整的 SFT → RLHF 流程对齐，发布 LLaMA-2-Chat（4种规模）
  • 硬件：70B 版本使用约 2,000 张 A100 (80G)

ChatGLM 系列（清华大学 & 智谱AI）

  • 参数规模：6B（系列均为6B，部署门槛低）
  • 首次发布：2023年5月，已迭代至 ChatGLM-3
  • 特色：中英双语对话，GLM 架构（自回归填空目标），在语义/数学/推理/代码/知识多维度评测优异
  • 衍生版本：ChatGLM3-6B-Base（基础模型）、ChatGLM3-6B-32K（长文本）、ChatGLM3-6B-128K（超长文本）
  • 更大模型：智谱AI 同步研发更强的 GLM-4

Falcon（TII，阿布扎比技术创新研究院）

  • 参数规模：7B / 40B / 180B（7B/40B 发布于2023.05，180B 发布于2023.09）
  • 训练数据：80%+ 来自 RefinedWeb（基于 Common Crawl 严格清洗的网页数据集）
  • 训练规模：7B 在 384×A100 上用 1.5T tokens；40B 在 384×A100 上用 1T tokens；180B 在 4,096×A100 上用 3.5T tokens
  • 180B 版本是当时参数量最大的开源预训练语言模型
  • 同步发布指令微调版本 Falcon Instruct

Baichuan / Baichuan-2（百川智能）

  • Baichuan（2023.06）：7B，中英双语，预训练数据 1.2T tokens，在中英多个基准取得同尺寸最优
  • Baichuan-2（2023.09）：7B / 13B，预训练数据扩展至 2.6T tokens，硬件：1,024×A800
  • 特色：多语言能力和垂域应用潜力（法律、医疗等），提供 SFT + 人类偏好对齐的对话模型

InternLM / InternLM-2（上海人工智能实验室）

  • InternLM（2023.07）：7B / 20B，20B 达到 LLaMA (70B) 水平，支持数十类插件工具调用
  • InternLM-2（2024.01）：1.8B / 7B / 20B，推理/代码/数学/对话全面提升
  • 完整工具链：InternLM-Train（预训练）、XTuner（低成本微调）、LMDeploy（部署推理）、OpenCompass（评测）、Lagent（智能体）
  • 多模态扩展：InternLM-XComposer（多模态）、InternLM-Math（数学）

Qwen 通义千问（阿里巴巴）

  • 首发：2023.08，持续更新
  • 参数规模：0.5B 到 72B（覆盖多种部署场景）
  • 训练数据：14B 版本达 3T tokens
  • Qwen-1.5 (72B)（2024.02）：在语言理解/推理/数学等测试基准上优于 LLaMA-2 (70B)
  • 专项模型：Code-Qwen（代码）、Math-Qwen（数学）、Qwen-VL（多模态）

Mistral 7B（Mistral AI，法国）

  • 发布：2023.09，参数规模 7B
  • 性能：在评估基准中全面优于 LLaMA-2 (13B) 和 LLaMA (34B)，代码生成接近 Code LLaMA (7B)
  • 核心技术：
    • 滑动窗口注意力（SWA）：在 16K 序列长度、4K 注意力窗口下速度提升 2×
    • 分组查询注意力（GQA）：减少 KV Cache 内存占用
  • 指令版本：Mistral Instruct，在 MT-bench 上优于多数 7B 对话模型

DeepSeek LLM（幻方科技）

  • 发布：2023.11，参数规模 7B / 67B
  • 训练数据：2T tokens（中英双语，代码和数学比例更高）
  • 性能：67B 在代码/数学/推理任务上超越 LLaMA-2 (70B)
  • 专项模型：DeepSeek-Math、DeepSeek-Coder、DeepSeek-VL
  • 对话版本：7B 和 67B 均提供对话模型，针对人类价值观对齐

Mixtral 8×7B（Mistral AI）

MoE 架构
  • 发布：2023.12，稀疏混合专家（Sparse MoE）架构，较早公开的 MoE 语言模型
  • 总参数：46.7B（8 组专家参数），每个 token 每层选择 Top-2 专家
  • 激活参数：12.9B，推理成本等同于 12.9B 密集模型
  • 上下文：支持 32K tokens
  • 性能：多项基准超越 LLaMA-2 (70B) 和 GPT-3.5，解码速度比 LLaMA-2 (70B) 快 6×
  • 多语言：英/法/意/德/西班牙语
  • 指令版本：Mixtral 8×7B Instruct，MT-bench 与 GPT-3.5 相当

Gemma（谷歌，2024.02）

  • 参数规模：2B / 7B，纯语言模型，专注英语任务
  • 训练数据：2B 版本 2T tokens，7B 版本 6T tokens（主要英语数据）
  • 技术路线与 Gemini 类似，提供 SFT 版本 Gemma IT

MiniCPM（面壁智能 & 清华大学，2024.02）

  • 参数规模：2B，极小参数量高性能
  • 训练创新：模型沙盒实验——先用小模型广泛实验寻找最优训练设置，再迁移至大模型
  • 训练方法：稳定训练 + 退火的两阶段学习，再进行 SFT 和人类偏好对齐
  • 系列：MiniCPM-2B-SFT、MiniCPM-2B-DPO、MiniCPM-V（多模态）

3.1.3 Mixtral MoE 架构详解

Mixtral 8×7B 是较早公开发布的稀疏混合专家（Sparse MoE）架构大语言模型，其核心思想是：用更多的参数存储知识，但每次推理只激活一小部分参数。

flowchart LR
    subgraph "输入层"
        IN["输入 Token\n序列"]
    end
    subgraph "Transformer Block（共32层）"
        ATT["多头注意力\nGQA"] --> GATE["门控网络\nGating Network\nSoftmax Top-2 路由"]
        GATE --> E1["专家1\nFFN (7B参数)"]
        GATE --> E2["专家2\nFFN (7B参数)"]
        GATE --> E3["专家3~8\n（未激活）"]
        E1 --> AGG["加权求和\nw1·E1 + w2·E2"]
        E2 --> AGG
    end
    subgraph "输出统计"
        STAT["总参数: 46.7B\n激活参数: 12.9B\n推理成本 ≈ 12.9B密集模型\n速度: 6× LLaMA-2 70B"]
    end
    IN --> ATT
    AGG --> STAT

MoE 路由公式：对于输入 token $x$，门控网络选择 Top-K 个专家：

$$\text{MoE}(x) = \sum_{i \in \text{TopK}(G(x))} G_i(x) \cdot E_i(x)$$

其中 $G(x) = \text{Softmax}(\text{TopK}(x \cdot W_g))$，$W_g$ 是门控权重矩阵，$E_i$ 是第 $i$ 个专家的 FFN。Mixtral 使用 $K=2$，每层从 8 个专家中选 2 个。

  • LAWGPT：法律领域
  • TaoLi：教育领域
  • Goat：数学领域
  • Cornucopia：金融领域

  • LLaVA：CLIP ViT-L/14 + Vicuna，线性投影层对齐
  • MiniGPT-4：EVA-CLIP + Vicuna，Q-Former 对齐
  • InstructBLIP：多任务视觉指令
  • PandaGPT：ImageBind + Vicuna，支持图像/音频/视频/点云

3.2.2 网页数据

网页是最主要的数据来源，包含新闻报道、博客文章、论坛讨论等多样化文本。

Common Crawl

  • 规模：PB 级，2008年至今持续更新
  • 内容：原始网页数据 + 元数据 + 提取文本
  • 注意：噪声和低质量数据极多，必须使用 CCNet 等工具清洗
  • 多数网页数据集均基于 Common Crawl 构建

C4（Colossal Clean Crawled Corpus）

  • 规模：800GB，包含超过 156B tokens
  • 来源：2019.04 的 Common Crawl，超过 365M 个互联网域
  • 子版本：en(806G)、en.noclean(6T)、realnewslike(36G)、multilingual(38T)
  • 使用模型：UL2、LLaMA

RefinedWeb

  • 规模：5T tokens 原始数据，开源部分 600B tokens（500GB）
  • 来源：2008-2023.06 所有 Common Crawl 记录，严格筛选去重
  • 解压需要 2.8TB 本地存储
  • 使用模型：Falcon（主要训练数据）

RedPajama-Data

  • 规模：100B 份文档，经过滤去重后约 30T tokens
  • 语言：英/法/西/德/意 5 种语言
  • 特色：40余种预标注数据注释，支持按标准筛选重加权
  • 数据处理脚本完全开源

中文网页数据集

ChineseWebText

中科院自动化所，1.42TB，2021-2023年网页快照，每篇附有质量评分，配套 EvalWeb 清洗工具

WanJuan 1.0 Text

上海AI Lab，1TB+，500M 文档，多来源（网页+书籍），用于 InternMultimodal 和 InternPuyu 训练

WuDaoCorpora Text

北京智源"悟道"项目，5TB（开源200GB），来源100TB原始网页，含50+行业数据标签

3.2.3 书籍与论文数据

BookCorpus

  • 11,038 本未出版书籍，约 74M 句子、1B 单词，5GB
  • 涵盖16种主题（浪漫/历史/冒险等）
  • 使用模型：GPT、GPT-2、MT-NLG、LLaMA
  • 原始数据不再公开，可用 BookCorpusOpen 镜像版（17,868本，9GB）

arXiv Dataset

  • 约 1.7M 篇预印本（物理/数学/CS等），总量 1.1TB
  • 每篇包含文本/图表/作者/引文/分类/元数据
  • 可在 Kaggle 下载

S2ORC / peS2o

  • 来源：Semantic Scholar 学术论文
  • S2ORC 已更新至 136M 篇论文
  • peS2o v2：约 42B tokens，Hugging Face 可下载

Project Gutenberg

  • 70K 部免费电子书，主要西方文学（小说/诗歌/戏剧）
  • 多语言：英/法/德等
  • 持续更新，官网免费下载

3.2.4 代码数据

The Stack v1.2（BigCode / Hugging Face）

  • 来源：GHArchive 2015.01.01 - 2022.03.31 GitHub 活跃仓库
  • 初始版本：3TB（30种编程语言），v1.2 扩展至 358种编程语言，6TB
  • 处理流程：数据筛选 + 过滤 + 许可证检测

StarCoder（BigCode）

  • 基于 The Stack v1.2，从 358 种语言中筛选 86 种
  • 进行人工抽样审核，确认为人类编写代码
  • 最终数据量：783GB
  • 用于训练同名模型 StarCoder (15.5B)

3.2.5 混合型数据集

The Pile（EleutherAI）

800GB+，22个多样化高质量子集混合，包含书籍/网站/代码/科学论文/社交媒体，按质量加权混合。用于 GPT-J(6B)、CodeGen(16B)、Megatron-Turing NLG(530B)。

ROOTS（BigScience）

1.6TB，59种语言（46种自然语言+13种编程语言），英语占30%，Java/PHP/C++超过一半代码。用于训练 BLOOM (176B)。

Dolma（Allen AI）

6TB（v1.6），来源：Common Crawl + Semantic Scholar + GitHub + 书籍 + Reddit + 维基百科，共3T tokens。配套高性能工具包，支持语言/质量/内容过滤和去重。用于训练 OLMo。

3.4.2 DeepSpeed（微软）

DeepSpeed 是微软开发的高性能深度学习训练库，广泛用于 MT-NLG、BLOOM 等超大模型训练。

ZeRO（Zero Redundancy Optimizer）内存优化

对于 $N$ 个参数的模型，在混合精度训练中，每个参数的内存开销：

  • 参数（FP16）：2 bytes
  • 梯度（FP16）：2 bytes
  • 优化器状态（FP32 参数副本 + 一阶矩 + 二阶矩）：12 bytes
  • 总计：16 bytes/参数

ZeRO 通过在 $N_d$ 个 GPU 间分片来减少每卡内存：

$$\text{ZeRO-1（优化器状态分片）}: \frac{2+2+12}{N_d} + 2+2 = \frac{12}{N_d} + 4 \text{ bytes/参数}$$ $$\text{ZeRO-2（+ 梯度分片）}: \frac{2+12}{N_d} + 2 = \frac{14}{N_d} + 2 \text{ bytes/参数}$$ $$\text{ZeRO-3（+ 参数分片）}: \frac{16}{N_d} \text{ bytes/参数}$$

当 $N_d = 64$ 时，ZeRO-3 可将每卡内存从 16B/参数降至约 0.25B/参数，实现约 64× 内存压缩。

DeepSpeed-MII（推理优化）

  • 块状键值缓存：将 KV Cache 分割为固定大小块，减少内存碎片化，提升吞吐量
  • 连续批处理：每次前向传播独立调度，细粒度调度优化内存效率
  • SplitFuse 技术：动态分解提示和生成结果，进一步改善连续批处理
  • 支持：LLaMA、Mistral、Falcon、Mixtral、Qwen

DeepSpeed-Chat（RLHF 训练）

  • 完整复现 InstructGPT 训练流程：SFT → RM → PPO
  • 数据抽象和混合功能，支持完整训练流程
  • 混合引擎（Hybrid Engine）：在 PPO 中无缝切换训练/生成模式
  • 简单脚本即可实现多步骤训练，提供对话测试 API

3.4.3 Megatron-LM（NVIDIA）

Megatron-LM 是 NVIDIA 专为超大规模 LLM 训练设计的深度学习框架，解决显存限制、计算效率和通信问题。

并行策略原理适用场景通信开销
数据并行（DP） 每个工作节点复制完整模型，输入数据切分多份，定期同步梯度 标准扩展，批大小增大 低（梯度同步）
张量并行（TP） 单个矩阵运算切分到多 GPU（行/列切分） 单层参数超过单卡容量 高（每层 all-reduce）
流水线并行（PP） 不同层分配到不同设备，微批次流水执行 模型层数极多 中（层间通信）
序列并行（SP） LayerNorm/Dropout 沿序列维度切分 超长序列训练 低

FlashAttention 集成

Megatron-LM 集成了 FlashAttention，通过 IO-aware 分块计算避免存储完整注意力矩阵：

  • 标准注意力：内存 $O(n^2)$，需要将 $n \times n$ 注意力矩阵写入 HBM
  • FlashAttention：内存 $O(n)$，分块计算 $\text{softmax}$，只在 SRAM 中保留中间结果
  • 速度：相比标准注意力快 2-4×，使超长序列（32K+）训练成为可能
$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

FlashAttention 将 $Q, K, V$ 分块，逐块计算并使用在线 softmax 技术合并结果，避免 $O(n^2)$ 的中间矩阵存储。

3.5.1 关键技术解析

RMSNorm vs LayerNorm

LayerNorm 对每层输出进行均值和方差归一化：

$$\text{LayerNorm}(x) = \frac{x - \mu}{\sigma} \cdot \gamma + \beta$$

RMSNorm 省去均值中心化步骤，只做方差归一化：

$$\text{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{n}\sum_{i=1}^n x_i^2 + \epsilon}} \cdot \gamma$$

RMSNorm 计算量减少约 7-15%，实践中效果与 LayerNorm 相当，已成为大多数开源 LLM 的默认选择。

SwiGLU 激活函数

由 Noam Shazeer 提出，在 FFN 层中引入门控机制：

$$\text{SwiGLU}(x, W, V) = \text{Swish}(xW) \odot (xV)$$ $$\text{Swish}(x) = x \cdot \sigma(\beta x)$$

其中 $\odot$ 是逐元素乘法，$\sigma$ 是 Sigmoid 函数。相比 ReLU，SwiGLU 的平滑性和门控机制使模型在相同参数量下性能更好，但 FFN 的隐藏层维度通常需要调整为 $\frac{2}{3} \times 4d$（以保持参数量不变）。

RoPE 旋转位置编码

将位置信息编码为旋转变换，作用于 Q、K 矩阵：

$$q_m^T k_n = \text{Re}[(W_q x_m)^* \cdot e^{i(m-n)\theta}(W_k x_n)]$$

RoPE 的优势：相对位置感知（只依赖 $m-n$）、外推性好（可通过插值扩展上下文）、无需额外参数。LLaMA、Mistral、Qwen、DeepSeek 均采用 RoPE。

GQA vs MQA vs MHA

MHA（Multi-Head Attention）：$n_h$ 个 Q 头，$n_h$ 个 KV 头，KV Cache $\propto n_h$

MQA（Multi-Query Attention）：$n_h$ 个 Q 头，1 个 KV 头，KV Cache 减少 $n_h$ 倍

GQA（Grouped Query Attention）：$n_h$ 个 Q 头，$n_g$ 个 KV 头（$1 < n_g < n_h$），KV Cache 减少 $n_h/n_g$ 倍

GQA 是 MHA 和 MQA 的折中，在几乎不损失性能的前提下显著减少推理内存。LLaMA-2 (70B)、Mistral 7B 采用 GQA；Falcon 采用 MQA。

3.5.2 Mistral 滑动窗口注意力（SWA）

Mistral 7B 引入滑动窗口注意力解决长序列计算效率问题：

  • 每层注意力只关注最近 $w$ 个 token（窗口大小 $w = 4,096$）
  • 但通过层叠效果，第 $k$ 层的有效感受野为 $k \times w$
  • 在 16K 序列长度下，相比标准注意力速度提升 2×
$$\text{第 } k \text{ 层有效感受野} = k \times w$$

对于 32 层、$w=4096$ 的 Mistral，最后一层有效感受野为 $32 \times 4096 = 131,072$ tokens，远超实际窗口大小。

3.7 本章小结

模型资源层面

  • LLaMA 系列建立开源 LLM 技术标准（Pre-Norm + RMSNorm + SwiGLU + RoPE）
  • 中文模型（ChatGLM、Qwen、InternLM）填补中文语境空白
  • Mistral/Mixtral 展示高效架构设计（SWA、GQA、MoE）
  • 闭源 API（GPT-4 Turbo、Claude 3）仍是性能最强选择

数据资源层面

  • 网页数据（Common Crawl 及衍生）是最主要来源
  • 中文数据集（ChineseWebText、WanJuan、WuDaoCorpora）支撑中文 LLM
  • 代码数据（The Stack、StarCoder）增强推理和代码能力
  • 混合数据集（The Pile、Dolma）降低数据工程门槛

框架资源层面

  • Hugging Face 生态提供研究基础设施（Transformers/Datasets/Accelerate）
  • DeepSpeed ZeRO 技术解决显存瓶颈，实现 $N_d$ 倍内存压缩
  • Megatron-LM 3D 并行（DP×TP×PP）支撑超大规模训练
  • 本书配套：LLMSurvey + YuLan-Chat + LLMBox
开源生态的繁荣使 LLM 研究从少数科技巨头的专属领域，扩展为全球学术界和工业界共同参与的开放研究平台。Stanford Alpaca 证明了"廉价指令微调"的可行性（$600 + 3小时），LLaVA 等多模态模型拓展了 LLM 的感知边界，领域专精模型展示了 LLM 的专业化路径。
