1. 总体架构概览

本项目基于 VERL（Versatile Reinforcement Learning Framework），在 PPO/GRPO 等强化学习训练过程中， 支持 LLM 在 rollout 阶段通过 HTTP API 调用外部工具（美团搜索、POI 查询等），形成多轮对话轨迹， 再用于 actor/critic 的参数更新。

http_manager.py 是整个工具调用体系的核心，负责 工具注册 → 响应解析 → HTTP 执行 → 结果返回 的全流程。

4.1 response_mask：Token 损失遮罩机制

agent_loop 用 response_mask 列表逐 token 标记是否纳入 PPO/GRPO 损失计算， 1 = 计入 loss（LLM 生成），0 = 不计入 loss（工具结果/用户消息）。

Token 来源 mask 值 代码位置 说明
LLM 生成 (assistant) [1, 1, …, 1] response_mask += [1] * len(response_ids) 对话轨迹中 LLM 输出的每个 token，参与梯度更新
工具结果 (tool response) [0, 0, …, 0] response_mask += [0] * len(response_ids) HTTP 工具返回内容 tokenize 后追加，不计入损失
load_skill 重建 prompt 全部清空 [] agent_data.response_mask = [] 工具披露触发 PENDING 状态时，mask 完全重置再重建
── prompt_ids 拼接顺序（完整一轮）────────────────────────────────────────── prompt_ids = [system_tokens] + [user_tokens] # 初始 prompt + [assistant_resp₁] # LLM 生成 → mask = [1,1,...1] + [tool_result₁_tokens] # 工具结果 → mask = [0,0,...0] + [assistant_resp₂] # LLM 生成 → mask = [1,1,...1] + ... ── 损失只对 mask=1 的位置计算 ──────────────────────────────────────────────── loss = cross_entropy(logits[mask==1], labels[mask==1])
💡
TOOL_EXHAUSTED_MARKER 与 mask：当工具返回全部为业务空结果时， 结果文本前追加 [[TOOL_EMPTY_EXHAUSTED]]。agent_loop 检测到此标记后， 可将该轮工具调用标记为无效，防止 LLM 学习"空结果也继续追问"的错误行为。 工具结果本身始终以 mask=0 追加，不参与梯度计算。

6. 核心方法详解

6.1 _get_tool_schema(tool_name) — 获取工具 Schema

verl/envs/tool_manager/http_manager.py : 144-176
def _get_tool_schema(self, tool_name: str) -> Dict:
    """从工具服务 HTTP API 获取工具的输入 Schema，并过滤透传参数"""
    response = requests.get(f"{self.base_url}/api/tools/list")
    for tool_json in all_tools:
        if tool_json['name'] == tool_name:
            schema = tool_json['inputSchema'].copy()
            # 过滤 IGNORED_KEYS（useCache/userId/lat/lng 等），记录哪些键需要透传
            for key in self.IGNORED_KEYS:
                if key in schema['properties']:
                    del schema['properties'][key]
                    removed_keys.append(key)
            self.tool_ignored_keys[tool_name] = removed_keys  # 记录该工具的透传键
            return {'name': ..., 'description': ..., 'parameters': schema}
💡
IGNORED_KEYS 机制：useCache, userId, lat, lng, cityId 等参数从 LLM 可见的 Schema 中移除， 但实际调用时由 agent_loop 通过 tool_kwargs 透传，避免 LLM 幻觉填入错误值。

6.2 parse_response(response_content) — 响应解析

verl/envs/tool_manager/http_manager.py : 461-504
def parse_response(self, response_content: str, current_functions: list = None):
    """解析模型输出，识别工具调用 vs 最终答案

    Returns: (action_type, tool_info, reasoning_content, normal_text)
    """
    # Step 1: 用 sglang ReasoningParser 分离 <think> 思维链
    if self.enable_thinking:
        reasoning_content, content = self._get_reasoning_parser().parse_non_stream(text)

    # Step 2: 检测 <answer>...</answer> 标签
    answer_match = re.search(r'<answer>(.*?)</answer>', content, re.DOTALL)
    if answer_match:
        return 'answer', answer_text, reasoning_content, content

    # Step 3: 提取 <tool_call>...</tool_call> 工具调用
    normal_text, tools = self.parse_tools(content, current_functions=current_functions)

    if isinstance(tools, list):
        return 'actions', tools, reasoning_content, normal_text  # 有工具调用
    else:
        return 'answer', normal_text, reasoning_content, normal_text  # 纯文本回复

6.3 parse_tools(response) — sglang 工具解析

verl/envs/tool_manager/http_manager.py : 536-557
def parse_tools(self, response: str, current_functions: list = None):
    """使用 sglang FunctionCallParser 解析 <tool_call> 格式工具调用"""
    if "<tool_call>" not in response:
        return response, None  # 无工具调用

    detector = self._get_fc_detector()        # 懒加载 FunctionCallParser
    tools = self._build_sglang_tools(current_functions)  # 实时构建 Tool 列表
    result = detector.detect_and_parse(response, tools)

    return result.normal_text, [
        {"name": item.name, "args": item.parameters}
        for item in result.calls if item.name
    ]

6.4 execute_actions(responses) — 批量工具执行

verl/envs/tool_manager/http_manager.py : 559-639
def execute_actions(self, responses, batch_tools_kwargs=None, remaining_tool_turns=None, intents=None):
    """批量执行工具调用，返回 (actions, tool_results)"""
    for i, response in enumerate(responses):
        action_type, tool_info, _, _ = self.parse_response(response)

        if action_type == 'actions':
            first_tool = tool_info[0]
            tool_name = first_tool['name']
            tool_args  = first_tool['args']

            result = self.call_tool(tool_name, tool_args, tool_kwargs=tool_kwargs)
            actions.append(tool_name)
            tool_results.append(result)

        elif action_type == 'answer':
            actions.append("")
            tool_results.append(tool_info)  # 答案文本直接作为结果

    return actions, tool_results

6.5 GENERATING 状态 — 工具参数类型校验

verl/experimental/agent_loop/rl_factory_agent_loop.py — _handle_generating_state()

在解析到 action_type='actions' 后，agent_loop 会立即对 LLM 生成的参数进行类型校验， 防止格式错误的调用流入工具服务。 

# 构建 schema 属性映射（工具名 → {参数名: {type: ...}}）
schema_props = {
    tool.get('name'): tool.get('parameters', {}).get('properties', {})
    for tool in self.tool_schemas
}

for tc in parsed_tool_calls:
    props = schema_props.get(tc['name'], {})
    for param_name, param_val in tc['args'].items():
        expected_type = props.get(param_name, {}).get('type', '')
        if expected_type == 'array'  and not isinstance(param_val, list):
            invalid_param = f"expected array, got {type(param_val).__name__}"
        elif expected_type == 'object' and not isinstance(param_val, dict):
            invalid_param = f"expected object, got {type(param_val).__name__}"

# 类型校验失败 → AgentError.RolloutFormatError，生成一条拒绝消息后继续
⚠️
类型校验只覆盖 array / object 两种强类型。 string / integer 类型由工具服务侧自行处理。 校验失败不终止 rollout，而是记录 AgentError.RolloutFormatError 并继续生成。

7. 参数透传（Passthrough）机制

部分参数（用户位置、城市 ID 等）不应由 LLM 自行填充，而应由系统统一注入。 这套机制通过 三层参数流 实现：

① LLM 可见 Schema（精简版）

  • 从 HTTP API 获取完整 Schema
  • 删除 IGNORED_KEYS 列表中的参数
  • LLM 只看到业务相关参数
  • 避免 LLM 幻觉填错位置信息

② tool_kwargs 透传（agent_loop → tool）

  • agent_loop 从数据集读取 default_tool_kwargs
  • 包含: userId, lat, lng, cityId 等
  • 在 call_tool() 中按工具过滤
  • 只注入该工具 schema 中有的透传键

③ 系统默认参数（HTTP 请求层）

  • useCache = True
  • searchSource = 6
  • customParams = ""
  • 工具参数优先，不覆盖
# IGNORED_KEYS 完整列表（从 Schema 隐藏，通过 tool_kwargs 透传）
IGNORED_KEYS = [
    "useCache", "uuid", "userId", "lat", "lng",
    "cityId", "appVersion", "deviceType",
    "originalQuery", "searchSource", "customParams"
]
✅
精妙之处：每个工具记录了自己实际需要透传的键（self.tool_ignored_keys[tool_name]）， call_tool() 中只把对应工具实际有的透传键注入，避免不必要的参数污染。

8. 特殊功能

🧠

Thinking 内容提取

通过 sglang ReasoningParser 懒加载，支持 Qwen3 的 <think>...</think> 思维链提取。 仅当 enable_thinking=True 时启用，独立于工具调用流程。

📚

渐进式工具披露

load_skill(skill_id) 工具由本地 mock 实现。LLM 调用后， 新工具 schema 追加到 tool_schemas，并触发 KV Cache 清理和 PENDING 状态重置， 让新工具在下一轮生成中可见。

🔄

空结果重试

针对特定工具（meituan_search_poi 等）的业务空结果进行透明重试（最多 3 次）。 若全部为空，在结果前追加 [[TOOL_EMPTY_EXHAUSTED]] 标记，供 agent_loop 执行 token mask。

🤝

多模型格式适配

通过 TOOL_MANAGER_REGISTRY 扩展：Qwen3 使用标准 <tool_call> 格式， DeepSeek 使用 DSHTTPToolManager 覆写解析逻辑，支持全角/半角混合括号。

🏪

业务路由 Mock

agent_handoff(id, rewriteQuery) 工具本地 mock 实现，根据 id 模拟美团内不同业务（外卖/医药/酒旅）的路由响应，无需真实服务。

⚡

懒加载解析器

_fc_parser（FunctionCallParser）和 _reasoning_parser 均为懒加载， 首次使用时实例化后复用，避免每个请求重复初始化 sglang 组件的开销。

空结果判断逻辑

def _is_empty_tool_result(tool_name: str, result: str) -> bool:
    if tool_name == "meituan_search_poi":
        return "未找到相关供给" in result or "空结果" in result
    if tool_name == "id_detail_pro":
        return "id_detail工具未能找到商家详情结果" in result
    if tool_name == "meituan_search_mix":
        return "工具未能搜索到相关结果" in result
    return False

# agent_loop 从数据集提取参数

10.5 数据设计要点

🔒

隐私隔离

用户真实坐标（lat/lng）、userId、uuid 通过 default_tool_kwargs 透传，不出现在 LLM 可见的 prompt 中，保护用户隐私。

🎯

意图标注

first_intent + second_intent 提供细粒度意图标签（如 gen/find-shop），ground_truth.intent 组合为完整意图串，支持规则 reward。

🌐

真实请求上下文

originalQuery 和 searchSource 保留了真实的搜索上下文，工具服务可利用这些信息做更精准的召回和排序。

📐

Schema 内嵌

工具 Schema 直接内嵌在 system prompt 中，确保训练时 LLM 看到的工具定义与推理时完全一致，避免分布偏移。

11. v2 离线实现（OfflineHTTPToolManager）

当 tool_manager 为 offline_http 或 qwen3_offline_http 时， 框架使用 http_manager_v2.py 中的 HTTPToolManager（即 OfflineHTTPToolManager）。 v2 针对离线工具服务器（internal toolserver）设计，与 v1 的核心差异如下：

11.1 v1 vs v2 对比

维度 v1 (http_manager.py) v2 (http_manager_v2.py)
目标环境 线上 agentenv（美团内网） 离线 toolserver（训练集群内网）
工具 Schema 来源 动态 — GET /api/tools/list 拉取 静态 — _TOOL_CLASS_MAP + agent_config.json
请求路径 动态 — /api/tools/{tool_name} 硬编码 — 每个工具类声明 path: str
响应字段 result.get('content') or result.get('message') data.get('renderedMarkdown')
请求体构造 直接传 LLM 参数 + tool_kwargs 合并 子类实现 build_request()，显式组装结构化请求
配置层 直接读 config dict OfflineConfig 类（默认值 + 运行时覆盖）
HTTP 封装 内联 requests 调用 OfflineHttpClient（与业务解耦）
注册键 http / qwen3_http / simple offline_http / qwen3_offline_http

11.2 v2 四层架构

① OfflineConfig
• BASE_URL（可被 config_path 覆盖）
• MAX_RETRIES = 5
• TIMEOUT = 300s
• LAT/LNG 北京望京 mock 默认值
② OfflineHttpClient
• post(path, body, token) → str|None
• 与业务完全解耦
• 重试 + raise_for_status
• 返回 renderedMarkdown
③ HTTPTool（抽象基类）
• path: str（子类声明）
• build_request(args) → dict（子类实现）
• call() → 透传参数合并 + 调 OfflineHttpClient
• _lat_lng / _user_info / _location_info 辅助
④ HTTPToolManager
• 读 config_path → _TOOL_CLASS_MAP 按名实例化
• OfflineConfig.BASE_URL 从配置文件覆盖
• parse_tools() / parse_response() 复用 v1 逻辑

工具注册 & Schema 管理

🌐

可靠 HTTP 执行
