Qwen3-ASR Technical Report

全能语音识别模型：52 语言 ASR + 语言识别 + 强制对齐 · 1.7B/0.6B + ForcedAligner-0.6B

A1. 概述与核心贡献

Qwen3-ASR 家族包含三个模型，全部基于 Qwen3-Omni 为基础模型后训练：

模型参数核心能力推理模式最大时长
Qwen3-ASR-1.7B1.7B LM + 300M AuT52 语言/方言 ASR + LID，最强开源 ASR流式 / 离线1200s
Qwen3-ASR-0.6B0.6B LM + 180M AuT同上，最佳精度-效率比，适合端侧部署流式 / 离线1200s
Qwen3-ForcedAligner-0.6B0.6B LM + 180M AuT11 语言强制时间戳对齐，首个基于 LALM 的对齐器NAR（非自回归）300s

A2. 模型架构

A2.1 AuT 音频编码器

flowchart LR
    AUDIO["输入音频\n原始波形"] --> FBANK["FBank 特征\n128维, 100Hz"]
    FBANK --> CONV["Conv2d 8倍下采样\n→ 12.5Hz token 率"]
    CONV --> ENC["AuT Encoder\n自注意力层 x32\n动态窗口 1s-8s"]
    ENC --> PROJ["投影层\nProjector"]
    PROJ --> LM["Qwen3 LLM\n0.6B 或 1.7B"]
    LM --> OUT["文本输出\nlanguage X + ASR text"]

AuT 是基于 AED（Attention-Encoder-Decoder）框架的 ASR 模型，独立预训练后与 Qwen3 LLM 拼接。动态 Flash Attention 窗口（1s-8s）同时支持流式短片段和离线长语音推理。

A2.2 ForcedAligner 架构（时间戳槽填充）

flowchart TD
    SPEECH["语音输入"] --> AUT["AuT Encoder\n帧级语音嵌入\n80ms 帧率"]
    TRANSCRIPT["文本 + [time] 槽位\n每词/字前后插入特殊token"] --> TOK["Qwen3 Tokenizer"]
    AUT --> LM2["Qwen3-0.6B LLM\n联合处理语音+文本"]
    TOK --> LM2
    LM2 --> HEAD["时间戳预测线性层\n分类数 3750 = 300s/80ms"]
    HEAD --> IDX["输出时间戳索引 n_i\n× 80ms = 实际时间"]
非自回归推理的关键：传统 LALM 训练时序列有一位偏移（next-token prediction），ForcedAligner 采用因果训练（causal training）——输出序列与标签序列不偏移，使模型能直接识别 [time] 槽位并非自回归地填充所有时间戳索引。损失只在 [time] 槽位计算，聚焦于时间戳预测任务。

时间戳准确度指标 AAS（Accumulated Average Shift）：

$$\mathrm{AAS} = \frac{1}{N}\sum_{i=1}^{N} |\hat{n}_i - n_i|$$

其中 $\hat{n}_i$ 为预测时间戳，$n_i$ 为参考时间戳（MFA 或人工标注），单位为帧（80ms/帧）。

B3. 模型架构与训练

B3.1 双轨自回归架构

flowchart LR
    TXT["文本 token\n标准 Qwen tokenizer"] --> BACKBONE["Qwen3 LM 骨干网络\n0.6B 或 1.7B"]
    SPK["说话人编码\n可学习 Speaker Encoder\n3s参考音频 or 文本指令"] --> BACKBONE
    BACKBONE -->|"25Hz 变体"| HEAD1["线性预测头\n输出单码本 token"]
    BACKBONE -->|"12Hz 变体"| HEAD2["预测第0层码本\n+ MTP 模块预测\n剩余15层 RVQ"]
    HEAD1 --> C2W1["块式 DiT + BigVGAN\n流式波形重建"]
    HEAD2 --> C2W2["因果 ConvNet\n即时流式解码"]
MTP（Multi-Token Prediction）模块的作用：12Hz 变体需要预测 16 层 RVQ 的所有码本，直接自回归建模开销大且误差积累严重。MTP 模块让骨干网络预测第0层（语义主导），再用轻量分支一次性生成剩余15层声学细节，在单帧内完成，大幅降低延迟。

C2. 核心洞见与读后评注

GSPO 在语音任务中的关键作用
两篇报告都用 GSPO 作为最终 RL 阶段，效果显著：ASR 的 GSPO 主要提升噪声鲁棒性和转录稳定性；TTS 的 GSPO 全面提升多任务能力和跨语言稳定性。这与 FIPO、R3 等工作的发现一致——RL 阶段对于解决"边缘情况"（噪声、方言、复杂文本）特别有效，而监督微调（SFT）容易在这些 case 上欠拟合。
12Hz 双码本 vs 25Hz 单码本的权衡
TTS 报告揭示了一个有趣的设计张力：25Hz 单码本的语义信息更丰富，适合精细控制（VoiceEditing）；但 12Hz 多码本的自回归建模更稳定（长时依赖更好），且因果 ConvNet 解码器使延迟降低约 40%（97ms vs 138ms）。这是"语义表达力"与"生成稳定性"的 trade-off，最终选择取决于应用场景。
非自回归 ForcedAligner 的工程价值
传统强制对齐（MFA/NFA）基于 HMM+GMM 或 CTC，依赖语言特定音素集。Qwen3-ForcedAligner 用 LALM 的槽填充框架，一模型支持 11 语言，AAS 降低 67-77%，且 RTF 接近 0.001（比实时快 1000 倍）。字幕生成、语音数据标注等工业场景将直接受益——不再需要为每种语言维护独立的对齐工具链。
Qwen 生态的语音闭环
Qwen3-ASR（语音→文本）+ Qwen3-TTS（文本→语音）+ Qwen3-Omni（多模态理解）共同构成了一个完整的语音 AI 生态。三者共享 AuT 编码器和 Qwen3 LM 骨干，开发者可以用统一的代码库和权重格式搭建语音助手、实时翻译、语音克隆等全链路应用，是当前开源语音 AI 生态中最完整的解决方案之一。
