标题Tree of Thoughts: Deliberate Problem Solving with Large Language Models

核心问题LLM 的 token 级左到右自回归机制是否足以处理需要探索、战略前瞻、回溯的复杂推理任务？

1. 核心问题与动机

1.1 自回归解码的根本局限

LLM 推理的本质是对下一个 token 的自回归预测，形式化为：

$$p_\theta(x) = \prod_{i=1}^{n} p_\theta(x[i] \mid x[1\ldots i-1])$$

这种机制在大多数任务上有效，但在以下场景根本失败：

flowchart LR
    AUTO["自回归解码\ntoken 级 · 从左到右\n每步无法回头"]
    S1["❌ 需要战略前瞻\nGame of 24：前几步决策影响全局"]
    S2["❌ 需要探索回溯\n填字游戏：局部死路需要撤销"]
    S3["❌ 需要全局评估\n写作计划：整体连贯性 > 局部流畅性"]
    AUTO --> S1 & S2 & S3
认知科学依据（Kahneman 双过程理论）：人类有"System 1"（快速、自动、直觉）和"System 2"（慢速、深思熟虑、有意识）两种思维模式。LLM 的 token 级生成类似 System 1——ToT 的目标是为 LLM 赋予 System 2 的规划能力。这与 Newell、Shaw、Simon 1950 年代的问题空间搜索理论直接呼应。

1.2 现有方法的局限性对比

方法中间步骤局部探索全局决策回溯
IO 提示无无无无
CoT顺序链式无无无
CoT-SC多条独立链无（链内）投票选最频结果无
ToT思维树有（每步多分支）LM 自评估有

2. 背景：推理方法形式化

论文对四种方法给出了统一的数学形式化（以 $p_\theta$ 表示预训练 LM，$x$ 为输入，$y$ 为输出，$z_i$ 为中间思维步骤）：

$$\text{IO: } y \sim p_\theta^{\text{IO}}(y \mid x)$$ $$\text{CoT: } z_i \sim p_\theta^{\text{CoT}}(z_i \mid x, z_{1\ldots i-1}),\quad y \sim p_\theta^{\text{CoT}}(y \mid x, z_{1\ldots n})$$ $$\text{CoT-SC: } \arg\max_y \#\{i \mid y^{(i)} = y\},\quad [z_{1\ldots n}^{(i)}, y^{(i)}] \sim p_\theta^{\text{CoT}}(z_{1\ldots n}, y \mid x)$$ $$\text{ToT: 在状态树 } s = [x, z_{1\ldots i}] \text{ 上搜索，用 } G(p_\theta, s, k) \text{ 生成，} V(p_\theta, S) \text{ 评估}$$

CoT-SC 的核心限制：链内无局部探索，且"最频繁输出"启发式仅适用于输出空间有限的情况（如多选题），不适用于需要连续决策的任务。

3. ToT 框架：四个核心设计

flowchart TD
    DECOMP["1. 思维分解\n将问题拆分为有意义的中间步骤\n粒度由任务决定：词/等式/段落"]
    GEN["2. 思维生成器 G(pθ, s, k)\n策略A：独立采样 k 个思维（丰富空间）\n策略B：顺序提出 k 个候选（约束空间）"]
    EVAL["3. 状态评估器 V(pθ, S)\n策略A：独立评分（1-10 / sure/maybe/impossible）\n策略B：跨状态投票选出最优候选"]
    SEARCH["4. 搜索算法\nBFS：按层保留 top-b 状态，适合有限步骤\nDFS：深度优先+剪枝回溯，适合约束明确任务"]
    DECOMP --> GEN --> EVAL --> SEARCH

3.1 思维生成策略

给定树状态 $s = [x, z_{1\ldots i}]$，生成 $k$ 个候选下一步思维 $z_{i+1}^{(j)}$（$j=1\ldots k$）：

$$\text{策略A（独立采样）：} z^{(j)} \sim p_\theta^{\text{CoT}}(z_{i+1} \mid s), \quad j = 1\ldots k$$ $$\text{策略B（顺序提出）：} [z^{(1)}, \ldots, z^{(k)}] \sim p_\theta^{\text{propose}}(z_{i+1}^{(1\ldots k)} \mid s)$$

策略 A 适合思维空间丰富（如段落写作）时保证多样性；策略 B 适合约束空间（如一行等式）时避免重复。

3.2 状态评估策略

给定当前搜索边界上的若干候选状态集合 $S$，评估器 $V(p_\theta, S)$ 为每个状态 $s \in S$ 赋予一个分值，指导搜索算法决定"往哪走、哪条路剪掉"。论文提出两种互补策略：

$$\text{策略A（独立评分）：} V(p_\theta, S)(s) \sim p_\theta^{\text{value}}(v \mid s), \quad \forall s \in S$$ $$\text{策略B（跨状态投票）：} V(p_\theta, S)(s) = \mathbf{1}[s = s^*], \quad s^* \sim p_\theta^{\text{vote}}(s^* \mid S)$$

两者的关键区别：策略 A 让模型独立审视每条路径，适合有客观可判断性的任务（数学、逻辑）；策略 B 让模型横向比较所有候选，适合主观性强、难以量化的任务（创意写作）。下面通过论文三个实验案例逐一展示。

策略 A — 独立评分（Value）

模型对每个状态单独打分，输出标量（如 1–10 分）或分类标签（sure / maybe / impossible）。每个状态独立送入 LLM，互不知晓其他候选的存在。

案例 1：Game of 24（数学推理）

任务：用 4 个数字（如 4 9 10 13）和四则运算凑出 24。每个中间状态是"已写出的部分等式 + 剩余待用数字"。

评估时，LLM 拿到形如下面的 Value Prompt，对每个中间步骤采样 3 次取众数作为最终分类：
Value Prompt — Game of 24（简化版）

// 示例（few-shot）

Input: 4 4 6 8    Steps so far: 4 + 8 = 12 (left: 4 6 12) → sure

Input: 2 9 10 12 Steps so far: 2 + 12 = 14 (left: 9 10 14) → maybe

Input: 4 9 10 13 Steps so far: 13 - 9 = 4 (left: 4 4 10) → maybe

Input: 1 3 5 7    Steps so far: 5 * 7 = 35 (left: 1 3 35) → impossible

// 待评估状态

Input: 4 9 10 13 Steps so far: [当前候选步骤]

Evaluate if the numbers left can reach 24 (sure/maybe/impossible):

三个标签的含义与作用：

标签含义搜索行为
sure剩余数字几步内必能凑出 24保留，高优先级展开
maybe不确定，需继续探索保留，与 sure 一起进入下一层
impossible剩余数字太大/太小，绝无可能剪枝，不再展开该分支

BFS 每层只保留被评为 sure 或 maybe 的 top-$b$（$b=5$）个状态，impossible 状态直接丢弃。消融实验表明：将此三分类改为随机评估，成功率从 74% 暴跌至约 10%，验证了 LLM 自评估的核心作用。

案例 2：5×5 填字游戏（约束满足）

与数学推理不同，填字游戏的评估不是打分，而是可行性验证：当前已填入的单词是否与剩余空格的字母约束相容？

DFS 每填一个词后，LLM 将现有填法转化为对剩余提示词的字母约束（如"第 2 行第 3 列必须是 'E'"），再判断每条剩余线索是否"可能填入"。一旦某条线索被判为 impossible（如约束要求某位置同时是 'A' 和 'T'），DFS 立即回溯到父节点，放弃当前子树。

策略 B — 跨状态投票（Vote）

当任务目标难以直接量化时（"这段文字好不好"无法给出客观分数），改用相对比较：把所有候选状态一起呈给 LLM，让它投票选出最优者。论文对同一批候选进行 $k$（通常 5）次独立投票，得票最多的候选胜出。

案例 3：创意写作（主观评估）

任务：给定 4 个结尾句，写出 4 段衔接连贯的段落。中间状态是"写作计划（Plan）"而非部分文本。

评估不问"这个计划有多少分"，而是问"在这 5 个计划里，哪个最有可能写出连贯的段落？"
Vote Prompt — 创意写作（简化版）

// 任务说明

Given an instruction and several choices, decide which choice is most promising.

Analyze each choice in detail, then conclude in the last line:

"The best choice is {s}", where s is the integer id of the choice.

// 任务指令

Instruction: Write a coherent passage of 4 short paragraphs. The end sentence of each paragraph must be:

  1. It isn't difficult to do a handstand if you just stand on your hands.

  2. It caught him off guard that space smelled of seared steak.

  3. When she didn't like a guy who was trying to pick her up, she started using sign language.

  4. Each person who knows you has a different perception of who you are.

// 5 个候选计划

Choice 1: [计划内容A]

Choice 2: [计划内容B]

…

两种策略的选用原则

维度 策略 A：独立评分（Value） 策略 B：跨状态投票（Vote）
核心问题 这个状态本身有多好？ 这几个状态中哪个更好？
适用场景 有客观标准可判定（数学、逻辑、约束满足） 主观性强、难以量化（创意写作、开放问答）
LLM 调用次数 每状态独立调用，共 $|S|$ 次 所有状态合并一次调用，重复 $k$ 次
输出形式 标量分数 或 sure/maybe/impossible "The best choice is X"
论文中使用任务 Game of 24 / 5×5 填字游戏 创意写作
可解释性 高（每条路径有独立得分） 中（只知最优选项，不知绝对质量）
LM 自评估的创新性：传统搜索启发式要么是人工编程（如 DeepBlue 的棋位评估函数），要么是从大量数据中学习（如 AlphaGo 的价值网络）。ToT 提出第三种方式——用 LM 自身的推理能力进行临时评估：既比编程规则灵活（可泛化到任意文本任务），又比学习启发式样本效率高（无需额外训练数据）。随着 LLM 推理能力的提升，这个评估器会自动变强，构成正向飞轮。

4. 算法伪代码（原文 Algorithm 1 & 2）

Algorithm 1: ToT-BFS

Input: x, pθ, G, V, step limit T, breadth b, candidates k

S₀ ← {x}

for t = 1, …, T do

S'ₜ ← {[s, z] | s ∈ Sₜ₋₁, z ∈ G(pθ, s, k)}

Vₜ ← V(pθ, S'ₜ) // 评估所有候选

Sₜ ← top-b states in S'ₜ by Vₜ

end for

return G(pθ, argmaxs∈Sₜ Vₜ(s), 1)

Algorithm 2: ToT-DFS

Input: state s, step t, pθ, G, V, limit T, threshold v_th

if t > T then record output G(pθ, s, 1)

end if

for s' ∈ G(pθ, s, k) do

if V(pθ, {s'})(s) > v_th then

DFS(s', t+1) // 递归深入

end if

// 否则剪枝，回溯到父状态

end for

4.1 BFS 具体走步演示：Game of 24（输入 4 9 10 13）

BFS 按层展开：每层对所有活跃节点各生成 $k$ 个候选思维，统一评估后只保留 top-$b$（论文取 $b=5$）个状态进入下一层。

问题设定：输入数字 4 9 10 13，目标凑出 24，每步写一个中间等式，共 3 步。

BFS 的关键特性：同一层的所有活跃节点并行展开，每层结束后统一"剪枝"，确保保留的 $b$ 个状态是全局最优而非局部贪心。适合树深度有限（≤3步）且每步候选数可控的任务。

4.2 DFS 具体走步演示：5×5 填字游戏

DFS 每次只展开一条路径，遇到死路则立刻回溯。适合深度大（最多10个词）但每步候选空间可以快速验证可行性的任务。

问题设定（简化为 3×3，保留核心逻辑）：横向提示 H1="使用 LLM 推理的框架"（TREE），H2="颜色"（RED），H3="数字"（ONE）；纵向提示 V1="植物"（TRO…），V2="哺乳动物"（REE…），V3="感受"（EDN…）。

━━━ Step 1：填置信度最高线索 H1 ━━━

4.3 BFS vs DFS：选用原则

维度 BFS（宽度优先） DFS（深度优先）
核心思路 按层展开，每层保留 top-b 沿最优路径深入，碰壁即回溯
适用场景 树深度小（≤3步），每步候选空间大 树深度大（可达10步），有强约束可剪枝
内存开销 $O(b \times T)$，随宽度线性增长 $O(T)$，只保存当前路径
评估时机 每层统一批量评估后剪枝 每步立即评估，不过阈值即剪枝
是否能回溯 不回溯（层内平行保留多个状态） 核心机制之一
论文任务 Game of 24、创意写作 5×5 填字游戏
LLM 调用次数 约 $b \times k \times T$（每层全展开） 依赖剪枝效率，最坏 $k^T$，实际远小于此
直觉类比：BFS 像多线并联的流水线——每层同时跑 b 条产线，质检后淘汰次品；DFS 像单人走迷宫——遇死路立刻退回上一个路口换方向。数学任务（有限步数、需全局最优）选 BFS；约束满足任务（步数多、局部可快速判断可行性）选 DFS。

6.2 评估策略消融

评估策略对结果至关重要：在 Game of 24 中，将"sure/maybe/impossible"三分类评估换成随机选择，成功率从 74% 降至约 10%，接近于盲目 BFS。这证明 LM 的自评估能力是 ToT 成功的核心，而非仅仅是搜索结构本身。

7. 局限性与适用边界

  • 计算成本高：每步需要多次 LM 调用（生成 + 评估），比 CoT 贵数倍到数十倍。b=5 的 Game of 24 需要约 500 次调用 vs CoT 的 100 次
  • 任务适用性受限：对于不需要搜索的任务（如直接问答），ToT 无优势。论文实验任务都是精心选择的难题
  • 思维分解依赖人工设计：不同任务的思维粒度（词/句/段）、评估方式（评分/投票）、搜索算法都需要人工指定
  • 外部影响风险：若在交互式环境中部署，多步搜索可能受到环境扰动（prompt injection 等）影响
  • 评估主观性：创意写作任务的"连贯性"评分由 GPT-4 完成，存在 self-serving bias 风险

8. 核心洞见与读后评注

本质贡献：把 LLM 推理建模为搜索问题
ToT 最深刻的贡献不是某个具体算法，而是提供了一个框架——将 LLM 推理从"生成问题"转化为"搜索问题"。IO/CoT/CoT-SC 都是 ToT 在特殊约束下的特例（深度1/宽度1的树）。这个统一视角为后续工作（LATS、AlphaCode、MCTS for LLM）奠定了概念基础。
LM 自评估：一个可扩展的启发式
传统搜索需要外部启发式函数（棋类游戏中的位置评估）。ToT 发现 LLM 自身可以作为启发式函数——用 prompt 让模型评估"当前状态离目标有多近"。这个技术在其他领域（代码调试、数学证明）同样适用，且随 LLM 能力提升而自动改善。
60% 第一步失败的深层含义
Game of 24 中 CoT 60% 在第一步失败，揭示了一个深层事实：LLM 的 token 预测能力和"问题求解"能力之间存在根本鸿沟。预测"下一个最可能的 token"和"下一个最有利于达成目标的 token"是两个不同的问题。ToT 用搜索+评估弥合了这一鸿沟。
对后续工作的影响
ToT 直接启发了：LATS（Language Agent Tree Search，结合 MCTS）、AlphaProof（数学证明的树搜索）、Reasoning with Search（OpenAI o1 系列的内核思路）、RAP（Reasoning via Planning，用世界模型做前向模拟）。"让 LLM 在推理时做搜索"已成为 2024-2026 年推理模型的核心设计哲学之一。
