一、开篇：为何搬数据比算数贵

现代计算的 central surprise：算术几乎免费，内存访问昂贵。从主存取一个值的时间内，处理器可完成数千次浮点运算——这不是待修复的工程缺陷，而是光速与硅片电子移动能量的物理后果。硬件加速的本质不是"算得更快"，而是组织内存、数据流与并行性以最小化数据移动成本。但"能跑多快"只是 half of the story——还须用可复现测量证明优化在端到端 SLO 下成立。

定义：硬件加速（Hardware Acceleration）

用面向 ML 张量运算的领域专用硅片替代通用处理器逻辑，以可编程性换取 $R_{\text{peak}}$ 与每瓦性能。A100 FP16 矩阵乘 312 TFLOP/s vs 服务器 CPU ~1–2 TFLOP/s，差距 156–312×。

  • 常见陷阱：峰值 TFLOP/s ≠ 实际吞吐；低算术强度内核无论芯片多快都会饿死等数据
  • 软硬协同：INT8 加速来自 Tensor Core 与算法共同设计，非"位数更少"的抽象收益

1.1 Amdahl 定律与加速上限

$$\text{Speedup} = \frac{1}{(1-p) + \frac{p}{G_{\text{accel}}}}$$

$p$ 为可并行分数（ML 中矩阵乘约 90–99%），$G_{\text{accel}}$ 为加速器相对 CPU 增益。5% 串行开销（数据加载、Python、kernel launch）即使 $G_{\text{accel}}=\infty$ 也仅 20× 总加速。

场景H100 硬件增益并行分数 $p$实际系统加速
ResNet-50 推理247×0.95~18.6×
GPT-2 逐 token 生成247×0.80~4.9×

算术强度（Arithmetic Intensity）

$I = O / D_{\text{vol}}$（FLOP/byte）——回答"搬数据 vs 算数"的核心指标。高 $I$ 的 tiled GEMM 受益于更多 TFLOP/s；低 $I$ 的 LayerNorm/Attention 受益于更多带宽。

TPUv1 vs K80 效率冲击（2015）

Google 首代 TPU 推理比 K80 GPU 快 15–30×，能效高 30–80×——剥离缓存、分支预测、乱序执行，_die 填满 256×256 8-bit 脉动阵列。证明针对算法原语定制硅片可获数量级增益，Moore 定律 alone 需数十年才能达成。

Systems Gap：模型算力需求年增约 6×，GPU 供应约 1.7×/年——差距须靠并行、压缩与协同设计填补，不能坐等下一代芯片。

三、AI 计算原语

ML 框架抽象的核心是矩阵乘（GEMM）、向量运算与非线性 SFU。全连接层、Attention QKV 投影、卷积 im2col 变换均归约为 GEMM。

3.1 执行单元演进

架构并行模型特点代表
SIMD单指令多数据向量宽度固定CPU AVX-512
SIMT单指令多线程线程级分支NVIDIA CUDA Core
Tensor Core混合精度矩阵块FP16/BF16/INT8/TF32A100/H100
脉动阵列数据流过 PE 网格权重驻留、数据流TPU, Google

Tensor Core 契约

A100 Tensor Core 仅对特定精度/维度触发（FP16、BF16、TF32）。工作负载用不支持的 FP32 累加路径会回退到 CUDA Core（约 1/16 吞吐）——硬件特性是 brittle contract，必须 conform 数据类型与 tile 形状。

3.2 N:M 稀疏与分块（Tiling）

分块原则：将大图/大张量切分为 SRAM 可容纳的 tile，在片上复用数据后再写回 HBM。FlashAttention 即 IO-aware 分块 attention，避免物化完整 $S \times S$ 矩阵。

FlashAttention 流量对比

标准 Attention（seq=4096, FP16）：物化 $S \times S$ 矩阵 → HBM 读写 $\mathcal{O}(S^2) \approx 67$ MB/层/head。
FlashAttention-2：分块在 SRAM 完成 softmax → $\mathcal{O}(S)$ 流量，A100 上 2–4× 加速，算术强度从 0.75 提升至 ~20 FLOP/byte（跨越 H100 脊点方向）。

四、AI 内存系统

AI 内存墙（AI Memory Wall）

当 $R_{\text{peak}}$ 增速远超 BW 时，性能由 $\frac{D_{\text{vol}}}{\text{BW}}$ 主导。H100：~989 TFLOP/s FP16 vs 3.35 TB/s HBM → 需 ~295 FLOP/byte 才能喂饱 ALU。

4.1 硬件平衡与脊点

$$I_{\text{ridge}} = \frac{R_{\text{peak}}}{\text{BW}}$$

脊点划分 memory-bound（$I \lt I_{\text{ridge}}$）与 compute-bound 两区域。H100 脊点 ~295 FLOP/byte；Jetson Xavier（~137 GB/s）脊点 ~20——同一 MobileNet 层在云端算力饥饿、边缘带宽饥饿。

4.2 内存层次

层级延迟带宽DL 用途
寄存器 / Shared SRAM~1–10 ns最高Tensor Core tile、FlashAttention
HBM~100 nsTB/s 级权重、激活、KV cache
DRAM/SSDµs–ms中–低checkpoint、KV offload

Horowitz 能量层级：片外 DRAM 读/写相对 INT8 加法约 6400×/21000×——优化须减少 bit 移动，非单纯堆 FLOP/s。

4.3 ML 不规则访问

Embedding lookup（DLRM）、变长序列、Attention KV-cache、小 batch 破坏缓存局部性——稠密 GEMM 擅长的加速器在不规则部分 struggle。结构化稀疏（2:4）是为对齐硬件而设计的折中。

4.4 手算：MobileNetV2 depthwise 层

输入 $112\times112\times32$，depthwise $3\times3$，pointwise $1\times1$ 扩至 64 通道：

  • Depthwise FLOPs：$112^2 \times 32 \times 9 \approx 1.1 \times 10^7$
  • Pointwise FLOPs：$112^2 \times 32 \times 64 \times 2 \approx 5.8 \times 10^7$
  • 读写字节（FP32 权重+激活）：约 1.6 MB → 算术强度 $I \approx 7$ FLOP/byte

H100 脊点 ~295 FLOP/byte：$I \approx 7$ → 严重 memory-bound，INT8 量化比加 FLOP/s 更有效。

利用率鸿沟：H100 vs A100

脊点从 A100 ~153 升至 H100 ~295 FLOP/byte。$I=200$ 的算法在 A100 上 compute-bound，在 H100 上变 bandwidth-bound——"遗留"代码常只见 1.6× 而非 3.2× 加速（带宽比 vs FLOP 比）。

六、硬件映射与数据流

映射问题：给定计算图与加速器，如何 placement（算子放哪）、allocation（张量放哪级内存）、scheduling（执行顺序）以最大化复用？组合爆炸使编译器/运行时（TVM、XLA、TensorRT）成为必需。

6.1 数据流模式

数据流权重/激活移动适用
Weight Stationary (WS)权重驻留 PE推理权重复用高
Output Stationary (OS)部分和驻留输出复用
Row/Col Stationary输入行/列驻留不同 reuse 模式

TPU 脉动阵列采用 weight-stationary：权重加载一次后在 PE 间流动，输入激活流过，最小化 HBM 往返。GPU 通过 shared memory tiling 模拟类似复用。

编译器链（DR 部署）：PyTorch → ONNX → TensorRT；trtexec --onnx=mobilenetv2_dr.onnx --saveEngine=dr.plan --fp16 --int8。须 profiling 确认 kernel 命中 Tensor Core——FP32 累加路径峰值从 312 跌至 ~19 TFLOP/s。

Tensor 生命周期（KWS on GPU）

16K 样本 FP16 音频：HBM（~300 ns, ~20 pJ/bit）→ L2（~4 ns）→ L1/Shared（~1 ns）→ 寄存器/Tensor Core（~0.1 pJ/bit）。Roofline 由 Step1→Step4 的链路带宽决定——光速极限意味着不能比搬数据更快地计算。

过渡：从 Profile 到 Proof。Roofline 告诉你该优化带宽还是算力；基准测试验证优化是否在端到端 SLO 下成立。Profile 给出方向，Benchmark 给出问责——二者缺一不可。

七、为何需要 ML 基准测试

剪枝模型在 A 加速器上 2× 更快，在 B 上无改善；增大 batch 提升利用率却违反延迟 SLO。每项优化都带承诺——基准测试是将理论主张转化为可验证工程知识的纪律，量化 peak 与 sustained 性能之间、实验室与生产之间的鸿沟。

定义：ML 基准测试

在代表性 ML 工作负载上端到端测量系统性能，将厂商峰值规格与 realistic 条件下可持续的吞吐/延迟解耦。A100 峰值 312 TFLOP/s，生产 Transformer 训练 MFU 通常 30–50%（93.6–156 TFLOP/s）——$\eta_{\text{hw}}$ 鸿沟须由基准量化。

  • 系统基准：硬件是否在 realistic 负载下兑现承诺（带宽饱和、dispatch 开销）
  • 模型基准：优化是否在全输入分布上保留质量（非仅测试集）

三条原则

  1. 基准是代理，非真理——Offline 10K QPS vs Server 模式可能差一个数量级
  2. Goodhart 定律：指标成为目标即失效（BLEU 刷榜 vs 用户延迟）
  3. 端到端 > 组件指标：推理 5 ms→10 ms 模型阶段在 50 ms 流水线中仅 ~1.2× 端到端改善

十、训练 vs 推理基准

同一加速器在训练与推理中相反方式失败：训练 waste 天数于梯度同步；推理 miss SLO 于 tail latency 尖峰。故 MLPerf Training 与 Inference 分离。

维度TrainingInference
计算方向Forward + BackwardForward only
内存参数+梯度+优化器+激活（3–4× 推理）权重+激活+KV cache
优化目标Time-to-accuracy、scalingLatency 分位数、QPS
绑定约束小 scale 算力；大 scale 通信 BW延迟、tail、冷启动
能耗模式一次性摊销（GPT-3 ~1287 MWh）每 query 累积（$E = P \times T$）

十一、训练基准与 MFU

$$T_{\text{train}} = \operatorname{arg\,min}_{t}\big\{\text{Accuracy}(t) \geq \text{target accuracy}\big\}$$
$$\text{Throughput} = \frac{N_{\text{samples}}}{T_{\text{train}}}$$

吞吐 alone 无意义——MLPerf ResNet-50 须达 75.9% top-1 才有效。未达目标的"快"不算数。

11.1 扩展效率

$$\text{Eff}_{\text{scaling}} = \frac{T(1)}{N_{\text{GPU}} \times T(N_{\text{GPU}})} \times 100\%$$

例：单卡 24 h，8 卡 4 h → $\text{Eff} = 24/(8 \times 4) = 75\%$。丢失 25% 来自 AllReduce（10–15%）、CPU↔GPU 拷贝（3–5%）、负载不均（2–5%）。

11.2 MFU（Model FLOPs Utilization）手算

$$\text{MFU} = \frac{\text{Achieved FLOP/s}}{\text{Peak FLOP/s}} = \frac{6 \times N \times D \times H \times L \times T / T_{\text{step}}}{R_{\text{peak}}}$$

例：GPT-2 117M，batch=32，seq=1024，A100 FP16 峰值 312 TFLOP/s，实测 step 120 ms：

  • 每 step FLOPs ≈ $6 \times 32 \times 1024 \times 768 \times 12 \approx 1.8 \times 10^{12}$
  • Achieved = $1.8 \times 10^{12} / 0.12 \approx 15$ TFLOP/s
  • MFU = $15/312 \approx 4.8\%$（小模型 GPU 利用率极低——CPU/Python 开销主导）

LLM 7B+ scale MFU 30–50% 常见；MFU 低 ≠ 浪费，小 scale 通信/launch 占比高是物理现实。MFU 是 Roofline compute-bound 区域的利用率度量——与 memory-bound 操作的 $R_{\text{attain}}$ 互补。

十二、推理基准与有效 QPS

12.1 推理指标

  • Latency：单请求延迟；生产关注 p95/p99 而非均值
  • Throughput：满足 SLO 的有效 QPS——违反 SLO 的请求不计入
  • Tail latency：多组件 fan-out 时 tail 放大（Tail at Scale）

12.2 MLPerf 执行场景

场景负载模式优化目标
SingleStream逐条顺序最低延迟
MultiStream多流并行多传感器/多摄像头

Server 场景要点

10,000 QPS 但 5% 违反 99%ile SLO → 报告有效 QPS 9,500。Server 模式模拟真实 serving：请求随机到达、batch 与队列竞争同一延迟预算。

12.3 有效 QPS 手算

$$\text{QPS}_{\text{valid}} = \text{QPS}_{\text{raw}} \times (1 - p_{\text{SLO violation}})$$

例：ResNet-50 Server 模式测得 raw 12,000 QPS，p99 目标 15 ms，实测 8% 请求 p99 > 15 ms → 有效 QPS = $12000 \times 0.92 = 11040$。若只报 12K 则 overstate 产能 7.3%。

十三、功耗测量

SPEC Power（2007）在 0–100% 共 11 档负载测 ssj_ops/W——ML serving 很少 100% 满载，部分负载效率决定真实电费。Green500 按 FLOP/s/W 排名，教训是最快集群 ≠ 最经济集群。

$$E_{\text{total}} = \text{Power} \times T$$

300 W 加速器、10 ms 推理 → $300 \times 0.01 = 3$ J（~0.0008 Wh）。MLPerf Power 标准化测量边界：加速器 alone vs 整机 vs 机架级——边界选择可差 2–3×。

算法能效 vs 硬件功耗

压缩（INT8 量化）通过减少工作量降能耗，非仅换更省电硬件。MobileNet 深度可分离卷积 + INT8 可在算法与数值两层同时攻击 $D_{\text{vol}}$ 与 $O$ 项——Roofline 低 $I$ 区域的首选策略。

十四、最佳实践与陷阱

  • 统计 rigor：多次 run、报告分布而非单次 best；GPU boost/thermal throttling 可淹没小增益
  • Benchmark-production gap（2–10×）：漂移、节流、动态负载、静默退化——再精密的仪器 alone 无法消除
  • Benchmark gaming：test-set 调参、kernel 特化——MLPerf 多工作负载缓解
  • 模型评估盲区：高准确率 ≠ 校准良好；须测子群指标（DR 农村 0.88 vs 全局 0.95 → 拒绝部署）与分布外性能

移动/边缘 omitted 条件

厂商 burst 推理数字若未测 sustained 热节流，steady-state 性能可远低于峰值——Jetson DR 部署最常被误导的 omitted 条件，直接关联 p99 < 2000 ms 验收基准。

十五、章节总结

核心要点

  1. 内存墙是物理约束：搬数据能量 >> 算术，Roofline 脊点 $I_{\text{ridge}}$ 是选择优化方向的首要诊断
  2. DSA（TPU/Tensor Core）用可编程性换 10–300× 张量吞吐，但仅匹配规则并行负载；Amdahl 串行分数限制端到端加速
  3. MFU 量化 compute-bound 利用率；memory-bound 操作看 $R_{\text{attain}} = \min(R_{\text{peak}}, \text{BW} \times I)$
  4. 基准是 D·A·M 协同设计的问责机制——系统/模型/数据三维 + micro/macro/e2e 粒度按决策问题选择
  5. 训练看 time-to-accuracy 与 scaling efficiency；推理看 SLO 约束下的有效 QPS 与 tail
  6. DR 验收：农村灵敏度 ≥0.90 + p99 < 2000 ms + PSI < 0.20——Profile 与 Proof 的统一落地
  7. Goodhart + benchmark-production gap：设计 for benchmark = 对 shifting reality 过拟合
选芯片的问题不是"哪个最快"，而是哪个芯片的内存系统最匹配模型的访问模式——然后用 MLPerf Server 场景证明该选择在 SLO 下成立。
