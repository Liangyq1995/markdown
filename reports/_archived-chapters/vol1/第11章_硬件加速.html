一、开篇：为何搬数据比算数贵

现代计算的 central surprise：算术几乎免费，内存访问昂贵。从主存取一个值的时间内，处理器可完成数千次浮点运算——这不是待修复的工程缺陷，而是光速与硅片电子移动能量的物理后果。硬件加速的本质不是"算得更快"，而是组织内存、数据流与并行性以最小化数据移动成本。

定义：硬件加速（Hardware Acceleration）

用面向 ML 张量运算的领域专用硅片替代通用处理器逻辑，以可编程性换取 $R_{\text{peak}}$ 与每瓦性能。A100 FP16 矩阵乘 312 TFLOP/s vs 服务器 CPU ~1–2 TFLOP/s，差距 156–312×。

  • 常见陷阱：峰值 TFLOP/s ≠ 实际吞吐；低算术强度内核无论芯片多快都会饿死等数据
  • 软硬协同：INT8 加速来自 Tensor Core 与算法共同设计，非"位数更少"的抽象收益

1.1 Amdahl 定律与加速上限

$$\text{Speedup} = \frac{1}{(1-p) + \frac{p}{G_{\text{accel}}}}$$

$p$ 为可并行分数（ML 中矩阵乘约 90–99%），$G_{\text{accel}}$ 为加速器相对 CPU 增益。5% 串行开销（数据加载、Python、kernel launch）即使 $G_{\text{accel}}=\infty$ 也仅 20× 总加速。

场景H100 硬件增益并行分数 $p$实际系统加速
ResNet-50 推理247×0.95~18.6×
GPT-2 逐 token 生成247×0.80~4.9×

算术强度（Arithmetic Intensity）

$I = O / D_{\text{vol}}$（FLOP/byte）——回答"搬数据 vs 算数"的核心指标。高 $I$ 的 tiled GEMM 受益于更多 TFLOP/s；低 $I$ 的 LayerNorm/Attention 受益于更多带宽。

TPUv1 vs K80 效率冲击（2015）

Google 首代 TPU 推理比 K80 GPU 快 15–30×，能效高 30–80×——剥离缓存、分支预测、乱序执行，_die 填满 256×256 8-bit 脉动阵列。证明针对算法原语定制硅片可获数量级增益，Moore 定律 alone 需数十年才能达成。

Systems Gap：模型算力需求年增约 6×，GPU 供应约 1.7×/年——差距须靠并行、压缩与协同设计填补，不能坐等下一代芯片。

三、AI 计算原语

ML 框架抽象的核心是矩阵乘（GEMM）、向量运算与非线性 SFU。全连接层、Attention QKV 投影、卷积 im2col 变换均归约为 GEMM。

3.1 执行单元演进

架构并行模型特点代表
SIMD单指令多数据向量宽度固定CPU AVX-512
SIMT单指令多线程线程级分支NVIDIA CUDA Core
Tensor Core混合精度矩阵块FP16/BF16/INT8/TF32A100/H100
脉动阵列数据流过 PE 网格权重驻留、数据流TPU, Google

Tensor Core 契约

A100 Tensor Core 仅对特定精度/维度触发（FP16、BF16、TF32）。工作负载用不支持的 FP32 累加路径会回退到 CUDA Core（约 1/16 吞吐）——硬件特性是 brittle contract，必须 conform 数据类型与 tile 形状。

3.2 N:M 稀疏与分块（Tiling）

分块原则：将大图/大张量切分为 SRAM 可容纳的 tile，在片上复用数据后再写回 HBM。FlashAttention 即 IO-aware 分块 attention，避免物化完整 $S \times S$ 矩阵。

FlashAttention 流量对比

标准 Attention（seq=4096, FP16）：物化 $S \times S$ 矩阵 → HBM 读写 $\mathcal{O}(S^2) \approx 67$ MB/层/head。
FlashAttention-2：分块在 SRAM 完成 softmax → $\mathcal{O}(S)$ 流量，A100 上 2–4× 加速，算术强度从 0.75 提升至 ~20 FLOP/byte（跨越 H100 脊点方向）。

四、AI 内存系统

AI 内存墙（AI Memory Wall）

当 $R_{\text{peak}}$ 增速远超 BW 时，性能由 $\frac{D_{\text{vol}}}{\text{BW}}$ 主导。H100：~989 TFLOP/s FP16 vs 3.35 TB/s HBM → 需 ~295 FLOP/byte 才能喂饱 ALU。

4.1 硬件平衡与脊点

$$I_{\text{ridge}} = \frac{R_{\text{peak}}}{\text{BW}}$$

脊点划分 memory-bound（$I \lt I_{\text{ridge}}$）与 compute-bound 两区域。H100 脊点 ~295 FLOP/byte；Jetson Xavier（~137 GB/s）脊点 ~20——同一 MobileNet 层在云端算力饥饿、边缘带宽饥饿。

4.2 内存层次

层级延迟带宽DL 用途
寄存器 / Shared SRAM~1–10 ns最高Tensor Core tile、FlashAttention
HBM~100 nsTB/s 级权重、激活、KV cache
DRAM/SSDµs–ms中–低checkpoint、KV offload

Horowitz 能量层级：片外 DRAM 读/写相对 INT8 加法约 6400×/21000×——优化须减少 bit 移动，非单纯堆 FLOP/s。

4.3 ML 不规则访问

Embedding lookup（DLRM）、变长序列、Attention KV-cache、小 batch 破坏缓存局部性——稠密 GEMM 擅长的加速器在不规则部分 struggle。结构化稀疏（2:4）是为对齐硬件而设计的折中。

4.4 手算：MobileNetV2 depthwise 层

输入 $112\times112\times32$，depthwise $3\times3$，pointwise $1\times1$ 扩至 64 通道：

  • Depthwise FLOPs：$112^2 \times 32 \times 9 \approx 1.1 \times 10^7$
  • Pointwise FLOPs：$112^2 \times 32 \times 64 \times 2 \approx 5.8 \times 10^7$
  • 读写字节（FP32 权重+激活）：约 1.6 MB → 算术强度 $I \approx 7$ FLOP/byte

H100 脊点 ~295 FLOP/byte：$I \approx 7$ → 严重 memory-bound，INT8 量化（第 10 章）比加 FLOP/s 更有效。

利用率鸿沟：H100 vs A100

脊点从 A100 ~153 升至 H100 ~295 FLOP/byte。$I=200$ 的算法在 A100 上 compute-bound，在 H100 上变 bandwidth-bound——"遗留"代码常只见 1.6× 而非 3.2× 加速（带宽比 vs FLOP 比）。

六、硬件映射与数据流

映射问题：给定计算图与加速器，如何 placement（算子放哪）、allocation（张量放哪级内存）、scheduling（执行顺序）以最大化复用？组合爆炸使编译器/运行时（TVM、XLA、TensorRT）成为必需。

6.1 数据流模式

数据流权重/激活移动适用
Weight Stationary (WS)权重驻留 PE推理权重复用高
Output Stationary (OS)部分和驻留输出复用
Row/Col Stationary输入行/列驻留不同 reuse 模式

TPU 脉动阵列采用 weight-stationary：权重加载一次后在 PE 间流动，输入激活流过，最小化 HBM 往返。GPU 通过 shared memory tiling 模拟类似复用。

编译器链（DR 部署）：PyTorch → ONNX → TensorRT；trtexec --onnx=mobilenetv2_dr.onnx --saveEngine=dr.plan --fp16 --int8。须 profiling 确认 kernel 命中 Tensor Core——FP32 累加路径峰值从 312 跌至 ~19 TFLOP/s。

Tensor 生命周期（KWS on GPU）

16K 样本 FP16 音频：HBM（~300 ns, ~20 pJ/bit）→ L2（~4 ns）→ L1/Shared（~1 ns）→ 寄存器/Tensor Core（~0.1 pJ/bit）。Roofline 由 Step1→Step4 的链路带宽决定——光速极限意味着不能比搬数据更快地计算。

七、章节总结

核心要点

  1. 内存墙是物理约束：搬数据能量 >> 算术，决定加速器设计优先级
  2. DSA（TPU/Tensor Core）用可编程性换 10–300× 张量吞吐，但仅匹配规则并行负载
  3. 算术强度 $I$ 与 Roofline 脊点 $I_{\text{ridge}}$ 是选择优化方向的首要诊断工具
  4. Amdahl 串行分数限制端到端加速；LLM 解码 $p$ 更低，更依赖 batching/投机解码
  5. 内存层次 + tiling + 融合是将 paper FLOPs 转化为 wall-clock 的关键
  6. 软硬协同：INT8/2:4 稀疏/FP8 等需算法与编译器共同 conform 硬件契约
选芯片的问题不是"哪个最快"，而是哪个芯片的内存系统最匹配模型的访问模式——大 embedding 表 vs 紧凑权重张量需要截然不同的加速器。
