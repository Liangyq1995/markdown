概述

人工智能正在以前所未有的速度渗透科学研究的各个环节。从文献综述、假设生成到实验设计、数据分析，再到最终的论文撰写，AI 编程 Agent（如 Claude Code、Codex CLI、OpenClaw 等）正被越来越多地标榜为"能够自主开展科学研究"的工具。然而，一个根本性的问题始终悬而未决：这些系统是否真的具备端到端的科学发现能力？我们如何客观、可重复地衡量这种能力？

现有的 AI 科学能力评测体系存在严重碎片化问题。GPQA、MMLU、SciQ 等基准测试聚焦于科学知识的问答与推理，考察的是孤立的知识点，而非完整的研究过程。MLAgentBench、MLE-bench 等基准虽然引入了 Agent 执行循环，但主要局限于机器学习工程领域，缺乏对自然科学多样性的覆盖。PaperBench 要求 Agent 复现已知论文，但目标论文对被评估系统是可见的——这与真实科研场景中"先有问题、后有发现"的逻辑截然相反。

ResearchClawBench（RCBench）正是为填补这一空白而生。它的核心设计哲学是：以真实已发表论文为锚点，但在评估时对系统隐藏目标论文，要求系统仅凭任务描述、相关文献和原始数据，独立完成"重新发现"。这一设计使评估既有明确的科学锚点（可验证性），又保留了真实研究的开放性（发现空间）。基准涵盖 40 个任务、10 个科学领域，并引入了 ResearchHarness 评估框架，使原生 LLM 也能参与端到端评测。

实验结果令人警醒：最强系统（Claude Code）平均分仅 21.5/100，距离"重发现阈值"（50 分）还有相当大的差距；最强 LLM（Claude-Opus-4.7）平均分 20.7，LLM 前沿均值仅 26.5。错误分析表明，失败主要集中在实验协议不匹配（89.5%）、证据不匹配（78.5%）和科学核心缺失（68.0%）三种模式，揭示了当前 AI 自主科研能力的真实边界。

RCBench 的核心价值不仅在于提供了一个排行榜，更在于它将"AI 能否做科学"这一模糊问题转化为了可测量、可重复的工程挑战，为未来自主科研系统的迭代提供了清晰的评估坐标。

研究背景

自主 AI 科研的发展脉络

AI 辅助科研的探索可以追溯到早期的专家系统，但真正意义上的"自主 AI 科学家"概念在 LLM 时代才开始具备可行性。2024 年，Lu 等人提出的 The AI Scientist 展示了 LLM Agent 自动生成论文草稿的可能性；Gottweis 等人的 AI Co-Scientist 探索了"科学家在环"的假设演化框架。2026 年，InternAgent-1.5 进一步尝试长时域自主科学发现，Tang 等人的 AI-Researcher 则专注于自主科学创新。与此同时，商业编程 Agent（Claude Code、Codex CLI 等）也开始被广泛用于科学计算任务，形成了"工具型 Agent"与"科研型 Agent"并行发展的格局。

ResearchClawBench 的关键创新在于三点：第一，隐藏目标论文——系统无法直接"抄答案"，必须真正完成科学推理；第二，10 个自然科学领域的广泛覆盖，避免了对单一领域能力的过拟合；第三，专家策划的 Rubric 评估体系，将开放式科学输出转化为可量化的加权评分，同时预留了"超越目标论文"的发现空间。

40 个任务的构建方法

RCBench 的任务构建遵循严格的专家策划流程，确保每个任务都具有真实的科学价值和可执行性。 

flowchart LR
    A["高质量论文筛选\n高影响力期刊\n问题清晰+数据可访问"] --> B["核心问题提取\n改写为可执行任务描述\n不泄露目标答案"]
    B --> C["数据与文献整理\n原始数据 + 约4篇参考文献\n不含目标论文"]
    C --> D["Rubric 构建\n关键科学产出\n加权评分标准"]
    D --> E["交叉验证\n专家复现验证\n修复并过滤样本"]
    E --> F["标准化任务包\nτ = (q, L, D, p★, A)"]
  1. 高质量论文筛选：领域专家从高影响力期刊中筛选目标论文，标准包括：问题定义清晰、数据公开可访问、具有实际科学价值（涵盖科学、经济、生态、医学等维度）。
  2. 核心问题提取：专家识别论文的核心科学问题，并将其改写为可执行的任务描述，确保问题表述不泄露目标答案。
  3. 数据与文献整理：收集任务所需的原始数据（NetCDF、CSV、FASTA 等多种格式）和约 4 篇相关参考文献，但不包含目标论文。
  4. Rubric 构建：围绕目标论文的关键科学产出（图表、数值结论、机制解释）构建加权评分标准，每个 Rubric 项包含具体标准、技术关键词和权重。
  5. 交叉验证：专家交叉检查任务包，确保任务可重现性（专家自己能按任务描述复现目标论文结果），修复问题并过滤不适合的样本。

Rubric 评估体系设计

每个 Rubric 项围绕目标论文中的具体科学产出构建，分为两种类型：

  • 文本类（Text）：评估文字形式的科学内容，如数值结论、机制描述、方法步骤等。
  • 图像类（Image）：评估多模态图表证据，如实验结果图、对比曲线、可视化分析等。

评分锚点设计是 RCBench 的一大创新。50 分被定义为"目标论文级别重发现"的阈值：低于 50 分意味着未达到目标论文水平，50 分意味着系统恢复了目标结果，高于 50 分则意味着系统的发现超越了目标论文。这一设计使得同一评分空间内既能衡量重发现能力，也能识别真正的新发现。

以 Astronomy_000 任务为例，Rubric 设计如下：

Rubric 项具体要求权重
数据摄入正确读取后验样本并汇总质量/自旋后验分布，作为观测约束的基础输入20%
排除曲线生成通过积分后验样本（95% 阈值）生成 M33 X-7 超辐射排除曲线30%
耦合强度上限推导利用排除曲线推导玻色子自相互作用耦合强度在相关质量范围内的上限50%

任务形式化定义

RCBench 中的任务被形式化定义为：

$$\tau = (q,\, \mathcal{L},\, \mathcal{D},\, p^{*},\, \mathcal{A})$$

其中 $q$ 为任务描述，$\mathcal{L}$ 为相关文献集合，$\mathcal{D}$ 为原始数据，$p^{*}$ 为隐藏的目标论文，$\mathcal{A}$ 为围绕目标论文构建的评估产出集合。给定任务 $\tau$ 和可执行环境 $\mathcal{E}$，系统需要生成：

$$y = (\pi,\, o,\, r)$$

其中 $\pi$ 为实验代码与执行过程，$o$ 为中间结果、图表和输出文件，$r$ 为最终研究报告。基准的核心目标是判断系统能否仅凭 $(q, \mathcal{L}, \mathcal{D})$ 生成高质量研究产出，并使这些产出达到或超越目标论文 $p^{*}$ 的水平。

ResearchHarness 系统设计

ResearchHarness 是一个轻量级的工具使用评估框架，使原生 LLM 能够参与 RCBench 评测，而无需完整的 Agent 脚手架。其设计目标是：最小化框架干预，最大化模型本身能力的体现。

ResearchHarness 遵循简洁的 ReAct 风格循环，通过 OpenAI 兼容 API 和原生工具调用获得工具使用能力。工具集分为三类：

类别工具列表典型用途
网络与检索WebSearch, ScholarSearch, WebFetch搜索网络（Serper API）、查找学术文献、通过 Jina Reader 获取网页内容
本地文件Glob, Grep, Read, ReadPDF, ReadImage, Write, Edit文件发现、文本/PDF（MinerU）/图像内容检查、创建和修改工作区文件
本地执行Bash, TerminalStart, TerminalWrite, TerminalRead, TerminalInterrupt, TerminalKill一次性命令执行、持久终端会话管理（用于较长的本地工作流）

ResearchHarness 还支持自动上下文压缩：当消息历史接近输入预算时（默认触发阈值为 128k tokens），框架自动将累积的交互历史压缩为紧凑记忆，并以此记忆继续运行，避免长任务中的上下文溢出问题。

评分体系：从重发现到新发现

RCBench 的评分体系围绕"重发现-新发现"连续谱设计。50 分是重发现阈值，具体评分区间含义如下：

分数区间诊断分析任务含义目标优化任务含义
0–20标准缺失、仅模糊提及，或缺乏实质性机制/理论分析标准缺失、仅模糊提及，或定量结果缺失/根本无效
21–40有分析尝试，但证据不足、推理有漏洞或关键论点缺失提供了定量结果，但方法存在重大缺陷，结果与目标论文偏差大
41–50分析接近目标论文水平；50 分标志着目标论文级别的重发现结果接近目标论文水平；50 分标志着目标论文级别的重发现
51–80推理比目标论文更完整、更严谨，有更深入分析或新见解指标明显超越目标论文，方法更强或定量结果有实质改进
81–100远超目标论文，提供原创贡献或突破性见解结果大幅超越目标论文，达到突破性定量表现或发现

关键发现

  • 整体差距显著：最强系统（Claude Code）平均分 21.5，距离重发现阈值（50 分）仍有约 57% 的差距，表明当前 AI 系统距离可靠的科学重发现还很远。
  • Agent 并不显著优于 LLM：最强自主 Agent（Claude Code 21.5）与最强 LLM（Claude-Opus-4.7 20.7）得分相近，表明复杂的 Agent 脚手架并未带来决定性优势。
  • 任务难度高度一致：7 个 Agent 在任务级别的相关性中位数为 0.79（范围 0.64–0.86），说明任务难度是客观的，不依赖于特定系统。
  • 领域优势各异：Claude Code 仅在 40 个任务中赢得 14 个最高分；GLM-5.1 领先化学，Gemini-3.5-Flash 领先信息科学，DeepSeek-V4-Pro 领先材料科学。
  • 资源投入与得分弱相关：成本和运行时间与得分仅有弱正相关（成本 $r = 0.66$，$R^2 = 0.44$；运行时 $r = 0.54$，$R^2 = 0.29$），说明"花更多钱"并不能可靠地提升科研质量。
  • 物理和天文领域相对较高：多数系统在物理（~19-38）和天文（~21-35）领域得分较高，而化学（~3-11）和神经科学（~2-10）领域得分普遍偏低。

值得注意的是，所有系统在专业性维度的得分（70+）远高于其他维度，而 Rubric 核心得分却很低（12–22）。这揭示了一个关键矛盾：模型擅长生成格式规范、表述专业的报告，但无法恢复 Rubric 要求的关键科学证据。报告的"外表"与"内核"之间存在严重脱节。四维补充评分与 Rubric 核心分的相关性也很弱，进一步证明核心挑战在于科学内容质量，而非报告呈现质量。

失败模式分析

研究者对 7 个自主 Agent 在 40 个任务上的全部 280 次运行进行了系统性错误分析，将细粒度标签归纳为六种错误类型，并统计了每种错误类型在所有运行中的出现比例。

失败模式一：实验协议不匹配（89.5% 的运行出现）

这是最普遍的失败类型，涵盖协议偏差、处理方式差异、基线选择错误和验证设置不当四个子类。Agent 选择了错误的数据处理方法、基线选择、验证设置或实验协议，导致结果与目标论文的方法论不一致。例如，在量子电路采样任务中，Agent 仅计算了线性 XEB，而目标论文还要求 log-XEB、MB 回归和镜像电路推断的多估计器一致性比较。这类失败表明 Agent 对科学方法论的精细理解不足，往往只能捕捉到最直接的分析路径，而忽略了目标论文中更精细的验证步骤。

失败模式二：证据不匹配（78.5% 的运行出现）

Agent 生成的图表、数值或结论与目标论文的关键证据不符。这包括：数值结果偏差过大（超出合理误差范围）、图表类型错误（如用折线图代替散点图）、关键对比曲线缺失、结论方向相反等。这类失败往往发生在 Agent 完成了正确的分析方向，但在具体执行细节上出现偏差——"方向对了，但数字错了"。

失败模式三：科学核心缺失（68.0% 的运行出现）

Agent 无法识别或重现目标论文的核心科学机制或关键发现。这类失败最为根本——Agent 可能生成了一份完整的报告，但完全错过了论文的核心贡献。例如，在分析大气机制时，Agent 描述了表面现象但未能解释底层物理机制；在材料设计任务中，Agent 找到了可行的候选材料但未能达到目标论文的性能指标。这反映了 AI 系统在识别"什么是科学核心"这一元认知能力上的缺失。

其他失败模式

目标错位（32.0%）：Agent 解决了一个相关但非等价的问题，偏离了原始任务目标。这通常发生在任务描述存在歧义时，Agent 会选择"更容易"的解读方式。
可靠性/报告失败（10.9%）：包含无支撑声明、无效证据或报告格式问题。
执行失败（1.5%）：完全无法生成可用的研究产出（代码崩溃、环境错误等）。执行失败率极低说明当前 Agent 在技术执行层面已相当可靠。

关键洞察：执行失败率极低（1.5%）说明当前 Agent 在技术执行层面已相当可靠。真正的瓶颈在于科学理解层面——Agent 能"跑起来"，但跑出来的结果与目标论文的科学逻辑存在系统性偏差。这是一个认知问题，而非工程问题。

案例研究：Physics_002（量子随机电路采样）

以 OpenClaw 在 Physics_002 任务上的表现为例，该任务要求评估任意几何结构上随机量子电路采样（RCS）的计算能力，需要从测量比特串计数和理想分布信息中估算保真度。OpenClaw 是所有 Agent 中该任务得分最高的，但仅获得 27.45/100。

Rubric 项权重目标要求OpenClaw 表现
固定深度 d=12，N 扫描20%线性 XEB、log-XEB 和 MB 回归一致趋势恢复线性 XEB 趋势，但缺少 log-XEB 和多估计器比较
N=40 深度缩放20%不同估计器在不确定性范围内一致重现主要线性 XEB 衰减（0.63→0.27-0.30），但缺少多估计器比较
N=56 MB 回归15%MB 回归 + 镜像电路推断 + depth-12 保真度点仅绘制简单 MB 命中率，缺少 MB 回归和镜像电路推断
门计数模型25%从门计数预测保真度，传播不确定性形成 1σ 带完全缺失：无门计数曲线，无不确定性传播，无模型预测
计数加权线性 XEB25%N=40 全深度，每深度 50 个电路实例，保真度衰减趋势覆盖全部深度，50 个实例，成功重现 XEB 衰减趋势（得分最高项）

这个案例生动地展示了 Agent 的典型失败模式：能够抓住最直接的分析路径（线性 XEB），但在需要更深层物理建模（门计数误差传播）和多步骤验证（多估计器一致性）的环节上系统性失败。

局限性

论文作者明确指出了 ResearchClawBench 当前版本的三项主要局限性：

  1. 仅覆盖干实验室研究：当前任务主要评估基于现有数据、代码和文献的"干实验室"研究，无法评估需要真实实验平台、样本制备或仪器操作的"湿实验室"研究。生命科学、化学等领域中大量重要的科学发现依赖于真实的实验操作，这部分能力目前完全不在评估范围之内。
  2. 评分仅针对最终报告：当前评分主要针对最终研究报告，而非细粒度的研究步骤。这意味着 Agent 在中间过程中的推理质量、假设生成能力、实验设计思路等都无法被直接评估。一个"歪打正着"的 Agent 可能与一个"过程严谨"的 Agent 获得相同的分数。
  3. 真正新发现难以评估：评估真正新颖的科学结论需要比围绕现有目标论文构建的 Rubric 更可靠的评估方法。当 Agent 的输出超越目标论文时，现有 Rubric 框架可能无法准确识别和量化这种"真发现"。这是科学发现评估领域的根本性挑战，目前尚无成熟解决方案。

此外，可以补充以下潜在局限性：

  • 任务规模有限：40 个任务在统计意义上仍然有限，特别是每个领域仅 4 个任务，可能无法充分代表该领域的全部难度分布。
  • 评判者偏差风险：使用 GPT-5.1 作为评判者可能引入系统性偏差，尤其是对于 GPT 系列模型可能存在有利偏向（自我偏好问题）。
  • 时效性问题：基于已发表论文的基准存在时效性问题——随着时间推移，这些论文可能出现在训练数据中，使评估结果失去意义（数据污染风险）。
  • 评估成本高：端到端评估每次运行需要大量计算资源和时间，限制了大规模重复实验和消融研究的可行性。

总结与启发

核心贡献回顾

ResearchClawBench 通过三项核心贡献推进了自主 AI 科研能力的评估：40 个真实科学发现任务（含专家标注 Rubric，覆盖 10 个领域）、ResearchHarness（用于 LLM 基线的轻量级评估框架），以及对 7 个自主 Agent 和 17 个原生 LLM 的系统性横向评估。这三项贡献共同构成了一个完整的评估生态，既有基准，又有工具，还有基线数据。

对 AI 自主研究能力的深层思考

RCBench 的实验结果揭示了当前 AI 自主科研能力的一个深刻悖论：系统在"表达"层面已经相当成熟，但在"理解"层面仍然严重不足。几乎所有系统都能生成格式规范、语言流畅的研究报告（专业性得分 70+），但核心科学内容的准确性（Rubric 得分 12–22）却令人担忧。这说明当前 LLM 的能力更接近于"科学写作助手"而非"科学发现引擎"。

从失败模式分析来看，89.5% 的运行出现实验协议不匹配这一数字尤为值得关注。它意味着 Agent 在面对开放性科学问题时，往往会选择"最直接"的分析路径，而非目标论文所采用的"最正确"的方法论路径。这反映了 AI 系统在科学方法论层面的理解缺陷——不是不会做实验，而是不知道该用哪个实验来验证哪个假设。这种"方法论盲目性"是当前最需要突破的瓶颈。

资源投入与得分的弱相关性也传递了一个重要信号：当前任务的失败不是因为"算力不够"或"时间不足"，而是因为系统在科学目标理解和实验设计上存在根本性偏差。这意味着简单地增加计算预算、延长推理时间，并不能有效提升自主科研能力。未来的突破方向可能更多在于训练数据质量和科学推理能力的专项强化，而非单纯的规模扩展。

对于未来研究方向，RCBench 的结果指向了几个关键突破口：

  • 科学方法论的内化：如何让 AI 系统真正理解不同科学领域的方法论规范，而非仅仅模仿表面形式？这可能需要专门的科学方法论训练数据和评估机制，例如包含完整实验设计逻辑的合成数据。
  • 长程科学推理：端到端科学研究要求系统在数小时乃至数天的时间跨度内保持一致的科学目标，当前的上下文压缩机制是否足以支撑这种长程推理？如何避免"目标漂移"是关键挑战。
  • 多模态科学理解：科学证据往往以图表、光谱、序列等多模态形式呈现，提升 AI 对科学图像的理解能力是突破证据不匹配瓶颈的关键。
  • 科学假设生成与验证的闭环：真正的科学发现需要"假设-实验-验证"的迭代闭环，当前 Agent 在这一闭环中的哪个环节最为薄弱，值得深入研究。
  • 跨领域科学迁移：不同科学领域的方法论差异巨大，如何构建具有跨领域迁移能力的科研 Agent，而非为每个领域单独优化，是长期挑战。

从更宏观的视角来看，RCBench 的意义在于它将"AI 能否做科学"这一哲学问题转化为了可测量的工程挑战。当前 21.5 分的天花板不是终点，而是起点——它为未来自主科研系统的迭代提供了清晰的坐标系。随着基准的不断扩展（更多领域、更多任务、湿实验室评估），以及 AI 系统在科学方法论理解上的持续进步，我们有理由期待这一数字在未来几年内的显著提升。而当某个系统真正突破 50 分阈值时，那将是 AI 科研能力发展史上真正的里程碑。
