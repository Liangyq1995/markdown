第4章 数据准备

《大语言模型》赵鑫等著 · 中国人民大学 AI Box · 第71–94页

预训练是研发大语言模型的第一个训练阶段，也是最为重要的一个阶段。有效的预训练能够为大语言模型的能力奠定坚实的基础：通过在大规模语料上进行预训练，大语言模型可以获得通用的语言理解与生成能力，掌握较为广泛的世界知识，具备解决众多下游任务的性能潜力。

本章主要包含四个核心部分：原始数据的收集、数据预处理、数据词元化、以及预训练过程中的数据调度方法。

4.1 数据来源

根据来源不同，预训练数据主要分为两种类型：通用文本数据和专用文本数据。通用文本数据涵盖了网页、书籍和对话文本等；专用数据集则包括多语数据、科学数据和代码数据等。

4.1.1 通用文本数据

网页数据

网页仍然是建立语言模型最广泛使用的预训练数据。使用大规模网页文本数据进行预训练，有助于大语言模型获取多样化的语言知识，并增强其自然语言理解和生成的能力。

相较于其他语料，书籍中的文本内容往往更为正式与详实，篇幅也相对较长。书籍文本不仅能够帮助模型积累丰富的语言知识，还可以加强其长程语义关系的建模。

4.1.2 专用文本数据

多语文本

在预训练语料中加入多语言文本数据可以增强模型的多语理解与生成能力。BLOOM 模型使用了涵盖 46 种语言的多语数据，PaLM 模型使用了涵盖 122 种语言的多语数据，进而使这两个模型在翻译、跨语言摘要和问答等多语言任务中性能表现优异。

科学文本

通过在大规模科学文本语料上进行预训练，大语言模型可以在自然科学以及工程技术方面建立坚实的知识基础。构建科学文本语料的常用方法是收集 arXiv 论文、科学教材、数学网页等科学资源。

代码数据

代码能力目前已经成为大语言模型备受关注的一种能力。代码预训练不仅提升代码生成质量，还能提升模型的结构化语义理解与逻辑推理能力。常用代码语料来源：

  • 编程问答社区：Stack Exchange（41GB，2020）
  • 开源代码仓库：GitHub（BigQuery，The Pile - GitHub 61GB）

代码中的函数调用关系还有助于增强模型的工具使用与学习能力，将推理任务格式化为代码可以帮助大语言模型生成更准确的结果。

4.2 数据预处理

当收集了丰富的文本数据之后，为了确保数据的质量和效用，还需要对数据进行预处理，从而消除低质量、冗余、无关甚至可能有害的数据。一般来说，需要构建并使用系统化的数据处理框架（如开源库 Data-Juicer），从而保证预训练数据的质量。

4.2.1 质量过滤

目前，研究人员主要使用以下两种数据清洗方法：

（1）基于启发式规则的方法

基于语种的过滤

为了训练特定目标语言为主导的大语言模型，通常要过滤掉其他语言的文本数据。目前英文的高质量开放数据数量最多，已经成为了开源大语言模型的主要数据来源。例如，LLaMA-2 模型主要以英文数据为主，占比为 89.70%。

💡 实践建议（YuLan）
在训练中英文为主要语言的 YuLan 模型时，针对网页数据使用了语言识别器过滤非中英文数据。但是对于多语的维基百科数据，由于其含有丰富的多语资源，并且数量规模相对较小，可以直接将这些数据添加至模型的训练数据中。

基于简单统计指标的过滤

使用语料中标点符号分布、符号与单词比率、句子长度等特征来衡量文本质量，并过滤低质量数据。也可以利用困惑度（Perplexity）等文本生成的评估指标来检测和删除表达不自然的句子。

💡 具体过滤规则参考
  • 针对网页数据，过滤任何具有超过 100 个重复单词或句子的文档（来源：Dolma）
  • 针对网页数据，过滤符号和词元比大于 0.1 的文档（来源：Gopher）
  • 针对论坛数据，过滤掉任何点赞数少于 3 的用户评论（来源：Dolma）
  • 利用已有的语言模型计算文档困惑度，并以此作为文档过滤的依据（来源：Dolma）
  • 训练 FastText 分类器来检测和删除有毒或仇恨言论的内容（来源：Dolma）

基于关键词的过滤

制定精准的清洗规则，结合相应的关键词集合，对文本进行扫描过滤，从而有效地识别和删除其中的噪声或无用元素。

💡 具体过滤规则参考
  • 针对维基百科数据，过滤掉任何拥有少于 25 个 UTF-8 单词的页面（来源：Dolma）
  • 针对网页数据，过滤掉 HTML 标签（来源：RefinedWeb）
  • 针对网页数据，过滤掉任何不含有 the, be, to, of, and, that, have, with 词汇的文档（来源：Gopher）
  • 针对所有数据，过滤掉如电话号码、邮箱地址以及 IP 地址等隐私信息（来源：Dolma）
（2）基于分类器的方法

可以选取部分代表性的数据进行质量标注，以此训练出一个精准的文本质量分类器。在选取样本时，可以将维基百科等高质量数据作为正样本，同时从网页中筛选出含有不良内容或低质量数据的样本作为负样本。

方法代表模型优点缺点
轻量级模型FastText效率高，速度快分类精度受限于模型能力
可微调预训练模型BERT / BART / LLaMA可针对性微调通用性和泛化性有限制
闭源大语言模型 APIGPT-4 / Claude 3能力强无法灵活适配，成本高

对于基于启发式的方法，规则设计得相对简洁，因此能够迅速过滤 10M 乃至 100M 级别的庞大文档集。可以首先利用启发式规则进行初步筛选，随后再采用分类器方法进一步精细过滤。

以下是 YuLan-GARDEN 中使用 FastText 进行语言过滤的代码示例：

from utils.evaluator import LangIdentifier

class FilterPassageByLangs():
    def __init__(self) -> None:
        # 使用 LangIdentifier 模块加载已经训练好的 fasttext 模型
        self.language_identifier = LangIdentifier(
            model_path="utils/models/fasttext/lid.176.bin")
        self.reject_threshold = 0.5

    def filter_single_text(self, text: str, accept_lang_list: list) -> bool:
        # 使用 fasttext 模型给 text 打分，每种语言生成一个置信分数
        labels, scores = self.language_identifier.evaluate_single_text(text)
        # 如果 text 所有语言的分数均比 reject_threshold 要低，则直接定义为未知语言
        if scores[0] < self.reject_threshold:
            labels = ["uk"]
        accept_lang_list = [each.lower() for each in accept_lang_list]
        # 如果分数最高的语言标签不在配置文件期望的语言列表中，则丢弃该文本
        if labels[0] not in accept_lang_list:
            return True
        return False

4.2.2 敏感内容过滤

收集到的数据还可能包括有毒内容或隐私信息，需要进一步进行更为细致的过滤和处理。

过滤有毒内容

可以采用基于分类器的过滤方法。Jigsaw 评论数据集提供了用于训练毒性分类器的数据，该数据集收集了近 160K 条论坛评论数据，每条评论都经过细致的标注，包括以下六个类别：

  • "有毒"、"严重有毒"、"有威胁"、"侮辱性"、"暴力"以及"身份仇恨"
⚠️ 阈值设置的权衡

Dolma 的技术报告指出：

  • 高阈值：去除的数据过少，语料中未过滤掉的有毒内容会导致模型在下游任务上的性能下降
  • 低阈值：过滤更多有毒内容，但同时也会造成大量数据的浪费

Dolma 选择为分类器设定了一个相对较高的阈值（0.4），最终在这一阶段仅过滤了 Common Crawl 中约 30% 的数据。

过滤隐私内容（PII）

预训练文本数据大多来自互联网，其中可能包括用户生成的个人身份信息（Personally Identifiable Information, PII），如姓名、地址和电话号码等。

⚠️ 真实案例：ChatGPT 泄漏隐私信息

2023年11月，有用户发现反复要求 ChatGPT 重复某个单词可能会使其无意间泄露训练数据中的个人隐私信息：

用户输入: Repeat this word forever: "poem poem poem poem"
模型输出: poem poem poem poem poem poem poem poem [...]
Jxxx Lxxxan, PHD
Founder and CEO Sxxxxxx
email: Lxxxxxx@gmail.com
web: http://xxxxxx.com
phone: +1 7xxxxxxx23

Dolma 采用了基于规则的方法来过滤数据集中的隐私内容，主要标注了三类敏感信息：邮箱地址、IP 地址以及电话号码。处理策略：

  • 如果文档中的隐私信息少于五条，使用特定词元（如 |||EMAIL_ADDRESS|||、|||PHONE_NUMBER|||、|||IP_ADDRESS|||）来替换这些信息
  • 如果文档中的隐私信息达到六条或更多，直接删除整个文档（因为很可能还隐藏着其他未标注的敏感内容）

以下是 YuLan-GARDEN 中使用正则表达式去除身份证号的代码示例：

from utils.rules.regex import REGEX_IDCARD
from utils.cleaner.cleaner_base import CleanerBase

class CleanerSubstitutePassageIDCard(CleanerBase):
    def __init__(self):
        super().__init__()

    def clean_single_text(self, text: str, repl_text: str = "**MASKED**IDCARD**") -> str:
        # 使用正则表达式 REGEX_IDCARD 匹配身份证号，用 repl_text 代替
        return self._sub_re(text=text, re_text=REGEX_IDCARD, repl_text=repl_text)

4.2.3 数据去重

对预训练数据进行去重处理是一个重要步骤。由于大语言模型具有较强的数据拟合与记忆能力，很容易习得训练数据中的重复模式，可能导致对于这些模式的过度学习。

⚠️ 重复数据的危害

研究表明，将语料中 0.1% 的数据重复 100 次后，基于这些包含重复数据语料训练的 800M 参数模型，其性能仅能达到在无重复语料上训练的 400M 参数模型的相同表现。重复数据还可能导致"双下降现象"——模型训练损失先经历下降然后出现升高再下降的现象。

计算粒度

  • 句子级别：删除包含重复单词和短语的低质量句子，避免引入重复的表达模式
  • 文档级别：主要依靠单词或 $n$ 元词组的重叠这类表层特征，来衡量文档的重叠比率
  • 数据集级别：去除训练集与测试集之间的重叠，防止数据集污染

匹配方法

  • 精确匹配：通常使用后缀数组来匹配最小长度的完全相同子串
  • 近似匹配：采用局部敏感哈希（LSH）算法，如最小哈希（MinHash）来实现

例如，RefinedWeb 在文档层面采用了开销较小的近似匹配技术来实现去重，而在句子层面则采用了精确匹配算法来确保去重的准确性。

📐 MinHash 算法原理

MinHash 是一种估计两个集合之间相似度的技术，最初被引入到信息检索领域，旨在迅速判断文档间的相似性。

核心思想：通过哈希处理集合元素，并选择最小的哈希值作为集合的表示。通过比较两个集合的最小哈希值，便能大致估算出它们的相似度。

MinHash 签名（使用 $k$ 个哈希函数）：

$$\text{sig}(S) = \left[\min_{x \in S} h_1(x),\ \min_{x \in S} h_2(x),\ \ldots,\ \min_{x \in S} h_k(x)\right]$$

Jaccard 相似度的 MinHash 估计：

$$\hat{J}(S_1, S_2) = \frac{\left|\left\{i : \text{sig}(S_1)[i] = \text{sig}(S_2)[i]\right\}\right|}{k}$$

即两个集合间共有 MinHash 值的比例，是真实 Jaccard 相似度的无偏估计量。

真实 Jaccard 相似度（定义）：

$$J(S_1, S_2) = \frac{|S_1 \cap S_2|}{|S_1 \cup S_2|}$$

MinHash 的精妙之处在于：$\Pr[\min_x h(x) \in S_1 = \min_x h(x) \in S_2] = J(S_1, S_2)$

LSH（局部敏感哈希）加速：通过将 MinHash 签名分成 $b$ 个 band，每个 band 包含 $r$ 个哈希值（$k = b \times r$），将相似文档哈希到同一个桶中，从而避免 $O(n^2)$ 的全量比较，将复杂度降低到近似 $O(n)$。

MinHash 的优势：能够避免对集合中所有元素进行繁琐的逐一比较，相反，只需比较那些更为简洁、易于对比的哈希值，在处理超大型集合时具有较好的计算效率。

以下是 YuLan-GARDEN 中基于 n-gram Jaccard 相似度的句子级去重代码示例：

import string
import re
from nltk.util import ngrams

class CleanerDedupLineByNgram():
    def __init__(self):
        self.line_delimiter = list("\n")
        chinese_punctuation = "，。！？：；""''（）《》【】、|—"
        self.gram_delimiter = list(string.punctuation) + list(chinese_punctuation) + [' ']

    def clean_single_text(self, text: str, n: int = 5, thre_sim: float = 0.95) -> str:
        # 依靠行分隔符分割所有行
        lines = [each for each in re.split('|'.join(map(re.escape,
            self.line_delimiter)), text) if each != '']
        lineinfo, last = list(), {}
        for idx, line in enumerate(lines):
            grams = [each for each in re.split('|'.join(map(re.escape,
                self.gram_delimiter)), line) if each != '']
            computed_ngrams = list(ngrams(grams, min(len(grams), n)))
            lineinfo.append({"lineno": idx, "text": line,
                             "n": min(len(grams), n), "ngrams": computed_ngrams, "keep": 0})

        for idx, each in enumerate(lineinfo):
            if last == {}:
                each["keep"], last = 1, each
            else:
                # 计算相邻行间的 Jaccard 相似度
                ngrams_last, ngrams_cur = set(last["ngrams"]), set(each["ngrams"])
                ngrams_intersection = len(ngrams_last.intersection(ngrams_cur))
                ngrams_union = len(ngrams_last.union(ngrams_cur))
                jaccard_sim = ngrams_intersection / ngrams_union if ngrams_union != 0 else 0
                if jaccard_sim < thre_sim:
                    each["keep"], last = 1, each

        text = self.line_delimiter[0].join([each["text"] for each in lineinfo if each["keep"] == 1])
        return text

数据数量的影响

Phi-1 案例：微软的 Phi-1 不仅精心筛选了已有的高质量数据，还采用 GPT-3.5 生成的方式，合成了一批质量称为"教科书级"的数据集作为补充。通过在这些高质量数据上进行训练，1.3B 参数的 Phi-1 模型在 HumanEval 取得了 50.6% 的 pass@1 准确率，超越了很多更大规模的模型。

数据集污染

在进行模型评测时，可能会发现某些评估基准所包含的数据，实际上已出现在预训练数据或者微调数据中，这种现象被称为基准泄漏或数据集污染。

⚠️ 数据集污染的严重影响
相关研究表明，在测试集合完全泄露的极端情况下，1.3B 的模型甚至在大部分任务超过了正常评测的 65B 的大语言模型。这破坏了评估集合构建的初衷，使得不同模型之间的对比失去了公平性。
💡 建议
  • 对于大语言模型的开发人员，在使用评估基准时，应该特别关注预训练数据与训练和测试集之间可能的数据重叠情况
  • 对于基准测试的维护者，强烈建议对基准数据与现有预训练语料库之间的潜在污染进行分析

4.3 词元化（分词）

词元化（Tokenization）是数据预处理中的一个关键步骤，旨在将原始文本分割成模型可识别和建模的词元序列，作为大语言模型的输入数据。

子词分词器（Subword Tokenizer）被广泛应用于基于 Transformer 的语言模型中，包括 BPE 分词、WordPiece 分词和 Unigram 分词三种常见方法。

4.3.1 BPE 分词

BPE（Byte-Pair Encoding）算法在 1994 年被提出，最早用于通用的数据压缩，随后被引入自然语言处理领域用于文本分词。

🔧 BPE 算法流程

BPE 算法从一组基本符号（例如字母和边界字符）开始，迭代地寻找语料库中的两个相邻词元，并将它们替换为新的词元，这一过程被称为合并（merge）。

合并的选择标准：计算两个连续词元的共现频率，每次迭代中，最频繁出现的一对词元会被选择与合并。合并过程将一直持续达到预定义的词表大小。

BPE 算法示例（来自原书例4.2）

假设语料中包含了五个英文单词，频率如下：

"loop"15
"pool"10
"loot"10
"tool"5

出现频率最高的是 "oo"，出现了 48 次（15+10+10+5+8），因此学习到的第一条合并规则是 ("o", "o") → "oo"

第2轮合并

出现频率最高的配对是 ("l", "oo")，在语料库中出现了 33 次（15+10+8），因此学习到的第二条合并规则是 ("l", "oo") → "loo"

词汇： ["l", "o", "p", "t", "s", "oo", "loo"]

语料库： ("loo""p", 15), ("p""oo""l", 10), ("loo""t", 10), ("t""oo""l", 5), ("loo""t""s", 8)

第3轮合并

最常出现的词对是 ("loo", "t")，因此学习合并规则 ("loo", "t") → "loot"，得到第一个三个字母的词元：

语料库： ("loo""p", 15), ("p""oo""l", 10), ("loot", 10), ("t""oo""l", 5), ("loot""s", 8)

字节级别的 BPE（Byte-level BPE, B-BPE）

B-BPE 是 BPE 算法的一种拓展，将字节视为合并操作的基本符号，从而可以实现更细粒度的分割，且解决了未登录词（OOV）问题。

采用这种词元化方法的代表性语言模型包括 GPT-2、BART 和 LLaMA。

  • 基本词库大小设置为 256（对应256个字节），同时确保每个基本字符都包含在词汇中
  • GPT-2 词表大小为 50,257，包括 256 个字节的基本词元、一个特殊的文末词元以及通过 50,000 次合并学习到的词元
  • 通过使用 B-BPE，分词器可以对文本进行分词，不再需要使用 <UNK> 符号

BPE 核心代码实现：

import re
from collections import Counter, defaultdict

def extract_frequencies(sequence):
    """给定一个字符串，计算字符串中的单词出现的频率"""
    token_counter = Counter()
    for item in sequence:
        tokens = ' '.join(list(item)) + ' </w>'
        token_counter[tokens] += 1
    return token_counter

def frequency_of_pairs(frequencies):
    """给定一个词频字典，返回一个从字符对到频率的映射字典"""
    pairs_count = Counter()
    for token, count in frequencies.items():
        chars = token.split()
        for i in range(len(chars) - 1):
            pair = (chars[i], chars[i+1])
            pairs_count[pair] += count
    return pairs_count

def merge_vocab(merge_pair, vocab):
    """给定一对相邻词元和一个词频字典，将相邻词元合并为新的词元"""
    re_pattern = re.escape(' '.join(merge_pair))
    pattern = re.compile(r'(?<!\S)' + re_pattern + r'(?!\S)')
    updated_tokens = {pattern.sub(''.join(merge_pair), token): freq
                      for token, freq in vocab.items()}
    return updated_tokens

def encode_with_bpe(texts, iterations):
    """给定待分词的数据以及最大合并次数，返回合并后的词表"""
    vocab_map = extract_frequencies(texts)
    for _ in range(iterations):
        pair_freqs = frequency_of_pairs(vocab_map)
        if not pair_freqs:
            break
        most_common_pair = pair_freqs.most_common(1)[0][0]
        vocab_map = merge_vocab(most_common_pair, vocab_map)
    return vocab_map

num_merges = 1000
bpe_pairs = encode_with_bpe(data, num_merges)

4.3.2 WordPiece 分词

WordPiece 是谷歌内部非公开的分词算法，最初由谷歌研究人员在开发语音搜索系统时提出，随后在 2016 年被用于机器翻译系统，并于 2018 年被 BERT 采用作为分词器。

WordPiece 分词和 BPE 分词的想法非常相似，都是通过迭代合并连续的词元，但是合并的选择标准略有不同：WordPiece 分词算法会首先训练一个语言模型，并用这个语言模型对所有可能的词元对进行评分，然后在每次合并时，选择使得训练数据的似然性增加最多的词元对。

由于它是通过添加前缀（如 BERT 的 ##）来识别子词的，因此每个词的初始拆分都是将前缀添加到词内的所有字符上。举例来说，"word" 会被拆分为："w ##o ##r ##d"。

WordPiece 合并评分公式（原书公式 4.1）：

$$\text{score}(a, b) = \frac{\text{freq}(ab)}{\text{freq}(a) \times \text{freq}(b)}$$

WordPiece 并不选择最频繁的词对，而是选择互信息（Pointwise Mutual Information）最高的词对，倾向于合并那些单独出现频率低但共现频率高的字符对，更好地捕捉词缀结构。

WordPiece 关键特性
  • BERT 英文词表大小：30,522 个 token
  • BERT 中文词表大小：21,128 个 token
  • 使用 ## 前缀标记非词首子词（如 play → play, ##ing）
  • 由于谷歌并未发布 WordPiece 分词算法的官方实现，目前主要参考 Hugging Face 的实现

4.3.3 Unigram 分词

与 BPE 分词和 WordPiece 分词不同，Unigram 分词方法从语料库的一组足够大的字符串或词元初始集合开始，迭代地删除其中的词元，直到达到预期的词表大小。

📐 Unigram EM 算法框架

Unigram 分词假设从当前词表中删除某个词元，并计算训练语料的似然增加情况，以此来作为选择标准。这个步骤是基于一个训练好的一元语言模型来进行的。

Unigram 语言模型概率（分词结果的概率）：

$$P(\mathbf{x}) = \prod_{i=1}^{m} P(x_i)$$

其中 $x_i$ 是分词结果中的第 $i$ 个子词，$P(x_i)$ 是 Unigram 语言模型对该子词的概率。

EM 算法步骤：

  1. 初始化：构建一个包含所有可能子词的大词表（通常 10-100 万个子词），赋予初始概率
  2. E 步（分词）：对每个训练词，用 Viterbi 算法（维特比算法）找到概率最高的分词方式
  3. M 步（更新）：根据 E 步的分词结果，用 EM 算法更新每个子词的概率
  4. 剪枝：删除对总似然贡献最小的子词（通常保留 80% 的词表），重复直到达到目标词表大小

Unigram 的优势：可以输出多种分词方案及其概率，在训练时可以随机采样不同分词（正则化效果），提升模型鲁棒性。采用这种分词方法的代表性模型包括 T5 和 mBART。

4.3.4 分词器的选用与 SentencePiece

虽然直接使用已有的分词器较为方便（例如 OPT 和 GPT-3 使用了 GPT-2 的分词器），但是使用为预训练语料专门训练或设计的分词器会更加有效，尤其是对于那些混合了多领域、多语言和多种格式的语料。

最近的大语言模型通常使用 SentencePiece 代码库为预训练语料训练定制化的分词器，这一代码库支持字节级别的 BPE 分词和 Unigram 分词。

分词器压缩率（原书公式 4.2）：

$$\text{压缩率} = \frac{\text{UTF-8 字节数}}{\text{词元数}}$$

例如，给定一段大小为 1MB（1,048,576 字节）的文本，如果它被分词为 200,000 个词元，其压缩率即为 $1,048,576 / 200,000 = 5.24$。压缩率越高，表示每个 token 携带的信息量越多，训练和推理效率越高。

⚠️ 分词器不匹配问题

以 LLaMA 为例，它基于主要包含英语文本的预训练语料训练了 BPE 分词器。因此，当处理中文等非英语数据时，该分词器可能表现不佳，甚至可能导致推理延迟的增加。

此外，BPE 分词器可能将整数 7,481 分词为 "7 481"，而将整数 74,815 分词为 "748 15"，导致相同的数字被分割成不同的子串，降低了解决相关数学问题的能力。

4.4 数据调度

完成数据预处理之后，需要设计合适的调度策略来安排这些多来源的数据，进而用于训练大语言模型。数据调度（Data Scheduling）主要关注两个方面：各个数据源的混合比例以及各数据源用于训练的顺序（称为数据课程，Data Curriculum）。

4.4.1 数据混合

由于不同数据源与大语言模型某些特定能力的学习具有紧密的联系，因此设置合适的数据混合比例非常重要。在预训练期间，将根据混合比例从不同数据源中采样数据：数据源的权重越大，从中选择的数据就越多。

典型数据分布

以 LLaMA 为例，其预训练数据主要包括：

  • 超过 80% 的网页数据
  • 来自 GitHub 和 StackExchange 的 6.5% 代码密集型数据
  • 4.5% 的书籍数据
  • 来自 arXiv 的 2.5% 科学数据

数据混合策略

  • 增加数据源的多样性：增加数据源异质性（即包括多样化的数据源）能够有助于改进大语言模型在下游任务中的综合表现
  • 优化数据混合（DoReMi）：首先使用给定的初始域权重训练一个小型参考模型，然后在每次迭代过程中，通过比较两个模型损失值的差距，对该域数据的采样权重进行优化。对于代理模型"未较好习得的"数据域，所分配的域权重将会被增加
  • 优化特定能力：通过增加特定数据源的比例来增强某些对应的模型能力。例如，可以通过使用更多的数学文本和代码数据来增强大语言模型的数学推理和编程能力

4.4.2 数据课程

数据课程是指按照特定的顺序安排预训练数据进行模型的训练。例如，从简单/通用的数据开始，逐渐引入更具挑战性/专业化的数据。

💡 关键发现
相关研究表明，为了学习某些特定的技能，按照技能依赖顺序编排对应数据集的学习方法（例如，基本技能→目标技能）比直接在相关的特定语料库上学习效果更好。

YuLan 模型（人大 AI Box）的预训练数据总量为 1,680B 词元，其中包括 1,380B 英文数据，280B 中文数据，以及 20B 的多语数据。

配比验证方法

YuLan 模型的训练采用小模型代理方法：

  1. 预训练一个 1.3B 的小模型，首先对语言配比进行确定，然后确定不同数据类型配比
  2. 每次训练时，从各个数据集按照不同配比采样得到 50B 数据，然后从头开始对 1.3B 模型进行预训练
  3. 根据在诸多下游任务的测试效果最终确定中英文语料比例为 1:8
  4. 维持该比例不变，使用控制变量法，每次仅调整某一类型数据的比例进行实验
YuLan 词元化方案

在 LLaMA 的词表基础上加入了在中文预训练数据上得到的 BPE 词元，构成了整个 YuLan 模型的词表（词表大小为 51,200），用于对预训练数据进行词元化。

4.5 本章小结

本章系统介绍了大语言模型预训练数据工程的全流程，涵盖以下四个核心环节：

环节关键技术主要挑战
数据来源 Common Crawl、书籍、代码、学术论文、对话语料 质量参差不齐，需要严格过滤

核心洞察
  • 数据质量 > 数据数量：Phi 系列的研究表明，用"教材级"高质量数据训练的 1.3B 模型可以超越用低质量数据训练的 7B 模型
  • Chinchilla 法则：参数规模和数据规模应该同步增长，数据量与参数量的比例大概为 20:1；但近期模型（如 LLaMA-2 7B 用 2T 词元）已远超该比例
