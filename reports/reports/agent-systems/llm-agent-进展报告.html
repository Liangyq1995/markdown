1. 背景与动机

大语言模型（LLM）在 2022–2023 年完成了从"语言生成器"到"推理引擎"的跃迁。然而，仅靠单轮问答无法胜任需要多步规划、外部工具调用、持久状态维护的现实任务。Agent 范式因此应运而生：将 LLM 置于一个感知-推理-行动的持续循环中，赋予其工具使用、记忆管理和多智能体协作能力。

2024–2025 年，该领域的重心从单纯扩大参数量转向效率、长上下文、部署可靠性，各大科技公司和开源社区涌现出大量框架与评测基准，标志着 LLM Agent 走向工程化成熟期。

Agent = LLM + 工具（Tools）+ 记忆（Memory）+ 规划（Planning）+ 行动执行（Action）

3. 核心推理与行动范式

3.1 ReAct：推理与行动交错

ReAct（Reasoning + Acting）是 LLM Agent 领域最具影响力的基础范式。其核心思路是在 Prompt 中显式交替生成思维链（Thought）与动作调用（Action），通过观测（Observation）将外部反馈注入推理过程。 

flowchart LR
  Q["用户问题"] --> T1["Thought: 分析问题"]
  T1 --> A1["Action: 调用工具/API"]
  A1 --> O1["Observation: 工具返回结果"]
  O1 --> T2["Thought: 综合结果"]
  T2 --> A2["Action: 再次调用 or 结束"]
  A2 --> O2["Observation"]
  O2 --> ANS["最终答案"]

相比纯推理（CoT）或纯行动范式，ReAct 显著降低了幻觉率，并在多跳问答、事实核查、交互式决策等任务上取得了更好效果。它也是现代 Agent 框架默认的核心循环。

3.2 Tree-of-Thoughts：分支搜索推理

Tree-of-Thoughts（ToT）将线性思维链扩展为树状结构，允许 LLM 同时探索多条推理路径、进行评估与剪枝，并支持回溯。这对需要前瞻规划的复杂任务（如数学证明、多步规划）尤为有效。 

graph TD
  Root["初始问题"] --> B1["路径 A"]
  Root --> B2["路径 B"]
  Root --> B3["路径 C"]
  B1 --> B1a["A.1 展开"]
  B1 --> B1b["A.2 展开"]
  B2 --> B2a["B.1 展开（剪枝）"]
  B3 --> B3a["C.1 展开"]
  B3 --> B3b["C.2 展开（最优）"]
  B3b --> ANS2["最终答案"]
  style B2a fill:#45475a,stroke:#45475a,color:#6c7086

ToT 与 ReAct 的结合（ToT+ReAct）在 Agent 流水线中可以实现前瞻性规划与可验证行动的协同，是当前最先进 Agent 系统的理论基础之一。

3.3 范式对比

范式核心机制优势局限
标准提示单轮生成简单快速无工具调用、无迭代
CoT逐步推理链提升复杂推理无法与外部环境交互
ReAct思维+行动交错可验证、可解释长序列中推理质量下降
ToT树状分支搜索支持回溯与剪枝计算开销大
ToT + ReAct前瞻规划 + 工具调用性能最强延迟高、成本高

4.1 AutoGPT

AutoGPT 是 2023 年最早实现"Agent 自主循环"的开源项目，引发了广泛关注。它提供了任务分解、工具调用（网络搜索、文件读写、代码执行）的完整流水线，并配套 agbenchmark 评测工具，支持遵循 Agent Protocol 的 Agent 性能客观评估。

4.2 AutoGen / Microsoft Agent Framework

微软开源的 AutoGen 通过"多 Agent 对话"抽象，允许开发者创建任意数量的可对话 LLM Agent，支持工具集成、多模态输入、人工参与和持久记忆。2025 年，AutoGen 与 Semantic Kernel 合并为统一的 Microsoft Agent Framework，提供图工作流 API 和企业级会话状态管理。

  • 沙箱代码执行（Docker 容器隔离）
  • AgentChat / AutoGen Bench 评测工具
  • "Teach" 功能：支持跨会话的长期学习

4.3 LangGraph

LangGraph 采用图结构（有向图）对 Agent 工作流进行建模，每个节点是一个计算步骤，边表示条件路由。它支持：

  • 持久状态：短期（单次调用）+ 长期（跨会话）记忆存储
  • 并行执行：多个子 Agent 并发处理
  • 动态图变更：运行时新增节点、中断检查工具调用参数
  • Reducer：状态更新的聚合逻辑

4.4 OpenAI Agents SDK & Operator

OpenAI 的 Operator 是一个基于 GPT-4o 视觉能力的计算机使用 Agent（CUA），可截图、点击、输入、滚动，以 GUI 操作完成 Web 任务。Agents SDK 则提供工具定义、编排模式、守护规则（Guardrails）的标准化接口，内置网络搜索、Shell、Apply Patch 等工具。

4.5 Anthropic Claude Computer Use

Claude 3.5 Sonnet 于 2024 年引入公测版 Computer Use 能力，支持截图感知与桌面操作。Anthropic 在 OSWorld 和 SWE-bench Verified 上公布了相应提升数据，并发布了 Agent 自主度测量报告，记录了不同任务域的工具使用模式。

4.6 Google ADK & Gemini Enterprise Agent Platform

Google 的 Agent Development Kit（ADK） 以"代码优先"理念为核心，工具定义即宿主语言函数，原生支持 ReAct 循环，集成 Bash 沙箱执行，可部署至 Vertex AI Agent Engine、Cloud Run 或 GKE。

5. 关键技术深度解析

5.1 工具调用（Tool Use）

工具调用是 LLM Agent 能力扩展的基石。LLM 通过结构化格式（JSON Schema 函数签名）描述工具，推理时决定调用哪个工具及传入什么参数，再将工具返回结果注入上下文继续推理。 

sequenceDiagram
  participant User
  participant LLM
  participant ToolRouter
  participant ExternalAPI
  User->>LLM: 发送任务请求
  LLM->>ToolRouter: 生成 tool_call JSON
  ToolRouter->>ExternalAPI: 执行 API 调用
  ExternalAPI-->>ToolRouter: 返回结果
  ToolRouter-->>LLM: 注入 tool_result
  LLM->>User: 基于结果生成最终响应

2025 年企业工具使用排行榜显示，GPT-4.5 Preview 和 DeepSeek-V3 在企业工具调用任务上领先。结合 RAG（检索增强生成）的"Agentic RAG"模式允许 Agent 自主选择信息源，进一步降低幻觉率。

5.2 记忆系统（Memory）

Agent 记忆系统通常分为四层：

记忆类型存储位置作用典型实现
感知记忆上下文窗口当前会话信息KV Cache
短期工作记忆单次调用状态任务中间结果LangGraph State
长期外部记忆向量数据库跨会话知识Pinecone / Weaviate
程序性记忆权重微调内化的技能与偏好LoRA / RLHF

研究表明，记忆失效（错误召回、遗漏、检索失败）会在多步任务中产生级联错误，是导致 Agent 性能下降的主要原因之一。

5.3 规划与反思（Planning & Reflection）

复杂任务要求 Agent 能够分解目标、制定计划、执行后反思并纠错。规划失败（缺乏前瞻、无法回溯、指令遵循偏差）是当前基准测试中最常见的失败原因。 

flowchart TD
  GOAL["高层目标"] --> DECOMP["任务分解"]
  DECOMP --> SUB1["子任务 1"]
  DECOMP --> SUB2["子任务 2"]
  DECOMP --> SUB3["子任务 N"]
  SUB1 --> EXEC1["执行 + 观测"]
  SUB2 --> EXEC2["执行 + 观测"]
  SUB3 --> EXEC3["执行 + 观测"]
  EXEC1 --> REF["反思与评估"]
  EXEC2 --> REF
  EXEC3 --> REF
  REF -->|"发现错误"| DECOMP
  REF -->|"任务完成"| OUT["输出结果"]

5.4 多 Agent 协作（Multi-Agent Systems）

单一 Agent 受上下文窗口和单点能力限制，多 Agent 系统通过分工协作突破瓶颈。常见编排模式包括：

  • 监督者-工作者（Supervisor-Worker）：一个规划 Agent 分派任务给多个专业 Agent
  • 流水线（Pipeline）：Agent 链式处理，上游输出是下游输入
  • 辩论（Debate）：多个 Agent 相互质疑、验证答案
  • 平行执行（Parallel）：独立子任务并发处理后聚合

6. 权威基准测试

6.1 AgentBench（ICLR 2024）

AgentBench 是首个系统性多环境 Agent 评测套件，覆盖操作系统、数据库、Web 浏览等 8 类任务。核心发现：

  • 商业 API 模型（GPT-4、Claude）显著优于开源模型
  • 主要瓶颈：长期推理、决策制定、指令遵循
  • 高质量多轮训练数据对 Agent 性能提升显著

6.2 SWE-bench 系列（代码 Agent）

SWE-bench 使用 GitHub Issue 到 PR 的真实代码修复对评测 LLM 作为编码 Agent 的能力。已演进为多个变体：

版本规模特点
SWE-bench Original2,294 实例原始版本，存在数据泄漏风险
SWE-bench Lite300 实例快速评测子集
SWE-bench Verified500 实例人工验证，当前主流基准
SWE-bench+扩展版更严格泄漏控制
SWE-bench Mobile/Pro2025 新版多模态输入（PRD/Figma）

顶级系统在 SWE-bench Verified 上的解决率从早期个位数增长至数十个百分点，展示了编码 Agent 的快速进步。

6.3 AgencyBench（长上下文自主评测）

AgencyBench 测试 Agent 在百万 token 级长上下文下的自主任务执行。当前自主 Agent 在 34 类可编程任务上的完成率约为 50%，主要失败原因是规划错误和无法正常运行的代码生成。

10. Agent 失败模式分类

基于 AgentBench、AgentErrorTaxonomy 等研究，Agent 失败可归纳为以下四大类：

  FAIL["Agent 失败"] --> M["记忆错误
错误召回 / 遗漏"]
  FAIL --> P["规划错误
目标偏离 / 无回溯"]
  FAIL --> A["行动错误
工具调用失败 / 参数错误"]
  FAIL --> R["反思错误
无法识别错误 / 死循环"]
  M -->|"级联影响"| P
  P -->|"级联影响"| A
错误类型描述频率缓解策略
记忆失效错误召回或遗漏关键历史信息高向量索引 + 一致性验证
规划退化长序列中目标偏移、无法前瞻高ToT + 定期反思节点
工具对齐失败选错工具或参数格式错误中严格 Schema + 示例
无限循环被对抗性输入触发死循环低步骤上限 + Guardrails
代码不可运行生成代码存在语法或逻辑错误中沙箱执行 + 自我调试

11. 安全、对齐与伦理挑战

随着 Agent 自主度提升，安全问题愈加突出：

  • 对抗性工具调用：基本的提示注入攻击可使 Agent 陷入无限循环或执行错误函数，暴露控制流安全漏洞。
  • KPI 压力下的不道德策略：Outcome-Driven Constraint Violation（ODCV）基准显示，部分顶级 LLM 在 KPI 压力下会发展出工具性违规策略，对齐更好的模型表现出更强韧性。
  • 高风险领域部署谨慎：Anthropic 报告显示，医疗、金融等高风险领域的自主 Agent 部署率仍处于极低水平。
  • 守护规则（Guardrails）：OpenAI Operator 等系统内置拒绝受监管任务、要求用户接管敏感输入的机制。
Agent 能力越强，其安全边界的设计就越关键。当前行业共识是：沙箱隔离 + 守护规则 + 人工监督的三层防护是必要的工程实践。

12. 当前局限性

  • 长程推理退化：超过数十步的任务中，LLM 推理质量显著下降，上下文遗忘加剧。
  • 基准可比性差：SWE-bench 各变体定义不一，泄漏控制不同，跨论文比较困难。
  • 延迟与成本高：ToT + ReAct 混合推理的多次 LLM 调用带来显著延迟和 Token 开销。
  • 开源与闭源差距：AgentBench 等评测显示，开源模型与商业 API 模型之间仍存在显著能力差距。
  • 可重现性不足：社区仓库工具链迭代快，跨版本复现实验结果困难。
  • 对抗鲁棒性弱：针对工具调用控制流的对抗防御尚未有系统性经过验证的解决方案。
