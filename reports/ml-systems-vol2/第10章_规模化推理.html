第10章 规模化推理（Inference at Scale）

《Machine Learning Systems at Scale》Vijay Janapa Reddi · MIT Press · Vol.2 · 生成日期：2026-07-04

核心主线推理经济学 → 服务架构维度 → 连续批处理/KV → 分片与路由 → 多租户与全球 autoscaling
学习目标在 Prefill/Decode 双阶段 physics 下做容量规划；将 Vol.1 Llama3 单卡算例扩展到多副本舰队

一、推理经济学

训练是一次性 CapEx；推理是持续性 OpEx——Facebook 2018 量级：每日数十万亿次推理。LLM API 价格竞争使 $/token 成为产品 KPI。Vol.1 单 H100 Llama3 8B AWQ：Prefill 瓶颈 10 req/s → ~$0.066/M tokens（$3/hr 云租）。舰队级须乘上：副本数、利用率 headroom、跨 AZ 网络、冷启动浪费。

成本分解

$/token ≈ (GPU·hr 单价 × 副本数) / (有效 tok/s × 3600)。若 p99 SLO 强制 $\rho < 60\%$，账单 ×1.67。若 30% 副本冷启动空转，再 ×1.43。

二、服务架构维度

维度选项权衡
部署集中 / 边缘 / 混合延迟 vs 规模经济
状态无状态 / KV 有状态LLM 必须 sticky routing 或共享 KV 层
精度FP16 / INT8 / INT4带宽地板 ∝ 权重大小
并行TP / PP / DP 推理TP 限 NVLink 域；跨 AZ PP 延迟高

三、批处理：Continuous Batching

Static batch 等最长序列 → GPU 空泡。Continuous batching（vLLM/TGI）在iteration 级插入/移除序列，Prefill 与 Decode 可异构混批。

$$L_{\text{total}} \approx T_{\text{prefill}}(\text{prompt}) + N_{\text{out}} \times \text{TPOT}$$

舰队吞吐上限常由Prefill 算力或KV 驻留容量二选一绑定（Vol.1 Llama3：10 req/s vs 1749 并发槽）。

四、KV 与 Decode 内存

70B GQA FP16：KV ≈ 0.31 MB/token/序列。32 序列 × 8K context ≈ 80 GB 仅 KV——超过单卡 HBM，须 PagedAttention 分页 + 跨卡 TP 或 KV offload（PCIe 下限 ~32 GB/s → TPOT 下限抬升）。

PagedAttention 工程点

块大小（如 16 token/block）影响碎片率：40–50% → 90%+ 利用率，等效并发从 ~700 提至 ~1700（同 80 GB 卡）。

五、负载均衡与路由

  • 最短队列 / 加权轮询：忽略 KV 亲和则 Prefill 重复计算
  • Session affinity：同会话粘滞 GPU，利于 prefix cache
  • Prefill-Decode 分离（PD disaggregation）：算力型 Prefill 池 + 带宽型 Decode 池，各自 autoscale

六、Autoscaling 与多租户

K8s HPA 基于 CPU 对 GPU LLM 失效——应用指标：TTFT p99、TPOT、队列深度。多租户须 GPU 时间片或 MIG 隔离；INT4 租户 A 与 FP16 租户 B 混部需内存配额防 OOM 连坐。

七、章节总结

  1. 推理舰队优化 $/token 与 SLO，非峰值 TFLOP/s
  2. Prefill（compute-bound）与 Decode（memory-bound）须分池度量与扩容
  3. Continuous batching + PagedAttention 是 LLM 舰队利用率核心
  4. 路由与 PD 分离决定 Prefill 重复劳动与 KV 局部性
  5. Vol.1 单卡算例的瓶颈项（Prefill 10 req/s）在舰队中变为调度问题
