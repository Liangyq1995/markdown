12.1 评测指标与评测方法

评估大语言模型需要从多个维度全面考量其性能。根据应用场景不同，评测指标可分为：语言建模任务、分类任务、条件文本生成任务、执行类任务和偏好排序类任务五大类。

评测任务评测指标介绍
语言建模困惑度（PPL）衡量模型对参考文本的建模概率
分类任务精确率 / 召回率 / F1衡量分类结果的准确性与覆盖度
文本生成BLEU / ROUGE衡量候选文本与参考文本的重叠度
问答任务准确率（Accuracy）衡量模型预测正确答案的比例
执行类任务成功率 / Pass@k衡量代码/任务执行通过率
偏好排序Elo 等级分衡量模型在成对比较中的相对水平

12.1.1 常见评测指标

困惑度（Perplexity，PPL）

困惑度是语言建模任务中最重要的评测指标，衡量模型对参考文本的建模概率。文本建模概率定义为：

$$P(\boldsymbol{u}) = \prod_{t=1}^{T} P(u_t \mid \boldsymbol{u}_{\lt t}) \tag{12.1}$$

困惑度定义为建模概率的负对数几何平均：

$$\text{PPL}(\boldsymbol{u}) = P(\boldsymbol{u})^{-\frac{1}{T}} \tag{12.2}$$

为避免数值下溢，实践中通常采用对数概率求和：

$$\text{PPL}(\boldsymbol{u}) = \exp\!\left(-\frac{1}{T}\sum_{t=1}^{T} \log P(u_t \mid \boldsymbol{u}_{\lt t})\right) \tag{12.3}$$
PPL 解读：PPL 越低，模型对参考文本的建模概率越高，语言建模能力越强。PPL 受词表大小和测试集领域影响，跨模型直接比较需谨慎。

分类任务指标：Precision / Recall / F1

分类任务通过混淆矩阵（TP/FP/TN/FN）衍生出多个指标：

预测为正预测为负
真实为正TP（真正例）FN（假负例）
真实为负FP（假正例）TN（真负例）
$$\text{Precision} = \frac{TP}{TP + FP} \tag{12.4}$$ $$\text{Recall} = \frac{TP}{TP + FN} \tag{12.5}$$ $$F_1 = \frac{2 \times \text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} \tag{12.6}$$

BLEU（机器翻译评测）

BLEU（Bilingual Evaluation Understudy）通过计算候选文本与参考文本的 n-gram 共现频率来评估翻译质量：

$$\text{BLEU} = \text{BP} \times \exp\!\left(\sum_{n=1}^{N} w_n \log p_n\right) \tag{12.7}$$

其中 BP 为简短惩罚因子（Brevity Penalty），用于修正候选文本过短导致的评分偏差：

$$\text{BP} = \begin{cases} 1, & \text{if } l_c > l_r \\ \exp\!\left(1 - \dfrac{l_r}{l_c}\right), & \text{if } l_c \leq l_r \end{cases} \tag{12.8}$$

$p_n$ 为 n-gram 精确率（截断精确率）：

$$p_n = \frac{\displaystyle\sum_{\text{n-gram} \in C} \min\!\big(\text{count}_C(\text{n-gram}),\; \max_{R \in \mathcal{R}} \text{count}_R(\text{n-gram})\big)}{\displaystyle\sum_{\text{n-gram} \in C} \text{count}_C(\text{n-gram})} \tag{12.9}$$
实践设置：通常取 $N=4$，权重 $w_n = 1/4$（各阶等权），即 BLEU-4。BLEU 偏向精确率，不适合评估召回率导向的任务（如摘要）。

ROUGE（文本摘要评测）

ROUGE（Recall-Oriented Understudy for Gisting Evaluation）侧重召回率，强调信息覆盖度：

$$\text{ROUGE-}n = \frac{\displaystyle\sum_{\text{n-gram} \in R} \min\!\big(\text{count}_C(\text{n-gram}),\; \text{count}_R(\text{n-gram})\big)}{\displaystyle\sum_{\text{n-gram} \in R} \text{count}_R(\text{n-gram})} \tag{12.10}$$

ROUGE-L 基于最长公共子序列（LCS），以 F1 分数综合精确率和召回率：

$$\text{Recall}_{\text{lcs}} = \frac{\text{LCS}(C, R)}{\text{length}(R)}, \quad \text{Precision}_{\text{lcs}} = \frac{\text{LCS}(C, R)}{\text{length}(C)}$$ $$\text{ROUGE-L} = \frac{(1+\beta^2) \cdot \text{Precision}_{\text{lcs}} \cdot \text{Recall}_{\text{lcs}}}{\beta^2 \cdot \text{Precision}_{\text{lcs}} + \text{Recall}_{\text{lcs}}} \tag{12.11}$$
BLEU vs ROUGE 对比：BLEU 基于精确率（候选→参考），适合机器翻译；ROUGE 基于召回率（参考→候选），适合文本摘要。ROUGE-L 不要求 n-gram 连续出现，能更灵活地捕捉文本相似性。

Pass@k（代码合成评测）

Pass@k 由 OpenAI 在 HumanEval 中提出，衡量 k 次生成中至少有一次通过测试的概率：

$$\text{Pass@}k = \mathbb{E}\!\left[1 - \frac{\dbinom{n-c}{k}}{\dbinom{n}{k}}\right] \tag{12.12}$$

其中 $n$ 为每题生成总数，$c$ 为通过测试的代码数。$\dfrac{\binom{n-c}{k}}{\binom{n}{k}}$ 是 $k$ 次全部失败的无偏估计，取反即为 Pass@k 的无偏估计。

为什么用无偏估计？ 直接采样 k 次会引入高方差。使用组合数公式，通过一次大规模采样（如 $n=200$）精确估计所有 $k$ 的 Pass@k，降低计算复杂度并提高估计精度。

Elo 评分体系（偏好排序评测）

Elo 评分源自国际象棋，用于基于成对比较的模型排名：

期望胜率： $$E_A = \frac{1}{1 + 10^{(r_B - r_A)/400}}, \quad E_B = \frac{1}{1 + 10^{(r_A - r_B)/400}} \tag{12.13, 12.14}$$
分数更新： $$r_A' = r_A + K \times (S_A - E_A) \tag{12.15}$$

其中 $K$ 为调整系数，$S_A$ 为实际得分（胜=1，平=0.5，负=0）。

12.2 基础能力评测

大语言模型的基础能力评测涵盖三大维度：语言生成、知识利用和复杂推理。这些能力构成模型应用于各类下游任务的基础。

12.2.1 语言生成

语言生成能力是大语言模型执行各类任务的核心基础，包括语言建模、条件文本生成和代码合成三个子类。

语言建模基准

  • Penn Treebank / WikiText-103：经典英语语言建模基准，以 PPL 为指标
  • the Pile：多领域大规模语料，用于评测模型跨域建模能力
  • LAMBADA：10,022 个段落，测试长程依赖理解；模型需预测段落最后一个词，零样本评测

条件文本生成基准

  • WMT 系列（14/16/19/20/21/22）：机器翻译标准数据集，含多语言对，BLEU/COMET/BLEURT 评测
  • CNN/DailyMail / XSum：新闻摘要数据集；XSum 含 226,711 篇 BBC 文章及一句话摘要，ROUGE 评测

代码合成基准

  • HumanEval：164 个专家编写的 Python 编程题，含函数定义、文档字符串和单元测试，零样本 Pass@k 评测
  • MBPP（Mostly Basic Python Problems）：974 道 Python 题，难度较低，单元测试验证
  • APPS：竞赛级编程题，难度更高

12.2.3 复杂推理

复杂推理涵盖知识推理、符号推理和数学推理三类，是区分顶级模型的关键维度。

知识推理数据集

  • CommonsenseQA：12,247 题，基于 ConceptNet 知识图谱，人类准确率 88.9%
  • HellaSwag：70K 情景描述，四选一补全，错误选项对抗性生成，极具挑战性
  • Social IQA（SIQA）：38,000+ 社交常识推理题，含情感、社会规范等场景

数学推理数据集

  • GSM8K：8,500 道小学数学题，2~8 步基本算术，含自然语言推理步骤
  • MATH：12,500 道数学竞赛题，难度 1~5 级，LaTeX 格式，答案等价性判断
  • miniF2F / PISA：自动定理证明基准，成功率评测

12.3 高级能力评测

高级能力评测涵盖人类对齐（诚实性、无害性）、环境交互（具身智能）和工具使用三大维度，是评估模型实际应用价值的关键。

12.3.1 人类对齐评测

人类对齐评测从有用性、诚实性和无害性三个维度考察模型行为是否符合人类价值观。

诚实性评测数据集

  • TruthfulQA：817 题，覆盖 38 个领域（健康、法律、金融、政治等），对抗性设计以触发错误认知；人工+自动评测结合
  • HaluEval：5,000 用户查询 + ChatGPT 回复，共 35,000 带/不带幻象的陈述对；评测模型识别幻象的能力

无害性评测数据集

  • CrowS-Pairs：1,508 例，涵盖种族、宗教、年龄等 9 类偏见；通过困惑度比较衡量模型偏向性
  • Winogender：720 句，120 个手写模板，评测职业性别偏见；通过代词共指消解任务
  • RealToxicityPrompts：100K 真实用户指令，自动评分器评估有害程度（0~1）

12.3.3 环境交互评测

  • ALFWorld：120 种室内模拟环境，文本指令导航与物品交互，任务完成率评测
  • WebShop：1.18M 真实产品 + 12K 购物指令，模拟在线购物行为，符合度分数 + 成功率

12.3.4 工具使用评测

  • HotpotQA：113K 多跳推理问答，需整合多个维基百科文章，精确匹配率 + F1
  • APIBench：16,450 指令-API 对，涵盖 TorchHub/TensorHub/HuggingFace，AST 匹配精确率 + 幻象率
  • ToolBench：16,464 个真实工具 API 指令，49 个 API 类别，通过率 + 胜率

12.4.1 MMLU

MMLU（Massive Multitask Language Understanding）是目前引用最广泛的综合评测数据集，覆盖人文、社会、自然科学和工程技术等 57 个子任务。任务形式为四选一选择题，标准评测设置为 5-shot。

GPT-4 在 MMLU 上的表现：5-shot 准确率 86.4%，远超此前最佳表现，接近人类专家水平（~89%）。模型性能通常随规模增加而提升，体现了扩展法则的作用。

12.4.2 BIG-Bench

BIG-Bench 包含 204 个任务，覆盖语言学、数学、常识推理、社会偏见、软件开发等多个领域。为降低评估成本，推出了 BIG-Bench Lite（24 个任务）和 BBH（BIG-Bench Hard，专攻大语言模型表现逊色于人类的任务）。

在少样本设置下，随着模型规模扩展，大语言模型在 65% 的 BIG-Bench 任务中能超过人类平均水平。BIG-Bench 还引入了 Brier Score 评估模型对预测选项概率的置信度校准情况。

12.4.3 HELM

HELM（Holistic Evaluation of Language Models）采用自顶向下的设计，包含 16 个核心场景（由任务、领域、语言三维度组成）和 7 类评估指标：

  • 准确性、校准性、鲁棒性、公平性、偏差、有害性、效率

HELM 还在 26 个额外场景中开展 7 项特定评估，涵盖语义理解、世界知识、推理、记忆与版权、虚假信息、偏见及有害内容生成等维度。

12.4.4 C-Eval

C-Eval 是专为中文大语言模型设计的综合评测体系，覆盖初中到专业四个难度级别，涉及 STEM、人文、社会科学等多领域。

数据污染问题

数据污染（Data Contamination）是指测试集数据出现在训练集中，导致评测结果虚高，是当前大语言模型评测面临的最严峻挑战之一。

污染类型

  • 精确污染：测试样本完全出现在训练数据中
  • 近似污染：测试样本的改写版本出现在训练数据中
  • 分布污染：测试集主题/领域在训练数据中过度代表

污染检测方法

N-gram 重叠检测：计算测试样本与训练数据的 n-gram 重叠率：

$$\text{ContamScore}(x_{\text{test}}) = \frac{|\text{n-grams}(x_{\text{test}}) \cap \text{n-grams}(\mathcal{D}_{\text{train}})|}{|\text{n-grams}(x_{\text{test}})|}$$

通常设定阈值（如 n-gram 重叠率 > 30%）判定为污染。

成员推断攻击（Membership Inference Attack）：污染样本的困惑度通常低于未污染样本。通过对比模型在已知训练数据和测试数据上的困惑度差异来检测污染：

$$\text{污染指标} = \text{PPL}_{\text{非成员}} - \text{PPL}_{\text{测试样本}}$$

若差值显著大于零，则该样本可能为训练集成员（即污染样本）。

对策方法适用阶段
训练前过滤从训练数据中删除与测试集重叠样本训练阶段
动态基准定期更新测试题目，使用时间戳控制基准设计
私有测试集不公开测试集，提交系统评测评测组织
污染报告要求论文报告检测到的污染比例学术规范

12.4.7 评测代码实践（LLMBox）

LLMBox 支持 53 个评测基准，基于 Transformers 代码库，支持 LLaMA-2、Mistral、Qwen 等开源模型和 OpenAI/Claude API。提供三种评测实现：

  • 困惑度评测：计算各选项在给定上下文下的 PPL，选最小值；适合基座模型（GPT-3、LLaMA）
  • 候选项概率评测：比较候选项字母（ABCD）的概率；适合对话模型（ChatGPT、LLaMA-2 Chat）
  • 生成式评测：直接生成答案，可结合思维链；适合所有生成式模型
# 使用 HellaSwag 基于 PPL 以零样本方式评测 LLaMA-2 (7B)
python inference.py -m meta-llama/Llama-2-7b-hf -d hellaswag

# 使用 CMMLU 基于候选项概率以 5-shot 方式评测 Qwen-1.5 (72B)
python inference.py -m Qwen/Qwen1.5-72B -d cmmlu -shots 5

# 使用 GSM8K 以 8-shot 生成式评测 GPT-3.5
python inference.py -m gpt-3.5-turbo -d gsm8k -shots 8

# 使用 GSM8K 以 8-shot 生成式评测 4 比特量化的 Phi-2
python inference.py -m microsoft/phi-2 -d gsm8k -shots 8 --load_in_4bit

# 使用 HumanEval 零样本（温度 0.1）评测 Mistral (7B)，采样 100 次，Pass@1
python inference.py -m mistralai/Mistral-7B-v0.1 -d humaneval \
  --temperature 0.1 --pass_at_k 1 --sample_num 100

本章小结

本章系统介绍了大语言模型评测的完整体系。核心洞察如下：

  1. 没有万能指标：PPL 适合语言建模，BLEU/ROUGE 适合生成任务，Pass@k 适合代码，Elo 适合偏好排序，需组合使用
  2. 三类范式各有优劣：自动评测（高效可复现）+ 人类评测（真实可靠）+ LLM-as-Judge（折中方案）需根据场景选择
  3. LLM-as-Judge 需警惕偏见：位置偏置、冗长偏置、自增强偏置是已知问题，需通过交换顺序、多评判者等方式缓解
  4. 数据污染是系统性问题：N-gram 检测和成员推断是主要检测手段，需在基准设计和训练数据处理两端共同应对
  5. 基准饱和驱动创新：HellaSwag、GSM8K 等已接近饱和，MATH、ARC-AGI 等更难基准成为新挑战
  6. Chatbot Arena 代表未来方向：基于真实用户的动态 Elo 排名比静态基准更能反映模型真实能力
评测不仅是衡量工具，也是引导研究方向的指挥棒——评测什么，模型就会被优化成什么。
