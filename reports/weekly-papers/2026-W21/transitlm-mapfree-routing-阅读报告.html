2. 核心问题与动机

2.1 范式转变：从地图驱动到数据驱动

公共交通路线规划是城市日常出行的核心基础设施服务，但传统系统高度依赖结构化地图数据和复杂工程管道。一条典型的传统规划流程包含：

  1. 地图数据检索：从拓扑网络中检索起点-终点间的候选路段；
  2. 路由算法：运行 Dijkstra、A*、RAPTOR 等算法在图上搜索最优路径；
  3. 候选排序：利用规则或排序模型对候选路线进行个性化排序。

这种传统架构存在三大固有局限：基础设施成本极高（需要维护实时地图与调度数据）、配置静态僵化（难以快速响应用户偏好变化）、以及跨城市扩展困难（每座城市都需要独立的路网图建模）。

核心洞察：交通平台每天产生海量规划日志，这些日志隐式编码了丰富的路由知识——包括换乘站、用户如何权衡速度、便利性和线路偏好。这激发了一个自然的问题：能否直接从这些数据中学习路线规划，完全绕开地图与路由引擎？

2.2 通用 LLM 为何不够用

人们自然会想到用 GPT-4、Qwen3 等通用大模型来解决这一问题。然而，近期研究表明自回归 LLM 在规划任务上有根本性的局限：

  • 能回忆热门站点或高频路线，但对低频起终点对会产生幻觉站点（hallucinated stations）；
  • 生成的路线常出现断裂连接（disconnected routes），即相邻站点之间没有共享线路；
  • 输出无效的上下车站点，与起终点的实际空间关系不符。

根本原因在于：缺少合适的训练数据。现有数据源各有缺陷：车辆轨迹数据集（T-Drive、Porto Taxi）缺少站点结构；静态网络数据（GTFS、OpenStreetMap）没有用户行为标注。TransitLM 正是为了填补这一空白而构建。

传统地图管道

  • 依赖结构化路网图
  • Dijkstra / A* / RAPTOR 算法
  • 候选检索 + 排序模型
  • 工业验证、高稳定性
  • 成本高、配置静态

通用 LLM（无领域数据）

  • 依赖文本语义线索
  • 幻觉站点 / 断裂路线
  • 缺乏拓扑结构知识
  • 端到端但精度极低
  • 无法隐式对齐 GPS

TransitLM（本文方案）

  • 从真实规划日志中学习
  • 端到端无地图生成
  • 隐式 GPS→站点对齐
  • 结构合法，高精度路线
  • 单模型跨任务泛化

4.2 数据收集细节

TransitLM 的原始数据来源于 Amap（高德地图）导航平台，覆盖北京、上海、深圳、成都四座中国主要城市。数据从单日导航日志中提取，每条规划会话包含以下字段：

  • 起终点 GPS 坐标（经纬度）及 POI 名称；
  • 候选路线列表：完整站点 ID 序列（唯一数字 ID，非自然语言站名）和线路标识符；
  • 分段级出行信息：各段距离、时间、票价；
  • 路线类型标注（bus-only / subway-only / bus+subway / mixed）；
  • 首末里程接驳信息：起终点到最近公交站的步行/骑行/打车细节；
  • 用户选择标签：用户实际点击的路线（反映真实偏好）。
关键设计选择：所有候选路线均由 Amap 生产路由引擎生成，天然满足连通性和可行性约束，提供了无需人工验证的高质量训练信号。

5. 关键技术详解

5.1 数据 Schema：CPT 语料库 vs SFT 基准数据

TransitLM 发布两种互补的数据资源：

CPT 记录格式（路线规划会话文本）

// 查询头部

城市：北京

起点：(lng, lat)，POI名称

终点：(lng, lat)，POI名称

// 候选路线（用户选择的路线排第一位）

路线1：线路序列 | 站点ID序列: [S1, S2, ..., Sn]

距离: X.X km | 时间: N min | 票价: ¥X.X

首里程: 步行/骑行/打车 → 站点S_board

末里程: 站点S_alight → 步行/骑行/打车

路线2：... （最多5条，多样性过滤后）

CPT 语料库还包括 880,854 条站点描述（名称、坐标、描述）和 147,918 条线路描述（线路长、停靠站序列、运营时间、连通性），共形成约 20B+ tokens 的训练语料。

5.2 词表扩展与站点 Token 化

TransitLM 的一个核心技术决策是将所有 120,845 个站点 ID 注册为词表中的独立 token。这一设计具有深远意义：

  • 防止字符级幻觉：若用字符组合表示站点 ID（如 "12345"），模型可能拼出现实中不存在的数字组合，产生幻觉站点；独立 token 使模型只能输出已注册的合法站点；
  • 直接编码空间关系：每个站点 token 的嵌入向量在预训练过程中逐渐捕获该站点在交通网络中的拓扑和空间位置信息；
  • 序列长度缩短：一个长数字 ID 变为单个 token，使中间站点序列的表示更紧凑，减少了生成误差累积。

5.3 GPS 坐标的隐式对齐机制

TransitLM 最令人印象深刻的能力之一是隐式空间对齐（Implicit Spatial Grounding）：模型仅根据 GPS 坐标输入，无需任何坐标到站点的显式映射模块，就能正确预测最近的上下车站点。

在 CPT 语料中，每条记录都包含 GPS 坐标和对应的上下车站点 ID。通过在 13.9M 条记录上的 next-token prediction，模型在统计上学到了 哪些坐标区域对应哪些站点，从而无需外部地理数据库即可完成隐式空间对齐。

评估方式：Station Grounding (SG) 指标检测预测的上下车站点是否在起终点坐标的模式特定距离阈值内（步行 3km / 骑行 5km / 打车 10km）。

GPS-only 消融实验进一步证实了这一能力：移除所有文本提示，仅保留 GPS 坐标输入时，领域专用模型性能几乎不下降（Qwen3-4B 的 Route Exact Match 仅从 71.0% 降至 70.4%），而通用 LLM 的 Station Grounding 从 72.0% 骤降至 16.8%。

7.6 GPS-only 消融：隐式空间对齐的证据

核心发现：通用 LLM 在仅有 GPS 坐标（无文本提示）时，Station Grounding 从 72.0% 暴跌至 16.8%（DeepSeek-V4），而 Route Exact Match 几乎归零（< 1%）；相比之下，领域专用模型（Qwen3-4B）在同等条件下 Route Exact Match 仅降低 0.6 个百分点（71.0% → 70.4%），证明其空间知识来自训练数据而非文本语义提示。

8. 核心洞见与读后评注

8.1 地图知识的隐式习得：规模替代工程

TransitLM 最深刻的洞见在于：当训练数据足够密集时，语言模型能够从语料的统计共现中习得与地理数据库等价的空间知识。传统系统需要精心维护的路网图和坐标映射模块，而 TransitLM 仅通过 1300 万条规划日志，就让模型内化了北京、上海、深圳、成都四座城市的公交拓扑。

这一发现有更广泛的含义：类似的"隐式结构学习"可能适用于其他领域，只要存在足够规模的行为日志（用户操作序列、推荐系统点击流、导航轨迹），就可能替代显式的知识图谱或规则系统。

8.2 Joint Training 消除负迁移：任务知识的正交性

Joint 模型在三个任务上全面超越或持平单任务模型，且在偏好感知规划上提升最明显（+2.1pp Connectivity，+2.2pp REM）。这说明三个规划任务不是相互竞争的，而是共享底层的拓扑表示——偏好约束和多样性要求都是在同一网络知识基础上的高阶约束。

这对实际部署很有价值：单模型即可服务所有规划场景，避免了多模型维护的工程复杂度。

8.3 学习层次结构：语法优先，精度其次

数据规模消融揭示了一个清晰的学习层次：

  • 仅用 6.25% 数据（约 810K 条会话）即可达到 94% 连通性——模型快速学会交通网络的结构"语法"；
  • Route Exact Match 对数据量极度敏感（从 6.25% 的 49.9% 到 100% 的 71.0%），说明精确路线选择需要密集的行为覆盖；
  • 数值字段（MAPE）同样对数据敏感，说明票价/时间估计依赖细粒度的距离-时间关系习得。

8.4 域知识 vs 模型规模：数据是核心瓶颈

一个令人印象深刻的结果是：0.6B 领域专用模型在更宽松评估条件下全面超越六个最强通用 LLM（包括 GPT-5.4-pro、Gemini-3.1-Pro 等）。这清楚地表明，对于结构性知识密集型任务，领域数据是核心瓶颈，而非模型参数规模。这对资源受限场景（如边缘部署、在线推理成本控制）有重要实践指导意义。

8.5 局限性与未来方向

  • 地理覆盖有限：数据仅来自 Amap 平台的四座中国城市，对其他国家城市、小城市或非中文路网的泛化能力未知；
  • 静态路网：当前数据集捕获的是静态路线结构，未包含实时延误、临时线路变更等动态信息；
  • 单平台偏差：所有路线均由 Amap 的生产路由引擎生成，可能带有该平台的排序偏好；
  • 多模态接驳建模粗糙：首末里程的建模依赖距离阈值规则，未充分利用实际步行/骑行网络；
  • 未来方向：扩展至更广泛地理区域、引入实时动态信息、探索更小模型（ < 0.6B）的可行性下限。
