第6章 数据选择与模型压缩

Vol.1 · Part III 优化 · 整合原第 9–10 章 · 生成日期：2026-07-04

整合主题优化有两个杠杆——少喂数据（Entropy/Gravity → Selection Gain）与小模型（结构→数值→执行三层压缩栈）；二者共同攻击铁律中的 $D_{\text{vol}}/BW$ 与 $O$
学习目标在精度约束下组合数据策略与压缩技术，沿 Pareto 前沿在「膝点」停止

一、两个杠杆与 Selection Gain

第 5 章把训练跑起来；本章问：能否用更少资源达到同样 ceiling？ 两条独立路径：

杠杆攻击铁律项核心思想
数据选择$D_{\text{vol}}/BW$、标注成本高 Entropy、低 Gravity 的样本优先
模型压缩$D_{\text{vol}}/BW$、$O$、内存容量消除参数/精度/执行冗余
$$\text{Selection Gain} \propto \frac{\text{Entropy}}{\text{Gravity}} \quad \text{去重 50\% 数据 → 减一半 } D_{\text{vol}}/BW \text{，熵不变或升}$$

Entropy 高 = 模型不确定、信息量大；Gravity 高 = 存储/传输/标注贵。数据侧 Selection Gain 与模型侧压缩栈共同攻击同一铁律项，但决策轴不同：前者在 Data 轴筛样本，后者在 Algorithm–Machine 轴重新谈判 Silicon Contract。

二、Coreset、Active Learning 与预算

2.1 Coreset 与预算

目标：从 $N=10M$ 中选 $k=100K$ 使 loss 接近全量。随机：$k/N=1\%$ 常不够；Coreset 按梯度范数/影响函数优先高杠杆点。算例：$0.01/图标注 × 100K = \$1K$ vs 全量 \$100K。

2.2 Active Learning 预算陷阱

10M 池、\$50K 标注预算、\$0.01/图 inference 打分：

  • 全池打分：\$100K → 超预算，标注为 0
  • 预过滤 500K + 打分 \$5K → 剩 \$45K 标 90K 难例 → 可行

不确定性采样：选 entropy 最高 $H(p)=-\sum p_i \log p_i$ 的样本送标。系统 lesson：打分成本须纳入总预算，否则 AL pipeline 在启动前已破产。

2.3 Curriculum 与去重

Curriculum：先易后难（小 loss 样本→大 loss），收敛可快 20–30% step，但错误排序引入 bias。MinHash LSH：Jaccard>0.9 近重复剔除，ImageNet 级可减 10–30% 存储与 step。

2.4 合成 vs 真实

KWS：750K 真实 + 2M 合成。纯合成失败于未建模口音/噪声；最优 mix 依部署子群 PSI 监控调整（呼应第 3 章工作流）。

过渡：数据杠杆把 $D_{\text{vol}}$ 和标注美元压下去；若部署信封（512 MB、200 ms p99）仍不满足，须转向模型侧——在 Pareto 前沿上用小模型换体积与延迟。

三、压缩栈与部署鸿沟

赢得基准测试的模型，很少能直接上生产。Cloud / Edge / Mobile / TinyML 各自施加内存、延迟、功耗硬约束——7B 参数 FP16 需 14 GB，智能手机共享 RAM 仅 8 GB。压缩不是「把模型做小」，而是在部署物理环境中重新谈判 Silicon Contract。

定义：模型压缩（Model Compression）

通过消除冗余参数（剪枝 Pruning）、降低数值精度（量化 Quantization）或将行为迁移到小架构（蒸馏 Distillation），在尽可能保留预测精度的前提下，降低计算成本与内存占用。

部署鸿沟（Deployment Gap）

MobileNetV2 INT8 约 3.5 MB，仍超出 TinyML ~524 KB 信封约 6.7×；专用 DS-CNN 关键词识别约 500 KB 可适配。压缩在 TinyML 上是生存问题，而非可选优化。

四、DR 案例：compress-validate-adjust 循环

第 3 章 512 MB / 灵敏度 ≥90% 约束在此落地为迭代管道——每步只接受可测指标晋升：

  1. FP32 MobileNetV2 ~14 MB → INT8 ~3.5 MB（量化）
  2. 验证农村子群灵敏度：0.923 → 0.891（低于 0.90 门槛）
  3. QAT 2 epoch + 校准集 500 张农村图 → 0.904（通过）
  4. Jetson 实测 p99 180 ms（< 2 s SLA）

FLOPs 降 4× 但灵敏度 0.88 则回滚上一 artifact。该循环同时体现 Data 轴（农村校准集）与 Algorithm–Machine 轴（INT8/QAT）的协同——与 Selection Gain 同一验收哲学。

五、Pareto 前沿与结构优化

5.1 Pareto 与停止准则

横轴延迟/体积，纵轴精度。膝点（knee）后：INT4 再省 2× 内存但灵敏度 −3 pt → 不采纳。工程在膝点停，而非追极限压缩比。数据选择同样在「100K Coreset vs 全量 10M」的精度–成本曲线上找膝点。

5.2 剪枝

$$\min_{\hat{W}} \mathcal{L}(\hat{W}) \quad \text{subject to} \quad \|\hat{W}\|_0 \leq k$$
类型移除对象硬件兼容
非结构化单个权重需稀疏内核，无支持则更慢
结构化通道/滤波器通用加速器友好，直接减 FLOPs
N:M (A100 2:4)每 4 权重留 2硬件约束，满足布局才获 ~2× 吞吐

5.3 三区域框架

区域技术精度代价系统收益
Region 1算子融合、layout 优化≈ 0延迟 −10–30%
Region 2INT8 PTQ、50% 结构化剪枝0.5–1 pt2–4× 吞吐/体积
Region 3INT4、蒸馏、NAS1–5 pt5–10× 但需重验证

工程顺序：先 Region 1（免费），再 Region 2（DR QAT 在此），Region 3 仅在约束仍不满足时进入。

六、蒸馏与量化

6.1 知识蒸馏

教师软标签（如 $[0.85, 0.10, 0.05]$）携带类间相似性「暗知识」，比硬标签 $[1,0,0]$ 信息更丰富。

$$\mathcal{L}_{\text{distill}} = (1-\gamma_{\text{KD}})\mathcal{L}_{\text{CE}}(\mathbf{p}_{\text{student}}, y) + \gamma_{\text{KD}} T^2 \mathcal{D}_{\text{KL}}(\mathbf{p}_{\text{teacher}}^{(T)} \Vert \mathbf{p}_{\text{student}}^{(T)})$$

DistilBERT：保留 BERT ~97% 性能，参数 110M→66M，延迟 85 ms→34 ms——适合架构根本不同的部署目标。

6.2 量化

$$q = \text{round}\left(\frac{x}{s}\right), \quad \hat{x} = q \cdot s$$

Horowitz 数据：32-bit DRAM 读相对 8-bit 整数加法的能量比约 21,333×——FP32→INT8 的「能量红利」。Llama 3 8B：FP16 16 GB vs INT4 4 GB；decode 时读权重主导 $D_{\text{vol}}/BW$。

  • PTQ：训练后转换，需校准集估计激活范围
  • QAT：训练图插入 fake quant，DR 案例农村子群靠 QAT 过 0.90 门槛
  • GPTQ/AWQ：LLM 4-bit 部署，保护 salient 通道
格式位宽存储缩减典型场景
FP3232-bit基准通用训练
INT88-bit4×边缘推理（DR 路径）
INT44-bit8×LLM 端侧

七、架构效率与组合选型

深度可分离卷积：标准卷积 $\mathcal{O}(hw C_{\text{in}} C_{\text{out}} k^2)$ 分解为 depthwise + pointwise，MobileNetV2 相对 ResNet-50 约 13.7× 运算量削减。算子融合：Conv-BN-ReLU 未融合时 3 次 launch、6 次内存传输；融合后 1 次 launch、2 次传输。

$$D_{\text{vol,unfused}} = 2NM \quad \Rightarrow \quad D_{\text{vol,fused}} = 2M$$

推荐流水线（MobileNet 部署示例）

  1. 数据侧：Coreset/去重减训练 $D_{\text{vol}}$
  2. 结构化剪枝 50% 滤波器（表示层）
  3. INT8 量化 + QAT 校准关键子群（数值层）
  4. BN 融合进卷积（执行层）

验收必须在部署芯片上测 p99 延迟与灵敏度——FLOP 计数不能替代实测。

8.2 谬误对照

谬误现实
「全量数据总是更好」50% 去重可减 step 且熵不降；Coreset 1% 可逼近全量 loss
「AL 只算标注成本」全池 inference 打分可超预算
「压缩 = 调小模型」三层栈须组合；非结构化稀疏无内核支持则更慢
「FLOPs 降 = 延迟降」须在 Jetson/目标芯片上测 p99
「PTQ 一次到位」DR 农村子群 PTQ 掉 3.2 pt，须 QAT + 分布匹配校准集

章节总结

  1. 两杠杆：Selection Gain $\propto$ Entropy/Gravity；压缩栈结构→数值→执行
  2. 数据侧：Coreset/AL 须把打分成本纳入预算；去重直接减 $D_{\text{vol}}/BW$
  3. 模型侧：Pareto 膝点停止；DR compress-validate-adjust 循环是可测晋升范式
  4. 组合：数据筛选 + 剪枝 + INT8 QAT + 融合；验收在部署芯片与子群指标

压缩的守恒定律：复杂度很少消失，只是从参数/精度迁移到运行时稀疏格式、蒸馏训练预算或路由开销。工程师的任务是把代价移到部署约束下最便宜的轴上。
