Apache Spark 技术报告

汇总自 md/note/spark学习

本报告对《Spark学习》《sparkRDD》《SparkSQL》《pyspark学习》《spark性能优化》五份笔记进行结构化提炼，涵盖部署与工程入门、RDD 编程模型、Spark SQL、PySpark 与 Pandas 集成、性能调优与数据倾斜处理等内容，版式与同目录下 HTML 技术报告保持一致，便于离线阅读与检索。

第一部分：概述与运行环境

1.1 Spark 在栈中的位置

Apache Spark 是围绕内存计算与统一批流与 SQL 引擎构建的分布式计算框架。Driver 持有用户程序与 DAGScheduler；Cluster Manager（Standalone、YARN、Kubernetes 等）分配 Executor；Executor 执行 Task 并缓存分区数据。

1.2 工程与依赖（Maven 要点）

Scala 项目通常引入 spark-core_2.12 等与集群 Spark 版本一致的构件，并配合 scala-maven-plugin 编译；打包上线常用 maven-assembly-plugin 生成带依赖的 fat JAR。笔记中以 Spark 3.0.0 为例，生产环境应以实际集群版本为准。

1.3 日志与可观测性

默认日志较冗长。可在 resources/log4j.properties 中将根级别设为 ERROR，并对 org.apache.spark、Jetty、Parquet、Hive 元数据等包单独降噪，便于本地与 shell 调试时看清业务输出。

第二部分：RDD 与核心执行模型

2.1 RDD 是什么

RDD（Resilient Distributed Dataset）是只读、可分区的记录集合，通过血统（lineage）容错。RDD 算子整体分为 Value 型、双 Value 型与 Key-Value 型。执行风格接近「装饰器」式链式转换：转换（Transformation）懒执行，遇到 行动（Action）（如 collect）才触发实际计算；RDD 默认不落盘保存中间结果，与带缓冲的 IO 流类比时需注意分布式语义差异。

2.2 创建与读取

  • 并行化集合：SparkContext.parallelize / makeRDD
  • 外部存储：textFile 等；本地路径必须在各 Worker 上同样可访问，否则应使用 HDFS 或共享存储

2.3 Transformation 与 Action

Transformation 返回新 RDD；Action 将结果送回 Driver 或写外部系统。默认每次 Action 可能从头重算整条血统，故对复用链路应 persist / cache，并可指定存储级别（内存、磁盘、副本等）。

类型代表算子备注
窄依赖map、filter、mapPartitions无 shuffle 或数据重分布代价低
宽依赖 / shufflereduceByKey、groupByKey、repartition、join跨分区拉取数据，成本高，易倾斜
Actioncollect、reduce、count、saveAsTextFile、foreachcollect 会把全量拉回 Driver，慎用大数据集

2.4 向集群传递函数与闭包

  • 推荐：短逻辑用匿名函数；或定义在 全局单例 object 的静态方法，避免序列化整个外部类实例
  • 在实例方法里引用 this 的字段会捕获整个对象，增大序列化与语义风险；可先拷贝到局部常量再闭包内使用
  • 不要在 RDD 算子中依赖「改 Driver 上变量」的副作用计数；应使用 Accumulator
  • rdd.foreach(println) 在集群上输出在 Executor 标准输出，Driver 不一定可见；需要时在 Driver 侧 collect 后再打印（注意数据量）

2.5 共享变量

广播变量（Broadcast）：大只读表在各 Executor 一份副本，减少 Driver 到 Task 的重复传输。累加器（Accumulator）：仅「可加」的聚合变量，供监控与分布式计数，不应用于业务关键且需强一致的场景替代 reduce。

第三部分：Spark SQL、DataFrame 与 Dataset

3.1 DataFrame 与 Dataset

DataFrame 即带列名与类型的二维表视图（Scala/Java 中为 Dataset[Row]），由 Catalyst 优化器生成执行计划，通常比手写 RDD 链更易优化。Dataset 在 DataFrame 上增加强类型与编码器（Encoder），适合复杂类型与编译期检查。与 RDD 互转需 import spark.implicits._（spark 为已创建的 SparkSession 变量名）。

3.2 入口与临时视图

统一入口为 SparkSession.builder().getOrCreate()。临时视图会话级；全局临时视图位于 global_temp 库，需用限定名引用。

3.3 Join 类型（SQL/DataFrame API）

类型语义摘要API 关键词示例
INNER默认；仅匹配键两侧都存在join(df, Seq("id"))
CROSS笛卡尔积，行数乘积级膨胀crossJoin
LEFT / RIGHT / FULL OUTER保留一侧或两侧未匹配行"left_outer"、"outer" 等
LEFT SEMI仅保留左表中「右表存在匹配」的行，不展开右表列"left_semi" / "semi"
LEFT ANTI保留左表中「右表无匹配」的行"left_anti" / "anti"

3.4 日期时间与比较陷阱

应用层应统一为日期/时间类型再比较，避免字符串与空串语义混乱。笔记示例：null <= '2022-01-10' 结果为 null；'' <= '2022-01-10' 可能为 true。常用函数包括 current_date、current_timestamp、to_date、to_timestamp、unix_timestamp、from_unixtime、date_add、datediff、trunc、date_trunc 等。

3.5 读写、分区与保存模式

支持 JSON、CSV、Parquet、ORC 等；可配置分隔符、表头、推断 schema、路径通配 pathGlobFilter、递归目录 recursiveFileLookup。分区表路径可自动解析分区列。保存模式包括 error、append、overwrite、ignore（非原子，覆盖会先删后写）。

3.6 性能与自适应（AQE）要点

  • 缓存：dataFrame.cache() / spark.catalog.cacheTable，列式压缩与扫描列裁剪由引擎优化
  • Join Hint：BROADCAST、MERGE、SHUFFLE_HASH 等提示执行策略，但不保证一定采纳
  • AQE（Spark 3.2+ 默认 umbrella）：运行期统计合并 shuffle 分区、广播小边、处理倾斜 Join 等；相关配置如 spark.sql.adaptive.enabled、spark.sql.adaptive.skewJoin.enabled 等

3.7 NULL 语义与聚合

比较运算符遇 NULL 多为 UNKNOWN；WHERE/HAVING/JOIN ON 仅「真」为保留。聚合中 NULL 通常被忽略（COUNT(*) 例外）。ORDER BY 默认 NULL 在前，可用 NULLS LAST。集合运算（UNION 等）中行比较对 NULL 采用 null-safe 相等语义。

3.8 SQL 与 Hive 运维片段

分区表若由已有目录创建，元数据可能未注册分区，可执行 MSCK REPAIR TABLE 或 ALTER TABLE RECOVER PARTITIONS。concat_ws 与 collect_list 场景下若多 mapper/reducer 破坏顺序，需结合 sort_array、补位排序键等技巧稳定输出顺序。

第四部分：PySpark、窗口函数与 Pandas 集成

4.1 创建 DataFrame

SparkSession.createDataFrame 接受 list、Row、Pandas DataFrame、RDD 等；可显式传入 schema，否则采样推断。DataFrame 仍为懒执行；多数列操作返回 Column 表达式。

4.2 窗口函数（Window）

窗口由 Window.partitionBy 与可选 orderBy 定义；每行对应一个 Frame。无序窗口在同分区内 Frame 可相同；有序窗口默认 Frame 常包含分区中从首行到当前行的范围（依函数而定）。

函数族说明
rank / dense_rank / row_number排名：是否留空位、并列是否连续、是否唯一序号
ntile、percent_rank分桶与相对排名
lag / lead取前/后若干行的列值

Frame 边界

rowsBetween 按物理行位移；rangeBetween 按排序列值与当前值的差。常配合 Window.unboundedPreceding、Window.currentRow、Window.unboundedFollowing 表达滑动累计等。

4.3 Pandas UDF 与 Arrow

开启 spark.sql.execution.arrow.pyspark.enabled 可加速 Spark 与 Pandas 之间的列式转换。pandas_udf（Spark 3.0+ 推荐类型注解）与 mapInPandas、applyInPandas、cogroup().applyInPandas 等 API 便于向量化与复杂分区内逻辑。

内存与分区

笔记实践：分区过大时，整分区转为 Pandas DataFrame 可能使 Python 侧内存膨胀数倍，并行多分区易导致 YARN OOM Kill。宜控制分区大小与并发、或先 repartition 再进入 Pandas UDF。

4.4 经典 UDF 与 SQL 注册

可用 @udf 或 udf(lambda, returnType)；在 SQL 中使用需 spark.udf.register。Scalar Pandas UDF 也可注册后在 SQL 中调用。

第五部分：性能调优与数据倾斜

5.1 资源与提交参数

在资源允许范围内，增加 Executor 数量、每 Executor 核数与内存，可提升并行度与 shuffle 可用内存、减少落盘。典型 spark-submit 含 --num-executors、--executor-memory、--executor-cores、--driver-memory、spark.yarn.executor.memoryOverhead 等。YARN 单容器上限受 yarn.scheduler.maximum-allocation-mb 等约束，需与 executor.memory + overhead 对齐。

5.2 并行度与 Spark SQL

官方经验：Task 数可为集群总 CPU 核数的约 2～3 倍以减少空转。spark.default.parallelism 主要作用于非 SQL Stage；SQL 类 shuffle 常用 spark.sql.shuffle.partitions（默认 200，大数据量宜调大）。Spark SQL 自动推断的 stage 并行度若过低，可在 SQL 读出的 RDD/DataFrame 后接 repartition 提升后续非 SQL Stage 并行度。

5.3 RDD 与算子层面

  • 避免重复计算同一血统：对复用分支 cache/persist
  • 尽早 filter 减少后续数据量
  • mapPartitions：按分区一次处理，减少函数调用开销，但单分区数据过大易 OOM
  • reduceByKey 相对 groupByKey 可在 map 端预聚合，减少 shuffle 量
  • 广播大变量：大表维表等用 Broadcast，减少每个 Task 副本
  • Kryo：spark.serializer=KryoSerializer 并注册自定义类型，可显著降低序列化开销
  • 本地化等待：spark.locality.wait 在数据局部性与资源利用间折中

5.4 Shuffle 调优

配置项作用方向
spark.shuffle.file.buffer增大 map 端缓冲，减少溢写次数（默认较小如 32KB 量级）
spark.reducer.maxSizeInFlightreduce 端单次拉取缓冲；过大可能 OOM，过小则网络往返增多
spark.shuffle.io.maxRetries / retryWait拉取失败重试与间隔；GC 或网络抖动场景可适当加大
spark.shuffle.sort.bypassMergeThresholdSortShuffle 下 reduce 分区数小于阈值可走 bypass，减少排序开销（需结合场景）

5.5 JVM 与堆外

老版本静态内存模型可调 spark.storage.memoryFraction；统一内存模型下 Storage 与 Execution 可动态借用。超大数据 shuffle 若出现 shuffle file not found、executor lost 等，可增大 spark.yarn.executor.memoryOverhead 与连接超时 spark.core.connection.ack.wait.timeout 等。

5.6 数据倾斜：识别与对策

倾斜表现为少数 Task 极慢或反复 OOM，与「全体 Task 都慢」的数据量过大不同。定位：查 shuffle 类算子与 Stage 日志。对策包括：上游 Hive 预聚合、过滤热点 key、提高 reduce 并行度（缓解但非根治）、随机前缀双重聚合、小表 广播 + map 侧 join、采样拆分倾斜 key 单独 join、以及 Spark 3 AQE 倾斜 Join 等。

5.7 故障排除摘要

  • reduce 端缓冲过大导致 OOM：适当减小 spark.reducer.maxSizeInFlight，以性能换稳定
  • GC 导致 shuffle 拉取失败：结合重试与等待参数；优化 JVM 与业务对象分配
  • 序列化错误：确保 RDD 元素类型、闭包捕获变量、第三方连接等可序列化或不在闭包中持有不可序列化对象
  • 算子返回 NULL 引发下游异常：用占位值 + filter 或显式处理空值
  • YARN client 模式 Driver 在本地，流量与稳定性需单独评估
