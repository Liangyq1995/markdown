1. 概述

研究的"传播层"——把一篇 camera-ready 论文转成会议 poster、talk video、博客推文——长期都是手工的"最后一公里"。它发生在作者最没空的时候（录用之后、开会之前），却要同时跑通图片裁剪、排版、配音、面向不同受众改写三套截然不同的制作流程。先前自动化工作把每个产物当作孤立系统来解：各自重新抽取论文、各自出图，输出一个作者无法在 PowerPoint/Word 里二次编辑的"单向渲染"（one-way render），并以"软"的 VLM 偏好分作为质量门槛——分数很快平台化，可关键章节却仍然空着。

本文把"最后一公里"当作一个架构问题而非"更好的单一产物"问题来解。其论点是：这一层最好被建成一个技能组合（composition of skills）——薄薄的、agent 可读的契约（contracts）共享一个上游抽取器，把确定性原语包在一个"计量填充循环"（measured-fill loop）里，其出口是硬性的通过/失败渲染门（hard pass/fail render gate），而非软分平台。该模式被实例化为 ResearchStudio-Reel：五个 Claude Code / Codex 技能——

  • Paper2Assets：唯一上游抽取器，把论文抽取一次，产出共享 bundle；
  • Paper2Poster / Paper2Video / Paper2Blog：三个可编辑生成器；
  • Paper2Reel：交互式收敛层，把三者绑成一个可按 section 跳转的 HTML 查看器。

核心结果：在 Paper2Poster 100 篇基准上，其 poster 在每一个美学与信息子准则上领先所有先验自动化系统与单次前沿 LLM，在两个 held-out VLM 评委下美学均值 3.52 vs 作者真值 2.94（领先约 0.6/5），并在 84%–93% 的论文上赢得总分；能力审计显示它是唯一同时交付三种可编辑产物的流水线。

2. 研究背景与动机

2.1 三大反复出现的缺口（G1–G3）+ 第四收益

G1 孤立抽取（Isolated extraction）：每个产物由一个独立的单体系统从头抽取图表、算 caption、拉元数据，跨产物的"事实一致性"（如 poster 上的 Figure 3 与 blog 引用的是否同一张）被丢给用户。
G2 单向渲染（One-way renders）：先验产物大多是 PDF poster / MP4 video / HTML 博客，作者无法在 PowerPoint/Word 里重开微调；任何事后修改都得重跑生成器而非就地编辑。
G3 软质量门（Soft quality gates）：每个产物用连续 VLM-as-judge / 美学分判分，7.8/10 的排版也被接受，即使承重章节空着；agent 与确定性原语的边界各系统画法不一，成本与可复现性不可比。
第四收益：统一交互式呈现面——把 poster ↔ video ↔ blog 绑成一个可按 section 导航的交付物，此前没有任何系统提供。

ResearchStudio-Reel 的定位不是"更好的单个产物"，而是沿四轴的组合：唯一一个跨产物共享上游抽取器（解 G1）、唯一一个在作者原生工具里出货（解 G2）、唯一一个用硬分类渲染门替换软偏好门（解 G3）、唯一一个引入统一可交互呈现面（第四收益）。

2.3 三大"现在才可行"的收敛

作者点出三点让该组合在当下变得可工程化：(i) Claude Code / Codex 提供了稳定的技能运行时；(ii) 确定性原语足够成熟可安全委托——headless Chromium 做 HTML→PDF、LibreOffice+ffmpeg 做 slides→video、python-docx 做编辑级 .docx；(iii) Edge TTS 在配音上已补齐差距，声音质量不再是瓶颈。

3.2 Agent 架构：技能契约 + 确定性原语 + 计量填充循环

3.3 Paper2Assets：唯一所有权的抽取

读一次 PDF，产出下游逐字消费的单一 bundle：保留分页的正文、检测到的图注、per-figure manifest、清洗后的图、元数据、九段结构化摘要（Problem / Motivation / Contribution / Method / Dataset-Benchmark / Key Result / Ablation / Headline Numbers / Takeaway，每段含 essential 条目 + 备用条目 + 口播脚本）、best-effort 机构 logo 与二维码。第二遍追加 inventory manifest（源 PDF 校验和、按 section 拆分带稳定 id 的记录、阅读序口播剪辑表），使非 poster 生成器永不再解析。

最耗时也最承重的是图片清洗链（只跑一次而非每个生成器重做）：确定性前缀剥离 chrome 残留、baked-in 图注条、均匀白边；随后视觉 AI 判定紧包围盒，新上下文子代理校验器独立重读原图对照提议裁剪，仅干净通过才提交，并在一张栅格图里塞了两张独立图时拆分。所有模式幂等、裁剪前原始备份一次。bundle 是 Paper2Assets 与系统其余部分的唯一接口——下游只读它、永不重开 PDF，靠稳定 figure 命名不变式让三产物事实一致而无需跨技能协调。

3.4 Paper2Poster：组合优于模板 + 分级填充循环

针对五个反复出现的需求（A1–A5），逐一给出工程化解：

需求解法
A1 无模板爆炸的组合构建期沿四正交轴组装：列布局（full/half/三列）、视觉风格（一族可互换 CSS 主题）、标题栏头部（5 种 logo/QR 排布）、底部 Scan-to-Read 块；仅布局由硬规则定（Method 图形状决定宽/全列 vs 半宽默认），其余可复现采样
A2 收敛的填充循环分级测量填充循环：每 pass 渲染并对每 section 算 fullRatio，量化成五档判定，判定独选修复动作
A3 大到无法重读的页面循环从不把整张 poster 拉进上下文；每次测量只回传偏离目标 section 的逐字源码，agent 就地改片段；文件间接生成、从不经输出通道打印，避免触发 compaction / 撑爆 per-turn token
A4 让图填满卡片图列高度不随文字响应，故通过高度上限而非周围 prose 调图；硬地板门保证文字编辑永不让图沦为一枚小邮票
A5 可编辑导出不栅格化后逆推形状，而是直接从实时 DOM 逐节点重建 PowerPoint：读 getBoundingClientRect 几何 + getComputedStyle 外观，CSS 像素按固定 canvas 比例转 EMU；文本容器→可编辑文本框、列表→原生悬挂缩进、img→可替换图、MathJax→原生 OMML 公式、装饰 div→圆角矩形

填充率量化与判定带

每个 section 被赋予标量填充率：

$$\mathrm{fullRatio} = \frac{h_{\mathrm{content}}}{h_{\mathrm{card}}} = \frac{\text{该 section 最低渲染元素底边（getBoundingClientRect）}}{\text{其卡片内高度}}$$

该比率被量化为五档分类判定，判定本身独选修复动作：

档位区间含义修复动作
EMPTYfullRatio < 0.70承重性欠填追加备用补充段 / 把可选 section 提升进列
SPARSE0.70 – 0.90可见欠填polish up：扩写 prose 或放大 widget 至触底
FULL0.90 – 1.00目标带不动
SPILLAGE1.00 – 1.10刚越卡片边polish down：收紧 prose 回到带内
OVERFLOW> 1.10明显越边删备用段或整个可选 section

Method 图同 pass 下走单独的图填充门，要求其至少在一个轴上涂满卡片 70%。循环终止条件是分类不动点（所有 section FULL 且无图触门）而非学习分平台。三类机制抑制 FULL 窄带内的振荡：每个动作按测量报告的有符号像素差定步长而非瞎猜；循环拒绝重施一个已在某 section 上越带的动作；盘上轮次计数器触发断路器，交付最佳测量态而非无限磨。

松门 + 渲染期 expand：填充门故意松到 90%（而非 98%），因为最后几个百分点正是离散编辑循环振荡处——把门收到 98% 会显著增加轮次，过 0.94 尤甚而视觉收益甚微。为无成本找回那几个百分点，单一渲染期 pass 把每个欠填卡片向 98% 拉伸（仅增长行间空白）。该 expand 构造上安全：图绝不缩放、任何会顶高固定 canvas 的卡片增长被回退，故无列底移动；且只烤进 poster 一次，使网页/PDF/PNG/PPTX 显示同一填充布局。

Algorithm 1: Paper2Poster 分级填充循环（measured-fill loop）

Input: bundle（Paper2Assets 产物）；目标带 [0.90, 1.00]；图地板 0.70；轮次上限 ~12

Output: 收敛的 poster.html + PDF + PNG + 可编辑 .pptx

// 1. 组合草稿

draft ← compose(bundle, layout_axis, style_axis, header_axis, scan_axis) // 仅 Method + ≥1 关键结果图

for round in 1..12:

page ← render_headless(draft)

for section in sections:

fullRatio ← getBoundingClientRect(section).bottom / card_inner_height(section)

verdict ← quantize(fullRatio) // EMPTY/SPARSE/FULL/SPILLAGE/OVERFLOW

offenders ← sections where verdict ≠ FULL

if offenders = ∅ and all figs ≥ 0.70 on one axis: break

// 2. 每轮只改一个偏离 section，步长按有符号像素差

apply_move(pick_one(offenders), verdict, signed_pixel_delta)

if not converged: circuit_breaker(ship_best_measured_state)

// 3. 渲染期 expand（仅行间空白，不动图，回退顶高）

render_time_expand(page, target=0.98)

assert deliverables_gate(canvas, fig_floor, RRP, PDF_match) // 硬门

return release_bundle(html, pdf, png, pptx)

3.5 Paper2Video：对齐保持的媒体契约

复用完整 ppt-master 工作流做 deck 创作（视为依赖而非独立声明）。技能角色是把 deck + 共享资产转成可审计媒体 bundle。五个媒体级需求（B1–B5）与解法：

需求解法
B1 渲染前先规划时长TTS 前估计脚本，过长/过短请求语义改写；渲染后 duration report 对比；小残差由有界语速计划修，大错回到改写——目标时长靠内容规划而非裁 MP4
B2 注意力引导把脚本转 visual-cue 需求；deck 工作流给 narration 命名对象附语义锚（图面板/公式块/表格行/method 卡）；cue resolver 合并脚本、word_timings、slide 几何、锚点产 visual_cues.json；默认 spotlight_laser 风格
B3 双字幕语境每 section 合成一段旁白 + 同 timing 模型写字幕 sidecar；先渲 video_no_subtitles.mp4，再烧字幕成 video.mp4；两者共享 slide 帧/音频对齐/高亮 timing，唯一差别是是否烧字幕
B4 导出后仍可寻址写 timeline.json 作为下游导航的规范 sidecar：每条映射一个 section/旁白块到其音频窗、字幕 cue、slide 帧、已接受 visual cue；Paper2Reel 直读它而非扒 MP4
B5 确定性媒体检查check_video_package.py 硬门：三文件存在/可放/有音轨/时长在容差；字幕 sidecar 非空、最终 MP4 非字节同于原始；cue 覆盖/归一化几何/语义 id/timing/拒词级高亮框；解析 PPTX+帧抓空帧/溢出/重叠/缩过头/裁切；时长控制须有 TTS rate plan 且拒不安全变速

3.6 Paper2Blog：单一证据底 + 双语编辑包

产出两份 root 交付：中文（微信公众号体）+ 英文（研究博客体），共享同一事实/图/数字/claim/源链，但读法不同。五个需求（C1–C5）：

需求解法
C1 一证据底供两语先从 bundle 建一份 evidence map（hook/problem/method 组件/main claims/定量结果/局限/源链/图角色）；两份草稿都读它；硬事实缺失则省略而非瞎猜
C2 写作时控语域两文分别写而非逐句翻译；draft 前读语言特定编辑风格指南；中文→克制公众号体（保留并解释必要英文术语），英文→中性研究博客体
C3 文章级图选择与置位只选有助解释的图，同一选中集用于两语，每图置于为其铺垫的 section 旁；非二次抽取，而是 selected-figure review：检查 DOCX 缩放后可读、caption 不打架、置位无明显失衡
C4 交付是 Word 而非纯文本固定文件名、嵌入媒体、对应语 caption、源链、编辑友好字体；固定 root 名是契约一部分，下游 upload/zip/CMS/Paper2Reel 无需解析论文标题或非 ASCII 文件名
C5 Word 排版编辑就绪把 DOCX 当渲染视觉产物检查：图 fit/分页/orphan tail 从内部结构读，严格模式渲染成页图检查近空页/稀疏页/非末页大底白

双语门聚焦可确定性检验的事实：比对嵌入图数量/身份顺序、outline 记录的图、抽取的数字 claim、技术术语——旨在抓"两篇母语文章分叉"的具体失败（如某图只出现在一语版本）。

3.7 Paper2Reel：交互式收敛层

不替代三个生成器，而是读其完成的 v2 交付，在其外构建自包含交互查看器。核心是 alignment sidecar：每个规范 section id 映射到对应 poster 块、≥1 slide 目标、视频起止时间、字幕轨、slide 缩略图、blog 块——查看器读它而非猜文件名/扒 poster/推断时间。设计上 poster-first（首屏是 poster，最紧凑的论文地图）；section 模态是主阅读单元，左侧视频（用无字幕源播放 + sidecar 字幕切换）右侧 blog（可中英切换），可拖拽分割条；slide 缩略图点击 seek。若在 PDF/arXiv link/部分 v2 bundle 上调用，会先检测缺哪些上游交付并跑完整工作流补齐，保持全包同 section id 与资产路径。

4. 实验结果与分析

4.1 实验设置

在 Paper2Poster 100 篇基准上，每篇从 PDF 端到端生成 poster，用两个 held-out VLM 评委（claude-opus-4.8、gpt-5.5）打分，复用 Paper2Poster 自带六准则美学/信息 rubric 与 PaperQuiz 阅读理解探针；每张 poster 缩到 ≤2560 px。对比三类系统：(1) 单次前沿 LLM（Claude-4.8 Opus、GPT-5.5、Gemini-3.1 Pro，固定 prompt 一次出整张 A0 poster）；(2) Poster Pipeline（先验 Paper2Poster Tool、P2P、PosterGen，及本文在 Claude Code / Codex 两种 harness 下跑同一技能）；(3) 作者真值 poster 作为人类参考。Aesthetic 与 Information 是其三个子准则在 1–5 尺度上的均值；PaperQuiz 是固定题集 exact-match 准确率。

4.4 PaperQuiz 与美学的张力

PaperQuiz 排序几乎与美学排序相反：PaperQuiz 奖励 poster 复现论文文本（密度越高越易答题），美学准则奖励选择性、可读性布局。P2P 凭全高纵向 canvas 塞近逐字论文，Quiz Detail 夺冠（75.40%）但美学垫底；Paper2Poster Tool 直接用基准自身的问答抽取组装内容，Quiz Understanding 拔得 95.65%；作者真值恰好相反——人手剪到几条头条结果，美学好但牺牲了理解探针奖励的细节，故真值在两个 Quiz 分项上均垫底。ResearchStudio-Reel 刻意居于两极之间：填充循环把每列填到目标密度而非穷尽，故 Quiz 仍有竞争力，同时结构化布局与图置位赢得每个美学子准则。

5. 消融实验与关键发现

5.1 技能机制 vs 模型（模型固定）

Table 1 自带两处消融：(i) 技能机制、模型固定。claude-opus-4.8 单次 prompt 出整张 poster 得美学均值 2.76、Layout 2.83；同一模型包进组合步骤 + 计量填充循环（Claude Code 设置）得美学 3.52、Layout 3.97——美学 +0.76、Layout 涨逾 1 分，可归因于循环与组合而非更强生成器。同一替换在 gpt-5.5 下把美学从 3.03 提到 3.36、Layout 从 3.22 提到 3.82，说明机制对任意基座模型都有效。

5.2 Harness 与模型（技能固定）

(ii) harness 与模型、技能固定。把 Claude Code+claude-opus-4.8 换成 Codex+gpt-5.5，质量保留大半（美学 3.36 vs 3.52），且两种设置仍领先所有先验 poster 流水线与所有单次基线——说明结果是技能的属性而非某个专有模型或 agent 运行时的属性。Codex 单元格当前在基准子集上评分，将刷新到全集；排序已稳定。Figure 10 定性印证：同一技能在 6 种生成器设置（真值 + 五种模型/reasoning 设置）下都收敛到满版可读单页，差别仅在图选、措辞密度与配色而非结构稳健性。

5.3 关键发现汇总

  • 架构 > 单产物：把"最后一公里"当组合问题，质量来自技能契约 + 填充循环 + 硬门，而非更强单次 LLM。
  • 硬分类门 > 软偏好分：终止条件是 fullRatio 分类不动点，可诊断（每轮记哪个动作施于哪个 section），失败可定位而非"agent 干了啥"之谜。
  • 松门 + 渲染期 expand：90% 门收敛快、98% 门轮次暴涨而视觉收益甚微；用渲染期空白拉伸找回剩余百分点，安全且只烤一次。
  • 共享抽取免协调一致：稳定 figure 命名不变式让 poster/video/blog 自动交叉引用，错裁只在源修一次即传播到三产物。
  • 原生可编辑是契约：从实时 DOM 重建 PowerPoint（含原生 OMML 公式），改字/换图/改色无需重跑循环。
  • Quiz 与美学真张力：系统刻意居中——目标密度而非穷尽，既保 Quiz 竞争力又赢所有美学子准则。
  • 缺口是生成性而非架构性：管线只用论文已有图，能匹配布局却画不出人手添加的 bespoke 方法/总览图；补这一缺口会引入分类门本欲压制的幻觉风险。

6. 总结与启发

研究传播的最后一公里最好被建成一小撮技能的组合：薄薄的、agent 可读的契约共享一个上游抽取器，以分类填充判定而非软偏好分作为出口门。ResearchStudio-Reel 用一个 Paper2Assets bundle + 三个可编辑生成器 + Paper2Reel 查看器实例化该模式，在一个 Claude Code / Codex 会话内把一篇 PDF 变成可印 poster、同步 talk-video 包与双语 Word 博客。在 100 篇基准上 poster 领先所有美学/信息子准则（美学 3.52 vs 真值 2.94），84%–93% 论文赢总分；能力审计显示无先验系统能从一次运行交付全部三种可编辑传播产物。

对本人的启发：

  • 当多产物系统各自重做同一上游工作（抽取/清洗）时，把它折进一个共享所有者是低门槛高收益的架构动作——既省成本又免费换来跨产物一致性。
  • "软分平台化"是 agent 评估的通病；换成分类判定 + 硬渲染门能把"看起来还行"升级为"可诊断地收敛"，这对任何生成-评审闭环都适用。
  • 把页面当 DOM 而非像素来桥接 HTML→原生 Office：几何与语义从 DOM 读，使导出可编辑且公式保持可选——这比 PDF→PPT 像素逆推鲁棒得多。
  • "松门 + 渲染期补全"是离散优化循环的实用抗振荡技巧：把门留在振荡带外、用确定性后处理找回百分点。
  • 评测设计要诚实：本文明确承认 PaperQuiz 与美学互拉、承认管线无法画 bespoke 图，并把 video/blog 的量化评测留给未来——这种"代理绑定的局限"自述比单纯刷分更有可信度。
