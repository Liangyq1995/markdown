UI-MOPD：面向持续 GUI Agent 学习的多平台 On-Policy 蒸馏

Multi-Platform On-Policy Distillation for Continual GUI Agent Learning · Niu Lian, Alan Chen, Zhehao Yu, Chengzhen Duan, Fazhan Liu, Hui Liu, Pei Fu, Jian Luan, Yaowei Wang, Shu-Tao Xia, Jinpeng Wang · 清华大学 / 小米 / 哈工大(深圳) / 浙江大学 / 鹏城实验室

标题UI-MOPD: Multi-Platform On-Policy Distillation for Continual GUI Agent Learning
核心问题如何让一个共享 GUI Agent 在持续学习跨桌面/移动等异构平台时，既能适应新平台、又不破坏各平台特有的交互行为约定（避免行为混淆与灾难性遗忘）
关键思路为每个平台训练专用教师，在学生 on-policy rollout 上按平台路由选择对应教师做 reverse-KL on-policy 蒸馏，把平台特有行为先验作为“行为锚点”注入共享策略
主要贡献(1) 构建 Uni-GUI 跨平台高质量数据集（约 11.5K 轨迹 / 160K 步）；(2) 首次将多教师 on-policy 蒸馏 (MOPD) 引入 GUI Agent 持续学习；(3) 提出平台条件化教师路由框架
核心结果OSWorld 38.2%、MobileWorld 12.0%，相对基座分别提升 12.7% 与 55.8%
基座模型学生：Qwen3-VL-8B-Thinking；教师：Qwen3-VL-32B-Thinking
开源地址论文标注 GitHub / Hugging Face / Homepage（链接见原文 § 标识）

1. 概述

随着多模态基础模型与 Agent 系统的发展，GUI Agent 正从“单平台任务执行”走向“跨平台交互”。真实工作流往往横跨桌面应用、移动 App 与 Web 服务，因此一个能干的 GUI Agent 必须在异构 GUI 环境间持续适应，同时保留每个平台各自的交互约定。

论文指出当前跨平台 GUI 学习存在两大瓶颈：

  • 高质量跨平台轨迹稀缺：现有数据集多聚焦单平台，存在无效动作、状态-动作对齐不准、任务粒度不一致等问题。
  • 平台行为语义差异：桌面与移动平台在动作语义与 affordance 上差异显著（例如“返回上一级”在桌面是关闭窗口，在移动端是按返回键），简单混合训练会产生过度平均的策略，并在持续学习中引发灾难性遗忘。

为此，作者先构建统一跨平台数据采集工具与 Uni-GUI 数据集，再提出 UI-MOPD——首个把多教师 on-policy 蒸馏 (MOPD) 引入 GUI Agent 持续学习的方法。其核心是：学生在线采样 rollout，按当前环境动态选择平台专用教师，通过平台条件化蒸馏把平台特有行为分布迁移到共享策略，从而在适应新平台的同时保留既有平台能力。

一句话总结：UI-MOPD 把 MOPD 从通用基础模型后训练迁移到 GUI Agent 场景，用“平台条件化教师路由 + on-policy reverse-KL”取代简单的 mixed-SFT / model merging，让单一 8B 学生同时吃下桌面与移动两套行为先验。

2. 研究背景与动机

2.1 两大瓶颈与三种朴素方案的失效

论文用 Figure 1 直观对比了三种整合桌面/移动信号的思路，前两种都会“塌缩”出平均策略，只有 MOPD 能保留平台行为约定：

方案整合方式问题
(a) Model Merge参数空间平均（weight averaging / TIES）桌面/移动动作在参数空间冲突，得到平均化策略
(b) Mixed SFT动作空间混合监督微调异构动作语义被混合，行为约定坍塌（Action Convention Collapse）
(c) MOPD (Ours)平台路由 + 多教师 on-policy 蒸馏各平台教师提供独立“行为锚点”，避免混淆

2.2 相关工作谱系

GUI Agent 从单平台到多平台。早期研究聚焦单平台：Web 环境（WebArena / VisualWebArena）、移动环境（AndroidWorld、MobileWorld、UI-R1、ClawGUI）、桌面环境（OSWorld、WindowsAgentArena、ComputerRL、EvoCUA）。近期的通用型 GUI Agent（MobileAgent-v3.5、UI-Venus-1.5、UI-TARS-2）尝试跨平台统一建模。UI-MOPD 的差异点在于聚焦持续学习，强调端到端长程导航同时保留/迁移各平台交互能力。

多教师 On-Policy 蒸馏 (MOPD)。后训练中不同能力常呈“跷跷板效应”。On-policy distillation (OPD) 从学生采样轨迹、用 reverse-KL 匹配教师分布，提供稠密 token 级监督；MOPD 进一步为每个能力维度选最强 checkpoint 作为教师，让学生在一个蒸馏阶段吸收多种能力。近期工作：MiMo-V2-Flash 与 GLM-5 用 MOPD 作最终后训练步、Nemotron-Cascade 2 用作专门 RL 阶段间的遗忘恢复、DeepSeek-V4 进一步用全词表 logits 与十余个教师。但 MOPD 在 GUI Agent 领域几乎未被探索，UI-MOPD 是首个将其引入 GUI Agent 并提出平台条件化蒸馏框架的工作。

2.3 与标准 RLHF 中 KL 项的本质区别

这是理解 UI-MOPD 的关键洞见：标准 RLHF 把 KL 当作保守正则项限制策略漂移；而 UI-MOPD 把 KL 升级为定向迁移机制——把平台专家交互行为迁移到共享学生。由于教师监督施加在“学生当前真正决策的状态分布”上，蒸馏信号与学生当前误差更匹配，使共享策略在通过 RL 提升任务成功率的同时保留桌面/移动的行为锚点。

3. 核心方法

3.1 方法总览：两阶段训练流程

UI-MOPD 训练一个能同时适应桌面与移动两类异构环境的统一原生 GUI Agent，包含两个阶段：

  • Stage 1（SFT 得教师）：在视觉-语言基座上对各平台高质量轨迹做 SFT，得到两个专家教师——桌面教师 $\pi_\mathrm{ref}^{d}$ 与移动教师 $\pi_\mathrm{ref}^{m}$（均初始化自 Qwen3-VL-32B-Thinking，在 Uni-GUI 上 SFT）。
  • Stage 2（MOPD 训学生）：用多教师 on-policy 蒸馏把两套专有能力整合进统一学生 $\pi_\theta$（初始化自 Qwen3-VL-8B-Thinking），学生在线采样 rollout，平台条件化路由选对应教师提供 reverse-KL 指导，并叠加规则化 rollout 奖励。

3.2 多教师 On-Policy 蒸馏（MOPD）算法推导

核心原则

把多教师知识整合建模为在线策略优化中的条件行为约束。不同于直接合并多个专家模型或从静态离线轨迹蒸馏，UI-MOPD 让学生 $\pi_\theta$ 在线采样 rollout，仅在学生实际访问的状态上施加教师监督。这样蒸馏信号集中在学生当前真正决策的状态分布上，而非要求学生模仿教师所有行为模式。

教师监督以平台条件化方式施加：不同平台的 rollout 对齐到对应平台教师。教师信号不简单聚合成单个 KL 罚，而是按 rollout 所属平台提供行为约束。

On-policy KL（公式 1-2）

对第 $i$ 条采样响应 $y^{(i)}=(y_1,\dots,y_T)$，设 $h_t^{(i)}=(x^{(i)}, y_{\lt t}^{(i)})$ 为 token $t$ 处的解码状态，$\pi_\mathrm{ref}^{(i)}$ 为路由到的平台教师。学生到教师的 on-policy KL 为：

$$D_\mathrm{KL}^{(t,i)} = D_\mathrm{KL}\!\left(\pi_\theta(\cdot\mid h_t^{(i)})\;\|\;\pi_\mathrm{ref}^{(i)}(\cdot\mid h_t^{(i)})\right). \tag{1}$$

等价地，按学生分布期望展开（这正是 on-policy 的体现——在 $\pi_\theta$ 自身采样上取期望）：

$$D_\mathrm{KL}^{(t,i)} = \mathbb{E}_{a\sim\pi_\theta(\cdot\mid h_t^{(i)})}\!\left[\log\pi_\theta(a\mid h_t^{(i)}) - \log\pi_\mathrm{ref}^{(i)}(a\mid h_t^{(i)})\right]. \tag{2}$$

Mini-batch MOPD 损失（公式 3）

$$\mathcal{L}_\mathrm{MOPD}(\theta) = \frac{\sum_{i\in B}\sum_t m_t^{(i)}\,\mu^{(i)}\,\hat{D}_\mathrm{KL}^{(t,i)}}{\sum_{i\in B}\sum_t m_t^{(i)}}, \tag{3}$$

其中 $m_t^{(i)}$ 把 prompt 与 padding token 掩掉，$\mu^{(i)}$ 是自适应 KL 掩码，$\hat{D}_\mathrm{KL}^{(t,i)}$ 是 token 级 KL 估计。

K3 估计器（公式 4-5）

在全词表上算完整 KL 开销过大，故采用 K3 估计器，只需学生与教师对采样 token 的对数概率。定义：

$$\delta_t^{(i)} = \log\pi_\mathrm{ref}^{(i)}(y_t\mid h_t^{(i)}) - \log\pi_\theta(y_t\mid h_t^{(i)}), \tag{4}$$

$$\rho_t^{(i)} = \exp(\delta_t^{(i)}), \tag{5a}$$

$$\hat{D}_\mathrm{KL}^{(t,i)} = \rho_t^{(i)} - \delta_t^{(i)} - 1. \tag{5b}$$

该估计量非负、在 $\pi_\theta$ 采样下对 $D_\mathrm{KL}(\pi_\theta\|\pi_\mathrm{ref})$ 无偏，且经验上方差低于直接 log-ratio 估计器。实现中对 $\delta_t^{(i)}$ 做 clamp 以保证数值稳定。

自适应 KL 掩码（公式 6）

教师约束在任务反馈仍弱时最有用；若某 prompt 组已获充分奖励，过强 KL 正则会不必要地限制探索。于是用组级掩码：

$$\mu^{(i)} = \begin{cases}0, & \text{if } \frac{1}{|g^{(i)}|}\sum_{k\in g^{(i)}} R^{(k)} \gt \tau_\mathrm{KL},\\ 1, & \text{otherwise.}\end{cases} \tag{6}$$

其中 $g^{(i)}$ 为样本 $i$ 的 prompt 组。该掩码在任务反馈已足以改进策略时移除教师罚，在低奖励 rollout 上保留教师指导。

3.3 平台条件化教师路由（公式 7）

跨平台 GUI 交互不仅在视觉布局上不同，在动作语义、affordance 结构、执行上下文上也不同：桌面任务常用鼠标、键盘快捷键、滚动、窗口切换；移动任务依赖 tap、swipe、长按、App 导航。单个教师或直接混合教师 logits 会把异构行为压成平均分布，削弱平台交互先验。

UI-MOPD 改为训练独立的专家教师，并按 rollout 的平台标签路由：

$$\pi_\mathrm{ref}^{(i)} = \begin{cases}\pi_\mathrm{ref}^{m}, & s_i \in S_\mathrm{mobile},\\ \pi_\mathrm{ref}^{d}, & s_i \in S_\mathrm{desktop},\end{cases} \tag{7}$$

其中 $s_i$ 是数据构建时记录的来源标签。该路由只影响教师对数概率计算，学生始终是单一共享策略——推理时不引入多 Agent 或额外教师模型。

每次 RL 更新中：学生先从混合平台 prompt 采样 rollout；mini-batch 按平台划分，各子集由对应教师评估；教师对数概率按原 batch 顺序合并回；K3 估计器（公式 5）为公式 3 提供 token 级蒸馏信号。这给每个平台在共享参数空间中一个独立行为锚点：RL 把策略推向更高任务奖励，路由教师约束该移动以免原生交互模式被另一平台信号覆盖。

3.4 结构化奖励设计（公式 8）

对 GUI 动作用结构化结果奖励。策略在 tool-call 格式内输出 action JSON（含动作类型、坐标、文本等）。对每个动作类型定义一组必需维度（动作类型正确性、坐标落入目标 bbox、滚动方向、按键集合相等、大小写不敏感文本匹配等）。设 $f_a\in[0,1]$ 为动作 $a$ 的匹配维度占比：

$$R(x,y) = \begin{cases}1.0, & f_a = 1,\\ -0.5, & 0 \le f_a \lt 1,\\ -1.0, & \text{unparsable or invalid action.}\end{cases} \tag{8}$$

中间罚 $-0.5$ 把“部分合法但错误”的动作与无效输出区分开，为策略优化中的 group-relative 优势估计保留有用的奖励间距。

3.5 训练目标（公式 9-12）

token 级优势（group-relative）：

$$A_t^{(i)} = R(x^{(i)},y^{(i)}) - \frac{1}{|g^{(i)}|}\sum_{k\in g^{(i)}} R(x^{(k)},y^{(k)}). \tag{9}$$

策略比率：

$$r_t(\theta) = \frac{\pi_\theta(y_t\mid h_t)}{\pi_{\theta_\mathrm{old}}(y_t\mid h_t)}. \tag{10}$$

对平台 $p$ 的 rollout，最大化正则化目标（非对称 clip 的 DAPO 风格策略损失 + 平台条件化 MOPD 罚）：

$$J(\theta) = \mathbb{E}_{p,x,y\sim\pi_\theta}\!\left[\sum_t m_t\,\ell_\mathrm{PG}^{(t)}(\theta) - \beta\,\mu\,\hat{D}_\mathrm{KL}^{(t,p)}\right], \tag{11}$$

$$\ell_\mathrm{PG}^{(t)}(\theta) = \min\!\left(r_t(\theta)A_t,\;\mathrm{clip}(r_t(\theta),\,1-\epsilon_\mathrm{low},\,1+\epsilon_\mathrm{high})\,A_t\right).$$

其中 $\hat{D}_\mathrm{KL}^{(t,p)}$ 由公式 7 选定的教师计算，$m_t$ 掩 response token，$\mu$ 为自适应 KL 掩码，$\beta$ 控制蒸馏强度（论文取 $\beta=0.01$）。等价地最小化：

$$\mathcal{L}(\theta) = -J(\theta) = \mathcal{L}_\mathrm{PG}(\theta) + \beta\,\mathcal{L}_\mathrm{MOPD}(\theta). \tag{12}$$

该目标通过在线 RL 提升长程任务完成度，同时通过路由教师监督保留平台特有行为锚点。

桌面轨迹使用 computer_use 工具接口（鼠标 + 键盘动作），移动轨迹使用 mobile_use 接口（触屏动作）。后处理时不同数据源动作被转换到这些平台特有 tool-call 格式。两套动作空间见表（对应原文 Table 5）：

视觉输入：训练只用当前截图；推理用 4 张历史截图 + 当前截图 + 完整文本动作历史。桌面图分辨率 1920×1080，移动 1080×2400。

3.8 数据策略：Uni-GUI 与统一采集工具

作者构建统一跨平台数据采集 harness（查询生成 → 轨迹采集 → 轨迹清洗 → 后处理四阶段）。桌面查询用 Kimi-K2.6 生成、移动查询用 Gemini-3.1-Pro 生成；从环境可执行功能点合成自然且可执行的用户查询。轨迹采集后做多阶段清洗：去除步骤结构异常、动作无法映射到学生动作空间、超过 40 步的过长轨迹、查询与环境不一致的轨迹；最后用 Gemini-3.1-Pro 作自动裁判，按子任务级判定整条轨迹是否完成（避免单次长上下文判定的噪声）。

4. 实验结果与分析

  • 评测基准：OSWorld（桌面，361 任务）、MobileWorld（移动，117 任务）；静态 GUI 能力用 AndroidControl⋆（4260 步级记录 / 781 条 Android 轨迹的评测子集）；GUI grounding 用 ScreenSpot-Pro、ScreenSpotV2、OSWorld-G。主指标为任务成功率。

5.2 关于“行为锚点”机制的作用讨论

论文未给出逐组件消融表（如去掉自适应 KL 掩码、去掉路由、换不同 β），但从 Table 2 的教师-学生对比可侧面验证“平台条件化行为锚点”的作用：32B 桌面教师单独达 46.3%、移动教师单独达 16.2%，而 UI-MOPD 把部分平台知识迁移进 8B 学生后达到 38.2%/12.0%——说明蒸馏确实把教师的部分行为先验压缩进了共享参数，而非在推理时依赖多教师。自适应 KL 掩码（公式 6）在“任务反馈已充分”时关闭教师罚以鼓励探索，是平衡蒸馏约束与 RL 探索的关键设计。

说明：原文未提供逐超参/逐组件的独立消融实验表（如 β 扫描、τ_KL 扫描、路由 ablation、有无 K3 估计器的对比），相关结论由主表与教师-学生分析间接支撑。

6. 总结与启发

6.1 工作总结

UI-MOPD 针对跨平台（桌面/移动）GUI Agent 持续学习中的行为模式混淆、平台能力退化、灾难性遗忘三大问题，给出了一套数据 + 方法协同的方案：统一跨平台采集 harness 与 Uni-GUI 数据集提供高质量轨迹基础；多教师 on-policy 蒸馏 + 平台条件化路由把平台特有行为作为“行为锚点”注入共享学生。在 OSWorld/MobileWorld 上达到 38.2%/12.0%，相对基座提升 12.7%/55.8%，并在 grounding/静态理解上基本无损。

6.2 核心启发与读后评注

  • KL 项的角色重定义：把 RLHF 中“保守漂移正则”升级为“定向能力迁移机制”，是把 MOPD 思想落到 Agent 场景的关键。这对所有“多专长合并进单策略”的后训练任务都有借鉴价值。
  • 平台条件化 ≠ 多 Agent：路由只决定用哪个教师算 log-prob，学生始终单一——这保证了推理时零额外开销，是一个工程上优雅的折中。
  • on-policy 是降低蒸馏噪声的关键：仅在学生当前访问的状态上施加教师监督，使蒸馏信号匹配学生当前误差，避免“要求学生模仿教师全部行为模式”带来的过约束。这与离线轨迹蒸馏形成对比。
  • K3 估计器 + 自适应掩码的工程组合：K3 只需采样 token 的师生对数概率，避免全词表 KL；自适应掩码在高奖励组关闭 KL 以鼓励探索。两者共同降低 on-policy 蒸馏的计算与稳定性代价。
  • “行为锚点”可作为持续学习的通用范式：未来若有第 3、第 4 个平台，只需训练对应教师并扩展路由表，理论上可增量扩展而不重训——这正是 continual learning 所需的可扩展性。

6.3 局限性

  • 实验仅覆盖桌面 + 移动两类平台，未验证 Web/平板/多语言等更多平台下的可扩展性。
  • 未提供逐组件/超参的独立消融（β、τ_KL、路由、K3、自适应掩码），机制归因主要靠主表与教师-学生对比间接支撑。
  • 移动端绝对成功率仍较低（12.0%），距离实用仍有差距；MobileWorld 任务数仅 117，方差可能较大。
  • 教师依赖更大模型 (32B) 与外部强模型（Kimi-K2.6 / Gemini-3.1-Pro）采集轨迹，数据构建成本较高。
