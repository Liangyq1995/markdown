标题AutoSearch: Adaptive Search Depth for Efficient Agentic RAG via Reinforcement Learning
机构中科院自动化所 SKL-MAIS / 中国科学院大学 / 美团（Jingbo Sun, Wenyue Chong, Qichao Zhang, Dongbin Zhao 等）
核心问题Agentic RAG 系统的多步检索存在大量冗余搜索，如何让 Agent 根据问题复杂度和自身能力自适应决定最小充分搜索深度？
代码github.com/bofusun/AutoSearch
关键结果6 个 QA 基准上同时提升 EM 准确率与搜索效率，Over-Searching Ratio 降至接近 0%

1. 核心问题与动机

1.1 Agentic RAG 的过搜索困境

flowchart TD
    PROB["Agentic RAG 的效率瓶颈"]
    P1["搜索步骤过多（Over-Searching）\n简单单跳问题也执行多次检索\n产生大量冗余计算与延迟"]
    P2["现有缓解方案的副作用\n固定步数上限 → 复杂问题探索不足\n惩罚搜索深度 → 牺牲复杂问题的准确率"]
    P3["根本原因\n忽视了最优搜索深度由问题复杂度\n和 Agent 能力共同决定这一事实"]
    PROB --> P1 & P2 --> P3
    P3 --> SOL["AutoSearch\n自适应识别最小充分搜索深度\n准确率与效率同时优化"]
核心研究问题：Agent 能否在保持答案准确率的同时，自适应调整到最小充分搜索步数？论文通过实验证明，这个最优深度由问题复杂度（单跳 vs 多跳）和 Agent 能力（3B/7B/14B）共同决定，不是固定值。

1.2 搜索深度的实验分析

论文首先在 Qwen2.5-14B-Instruct 上固定搜索步数，测量 EM 和过搜索率：

维度数据集/模型观察结果最优搜索深度
问题复杂度NQ（单跳）搜索 1 步接近最优 EM，更多步骤几乎无收益≈ 1
Bamboogle（多跳）搜索 3 步才达到峰值，超过后性能下降≈ 3
Agent 能力
（Bamboogle）		Qwen-3B随步数持续提升，在测试范围内未达到峰值= 最大步数
Qwen-7B第 2 步达到峰值，之后下降≈ 2
Qwen-14B第 3 步达到峰值，更强模型过搜索退化更明显≈ 3

核心结论：最小充分搜索深度 $t_c$ 由问题复杂度（数据集难度）和Agent 能力（模型规模）共同决定。

3. AutoSearch 方法

3.1 整体框架

flowchart TD
    Q["问题 q_i"] --> LOOP
    subgraph LOOP["多步检索 + 自答循环"]
        SEARCH["Step t：生成搜索查询\n调用检索引擎获取文档"]
        INTER["生成中间答案\n基于累积轨迹自评估"]
        JUDGE{"中间答案 EM = 1\n且达到最优深度 tc?"}

        STOP["停止搜索\n输出最终答案"]
        SEARCH --> INTER --> JUDGE
        JUDGE -->|否，继续| OVER --> SEARCH
        JUDGE -->|是| STOP
    end
    STOP --> REWARD["三类奖励信号\n基础奖励 + 搜索效率奖励 + 搜索质量奖励"]
    REWARD --> PPO["PPO 策略更新"]

3.2 中间答案生成与能力感知最优深度

每次检索后，Agent 基于累积轨迹 $x_{i,t}$ 生成中间答案：

$$x_{i,t} = \{q_i,\, s_{i,0},\, o_{i,0},\, \ldots,\, s_{i,t},\, o_{i,t}\}$$ $$a^{\mathrm{inter}}_{i,t} = \pi_\theta(x_{i,t})$$

能力感知最优深度 $t_c$（Capability-aware Optimal Search Depth）：

$$t_c = \min\bigl\{t \mid \mathrm{EM}(a^{\mathrm{inter}}_{i,t},\; a^{\mathrm{gold}}_i) = 1\bigr\}$$

若 Agent 始终无法正确回答，则 $t_c = -1$（欠搜索）。

3.3 三类奖励设计（完整公式）

① 基础奖励（Base Reward）

格式奖励（逐步评估，鼓励结构化行动）：

$$r^{\mathrm{format}}_{i,t} = \begin{cases} 0 & \mathrm{valid}_{i,t}=1,\; t \lt T \\ -0.05 & \mathrm{valid}_{i,t}=0,\; t \lt T \\ +0.1 & \mathrm{valid}_{i,t}=1,\; t = T \\ -0.5 & \mathrm{valid}_{i,t}=0,\; t = T \end{cases}$$

结果奖励（仅终止步）：

$$r^{\mathrm{result}}_{i,t} = \begin{cases} \mathrm{EM}(a^{\mathrm{pred}}_i,\; a^{\mathrm{gold}}_i) & t = T \\ 0 & t \lt T \end{cases}$$
$$r^{\mathrm{base}}_{i,t} = r^{\mathrm{format}}_{i,t} + r^{\mathrm{result}}_{i,t}$$

② 搜索效率奖励（Search Efficiency Reward）

将每步分为三类，差异化奖励：

$$r^{\mathrm{efficient}}_{i,t} = \begin{cases} +0.025 & t_c \lt 0 \quad \text{（欠搜索，鼓励继续）} \\[4pt] \dfrac{0.4}{t_c + \epsilon} - 0.05 & 0 \lt t \leq t_c \lt T-1 \quad \text{（有效搜索，深度越小奖励越高）} \\[4pt] -0.1 & 0 \lt t_c \lt t \lt T-1 \quad \text{（过搜索，惩罚）} \end{cases}$$
效率奖励的设计直觉：$\frac{0.4}{t_c+\epsilon}$ 确保同样是有效搜索，步数越少奖励越高（如 $t_c=1$ 时奖励 ≈0.35，$t_c=3$ 时 ≈0.1）。这驱动 Agent 在能够回答时尽早停止，而不是简单地惩罚搜索次数——对复杂问题不会过度压制探索。

③ 搜索质量奖励（Search Quality Reward）

用 F1 分数衡量中间答案质量，奖励相对前序步骤的增量提升：

$$\mathrm{F1}(a^{\mathrm{inter}}_{i,t},\; a^{\mathrm{gold}}_i) = \frac{2 \cdot I^N}{P^N + R^N}$$
$$r^{\mathrm{quality}}_{i,t} = \mathrm{F1}(a^{\mathrm{inter}}_{i,t},\; a^{\mathrm{gold}}_i) - \max_{t' \lt t}\, \mathrm{F1}(a^{\mathrm{inter}}_{i,t'},\; a^{\mathrm{gold}}_i)$$

只有当该步检索带来 F1 提升时才给正奖励，明确量化了每步检索的边际贡献。

综合奖励

$$r^{\mathrm{overall}}_{i,t} = r^{\mathrm{base}}_{i,t} + r^{\mathrm{efficient}}_{i,t} + r^{\mathrm{quality}}_{i,t}$$

3.4 PPO 训练目标（屏蔽检索 token）

$$J_{\mathrm{PPO}}(\theta) = \mathbb{E}_{\substack{(q,a)\sim D \\ o\sim\pi_{\mathrm{old}}(\cdot|q)}} \left[\frac{1}{\sum_{t=1}^{|o|} I(o_t)} \sum_{t=1}^{|o_i|} I(o_t) \cdot L_t\right]$$
$$L_t = \min\!\left(r_t \hat{A}_t,\; \mathrm{clip}(r_t, 1-\varepsilon, 1+\varepsilon)\hat{A}_t\right)$$

$I(o_t)$ 为掩码，将外部检索文档排除在训练损失外，梯度只流过 Agent 生成的推理和查询 token。

3.5 算法流程

AutoSearch 训练流程

Input: 训练集 D（NQ+HotpotQA 合并），检索引擎（Wiki 2018 + E5），策略 π_θ

for each 训练批次 (q_i, a^gold_i) ∈ D do

// 1. 多步搜索 Rollout

for t = 1, …, T do

生成搜索查询 s_{i,t}，调用检索器获取 o_{i,t}

生成中间答案 a^inter_{i,t} ← PromptPolicy(x_{i,t})

end for

// 2. 计算能力感知最优深度

t_c ← min{t | EM(a^inter_{i,t}, a^gold_i) = 1}，若无则 t_c = -1

// 3. 逐步计算三类奖励

for t = 1, …, T do

r_t ← r^base_t + r^efficient_t(t_c) + r^quality_t

end for

// 4. PPO 策略更新（掩码检索 token）

更新 π_θ 最大化 J_PPO(θ)

end for

5.2 PPO vs GRPO

将 AutoSearch 的累积奖励作为结果奖励，使用 GRPO 替代 PPO 训练，结果与 PPO 性能相当——说明 AutoSearch 的奖励设计对 RL 算法选择具有鲁棒性，方法的泛化性强。

训练动态的核心模式：AutoSearch 在训练初期允许 Agent 短暂探索更深的搜索（获取足够经验判断何时停止），然后效率奖励驱动 Agent 学会在 $t_c$ 处停止——这与课程学习的思路一致：先学会完成任务，再学会高效完成任务。

7. 局限性

  • 最大搜索步数范围有限：当前实验在较小的最大搜索深度下验证，更大深度范围下的准确率-效率权衡仍有待探索
  • 中间答案的计算开销：每步生成中间答案增加了每个 Rollout 的前向计算次数（虽然训练期间的成本，推理时不需要）
  • 单一检索器依赖：实验使用 E5 + Wikipedia，不同检索器质量对 $t_c$ 估计的影响未充分研究
  • 任务领域局限：仅在 QA 任务验证，代码生成、数学推理等需要不同形式外部信息的 Agent 任务有待验证

8. 核心洞见与读后评注

"最小充分深度"是 Agentic RAG 的正确优化目标
现有方法要么追求"搜索越少越好"（导致欠搜索），要么追求"答案越准越好"（导致过搜索）。AutoSearch 的核心贡献是提出了 $t_c$——既不是最小搜索步数，也不是最大准确率，而是"能正确回答所需的最少步数"。这个目标在概念上是正确的：评估标准是效率（单位搜索步获得的信息价值），而非绝对数量。
自评估信号比外部评判更高效
HIPRAG 用外部 LLM 判断每步是否需要继续搜索，引入了额外的大模型依赖。AutoSearch 用 Agent 自身生成中间答案作为自评估信号——这更符合"测试时 Scaling"的精神：在推理时分配计算资源给"思考是否需要继续"，而非依赖外部监督。中间答案的 EM 判断（是否已能正确回答）是一个干净、可靠的二值信号。
与 FIPO 的对比：两种密集信用分配路径
FIPO 通过 Future-KL 在生成 token 层面做密集信用分配；AutoSearch 通过中间答案在搜索步骤层面做密集信用分配。两者都解决了稀疏奖励问题，但针对不同的行动粒度——FIPO 面向生成模型内部推理，AutoSearch 面向外部工具调用序列。这预示了一个方向：将两种思路结合，实现从 token 级到工具调用级的全链路密集信用分配。
搜索质量奖励的反直觉价值
消融实验中，去掉搜索质量奖励后，模型反而过度减少了搜索（SD 从 1.36 降到 1.10），但准确率也大幅下降（44.3→40.3）。这揭示：纯效率奖励会让 Agent 学会"赌博式"的单次搜索——有时碰巧对，但整体不稳定。质量奖励（F1 增量）迫使 Agent 在每次搜索后验证信息是否真的有用，避免了低质量的"最小步数"策略。
