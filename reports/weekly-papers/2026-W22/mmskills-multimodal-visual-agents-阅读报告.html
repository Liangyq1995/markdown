论文摘要（精译）

MMSkills 提出了一个用于表示、生成和运行时使用可复用多模态过程的框架，专为视觉决策任务设计。 该框架将公开可用的历史操作轨迹转化为结构化的"技能包"（Skill Package），并在推理阶段通过 分支加载代理机制将相关技能注入当前决策流程，从而在不超载上下文窗口的前提下， 为主智能体提供精炼的、可执行的子目标指导。

在 OSWorld 基准上，使用 Qwen3-VL 骨干模型，成功率从 11% 提升至 25%， 游戏类和 GUI 操作类任务均获得显著增益，有力验证了多模态技能复用的有效性。

02 · 核心问题与动机

2.1 问题陈述

当前视觉语言智能体（Visual Language Agents, VLAs）在执行复杂 GUI 任务时， 每次都从零开始推理，无法利用历史经验中已被验证的操作过程。 这造成了以下核心矛盾：

现有方法的问题
  • 每次任务独立推理，无法复用成功经验
  • 将大量历史轨迹直接塞入上下文，导致上下文窗口爆炸
  • 纯文本提示忽略了界面的视觉状态信息
  • 缺乏"何时使用"某项知识的条件判断能力
MMSkills 的解决思路
  • 将轨迹提炼为紧凑的多模态技能包
  • 引入视觉状态卡片，捕捉关键界面状态
  • 通过分支加载实现按需检索，不污染主上下文
  • 提供结构化的适用性判断 + 子目标 + 下一步输出
核心研究问题（RQ）

如何将非结构化的历史操作轨迹转化为结构紧凑、可视觉对齐、运行时可高效使用的 多模态技能表示，从而在不破坏上下文效率的前提下显著提升视觉智能体的任务完成率？

2.2 主要挑战

1
多模态对齐挑战
文本步骤描述与对应视觉界面截图之间的精确对应关系难以自动建立—— 相同操作在不同软件版本、主题、语言中的视觉呈现差异巨大。
2
技能泛化 vs. 过拟合
从具体轨迹归纳出通用步骤过程（General Procedure）需要在保留足够操作细节 与避免过度具化（导致零迁移）之间取得平衡。
3
运行时检索效率
在数百乃至数千个技能包中快速找到当前状态最相关的技能， 且检索判断本身不能消耗过多 token 预算。
4
上下文开销控制
直接将完整技能包（含所有截图、关键帧）注入主智能体上下文会导致 视觉 token 爆炸，需要一种"渐进披露"机制。

03 · 背景与相关工作

3.1 视觉语言智能体（VLA）

视觉语言智能体以大型多模态模型（如 GPT-4V、Qwen-VL、LLaVA 系列）为核心， 通过感知屏幕截图并生成动作指令（点击、输入、滚动等）来自动化完成 GUI 任务。

感知层

截图/视频帧输入，OCR + 目标检测，UI 元素树解析

推理层

任务分解，子目标规划，动作序列生成，错误恢复

执行层

鼠标/键盘模拟，API 调用，状态验证，轨迹记录

代表性工作包括 WebAgent、AppAgent、UFO（微软）、 OS-Copilot 等。OSWorld 是当前最综合的通用桌面任务基准， 涵盖文件管理、办公软件、游戏操控、系统设置等多类别任务。

3.2 技能知识先验与经验复用

在强化学习领域，技能/选项（Skill/Option）复用已有深入研究（如 HRL、SKILL-IT）。 在 LLM 时代，以下几类方法尝试引入经验复用：

方法类别 代表工作 核心机制 不足
Few-Shot 示例库 Voyager, AgentBench 相似历史任务 + 解法注入上下文 上下文膨胀，无视觉信息
代码技能库 Voyager Skills, CodeAct LLM 生成可复用代码函数 限于可编程环境，无视觉状态
检索增强生成 (RAG) MemGPT, ExpeL 语义检索历史轨迹片段 检索粒度粗，轨迹噪音大
MMSkills (本文) — 多模态技能包 + 分支加载代理 覆盖视觉/文本/条件三维

05 · 关键技术详解

5.1 MMSkill 包结构（Package Structure）

MMSkill 包是框架的基本存储单元，它将一个可复用操作过程所需的 语义信息、视觉状态信息和使用条件信息耦合为一个紧凑结构。

① 文本过程（Textual Procedure）

由若干步骤指令（step-by-step instructions）构成的自然语言描述， 包含目标、前置条件及每步的操作意图。 这是技能的"骨架"，提供可解释的操作序列。

② 运行时状态卡片（Runtime State Cards）

技能执行过程中关键界面状态的视觉快照， 标注了可观测的 UI 元素与对应步骤的映射关系。 帮助代理在运行时核对"当前状态是否符合预期"。

③ 多视图关键帧（Multi-View Keyframes）

从多角度（不同应用状态、主题、版本）收集的触发条件视觉证据， 用于检索阶段判断"该技能是否适用于当前场景"， 提升跨环境泛化能力。

三者的协同设计实现了"知道做什么（文本过程）+ 知道当前做到哪了（状态卡片）+ 知道什么时候用（关键帧）"的完整技能表达。

1
工作流分组（Workflow Grouping）
将单条长轨迹按语义子目标切分为若干工作流片段。 使用 LLM 对动作序列做滑动窗口分析，识别语义边界 （如"打开文件"→"编辑内容"→"保存"构成三个片段）。 分组结果为后续归纳提供粒度合适的训练材料。
2
过程归纳（Procedure Induction）
给定工作流片段，LLM 被提示将其中具体的坐标、像素值、 应用内部路径等特化信息抽象为通用的操作步骤描述。 这一步类似"代码重构"——去掉具体值，保留操作模式。 结果为文本过程（Textual Procedure）。
3
视觉接地（Visual Grounding）
将归纳后的每个文本步骤与原始轨迹中的对应截图帧进行精确对齐， 提取关键 UI 元素的边界框和状态描述，生成状态卡片。 同时从多个轨迹中挑选具有代表性的场景截图作为多视图关键帧， 用于后续检索时的视觉条件匹配。
4
元技能引导审计（Meta-Skill-Guided Auditing）
使用一组预定义的"元技能"（Meta-Skills，覆盖质量维度如完整性、一致性、可迁移性） 对生成的技能包进行自动化质检。不符合标准的包被过滤或触发重生成。 这是保证技能库质量的关键安全阀。

5.3 分支加载多模态技能代理（Branch-Loaded Multimodal Skill Agent）

这是 MMSkills 在运行时发挥作用的核心机制。 它的设计目标是：在不向主智能体上下文注入大量原始技能数据的前提下， 提供精准、结构化的操作指导。

分支加载代理的四项关键设计

① 临时分支检查

代理在一个独立的、临时的上下文分支中工作， 完整加载状态卡片和多视图关键帧进行精细对齐分析。 该分支在完成后即销毁，不污染主智能体的对话历史。

② 视觉状态对齐

代理将技能包中的状态卡片与当前实时截图进行逐元素视觉比对， 判断当前界面处于技能执行的哪个阶段， 从而提供"从此刻开始的后续步骤"而非完整流程。

③ 结构化输出

输出严格遵循三字段格式： 适用性（是/否 + 理由）、 子目标（当前应完成的小目标列表）、 下一步（具体推荐动作）。 结构化保证了主智能体能高效解析。

④ 渐进披露（Progressive Disclosure）

主智能体只接收精炼的决策支持（文本摘要）， 而非完整技能包（含大量图像 token）。 这解决了视觉 RAG 中最常见的"上下文爆炸"问题。

与传统 RAG 对比的核心优势

传统 RAG 在检索后直接将原始文档/截图注入上下文， 信息密度低且噪音大。MMSkills 的分支加载机制相当于 在"检索"和"使用"之间增加了一个智能压缩层—— 由专门的子代理负责消化原始技能包，并以主智能体能直接使用的格式输出。 这类似于人类专家"先自己读懂手册再口头总结给同事"的工作方式。

06 · 实验结果

07 · 消融实验

论文通过系统性消融实验验证了各核心组件的独立贡献， 以及设计选择的合理性。

消融实验：各组件对整体成功率的贡献（OSWorld，%）
消融配置 成功率 (%) vs. 完整版 (pp) 结论
完整 MMSkills 25.0 — 完整系统
移除多视图关键帧 20.8 -4.2 关键帧对检索精度至关重要
移除运行时状态卡片 19.3 -5.7 状态对齐是最关键单一组件
移除元技能审计 21.5 -3.5 审计对技能库质量有显著贡献
用直接上下文注入代替分支加载 17.2 -7.8 分支机制是上下文效率的核心
仅文本过程（无视觉组件） 15.6 -9.4 视觉多模态信息不可或缺
基线（无技能） 11.0 -14.0 参照基线
消融实验关键发现
  1. 分支加载机制是贡献最大的单个设计决策（-7.8 pp when removed），表明如何注入技能知识比技能知识本身更重要。
  2. 运行时状态卡片是最关键的视觉组件（-5.7 pp），直接决定了代理"知道自己在哪"的能力。
  3. 移除所有视觉组件后（仅文本），性能仍优于基线（+4.6 pp），说明文本过程本身也有独立价值，但视觉信息大幅放大了这一价值。
  4. 直接上下文注入（-7.8 pp）不仅不如分支加载，甚至还不如部分消融配置，证明错误的注入方式可能比"不注入"更有害（上下文污染）。

08 · 局限性与未来工作

当前局限性
  • 技能库覆盖率上限：技能库质量和范围直接受制于可用的公开轨迹数据， 对长尾罕见任务覆盖不足。
  • 视觉漂移问题：当目标软件进行 UI 更新后， 已有状态卡片和关键帧可能失效，需要维护技能库更新机制。
  • 检索准确性瓶颈：多视图关键帧匹配在视觉相似但语义不同的场景下 仍存在误召回问题。
  • 生成管道计算成本：四阶段轨迹-技能生成器涉及多次 LLM 调用， 批量构建大规模技能库的成本较高。
  • 跨语言泛化：当前评估主要在英文界面环境， 多语言 GUI 环境的泛化性有待验证。
未来研究方向
  • 在线技能学习：让智能体在完成任务后自动将成功轨迹 转化为新技能，实现技能库的持续自我更新。
  • 技能组合：研究如何将多个基础技能组合为复杂技能， 支持更长程的任务规划。
  • 跨应用技能迁移：探索在不同但功能相似的软件之间 进行技能知识迁移（如 Word → WPS）。
  • 主动技能发现：当检索到的技能均不适用时， 智能体主动探索并生成新技能包。
  • 更大规模验证：在 WindowsAgentArena、AgentBench 等 其他基准上进行广泛验证。

09 · 核心洞见与评述

洞见 1：多模态知识表示的"三维耦合"范式

MMSkills 将语义（文本）、状态（视觉）、条件（关键帧）三个维度耦合在同一技能包中， 而非分离存储。这一设计使得技能不仅"能做什么"（语义），还"在哪种情况下用"（条件）， 以及"执行中如何自我定位"（状态），形成了一个完整的可操作知识单元。 这是对传统"代码函数式技能"的重大升级，也是对纯文本 RAG 的本质性超越。

洞见 2："智能中间层"架构的价值

分支加载代理本质上是一个智能中间层（Intelligent Middleware）—— 它将原始技能包的"信息密度"转化为主智能体能高效使用的"决策密度"。 这一思路与软件工程中的"适配器模式"和"门面模式"高度契合： 复杂性被封装在中间层，上层调用者只看到简洁接口。 这一架构原则未来可能被广泛应用于多智能体系统的知识共享设计。

洞见 3：经验提炼而非经验堆砌

许多 RAG 系统的隐含假设是"更多的原始信息 = 更好的性能"， 但 MMSkills 的消融结果（直接注入 vs. 分支加载）揭示了 信息的组织方式比信息量更重要这一反直觉发现。 轨迹-技能生成器正是一个专门执行"经验提炼"而非"经验搬运"的模块， 这与人类学习新技能的方式——从具体案例归纳通用原则——高度一致。

洞见 4：通用智能体的"技能字典"愿景

MMSkills 框架在更宏观层面提出了一个愿景： 未来的通用视觉智能体将配备一个持续更新的多模态技能字典， 就像人类大脑中的"程序性记忆"（Procedural Memory）一样， 将学习到的操作模式以高效压缩的形式存储， 并在遇到熟悉场景时快速调取而无需从头推理。 这与神经科学中"自动化技能"的概念深度呼应， 也为 AI 智能体向"终身学习"迈进提供了可行的工程路径。

个人评述与延伸思考

MMSkills 的工作相当扎实，尤其是技能包三元素设计和分支加载机制 具有很强的工程创新性。在实际部署中， 以下几个问题值得持续关注：

  1. 技能冲突处理：当多个技能都声称适用时，如何选择或融合？ 需要引入优先级机制或置信度评分。
  2. 负样本学习：当前框架主要从成功轨迹构建技能， 失败轨迹中包含的"反技能"（Anti-Patterns）同样有价值。
  3. 端到端优化：目前技能生成和使用相对独立， 能否通过强化学习信号端到端地优化整个管道是一个开放问题。
