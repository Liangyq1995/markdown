二、长上下文核心技术

2.1 RoPE 与 YaRN 扩展

RoPE 旋转角度：$\theta_i = 10000^{-2i/d}$，注意力得分只依赖相对距离：

$$\text{Attn}(q_m, k_n) \propto \text{Re}\left[q_m^* \cdot k_n \cdot e^{i(m-n)\theta}\right]$$

YaRN 扩展：新旋转角 $\theta_i^{\text{new}} = \theta_i / \lambda$（$\lambda > 1$）。低频分量（长程依赖）线性插值，高频分量（短程依赖）保持不变，同时引入温度缩放抵消注意力分布偏移。

2.2 分块注意力 + Partial Rollouts

Chunk Attention：将序列分块，块内完整注意力，跨块稀疏交互，将 $O(n^2)$ 降至 $O(n \cdot c)$（$c$ 为块大小）。

Partial Rollouts：RL 训练时复用前序轨迹的大部分内容，仅对新生成部分采样。避免从头重新生成整条轨迹，使 128K 上下文 RL 训练的效率提升数倍——这是 k1.5 能将 RL 上下文扩展至 128K 的关键基础设施创新。

2.3 Kimi Linear：混合线性注意力

KDA（Kimi Delta Attention）基于 Gated DeltaNet，通过秩-1修正更新有限状态记忆：

$$h_t = \beta_t h_{t-1} + v_t k_t^\top$$

其中 $\beta_t$ 为可学习衰减因子，控制遗忘程度；$v_t k_t^\top$ 是秩-1的记忆写入操作。

效果（1M token 上下文）：KV 缓存减少 75%，解码吞吐量提升 6.3×，RULER 基准（128K）= 84.3（与全注意力基本持平）。

3.2 在线策略镜像下降（核心算法）

优化目标

$$\max_\theta \mathbb{E}_{(x,y^*)\sim\mathcal{D}}\left[\mathbb{E}_{(y,z)\sim\pi_\theta}\left[r(x,y,y^*)\right] - \tau \cdot \text{KL}(\pi_\theta(x) \| \pi_{\theta_i}(x))\right]$$

解析最优解

$$\pi^*(y,z|x) = \frac{1}{Z} \pi_{\theta_i}(y,z|x) \cdot \exp\!\left(\frac{r(x,y,y^*)}{\tau}\right)$$

实际训练中通过迭代近似求解，每轮以更新后的策略作为新参考模型（在线更新）。相比 GRPO，镜像下降在长 CoT 场景下提供更强的理论收敛保证。

3.3 奖励函数与长度惩罚

$$r_\text{correct}(y, y^*) = \mathbf{1}[y \equiv y^*] \quad \text{（SymPy 等价验证）}$$ $$r_\text{final} = r_\text{correct} - \lambda \cdot \max\!\left(0,\, \frac{|y| - L_\text{budget}}{L_\text{budget}}\right)$$

长度惩罚防止模型通过生成冗长无效内容"刷"奖励；课程采样逐步提升问题难度，保证各难度级别充分探索。

3.6 RL Prompt 集合构建

高质量 RL Prompt 集合需满足三个核心属性：

  • 多样覆盖（Diverse Coverage）：涵盖 STEM、竞赛数学、代码、通用推理等领域，通过标签系统（Tagging System）确保各学科均衡覆盖
  • 均衡难度（Balanced Difficulty）：通过 SFT 模型以较高温度采样 10 次，用通过率（Pass Rate）作为难度代理指标——通过率越低表示越难
  • 可准确验证（Accurate Evaluability）：排除多选题、判断题、证明题（易出现 False Positive），并用模型无 CoT 猜测 N=8 次，若猜对则移除（防止 Reward Hacking）

3.7 CoT-RM 详细设计

背景：数学答案验证面临"不同书写形式等价"的挑战（如 $a^2-4$ 与 $(a+2)(a-2)$ 等价）。Kimi k1.5 采用两种奖励模型并行：

类型架构训练数据准确率（人工抽检）
Classic RMValue-head 标量输出~80 万条标注样本~84.4%
CoT-RM（采用）先生成 CoT 推理，再输出 JSON 判断~80 万条 CoT 标注样本~98.5%

CoT-RM 工作流程：输入「问题 + 参考答案 + 模型响应」→ 模型先逐步推理（判断答案是否等价、格式是否正确）→ 最后以 JSON 格式输出 {"correct": true/false}。

准确率从 84.4% 提升至 98.5% 的关键原因：CoT 推理过程使模型能处理复杂的等价性判断（多项式化简、三角恒等变换等），而 Classic RM 的标量输出无法捕捉这类细微差别。RL 训练全程采用 CoT-RM 以确保奖励信号准确。

3.8 消融实验结果

（1）长度惩罚消融

长度惩罚在训练初期会减缓学习速度，因此采用渐进式热启动策略：先进行标准 RL 训练（无惩罚），再施加常数长度惩罚。实验表明，对正确响应中较短的答案给予奖励、对较长的正确答案施加惩罚，同时对错误的长响应施加双重惩罚，能有效控制模型 token 消耗而不损失精度。

（2）Partial Rollout 效率提升

Partial Rollout 将超出 token 预算的轨迹保存到 Replay Buffer，下一轮迭代继续。由于只有当前迭代的片段需要 On-Policy 计算，之前片段可直接复用，显著降低了长 CoT RL 的计算开销，使 128K 上下文 RL 训练成为可能。

（3）Long2Short 方法对比（AIME 2024 vs 平均 tokens）

橙色：k1.5 系列（token 效率显著优于蓝色基线模型）；Long2Short RL 以 3,272 tokens 达到 60.8% AIME Pass@1

（4）上下文长度 Scaling 曲线

实验使用一个中等规模模型（小于 k1.5 正式版），在数学 Prompt 集合上训练，观察到随训练迭代次数增加，响应长度和准确率同步上升。更难的基准（如 AIME）响应长度增幅更大，说明模型学会了对复杂问题生成更详细的解题过程。最终 k1.5 将 RL 上下文扩展至 128K，在困难推理基准上持续改善。

4.2 MuonClip 优化器（完整原理）

Muon：Newton-Schulz 正交化梯度

$$G_\text{ortho} = \text{NewtonSchulz}(G), \quad W \leftarrow W - \eta \cdot G_\text{ortho}$$

Newton-Schulz 迭代（正交化）：$X_{k+1} = 1.5 X_k - 0.5 X_k X_k^\top X_k$，收敛至正交矩阵。本质是在谱范数约束下执行最速下降，比 AdamW 约有 2× 计算效率提升（相同 FLOPs 下更低困惑度）。

QK-Clip：解决 MLA 架构的训练不稳定

问题根源：MLA 训练时 Key 由完整 $W_{UK}$ 展开（RMSNorm 归一化值约为 1），推理时 Key 从低秩 $c_{KV}$ 展开（归一化行为不同），导致注意力 logit 在大规模训练中爆炸。

$$S_\text{max}^{(h)} = \max_{i,j} \frac{q_i^{(h)} \cdot k_j^{(h)}}{\sqrt{d_k}}, \quad \text{scale}^{(h)} = \min\!\left(\frac{t}{S_\text{max}^{(h)}},\, 1\right)$$

仅对超出阈值 $t$ 的注意力头进行缩放，其余头不受影响，最小侵入性地解决数值不稳定问题。

效果：Kimi K2 在 15.5T tokens 训练过程中零 Loss Spike，彻底解决了万亿参数 MoE 训练的稳定性挑战。

4.2b MuonClip 实验细节

Muon 为何更容易 Logit 爆炸（理论分析）

Logit 爆炸发生在 $S_\text{max} = \max_{i,j}(q_i \cdot k_j)$ 无界增长时。由于 RMSNorm 约束了输入 $\|x_i\|$，爆炸主要由 $W_q$ 或 $W_k$ 的谱范数增长驱动。

结构差异：Muon 的更新矩阵来自 msign 操作（Newton-Schulz 正交化），所有奇异值相等，有效秩为满秩。而 Adam 的更新矩阵奇异值谱偏斜，有效秩低。

后果：Muon 训练的权重奇异值熵更高（在 16B Moonlight 模型上验证），更高有效秩导致权重矩阵 $W$ 与更新矩阵 $\Delta W$ 的奇异向量更容易对齐，使对应奇异值累加式增长。注意力 logit 通过双线性形式 $q_i \cdot k_j = (x_i W_q)(x_j W_k)^\top$ 计算，$W_q W_k^\top$ 的谱范数是两者谱范数之积，任何一方的增长都被平方放大。

实验结果
Vanilla Muon（9B activated / 53B total MoE）训练 15,000 步后最大 logit 超过 1,000，出现明显 loss spike
Kimi K2 with MuonClip（τ=100）初期 logit 被钳制在 100，约 30% 训练步后 logit 自然衰减至稳定区间，全程零 Loss Spike
QK-Clip 质量影响（小规模消融，0.5B activated / 3B total，激进阈值 τ=30）与无 QK-Clip 的 Muon 相比，验证集 loss 曲线无统计显著差异，下游任务无性能下降

QK-Clip 自停用机制：在 Kimi K2 完整训练中，前 70,000 步有 12.7% 的注意力头至少触发一次 QK-Clip；70,000 步之后所有头的 $S_\text{max}$ 均自然降至 100 以下，QK-Clip 完全失活——说明该机制仅在训练初期起稳定作用，不影响后期训练动态。

五、Kimi-VL：多模态架构

5.1 MoonViT 原生分辨率视觉编码器

MoonViT 采用 NaViT 打包方案，支持任意分辨率图像，通过 2D RoPE 编码每个 patch 的空间位置：

$$\text{PE}(r, c, 2i) = \sin\!\left(\frac{r}{10000^{2i/d}}\right), \quad \text{PE}(r, c, 2i+1) = \cos\!\left(\frac{c}{10000^{2i/d}}\right)$$

其中 $r, c$ 为 patch 的行列坐标。不同分辨率图像在同一 batch 通过序列打包高效处理，彻底消除传统 VLM 的子图切分拼接操作。

效果：InfoVQA（高分辨率文档理解）= 83.2，ScreenSpot-Pro（UI 截图）= 34.5，以 3.2B 激活参数超越 GPT-4o-mini。

Pixel Shuffle 2×2：将 MoonViT 输出的视觉特征进行 2×2 空间下采样——4 个相邻 patch 的特征合并为 1 个，空间分辨率 ÷4，通道维度 ×4——减少 75% 送入 LLM 的 visual token 数量，同时保留完整语义信息。

六、Kimi K2 补充：Agentic 数据合成与 RL 扩展

6.1 稀疏度 Scaling Law

定义稀疏度（Sparsity）为总专家数与每 token 激活专家数之比：

$$s = \frac{\text{总专家数}}{\text{激活专家数}}$$

在相同激活参数量下，提高稀疏度可增加模型容量，但路由开销和通信成本也随之上升。Kimi K2 通过系统性实验确定最优稀疏度。

6.3b Self-Critique Rubric Reward 详细设计

设计动机：Verifiable Rewards 只能覆盖有明确正确答案的任务（数学/代码/逻辑），无法处理创意写作、开放问答等主观性任务。Self-Critique Rubric Reward 将 RL 对齐扩展到这些非可验证领域。

flowchart LR
  A["K2 Actor\n生成多个响应"] --> B["K2 Critic\n执行两两比较\n(Pairwise Evaluation)"]
  B --> C["Rubric 评分\n核心 Rubric + 规定性 Rubric\n+ 人工标注 Rubric"]
  C --> D["偏好信号\n作为 RL 奖励"]
  E["Verifiable Rewards\n(RLVR 任务)"] --> F["Critic 持续更新\n将客观信号蒸馏进 Critic"]
  F --> B

Rubric 设计（核心评分维度）

  • 清晰度与相关性（Clarity and Relevance）：响应是否简洁且完整回答用户意图，避免不必要细节，使用高效格式（简短段落/紧凑列表）
  • 对话流畅性与参与感（Conversational Fluency）：是否保持自然流畅的对话，适当参与话题，合理使用追问，根据语境调整语气（共情/正式/随意）
  • 客观与接地气（Objective and Grounded）：避免元评论（分析问题结构本身）和过度奉承，专注于任务实质，中立礼貌地交互

规定性 Rubric（Prescriptive Rubrics，防 Reward Hacking）

  • 禁止初始赞美：响应不得以对用户或问题的恭维开头（如"好问题！"）
  • 禁止显式自我辩护：不得包含解释为何响应很好或如何成功完成请求的句子

闭环 Critic 精炼：Critic 模型在 RL 训练过程中持续用 Verifiable Rewards 的 On-Policy rollout 更新，将客观性能信号蒸馏进 Critic 的主观判断能力，确保 Critic 与 Policy 同步进化。

适用范围：创意写作、开放问答、复杂推理解释、一般对话等无法用规则验证的任务。与 Verifiable Rewards Gym 互补，共同覆盖所有任务类型。

6.4 K2 RL 扩展

继承 k1.5 基础

K2 完整继承 k1.5 的在线策略镜像下降算法（Online Mirror Descent），在此基础上新增以下四项扩展：

新增：Budget Control

按任务类型（数学/代码/Agent）动态设定最大 token 预算，防止模型在简单任务上过度思考，同时保证复杂任务有足够推理空间。

新增：PTX Loss（防遗忘）

Pretrain-Text-Mix Loss，在 RL 训练中混入少量预训练文本的语言模型损失，作为辅助损失防止模型灾难性遗忘预训练知识。

新增：Self-Critique Reward

模型对自身生成的 Agent 轨迹进行自我批评，将批评质量作为额外奖励信号，鼓励生成可被高质量批评的轨迹（即可解释、可验证的行动链）。

大规模训练效率

K2 RL 训练中参数更新延迟 < 30 秒（1T 参数规模下），通过异步参数同步与流水线并行实现近实时策略更新。

视觉 token 比例消融实验（完整结论）

论文在固定总 token 预算下，对三种视觉比例（10%:90%、20%:80%、50%:50%）进行系统消融，并控制视觉数据引入时机：

  • 晚期融合（50%:50%，在 80% 训练进度时引入视觉）：文本性能出现"骤降-缓慢恢复"（dip-and-recover）模式，视觉任务也最差。原因：模态域迁移冲击已稳定的语言表示空间，强制模型临时牺牲文本能力换取跨模态对齐
  • 中期融合（20%:80%，在 50% 训练进度时引入视觉）：文本性能下降较小，视觉性能居中，但仍有轻微 dip
  • 早期融合（10%:90%，从训练起始即引入视觉）：文本性能曲线全程平稳，视觉性能最优；模型从一开始就协同优化两种模态，形成统一的多模态表示，梯度景观更平滑

最终选择 10% 早期融合：在固定 token 预算下，视觉数据越少反而越好——早期融合带来的表示统一收益远超数据量增加的收益。这一反直觉结论促使 K2.5 采用"适度视觉比例 + 全程早期融合"的原生多模态预训练策略。

7.3 Zero-Vision SFT（反直觉发现）

传统做法：视觉 SFT

在 SFT 阶段使用大量视觉-语言对话数据，直接教模型如何处理图像。

问题：视觉 SFT 数据质量参差不齐，容易引入幻觉，且难以覆盖所有视觉任务类型。

K2.5 做法：Zero-Vision SFT

SFT 阶段完全使用纯文本数据，不包含任何视觉样本。视觉能力通过预训练中的早期融合已经植入模型权重。

所有图像操作（读取、分析、变换）均通过 IPython 代码代理执行——模型生成 Python 代码来处理图像，而非直接"看"图像。

反直觉发现：Zero-Vision SFT 在视觉基准上的表现与传统视觉 SFT 相当甚至更好，同时完全避免了视觉 SFT 数据带来的幻觉问题，且纯文本推理能力得到更好保留。

IPython 工具调用格式示例

Zero-Vision SFT 的核心是用代码代理所有图像操作。以下是论文中描述的典型视觉任务处理方式：

# 示例：通过 IPython 工具执行视觉推理任务
# 任务：估算图像中目标物体的大小（像素级操作）

import numpy as np
from PIL import Image

# 读取图像（模型通过工具调用获取图像数据）
img = Image.open("input.png").convert("L")  # 转灰度
arr = np.array(img)

# 二值化：区分目标与背景
threshold = 128
binary = (arr < threshold).astype(np.uint8)

# 计数：估算目标区域像素数（用于大小估算）
object_pixels = binary.sum()
total_pixels = binary.size
ratio = object_pixels / total_pixels

print(f"目标占比: {ratio:.3f}")
print(f"估算目标大小: {object_pixels} 像素")

通过这种方式，模型可以执行：目标大小估算（二值化+计数）、目标定位（bounding box 提取）、计数任务（连通域分析）、OCR（调用 pytesseract 等库）等视觉任务，而无需在 SFT 数据中包含任何图像-文本对。

Zero-Vision SFT 的理论解释

为何纯文本 SFT 能激活视觉能力？论文给出的解释：

  1. 预训练已建立强视觉-文本对齐：Stage 2 的 15T token 联合预训练（10% 视觉）使模型权重中已经编码了丰富的视觉语义，视觉能力以"潜在"形式存在于模型中
  2. IPython 工具调用是通用视觉推理的泛化：纯文本 SFT 中的代码执行轨迹（IPython 工具调用）为模型提供了处理任意视觉任务的通用框架，避免了传统视觉 SFT 数据多样性不足的问题
  3. 视觉 SFT 反而有害：论文初步实验表明，在此阶段加入人工设计的视觉轨迹（chain-of-thought）会损害泛化性，可能因为这些数据限制了视觉推理到简单图表和基础工具操作（裁剪/旋转/翻转），而 Zero-Vision SFT + RL 可以学到更多样的视觉推理策略
  4. RL 阶段激活剩余视觉能力：Zero-Vision SFT 作为 RL 的冷启动，视觉 RL 的训练曲线（Figure 2）显示从此起点出发，视觉基准随 RL FLOPs 持续提升，证明 Zero-Vision SFT 已足够激活视觉推理的基础能力

7.6 Agent Swarm 架构

现有单 Agent 瓶颈

传统单 Agent 架构中，任务步骤必须串行执行，总延迟随任务步骤数线性增长：$T_\text{total} = \sum_{t=1}^{N} t_\text{step}$。对于需要 50+ 步的复杂 Agent 任务，延迟不可接受。

设计哲学：Orchestrator 可训练 + Sub-Agents 冻结

Sub-Agents 使用冻结的 K2.5 基础模型，无需额外训练；仅 Orchestrator 通过 PARL 进行强化学习，学习何时并行、如何分配子任务。这大幅降低训练成本，且 Sub-Agents 可随时替换为更强的模型。

7.7 PARL 奖励函数与训练数据构建

PARL（Parallel Agent Reinforcement Learning）的奖励函数平衡并行效率与任务完成质量：

$$r_\mathrm{PARL}(x,y) = \lambda_1 \cdot r_\mathrm{parallel} + \lambda_2 \cdot r_\mathrm{finish} + r_\mathrm{perf}(x,y)$$

其中：

  • $r_\mathrm{parallel}$：实例化奖励（instantiation reward），激励 Orchestrator 创建 Sub-Agent 并行执行，缓解"串行坍塌"（serial collapse）—— Orchestrator 退化为单 Agent 串行执行的局部最优
  • $r_\mathrm{finish}$：子 Agent 完成率奖励，激励分配的子任务被成功完成，防止"虚假并行"（spurious parallelism）—— Orchestrator 大量创建 Sub-Agent 但子任务未完成的奖励黑客行为
  • $r_\mathrm{perf}(x,y)$：性能奖励，基于最终答案正确性与质量（rule-based 验证 + GRM 评估）
  • $\lambda_1, \lambda_2$：训练过程中退火至零，使模型最终专注于任务性能而非形式上的并行化；两个辅助奖励仅在训练初期引导探索

Agent Swarm 训练数据构建

为诱导 Orchestrator 学习并行化策略，构建了专门的合成 prompt 套件：

  • Wide Search 类 prompt：要求同时探索多个独立信息源（如：同时调研 10 个竞争对手的产品特性），单 Agent 串行执行无法在步骤预算内完成
  • Deep Search 类 prompt：要求多个推理分支并行展开，最后汇聚（如：多角度分析一个复杂政策问题的影响）
  • 真实工作负载类 prompt：长文档分析（100+ 文档）、大规模文件下载、100K+ 字长文写作等极端规模任务
  • 关键设计原则：prompt 不显式指示模型并行化，而是通过任务结构使并行策略自然涌现（让环境反馈决定是否并行）

7.8 Critical Steps 度量

为防止 Orchestrator 盲目增加并发（并行但无效），引入 Critical Steps 度量：

$$\text{CriticalSteps} = \sum_{t=1}^{T}\!\left(S_\mathrm{main}^{(t)} + \max_i S_\mathrm{sub,i}^{(t)}\right)$$

其中 $S_\mathrm{main}^{(t)}$ 为第 $t$ 步 Orchestrator 的步骤数，$\max_i S_\mathrm{sub,i}^{(t)}$ 为最长子 Agent 的步骤数（关键路径）。

直觉：该度量等价于关键路径长度，激励 Orchestrator 均衡分配子任务（使各 Sub-Agent 工作量相近），而非将所有任务堆给少数 Sub-Agent。

7.9 Token 效率 RL：Toggle 策略

Toggle 策略通过交替训练相位，同时优化推理质量和 token 效率。论文中给出的精确公式：

$$\tilde{r}(x,y) = \begin{cases} r(x,y) \cdot \mathbb{I}\!\left[\frac{1}{K}\sum_{i=1}^{K} r(x,y_i) \lt \lambda \;\text{ 或 }\; |y_i| \leq \text{budget}(x)\right] & \text{若 } \lfloor t/m \rfloor \bmod 2 = 0 \text{（Phase 0）} \\ r(x,y) & \text{若 } \lfloor t/m \rfloor \bmod 2 = 1 \text{（Phase 1）} \end{cases}$$

其中各参数含义：

  • $m$：交替周期，每 $m$ 步切换一次 Phase 0/1
  • $\lambda$：准确率阈值，判断"可解但冗长"的标准——当该问题的平均准确率 $\bar{r}(x) = \frac{1}{K}\sum r(x,y_i) \geq \lambda$ 时，说明模型已能解决该问题，此时才施加预算约束（防止过早牺牲质量换效率）
  • $\text{budget}(x)$：问题相关预算，从训练初始估算，等于正确回答中 token 长度的第 $\rho$ 百分位数：$\text{budget}(x) = \text{Percentile}(\{|y_j| \mid r(x,y_i)=1\},\, \rho)$
  • $K$：每个问题的 rollout 数量
  • Phase 0 的约束是条件性的：仅当模型已能解决该问题（$\bar{r} \geq \lambda$）且当前回答超出预算时才惩罚，避免对困难问题过早施压

Toggle 效果数据

在 K2 Thinking 模型上验证 Toggle 效果（Figure 5）：

  • 平均 token 减少 25%～30%，几乎对所有基准均有效
  • 性能影响可忽略不计（negligible impact on performance）
  • CoT 中冗余模式（重复验证、机械计算）显著减少
  • 强域外泛化：仅在数学和编程任务上训练，GPQA 和 MMLU-Pro 上也获得一致的 token 减少，仅有轻微性能下降

Toggle 解决了之前 Budget Control 策略的"长度过拟合"问题（length-overfitting）：刚性预算约束会使模型在更高计算规模下无法有效利用额外 token，Toggle 的交替相位保留了模型的深度推理能力。

7.10 K2.5 RL 算法更新

完整 RL 目标函数（论文 Equation 1）

K2.5 的策略优化目标函数为：

$$\mathcal{L}_\mathrm{RL}(\theta) = \mathbb{E}_{x \sim \mathcal{D}}\left[\frac{1}{N}\sum_{j=1}^{K}\sum_{i=1}^{|y_j|} \mathrm{Clip}\!\left(\frac{\pi_\theta(y_j^i | x, y_j^{0:i})}{\pi_\mathrm{old}(y_j^i | x, y_j^{0:i})}, \alpha, \beta\right)\!\left(r(x,y_j) - \bar{r}(x)\right) - \tau\!\left(\log\frac{\pi_\theta(y_j^i | x, y_j^{0:i})}{\pi_\mathrm{old}(y_j^i | x, y_j^{0:i})}\right)^2\right]$$

各符号含义：

  • $K$：每个问题的 rollout 数量；$N = \sum_{j=1}^{K}|y_j|$ 为 batch 中总生成 token 数
  • $\bar{r}(x) = \frac{1}{K}\sum_{j=1}^{K} r(x,y_j)$：该问题所有 rollout 的平均奖励（用于 advantage 计算）
  • $\mathrm{Clip}(\cdot, \alpha, \beta)$：Token-Level Clipping，将 log-ratio 区间外的 token 梯度置零（$\alpha, \beta > 0$ 为裁剪边界）
  • $\tau > 0$：正则化系数，对应 $(\log\text{-ratio})^2$ 惩罚项，限制离线偏移
  • 与标准 PPO 的区别：本方法严格基于 log-ratio 界定离线偏移，不论 advantage 符号如何均裁剪，比 PPO 的条件裁剪更稳健

Token-Level Clipping（相比 K2 的改进）

K2 使用在线镜像下降，以序列级别控制策略更新幅度。K2.5 引入 Token-Level Clipping：

  • 基于每个 token 的 log-ratio（当前策略 vs 参考策略的对数概率比）进行裁剪
  • 区间 $[\alpha, \beta]$ 外的 token 梯度直接置零（而非缩放），作为简单的梯度掩码方案
  • 相比序列级裁剪，对单个异常 token 的控制更精细，避免少数 token 主导整个序列的更新方向
  • 论文指出此机制对于需要长时多步工具调用推理的复杂任务至关重要（essential）

7.11 DEP（解耦编码器处理）工程实现

多模态训练的主要效率瓶颈在于视觉编码器的前向传播与主干模型的反向传播耦合。DEP 利用视觉编码器在计算图中的特殊位置（前向传播的起点、反向传播的终点）将两者解耦：

DEP 三阶段详细流程

阶段详细操作工程设计要点
阶段一：均衡视觉前向
（Balanced Vision Forward）		 对全局 batch 中所有视觉数据执行前向传播。视觉编码器在所有 GPU 上复制（与其他并行策略无关）。按负载指标（图像数/patch 数）均匀分配计算，消除流水线并行（PP）带来的负载不均。丢弃所有中间激活值，仅保留最终输出激活。结果汇聚至 PP Stage-0。 视觉编码器小，复制开销可接受；丢弃中间激活以最小化峰值显存
阶段二：主干训练
（Backbone Training）		 使用阶段一缓存的视觉特征，执行主 transformer 主干的前向+反向传播。由于中间激活已在阶段一丢弃，可直接复用纯文本训练中验证过的任意高效并行策略（PP+EP+ZeRO-1）。反向传播结束后，梯度累积在视觉编码器输出处。 完全继承纯文本训练的并行优化，无需为视觉模态重新调优
阶段三：视觉重计算反向
（Vision Recomputation & Backward）		 重新计算视觉编码器的前向传播（recompute），然后执行反向传播，计算视觉编码器参数的梯度。 重计算代价小（视觉编码器相对 LLM 小得多）；按需计算，避免长期占用显存

训练基础设施配置

K2.5 在 NVIDIA H800 GPU 集群上训练，配置如下：

  • 节点间互联：8 × 400 Gbps RoCE
  • 并行策略：16-way Pipeline Parallelism（PP，virtual stages） + 16-way Expert Parallelism（EP） + ZeRO-1 Data Parallelism
  • 支持节点数：任意 32 的倍数
  • EP all-to-all 通信：与计算重叠（interleaved 1F1B 调度）
  • 显存优化：对 LayerNorm、SwiGLU、MLA up-projections 进行选择性重计算；不敏感激活值压缩为 FP8-E4M3；其余激活值 CPU offload（流式传输）
