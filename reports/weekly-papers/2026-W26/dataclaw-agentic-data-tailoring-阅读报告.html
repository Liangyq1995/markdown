DataClaw₀：从原始流中主动裁剪多模态数据

arXiv 2606.21337 2026-06-19 👍 70 upvotes CC BY-NC-SA 4.0
作者：Cong Wan, Zeyu Guo, Zijian Cai, Jiangyang Li, SongLin Dong, Lin Peng, Xiangyang Luo, Zhiheng Ma, Yihong Gong（共9人）
链接： arXiv · GitHub · 项目主页 · Hugging Face

概述

本文提出 Agentic Data Tailoring（主动数据裁剪） 范式，将多模态数据处理从被动标注提升为可学习的高阶能力。 核心贡献是 DataClaw₀-9B 模型：给定用户意图或下游目标，该 Agent 从长视频、GUI 操作日志、具身轨迹等高熵原始流中 过滤冗余信号、重组为密集可验证的结构化监督数据。 为解决训练数据悖论（训练数据精炼模型本身需要高质量精炼数据），论文设计了基于 Factual Anchors（事实锚点） 的两阶段自动构建流水线，并引入首个专用于数据精炼的基准 DataClaw₀-val。 在视频生成、时空 VQA、GUI 导航三项下游任务上的验证表明，DataClaw₀ 产出的数据质量可与 Gemini-3.1-Pro 媲美，同时成本大幅降低。

研究背景

随着多模态 AI 系统的快速发展，互联网上积累了海量非结构化多模态流数据——长视频、屏幕录像、机器人操作日志、AIGC 编辑序列等。 这类数据存在极高的 "数据熵"（Data Entropy）：信息密度低、噪声多、结构松散， 既阻碍人类高效获取知识，也制约 AI 后训练（post-training）的质量。

现有方法的局限

启发式规则方法

基于人工设计的规则进行过滤与标注，泛化能力差，无法适配多样化的下游任务意图，且维护成本高。

通用 VLM 标注方法

调用 GPT-4o、Gemini 等大模型进行标注，成本高昂、单调重复，且难以捕捉原始数据中深层的程序性逻辑（procedural logic）。

核心洞察：数据处理应成为可学习能力

现有方法都是"被动标注"（passive annotation）——给定数据，机械地打标签。 论文的核心洞察是：数据处理本身应是一种可学习的高阶推理能力，Agent 需要理解用户意图、 主动推断数据中的因果关系与程序逻辑，然后有针对性地重组输出。 这一范式转变被称为 Agentic Data Tailoring。

关键问题（数据悖论）：训练一个能精炼数据的模型，本身就需要高质量的精炼数据——如何打破这一循环？ DataClaw₀ 的答案是：利用确定性的事实锚点（Factual Anchors）约束生成式语义合成，以低成本自动构建大规模训练集。

核心方法

DataClaw₀ 的方法论由两个紧密耦合的部分组成：数据集构建的两阶段流水线 和 基于 Factual Anchors 的语义合成机制。前者解决训练数据从哪来的问题， 后者保证生成数据的事实正确性与结构完整性。

第一阶段：确定性 Factual Anchors 提取

是什么：Factual Anchors（事实锚点）是从原始多模态流中用轻量级确定性工具提取的低级事实信息集合， 如物体状态、时间边界、OCR 识别文本、GUI 操作事件等。

为什么：纯粹依赖强 VLM 进行语义理解容易产生幻觉（hallucination），且成本高。 Factual Anchors 提供可靠的低级事实"地基"，将生成式合成约束在事实范围内， 有效防止语义漂移，同时大幅降低对昂贵 VLM 的依赖。

怎么做：针对不同领域使用专用工具：

  • 具身 AI 域：深度估计、物体检测、3D 位姿追踪（参考 ScanNet、Habitat 等）
  • GUI 域：UI 元素解析器、点击/滚动事件日志提取器
  • 日常生活 / 教育域：ASR（语音识别）、OCR、场景图解析
  • AIGC 域：编辑操作元数据解析、帧差分检测

这些工具输出的锚点集合 A 具有确定性（deterministic）——同一输入总产生相同结果， 可作为后续生成阶段的事实约束。

第二阶段：生成式语义合成

是什么：以 Factual Anchors A 和用户意图 I 为条件，调用强 VLM（如 Gemini） 进行长程逻辑链推理，生成符合 schema 的结构化输出 Y_struct。

为什么：单纯的锚点提取只有低级事实，缺乏高级语义理解和跨帧逻辑推理。 VLM 的生成能力弥补了这一缺口，而 Factual Anchors 则防止 VLM 的幻觉问题。 两者结合实现了"确定性事实 + 生成式语义"的互补。

怎么做：VLM 以 Factual Anchors 为离散节点，执行多模态思维链（Multimodal Chain-of-Thought）， 在时间维度上进行长程逻辑连接，最终输出经过后验锚点验证的结构化数据。 推理完成后，系统还会对照锚点集合 A 进行 post-hoc grounding verification， 确保输出内容与原始流保持事实一致性。

模型训练：SFT + GRPO

DataClaw₀-9B 的训练采用两阶段策略：先用 监督微调（SFT） 建立基础能力， 再用 组相对策略优化（GRPO） 进一步对齐复杂裁剪意图。 此外，论文还探索了 Omni 模型（统一处理所有域）和 Expert 模型（每域专用）两种部署范式。

GRPO 奖励函数设计

GRPO 的核心在于设计多维度奖励函数 R(Y)，引导模型输出既符合 schema 又忠实于原始流的结构化数据：

三维奖励函数

R(Y) = λ₁·R_format(Y, Φ) + λ₂·R_anchor(Y, A) + λ₃·R_eff(Y)

  • R_format：Schema 合规性检查——输出是否符合目标结构定义 Φ（字段完整性）
  • R_anchor：锚点对齐度——生成内容与提取的 Factual Anchors A 的语义一致性（语义忠实度）
  • R_eff：效率惩罚——抑制过度冗长的推理过程，鼓励简洁高效的输出

组内归一化优势估计：对采样的一组输出 {g}，GRPO 计算归一化优势 Â(g) = (R(g) − μ_R) / σ_R，以组内相对排名替代绝对奖励， 稳定训练过程并降低奖励方差。

实验结果

实验分为两大设置：Setting A（DataClaw₀-val 基准上的结构化输出质量评测） 和 Setting B（以下游 SFT 任务性能为终极验证标准的定向精炼评测）。 两个设置共同回答：DataClaw₀ 产出的数据是否真正有助于 AI 模型的适应与提升？

Setting A：DataClaw₀-val 基准评测

DataClaw₀-val 是论文构建的首个专用于数据精炼的基准，从三个维度评估结构化输出质量：

  • Field（字段完整性）：输出是否包含所有必需字段，格式是否正确
  • Semantic（语义忠实度）：输出内容是否与原始流语义一致
  • Sequence（序列连贯性）：时序事件的顺序是否正确

DataClaw-E（Expert 配置）在 Field（97.53）和 Semantic（74.94）维度上与 GPT-4o、Gemini-3.1-Pro 相当， Sequence（48.86）维度略低于 Gemini（58.50）但接近 GPT-4o（49.43）。 这说明 DataClaw₀ 在结构化输出质量上已达到闭源顶级 VLM 的水平。

Setting B：下游任务定向精炼

固定原始流数据和 SFT 训练预算，仅改变标注者（Gemini-3.1-Pro vs. DataClaw）， 在三个下游任务上评估最终模型性能：GUI 导航、动作视频生成、时空 VQA。

总结与启发

核心贡献总结

  • 范式创新：将多模态数据处理从"被动标注"提升为"主动裁剪"， 开创了 Agentic Data Tailoring 新范式，为 AI 后训练数据的自动化生产提供了新路径。
  • 工程创新：Factual Anchors 两阶段流水线巧妙解决了数据悖论—— 用确定性工具约束生成式合成，在保证事实准确性的前提下实现大规模自动化构建。
  • 模型创新：SFT + GRPO 的三维奖励设计（Format + Anchor + Efficiency） 为多模态结构化输出任务的强化学习提供了可参考的奖励工程范例。
  • 评测创新：DataClaw₀-val 是首个专用于数据精炼质量评估的基准， Field / Semantic / Sequence 三维度框架为后续研究提供了标准化评测协议。

对研究者的启发

数据飞轮思路

DataClaw₀ 的成功说明：用 AI 生产 AI 训练数据 的闭环是可行的。 关键在于用确定性锚点约束生成过程，防止"幻觉传播"。 这一思路可推广到任何需要从非结构化数据中提取结构化监督信号的场景。

下游验证优先

论文将"下游 SFT 任务性能"作为终极验证标准，而非仅看中间指标。 这提醒研究者：数据质量的最终裁判是下游任务表现， 而非标注一致性或人工评分等代理指标。

专家路由的价值

消融实验清晰展示了跨域混用的危害。 对于多域统一模型，域感知路由或混合专家（MoE）机制 可能是在保持统一部署的同时维持各域性能的关键设计选择。

GRPO 奖励工程

R_anchor 的引入将"事实锚点对齐"显式纳入强化学习目标， 为基于外部知识源的奖励信号设计提供了参考。 类似思路可用于其他需要事实一致性的生成任务（如 RAG、知识图谱填充）。

局限性与未来方向

  • 代码与权重尚未开源：论文承诺在接受后发布，目前仅有论文和项目主页可参考。
  • Sequence 维度仍有差距：DataClaw-E（48.86）与 Gemini（58.50）在序列连贯性上仍有约 10 点差距，长程时序推理是下一步优化重点。
  • 域覆盖的扩展：当前五个域主要覆盖视觉-动作类任务，音频、代码、科学文献等域的扩展有待探索。
  • 实时/流式处理：当前流水线面向离线批处理，在线实时数据裁剪的效率优化是潜在方向。
