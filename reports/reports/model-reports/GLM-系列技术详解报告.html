第二章：GLM 核心预训练目标——自回归填空

2.1 Autoregressive Blank Infilling 原理

传统语言模型分为两大范式：BERT 采用掩码语言模型（MLM），双向编码器随机掩码若干词并预测；GPT 采用因果语言模型（CLM），单向自回归预测下一个词。两者各有优劣：MLM 适合 NLU 任务但不能直接生成；CLM 能生成文本但对 NLU 任务支持有限。

GLM 提出了自回归填空目标，将二者统一：

  1. 在输入文本中随机采样若干连续片段（spans）并替换为 [MASK] 标记，形成被破坏的文本 $\mathbf{x}_{corrupt}$；
  2. 将被掩盖的 spans 重新排列（shuffle），拼接到文本末尾，形成生成目标序列；
  3. 使用自回归方式逐词预测每个 span 的内容，同时利用双向注意力处理前缀（已知上下文）。

设原始文本为 $\mathbf{x} = [x_1, \ldots, x_n]$，被掩盖的 spans 集合为 $\{s_1, \ldots, s_m\}$，GLM 的预训练目标为最大化：

$$\mathcal{L}_{GLM} = \mathbb{E}_{\mathbf{x}} \left[ \sum_{i=1}^{m} \sum_{j=1}^{|s_i|} \log p_\theta\!\left(s_{i,j} \;\Big|\; \mathbf{x}_{corrupt},\; s_{i,\lt j},\; \{s_k\}_{k \lt i}\right) \right]$$

其中 $s_{i,j}$ 为第 $i$ 个 span 的第 $j$ 个词，$s_{i,\lt j}$ 为该 span 中已生成的前缀。

2.3 为什么同时适合 NLU 和 NLG

双向上下文理解（NLU）：前缀部分（已知文本）使用完全双向注意力，模型可以充分利用上下文信息进行理解和推理，这与 BERT 的双向编码器能力相当。

自回归生成（NLG）：被掩盖的 spans 采用自回归方式生成，模型需要逐词预测，自然具备了生成能力。通过控制 span 的数量和长度，可以模拟从完形填空（NLU）到完整文本生成（NLG）的连续谱系。

统一架构优势：无需分别维护编码器和解码器，单一 Transformer 架构即可处理所有任务，大幅降低了工程复杂度，同时在两类任务上均能达到竞争性水平。

第三章：GLM-130B（2022）

3.1 架构概述

GLM-130B 是 GLM 预训练目标在超大规模下的首次验证，于 2022 年发布，是当时首批开源的 100B 量级双语大模型之一。

核心架构参数

  • 总参数量：130B（约1300亿）
  • Transformer 层数：70 层
  • 隐藏维度：12,288
  • 注意力头数：96 个
  • FFN 中间维度：49,152（4× 隐藏维度）
  • 位置编码：旋转位置编码（RoPE）
  • 归一化：DeepNorm（深层网络稳定化）
  • 激活函数：GeLU

3.2 DeepNorm 稳定化训练

训练超大规模模型时，梯度爆炸/消失是主要挑战。GLM-130B 采用 DeepNorm 技术，在残差连接前对隐状态进行缩放：

$$\text{DeepNorm}(\mathbf{x}) = \text{LayerNorm}(\alpha \cdot \mathbf{x} + f(\mathbf{x}))$$

其中 $\alpha$ 为缩放因子（对于 130B 模型约为 $2N^{1/4}$，$N$ 为层数），初始化时对 FFN 和注意力权重使用 $\beta = (8N)^{-1/4}$ 的缩放。这使得模型在训练初期的梯度范数保持稳定，避免了超大规模训练中常见的不稳定问题。

3.4 INT4 量化——几乎无损的推理压缩

GLM-130B 的一大工程亮点是 INT4 量化几乎无性能损失。通过对权重进行 4-bit 量化：

  • 模型大小从约 260GB（FP16）压缩至约 65GB（INT4），缩减 4×；
  • 可在单张 A100 80GB 上完成推理（原本需要 8×A100）；
  • 在主流 NLU/NLG 基准上，INT4 量化版本性能损失不超过 1%；
  • 这一发现极大降低了超大模型的部署门槛，推动了开源社区对 130B 级模型的广泛应用。

3.5 开源意义

GLM-130B 是全球首批开源的 100B+ 参数双语大模型之一，与 OPT-175B 同期发布，但 GLM-130B 具备更强的中文能力，且提供了完整的量化推理方案，显著降低了研究门槛。

第四章：ChatGLM-2 & ChatGLM-3（2023）

4.1 ChatGLM-2-6B 架构升级

2023 年，GLM 系列从超大规模转向高效小模型路线，ChatGLM-2-6B 引入了多项当时最先进的效率优化技术：

ChatGLM-2 关键技术

  • 多查询注意力（MQA）：所有注意力头共享同一组 Key/Value，大幅减少 KV Cache 内存占用，推理速度提升约 42%；
  • FlashAttention：IO 感知的注意力计算内核，通过分块计算减少 HBM 读写，在长序列上效率提升显著；
  • RMSNorm：替代 LayerNorm，去除均值计算，仅保留方差归一化，计算更高效；
  • SwiGLU 激活：$\text{SwiGLU}(x, W, V) = \text{Swish}(xW) \odot (xV)$，相比 GeLU 在推理质量上有所提升；
  • 预训练数据：1.4T tokens（较 ChatGLM-1 大幅扩充），包含更多代码和推理数据；
  • 上下文长度：基础 8K，通过 RoPE 外推可扩展到 32K。

4.2 ChatGLM-3 新能力

ChatGLM-3 在 ChatGLM-2 基础上重点强化了工具调用和代码执行能力：

  • Function Calling：原生支持结构化工具调用，可与外部 API 和数据库交互；
  • 代码解释器集成：内置 Python 代码执行环境，模型可以编写并运行代码来解决数学、数据分析等问题；
  • 多种上下文选项：提供 8K、32K、128K 三种上下文长度版本，适配不同场景；
  • 更强的指令跟随：通过大规模 RLHF 优化，对复杂多步骤指令的理解和执行能力显著提升；
  • 多轮对话一致性：改进了对话历史的建模，减少了跨轮信息丢失问题。

第五章：GLM-4 系列（2024）

5.1 GLM-4 系列概览

2024 年，GLM 系列推出了覆盖不同规模的 GLM-4 家族，包括 GLM-4（旗舰版）、GLM-4-9B（开源高效版）和 GLM-4-32B（中等规模版），同时推出了多模态版本 GLM-4V。

5.2 核心架构创新：GQA + YaRN

分组查询注意力（GQA）

GQA 是 MHA 和 MQA 之间的折中方案：将注意力头分成若干组，每组共享一对 K/V 头。设总头数为 $H$，组数为 $G$，则 KV 头数为 $G$（远小于 $H$）。相比 MQA，GQA 在保持大部分推理效率的同时，通常具有更好的模型质量。GLM-4 系列使用 GQA 替代 ChatGLM-2/3 的 MQA，在效率和质量之间取得更好平衡。

YaRN RoPE 外推到 128K

YaRN（Yet another RoPE extensioN）通过对 RoPE 的旋转频率进行非均匀缩放，使预训练于短上下文的模型能够外推到更长的序列。具体地，对不同频率分量采用不同的缩放策略：低频分量（对应长程依赖）使用线性内插，高频分量（对应局部依赖）保持不变。GLM-4 系列通过 YaRN 将上下文从预训练的 4K/8K 外推到 128K，在长文档理解任务上性能显著提升。

5.3 预训练规模

GLM-4 系列在 10-15T tokens 的高质量语料上进行预训练，数据来源包括：

  • 多语言网页文本（英文为主，中文次之，涵盖 40+ 语言）；
  • 代码仓库（GitHub 全量 + 精选代码网页）；
  • 学术论文和书籍；
  • 合成推理数据（数学、代码竞赛等）。

5.4 GLM-4V 多模态架构

GLM-4V 是 GLM-4 的多模态扩展版本，采用经典的视觉-语言融合架构：

GLM-4V 三段式架构

  1. 视觉编码器（ViT）：使用预训练的 Vision Transformer（如 EVA-CLIP ViT-E）对输入图像进行编码，输出图像特征序列；
  2. MLP 适配器：两层 MLP 投影层，将视觉特征维度对齐到语言模型的隐藏维度，实现模态桥接；
  3. GLM-4 解码器：以视觉特征和文本 token 的拼接作为输入，进行自回归文本生成。

5.5 3D-RoPE 与视频理解

为支持视频输入，GLM-4V 引入 3D-RoPE，将旋转位置编码从一维扩展到三维（时间 × 高度 × 宽度），使模型能够感知视频帧的时空位置关系，有效处理视频理解任务。

5.6 后训练：GRPO + RLCS

GLM-4 系列的多模态对齐采用了组合 RL 策略：

  • GRPO（Group Relative Policy Optimization）：对同一问题采样多个回答，以组内相对奖励替代绝对奖励，稳定训练；
  • RLCS（课程采样 RL）：根据问题难度动态调整采样策略，从易到难逐步提升模型能力。

第六章：GLM-4.5——ARC 三位一体开源旗舰（2025）

GLM-4.5 是智谱 AI 于 2025 年发布的旗舰开源模型，论文发表于 arXiv:2508.06471（2025年8月）。其核心目标是将Agentic（智能体）、Reasoning（推理）、Coding（编程）三大能力统一在一个模型中，形成"ARC 三位一体"能力框架。

"GLM-4.5 ranks 3rd overall among all evaluated models and 2nd on agentic benchmarks, with much fewer parameters than several competitors." — GLM-4.5 Technical Report

6.1 MoE 架构设计

GLM-4.5 是 GLM 系列首个采用混合专家（MoE）架构的模型。与 DeepSeek-V3 和 Kimi K2 不同，GLM-4.5 选择了减宽增高的设计哲学：降低隐藏维度和专家数量，增加层数，以获得更强的推理能力。

96 注意力头的反直觉发现

GLM-4.5 使用了 96 个注意力头，对于 5120 的隐藏维度而言，这是 DeepSeek-V3（128头/7168维）的 2.5 倍头密度。实验发现：更多的注意力头虽然不能降低训练 loss，但能持续提升推理基准（MMLU、BBH）上的性能。这一反直觉现象表明，注意力头数量影响的是模型的"推理多样性"而非拟合能力。

QK-Norm

GLM-4.5 独家引入 QK-Norm：在计算注意力分数前，对 Query 和 Key 向量进行 L2 归一化，稳定注意力 logits 的量级，防止极端值导致的训练不稳定。这是 GLM-4.5 在四个对比模型中唯一使用 QK-Norm 的。

MTP-MoE 加速推测解码

GLM-4.5 在标准 MoE 层之外，额外添加了一个 MTP（Multi-Token Prediction）层，该层同样采用 MoE 结构。MTP 层在训练时预测后续多个 token，在推理时作为草稿模型用于推测解码（Speculative Decoding），可显著提升推理吞吐量。

6.2 预训练数据

SemDedup 语义去重

传统 MinHash 去重只能发现字面相似的文档，无法处理模板化生成的语义相似网页。GLM-4.5 引入 SemDedup：基于文档嵌入向量计算语义相似度，移除语义重复但字面不同的文档，有效清理了大量自动生成的模板化内容。

多级质量桶（Nemotron-CC 启发）

受 Nemotron-CC 启发，GLM-4.5 将网页文档按质量分数划分为多个桶：

  • 最高质量桶：在预训练中贡献超过 3.2 个 epoch（重复训练），强化高频知识；
  • 最低质量桶：直接丢弃；
  • 中间桶：按质量权重采样。

FIM 目标（Fill-In-the-Middle）

所有代码数据均应用 FIM 训练目标：随机将代码片段分为前缀、中间、后缀三部分，重新排列后要求模型填充中间部分。这使模型在代码补全（不仅是代码续写）任务上表现更强。

合成推理数据

收集大量数学、科学、编程竞赛题目，使用推理模型合成高质量的思维链（Chain-of-Thought）解答过程，作为预训练数据的一部分，以增强模型的推理能力。

6.3 中训练三阶段

GLM-4.5 在预训练后，通过三个递进的中训练阶段逐步提升专项能力并扩展上下文长度：

6.4 超参数设计

Muon 优化器

GLM-4.5 使用 Muon 优化器替代传统 AdamW，对除词嵌入、偏置、RMSNorm 权重之外的所有参数进行优化。Muon 基于矩阵正交化（Newton-Schulz 迭代）对梯度进行处理，相当于在 Steepest Descent 方向上施加了谱范数约束。

  • Newton-Schulz 迭代步数 $N = 5$
  • 动量 $\mu = 0.95$
  • 更新 RMS 缩放至 $0.2$
  • 优势：加速收敛，容忍更大的 batch size

余弦调度 vs WSD 消融

GLM-4.5 使用余弦衰减学习率调度，而非 MiniCPM 等模型采用的 WSD（Warmup-Stable-Decay）调度。消融实验表明：WSD 调度在 stable 阶段存在欠拟合，导致 SimpleQA、MMLU 等通用基准性能下降。

  • 学习率从 0 warmup 至 2.5e-4，余弦衰减至 2.5e-5（持续到中训练结束）；
  • Batch size 从 16M tokens 逐步增加至 64M tokens（前 500B tokens 内完成），此后保持不变；
  • 权重衰减 0.1，不使用 dropout。

6.6 推理 RL 关键技术

两阶段课程难度学习

RL 训练过程中，模型能力不断提升，静态数据集会导致梯度信号退化（全 1 或全 0 奖励）。GLM-4.5 采用两阶段课程难度：

  • 第一阶段：使用中等难度数据（pass@8 > 0），每个 prompt 采样 16 个回答；
  • 第二阶段：切换到极高难度数据（pass@8 = 0 但 pass@512 > 0），每个 prompt 采样 512 个回答。

实验结果：两阶段方法在 AIME'24 上达到 83.4%，而继续使用中等难度数据的基线在 81.8% 处停滞。

单阶段最长输出（64K）优于多阶段渐进

先前研究建议通过逐步增加最大输出长度来进行 RL 训练（如 16K → 32K → 48K → 64K）。GLM-4.5 发现：直接在 64K 长度进行单阶段 RL 效果更好。原因：SFT 阶段已经让模型学会生成 64K 长度的回答，多阶段渐进会导致模型"遗忘"长输出能力，产生不可逆的性能下降。单阶段 64K 在 AIME'24 上达到 83.4%，多阶段仅 80.6%。

动态采样温度

固定采样温度在 RL 后期效果变差（策略分布收窄导致探索不足）。GLM-4.5 提出动态调整采样温度：当 rollout 平均奖励稳定时，增大温度以鼓励多样性；通过在验证集上评估不同温度，选择性能下降不超过 1% 的最大温度值作为下一阶段温度。

6.7 Agent RL

XML 工具调用模板

传统 JSON 格式工具调用在代码参数中需要大量转义字符，增加模型学习负担。GLM-4.5 提出基于 XML 特殊标签的工具调用模板：

<tool_call>get_weather
<arg_key>city</arg_key>
<arg_value>Beijing</arg_value>
<arg_key>date</arg_key>
<arg_value>2024-06-27</arg_value>
</tool_call>

这种格式将参数键值封装在 XML 标签内，代码内容无需转义，大幅降低了模型在工具调用场景下的学习难度。

步级 + 端到端双重 RL

  • 步级规则 RL：对每一步工具调用设置严格奖励（格式正确且完全匹配 ground truth 才得 1 分），强化格式规范性；
  • 端到端多轮 RL：以任务最终完成状态为奖励，允许模型通过试错自主探索最优行动策略，处理单轮多步和多轮多步两类任务。

GLM-5 于 2026 年 2 月发布（arXiv:2602.15763），标志着 GLM 系列从"辅助编程"迈向"自主工程"的范式转变。GLM-5 在 ArtificialAnalysis Intelligence Index v4.0 上首次以开源模型身份达到 50 分，成为开源第一。

7.1 架构升级：744B/40B

GLM-5 将总参数量从 GLM-4.5 的 355B 翻倍至 744B，激活参数量从 32B 增至 40B。主要架构变化：

  • 专家数量：从 160 扩展至 256 个专家；
  • 层数：减少至 80 层（降低专家并行通信开销）；
  • 注意力机制：从 GQA 升级为 MLA-256 + DSA（详见下节）；
  • MTP 参数共享：3 个 MTP 层共享参数（见 7.3 节）；
  • 训练数据：28.5T tokens（较 GLM-4.5 的 23T 增加约 24%）；
  • 最大上下文：200K tokens（较 GLM-4.5 的 128K 显著提升）。

7.2 MLA + Muon Split：突破 GQA 性能瓶颈

Multi-Latent Attention（MLA）

MLA 通过低秩压缩 KV Cache 节省显存：将 Key 和 Value 压缩到低维潜在向量（576 维），推理时从潜在向量重建完整的 KV，在节省显存的同时保持注意力质量。然而，GLM-5 发现：在 Muon 优化器下，576 维 MLA 无法匹配 GQA-8（2048 维 KV）的性能。

Muon Split：解决 MLA 性能差距

原始 Muon 优化器对整个投影矩阵 $W^{UQ}, W^{UK}, W^{UV}$ 进行矩阵正交化。GLM-5 提出 Muon Split：将这些矩阵按注意力头拆分为若干小矩阵，对每个头的矩阵独立进行正交化。这允许不同注意力头以不同尺度更新权重，有效弥补了 MLA 在 Muon 优化器下的性能缺口。

MLA-256：降低解码计算成本

标准 MLA 在解码时需要进行 576 维点积（高于 GQA 的 128 维）。GLM-5 将注意力头维度从 192 增加到 256，同时减少 1/3 的注意力头数，在保持训练计算量不变的情况下降低解码计算成本。

7.3 MTP 参数共享

标准 MTP 需要 $n$ 个独立 MTP 层来预测后续 $n$ 个 token，内存开销随推测步数线性增长。DeepSeek-V3 仅训练单个 MTP 层但在推理时预测 2 个 token，存在训练-推理不一致。GLM-5 提出共享 3 个 MTP 层的参数：训练时使用 3 个位置的预测，推理时 3 个 MTP 层共享同一套权重，在不增加内存的情况下提升推测接受率。

7.4 DSA（DeepSeek Sparse Attention）适配

DSA 的核心思想是用动态内容感知的稀疏注意力替代传统 $O(L^2)$ 稠密注意力：通过"Lightning Indexer"选择最重要的 top-k 个 KV 条目，只对选中的条目计算注意力，在 128K 上下文下将注意力计算量降低约 1.5-2×。

两阶段 DSA 适配

GLM-5 从中训练结束后的 MLA 基础模型出发，进行 DSA 适配：

  1. 热身阶段（1000步）：仅训练 DSA Indexer，冻结所有基础模型权重；每步训练 14 个序列 × 202,752 tokens；最大学习率 5e-3；
  2. 稀疏适配阶段（20B tokens）：联合训练模型和 Indexer，沿用中训练的数据和超参数。

尽管训练预算远小于 DeepSeek-V3.2（943.7B tokens），GLM-5 的 DSA 适配仅用 ~20B tokens 即完成，长上下文性能与原始 MLA 模型相当甚至更好。

7.9 异步 Agent RL

版本号丢弃策略

异步 RL 中，不同轨迹可能由不同版本的模型生成，导致严重的 off-policy 问题。GLM-5 的解决方案：记录每个 rollout 使用的模型版本序列 $(w_0, \ldots, w_k)$，若最旧版本 $w_0$ 与当前版本 $w'$ 的差距超过阈值 $\tau$（即 $w' - w_0 \gt \tau$），则丢弃该样本。

双边重要性采样（Direct Double-sided Importance Sampling）

异步 RL 中无法追踪历史策略检查点，GLM-5 直接用 rollout 时的 log-prob 作为行为策略代理，重要性采样比定义为：

$$r_t(\theta) = \exp\!\left(\log \pi_\theta(a_t|s_t) - \log \pi_{rollout}(a_t|s_t)\right)$$

双边 token 级裁剪函数：

$$f(x; \epsilon_\ell, \epsilon_h) = \begin{cases} x, & \text{if } 1 - \epsilon_\ell \lt x \lt 1 + \epsilon_h \\ 0, & \text{otherwise} \end{cases}$$

最终优化目标：

$$\mathcal{L}(\theta) = \mathbb{E}_t\!\left[f(r_t(\theta), \epsilon_\ell, \epsilon_h) \cdot \hat{A}_t \cdot \log \pi_\theta(a_t|s_t)\right]$$

7.10 On-Policy 跨阶段蒸馏

多阶段 RL 的顺序优化会导致灾难性遗忘。GLM-5 在最后阶段使用在线跨阶段蒸馏：以各阶段最终检查点为教师模型，优势函数替换为：

$$\hat{A}_{i,t} = \text{sg}\!\left[\log \frac{\pi_{\theta_{teacher}}^{infer}(y_{i,t}|x, y_{i,\lt t})}{\pi_\theta^{train}(y_{i,t}|x, y_{i,\lt t})}\right]$$

关键设计：group size 设为 1（无需多个样本估计优势），batch size 设为 1024，大幅提升数据吞吐量。

7.11 DSA RL 确定性 top-k

DSA Indexer 使用 top-k 选择最重要的 KV 条目。RL 训练中，CUDA 的非确定性 top-k 实现（SGLang 默认）导致训练-推理不一致，出现严重的性能退化（熵急剧下降）。GLM-5 的解决方案：在训练引擎中使用 torch.topk（确定性但略慢），并冻结 Indexer 参数以加速训练并防止 Indexer 不稳定学习。

8.2 同步模式 vs 异步模式

模式架构适用场景优势
同步（Colocated）训练引擎和推理引擎驻留在同一 GPU推理 RL（数学/代码生成）减少 GPU 空闲时间，结合动态采样最大化资源利用率
异步（Disaggregated）训练 GPU 和推理 GPU 独立调度Agent RL（SWE、长视野任务）Agent 环境持续生成数据，不被训练周期阻塞；支持 Ray 框架灵活调度

8.3 Tail-Latency 优化（长尾延迟）

RL rollout 的性能瓶颈不是平均吞吐量，而是最慢样本的完成时间（长尾延迟）。一个缓慢的轨迹会阻塞整个 batch 的同步点。Slime 采用多层次优化：

  • No-queue serving：多节点推理部署（如 EP64+DP64，跨 8 个节点），充足的分布式 KV Cache 容量避免请求排队；
  • FP8 rollout + MTP：FP8 精度推理降低每 token 延迟；MTP 在小 batch 解码场景（RL 典型场景）下对长尾样本有不成比例的加速效果；
  • PD 分离（Prefill-Decode Disaggregation）：多轮 RL 中长前缀 prefill 频繁，与 decode 混合会造成严重干扰。Slime 将 prefill 和 decode 分配到独立资源，decode 不被打断，长视野样本持续推进，显著改善长尾行为。

8.4 Heartbeat 心跳容错机制

大规模训练中，单个服务器崩溃、网络抖动或性能退化不可避免。Slime 的心跳容错：

  • Rollout 服务器定期向编排层发送心跳信号；
  • 编排层监控心跳，发现异常服务器后主动终止并从推理路由器中注销；
  • 后续请求自动路由到健康服务器，无需人工干预，保持 RL 训练连续性；
  • 从根本上防止单点故障中断整个 RL 训练流程。

8.5 多任务 Rollout Orchestrator

GLM-5 的后训练跨越推理 RL、Agent RL、通用 RL 等多种任务，每种任务有不同的工具集和 rollout 逻辑。Slime 的多任务编排器：

  • 每个任务实现为独立微服务，注册到中央编排器；
  • 编排器控制每个任务的 rollout 比例和生成速度，实现跨任务平衡数据收集；
  • 所有 agentic 任务的轨迹统一转换为消息列表格式，支持联合训练；
  • 支持 1000+ 并发 rollout，自动动态调整任务采样比例，细粒度监控任务进度。

8.6 混合精度训练/推理

Slime 支持训练使用 BF16，推理使用 FP8：每次策略更新迭代时，对模型参数进行在线分块 FP8 量化后分发给 rollout 引擎，实现高效 FP8 推理，大幅提升数据收集吞吐量。

第十章：核心技术演进脉络

10.1 预训练目标演进

GLM 系列的预训练目标从最初的自回归填空（统一 NLU/NLG）出发，逐步演进：

  • 2021-2022：自回归填空（ABI）——核心创新，奠定 GLM 技术基础；
  • 2023-2024：加入 FIM（Fill-In-the-Middle）代码目标，增强代码补全能力；
  • 2025：引入合成推理数据（CoT 轨迹）作为预训练数据，推理能力大幅提升；
  • 2026：NextLong + EntropyLong 合成长上下文数据，支持 200K 上下文。

10.2 规模化路线

GLM 系列的规模化路线呈现出清晰的三个阶段：

  1. 基础能力阶段（2021-2022）：从小模型验证预训练目标，到 130B 验证超大规模可行性；
  2. 效率优化阶段（2023-2024）：聚焦 6B-32B 高效小模型，MQA/GQA/FlashAttention 等效率技术；
  3. MoE 扩展阶段（2025-2026）：通过 MoE 架构实现参数量翻倍（355B→744B）而激活量保持可控（32B→40B），同时引入 DSA 降低长序列计算成本。

10.3 后训练范式演进

从 GLM-4.5 开始，GLM 系列建立了系统化的后训练范式：

  • 专家模型迭代（GLM-4.5）：先训练推理/Agent/通用三类专家，再蒸馏为统一模型；
  • 多阶段 RL 流水线（GLM-5）：SFT → 推理 RL → Agent RL → 通用 RL → 跨阶段蒸馏，每个阶段有明确目标；
  • 基础设施支撑：Slime 框架统一支持同步/异步两种模式，心跳容错保障稳定性，多任务编排器支持异构任务并行训练。
