一、LLM 评测的4种核心方法

原文：Understanding the 4 Main Approaches to LLM Evaluation (From Scratch) | Oct 2025

如何评测 LLM 是实际项目中最常被问到的问题之一。Sebastian 将评测方法梳理为四大类：每类有不同的适用场景、优缺点和实现复杂度。理解这四类构成了解读基准测试、排行榜和论文结果的基础。

1.1 方法一：多选题基准测试（MCQ Benchmarks）

是什么：给模型预设选项（A/B/C/D），让模型选择正确答案。代表基准：MMLU（57个学科）、ARC、HellaSwag、BoolQ。

优点：自动化程度高、可重复、成本低、跨模型可比较。

缺点：容易被"刷榜"——模型可能记住训练集中出现的题目（数据污染）；多选题格式与真实使用场景差距大；评测的是"选答案"而非"生成答案"的能力。

# 多选题评测核心代码
def evaluate_mcq(model, tokenizer, question, choices, correct_idx):
    prompt = f"Question: {question}\n"
    for i, c in enumerate(choices):
        prompt += f"({chr(65+i)}) {c}\n"
    prompt += "Answer: ("

    inputs = tokenizer(prompt, return_tensors="pt")
    with torch.no_grad():
        logits = model(**inputs).logits[0, -1]  # 最后一个token的logits

    # 比较 A/B/C/D 对应token的概率
    choice_tokens = [tokenizer.encode(f" {chr(65+i)}")[0] for i in range(len(choices))]
    choice_logits = logits[choice_tokens]
    pred_idx = choice_logits.argmax().item()
    return pred_idx == correct_idx

1.2 方法二：验证器评测（Verifier-Based）

是什么：用确定性程序检验答案是否正确，无需人工判断。最适用于数学（答案数值对比）和代码（单元测试通过率）。

优点：客观、无歧义、可大规模自动化。

代表基准：MATH（数学推理）、HumanEval/MBPP（代码生成）、GSM8K（小学数学）。

import urllib.request, json

def call_llm_streaming(prompt, model="gpt-4o"):
    """调用 OpenAI 流式 API"""
    payload = json.dumps({"model": model, "messages": [{"role":"user","content":prompt}], "stream": True})
    request = urllib.request.Request(
        "https://api.openai.com/v1/chat/completions",
        data=payload.encode(), method="POST",
        headers={"Authorization": f"Bearer {API_KEY}", "Content-Type": "application/json"}
    )
    response_data = ""
    with urllib.request.urlopen(request) as response:
        while True:
            line = response.readline().decode("utf-8")
            if not line: break
            response_json = json.loads(line)
            response_data += response_json["message"]["content"]
    return response_data

def verify_math_answer(model_output, correct_answer):
    """验证数学答案"""
    import re
    # 提取模型输出中的最终答案
    match = re.search(r'\\boxed\{([^}]+)\}', model_output)
    if match:
        return match.group(1).strip() == str(correct_answer)
    return False

1.3 方法三：人类偏好排行榜（Human Preference Leaderboards）

是什么：真实用户盲测——同时看两个模型的回答，选哪个更好。Chatbot Arena（LMSYS）是最典型代表，用 Elo 评分体系。

优点：最接近真实用户体验，难以被"刷榜"（因为用户不知道是哪个模型）。

缺点：成本高、耗时长、受用户群体偏差影响（参与者大多是技术用户）；长文本和专业领域任务覆盖不足。

1.4 方法四：LLM-as-Judge

是什么：用一个强大的 LLM（如 GPT-4、Claude）充当评委，对被测模型的输出打分或做偏好判断。

优点：比 MCQ 更全面（可以评测开放式生成）；比人类评测便宜快速；可以给出详细理由。

缺点：存在位置偏见（倾向于选第一个回答）、自我增强偏见（Claude 偏向 Claude）；对超出评委模型能力的问题无法准确评分。

def llm_judge(response_a, response_b, question, judge_model="gpt-4o"):
    """使用 LLM 做偏好判断"""
    prompt = f"""你是一位公正的评委。请比较以下两个回答的质量。

问题: {question}

回答A: {response_a}

回答B: {response_b}

请判断哪个回答更好，并给出理由。最后用 [[A]] 或 [[B]] 表示你的选择。"""
    result = call_llm_streaming(prompt, judge_model)
    if "[[A]]" in result: return "A"
    if "[[B]]" in result: return "B"
    return "tie"

二、2025 年 LLM 进展回顾

原文：The State Of LLMs 2025: Progress, Problems, and Predictions | Dec 2025

2025 年是 LLM 领域的"推理年"——从 DeepSeek R1 到 RLVR，推理模型的崛起重新定义了什么叫做"强大的 LLM"。

2.1 年度最重要进展

DeepSeek R1 与 RLVR 范式

DeepSeek R1 证明：通过可验证奖励强化学习（RLVR），无需大量人工标注即可训练出极强的推理模型。"可验证"意味着可以用确定性程序判断答案是否正确（数学结果、代码测试通过）。这一范式的意义在于数据标注成本从"人工偏好对"降低到"题目+标准答案"。

推理时计算 Scaling

o1、DeepSeek R1 等模型证明：在推理时花更多计算（生成更长的思维链）可以大幅提升性能。这与传统的"更大模型=更聪明"形成了新的维度。

开源生态的爆发

Llama 3、Qwen2.5、Mistral 等开源模型快速追赶闭源模型，某些任务上开源模型已经超越 GPT-4（2023版）。DeepSeek V3 的发布更是震动了整个行业——以极低训练成本实现顶级性能。

2.2 主要挑战（Problems）

  • 基准污染：训练数据中可能包含测试集，导致高分不代表真实能力
  • 幻觉问题：模型仍然以高置信度给出错误信息
  • 长上下文可靠性：即使支持 128k+ 上下文，中间位置信息仍容易被忽略
  • 推理成本：推理时 Scaling 大幅提升了推理计算成本

2.3 2026 年预测

  • 经典 RAG 将逐渐淡出作为默认方案——长上下文 + 更好的小型开源模型将替代它
  • 多模态推理模型将成为标配
  • 推理时 Scaling 的成本优化将是关键工程方向
  • Agent 系统将从实验走向生产部署

三、2024 年度 AI 研究论文精选

原文：Part One | Part Two

3.1 上半年亮点（Part One）

2024 Q1Mixtral 8x7B（MoE 大众化）
Mistral 将 MoE 架构带入开源社区。每个 FFN 层替换为 8 个专家子网络，每次只激活 2 个，在保持推理计算量不变的同时大幅增加有效参数量。关键洞察：路由机制让不同专家专注不同 token 类型，而非如最初假设的"专注不同任务"。
2024 FebDoRA：权重分解低秩自适应
将预训练权重矩阵分解为幅度向量和方向矩阵，LoRA 只更新方向，同时单独训练幅度。实验表明 DoRA 在多个基准上优于 LoRA，且升级成本很低。
2024 Q2推断时计算扩展（Snell et al.）
系统研究了在模型权重不变的情况下，增加推理计算能提升多少性能。关键发现：小模型 + 推断时 Scaling 可超越大模型直接输出，为后来的 o1 奠定了理论基础。

3.2 下半年亮点（Part Two）

2024 AugTulu 3：开放式 LLM 后训练的完整配方
Allen AI 发布了详细的 Llama 后训练方法论，包含 DPO vs PPO 的系统性消融实验，以及新提出的用可验证问题做奖励的对齐方法（RLVR 的早期形式）。
2024 NovLLM 精度 Scaling 定律
将原始 Chinchilla Scaling Laws 扩展，加入"精度"维度 P。模型参数量 N 被重新解释为"有效参数量"，随精度降低而缩减。为低精度训练（FP8、FP4）提供了理论框架。DeepSeek V3 即在此理论支撑下用 FP8 训练。
