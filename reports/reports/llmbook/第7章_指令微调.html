第7章 指令微调（Instruction Tuning / SFT）

《大语言模型》 | 第7章 · PDF第150–177页 | 涵盖指令数据构建、SFT训练策略、参数高效微调（PEFT）全链路

指令微调（Instruction Tuning）是指使用自然语言形式的数据对预训练后的大语言模型进行参数微调，由谷歌研究员在2022年ICLR论文中正式提出。也称为有监督微调（SFT, Supervised Fine-tuning）或多任务提示训练。经过指令微调后，大语言模型能够展现出较强的指令遵循能力，可以通过零样本学习方式解决多种下游任务。

7.1 指令数据的构建

一个经过指令格式化的数据实例通常包含三个部分：任务描述（指令）、任务输入-输出以及可选的上下文示例。构建高质量指令数据集是指令微调成功的前提，主要有三条路径。

7.1.1 基于现有NLP任务数据集构建

学术界围绕传统NLP任务（机器翻译、文本摘要、文本分类等）发布了大量开源数据集。关键步骤是为已有的"输入-输出"对添加任务描述（指令），将其转化为指令格式。研究表明，去除任务描述后模型性能会显著下降，说明任务描述是指令跟随能力的关键。

众包平台 PromptSource 支持标注人员高效创建、共享和验证任务描述。还可通过"翻转输入-输出"创建新任务（如从答案生成问题）来丰富数据。

谷歌研究人员混合 FLAN、P3、Super-Natural Instructions 和思维链数据，推出了包含约 20M 条实例的 FLAN v2，是目前面向NLP任务微调大模型的首选指令集合。

7.1.2 基于日常对话数据构建

NLP任务数据多样性有限，与人类真实需求匹配度不高。InstructGPT 使用用户提交给 OpenAI API 的真实查询作为任务描述，并雇佣标注者撰写开放式生成、问答、头脑风暴等任务及对应答案。代表性开源数据集：

  • ShareGPT：63K 条真实用户与 ChatGPT 的多轮对话数据
  • OpenAssistant：人工精心标注，质量较高
  • Dolly：人工标注的开放任务数据集

7.1.3 基于合成数据构建（LLM自动生成）

半自动化合成方法借助已有高质量指令数据作为上下文示例，提示大语言模型生成大量多样化的任务描述和输入-输出数据。

Self-Instruct

仅需 175 条人工撰写的种子指令作为初始任务池，通过两个主要步骤迭代生成：

  1. 指令数据生成：随机选取少量指令作为示例，提示 ChatGPT/GPT-3 仿照生成新的任务描述和对应输出
  2. 过滤与后处理：去除与任务池相似度过高的指令、模型难以响应的指令、过长/过短指令及重复实例

原始论文使用 GPT-3 合成了 Self-Instruct-52K，Alpaca 使用 text-davinci-003 合成了 Alpaca-52K。

Evol-Instruct（WizardLM）

基于初始指令集（如 Alpaca）进行演化，包含两个方向：

  • 深度演化：通过添加约束、深化、具体化、增加推理步骤、使输入复杂化等5种方式使指令更难
  • 广度演化：扩充指令主题范围、能力范围和整体数据集多样性

数据后处理：移除差异很小的指令、含"sorry"的响应、过短响应及仅含标点/连词的指令。已扩展至 WizardMath、WizardCoder 等领域。

7.1.5 指令微调的作用

  • 整体任务性能改进：不同规模（77M~540B）的模型均可受益；经过指令微调的小模型甚至可超过未微调的大模型；成本仅为预训练的约万分之一
  • 任务求解能力增强：无需下游任务示例即可解决未见过的任务；英文指令微调可泛化到其他语言（BLOOMZ-P3 多语言任务提升超50%）
  • 领域专业化适配：Med-PaLM（医学）、本草（中文医学）、法律/金融领域均有成功案例

7.2 指令微调的训练策略

指令微调与预训练在优化器（AdamW/Adafactor）、稳定训练技巧（权重衰减、梯度裁剪）和训练技术（3D并行、ZeRO、混合精度）上保持一致，以下重点介绍差异部分。

7.2.1 优化设置

目标函数：序列到序列损失（Loss Masking）

预训练阶段优化每一个词元上的语言建模损失；指令微调采用序列到序列损失，仅在输出部分计算损失，输入部分的损失被掩码（mask）为 -100（IGNORE_INDEX）。

多轮对话数据的高效训练

传统做法是将多轮对话拆分成多个单独对话训练（效率低，重复计算前缀）。高效方法：将整个多轮对话一次性输入模型，通过损失掩码仅对每轮对话的模型输出部分计算损失，显著减少重复前缀计算开销。

7.3 参数高效的模型微调（PEFT）

由于大语言模型参数量巨大，全参数微调需要大量算力资源。参数高效微调（PEFT, Parameter-efficient Fine-tuning）旨在减少需要训练的模型参数量，同时保证微调后的模型性能能够与全量微调相媲美。

7.3.1 LoRA：低秩适配微调

LoRA（Low-Rank Adaptation）的核心洞察：模型在针对特定任务进行适配时，参数矩阵往往是过参数化（Over-parametrized）的，存在一个较低的内在秩。

数学原理

参数更新的一般形式：

$$\mathbf{W} = \mathbf{W}_0 + \Delta\mathbf{W} \quad \text{(7.1)}$$

LoRA 低秩分解：冻结 $\mathbf{W}_0 \in \mathbb{R}^{H \times H}$，用低秩矩阵近似参数更新：

$$\Delta\mathbf{W} = \mathbf{A} \cdot \mathbf{B}^\top, \quad \mathbf{A} \in \mathbb{R}^{H \times R},\ \mathbf{B} \in \mathbb{R}^{H \times R},\ R \ll H$$

前向传播修改：

$$\mathbf{h} = \mathbf{W}_0 \cdot \mathbf{x} + \mathbf{A} \cdot \mathbf{B}^\top \cdot \mathbf{x} \quad \text{(7.2)}$$

推理时参数合并（无额外开销）：

$$\mathbf{W} = \mathbf{W}_0 + \mathbf{A} \cdot \mathbf{B}^\top$$

初始化策略

  • 矩阵 A：使用标准差为 0.02 的正态分布初始化（$\mathcal{N}(0, 0.02^2)$）
  • 矩阵 B：初始化为全零矩阵，确保训练开始时 LoRA 分支输出为零，不影响原始模型行为
  • 训练期间：$\mathbf{W}_0$ 冻结不更新，仅 $\mathbf{A}$ 和 $\mathbf{B}$ 参与梯度更新

应用位置

LoRA 主要被应用在每个多头注意力层的 4 个线性变换矩阵上：$\mathbf{W}_Q, \mathbf{W}_K, \mathbf{W}_V, \mathbf{W}_O \in \mathbb{R}^{H \times H}$

显存节省分析

设 LoRA 可训练参数量为 $P_\text{LoRA}$，模型原始参数为 $P$：

$P_\text{LoRA} = 4 \times 2 \times L \times H \times R$（$L$=层数，$H$=隐藏维度，$R$=秩）

全量微调显存：$16P$（参数2P + 梯度2P + 优化器12P，混合精度）

LoRA 微调显存：$2P + 16P_\text{LoRA}$（原始参数2P + LoRA参数/梯度/优化器）

以 LLaMA (7B) 为例（$L=32, H=4096, R=8$）：

  • $P_\text{LoRA} = 8,388,608 \approx 8M$
  • 全量微调：$16P \approx 108\text{GB}$
  • LoRA 微调：$2P + 16P_\text{LoRA} \approx 14\text{GB}$
  • 因 $P_\text{LoRA} \ll P$，近似：LoRA 显存从 $16P$ 降至 $\approx 2P$

PyTorch 代码实现

# LoRA 线性层实现（来源：LLMBook 第7章）
class LoRALinear(nn.Linear):
    def __init__(self, in_features, out_features, config, bias=True):
        super().__init__(in_features, out_features, bias=bias)
        self.r = config.lora_r  # 低秩 R

        # A：输入 → 低秩空间 R
        self.A = nn.Linear(in_features, self.r, bias=False)
        # B：低秩空间 R → 原始输出空间
        self.B = nn.Linear(self.r, out_features, bias=False)

        self.dropout = nn.Dropout(p=config.lora_dropout)

        # 初始化：A 用正态分布，B 全零（保证初始输出不变）
        self.A.weight.data.normal_(std=0.02)
        self.B.weight.data.zero_()

    def forward(self, input):
        # 原始权重输出（W0·x）
        linear_output = F.linear(input, self.weight, self.bias)
        # LoRA 分支输出（B·A·x）
        lora_output = self.B(self.A(self.dropout(input)))
        # 合并：h = W0·x + B·A·x
        return linear_output + lora_output

LoRA 变种

变种 改进点 核心机制
AdaLoRA 固定秩 R 忽略不同矩阵差异 动态调整每个参数矩阵的秩：重要矩阵赋高秩，不重要矩阵赋低秩，总参数量受控
QLoRA LoRA 对百亿级模型仍成本高 原始参数矩阵量化为 4-bit（NF4），低秩参数仍用 16-bit 训练；显存从 $2P$ 进一步降至 $0.5P$；可在单张 A6000 (48GB) 上微调 65B 模型
QLoRA 的 NF4 量化原理：NF4（NormalFloat 4-bit）是一种专为正态分布权重设计的量化格式。它通过分位数量化（Quantile Quantization）使得每个量化区间包含等数量的权重值，相比均匀量化在正态分布数据上信息损失更小。原始矩阵 $W_0$ 以 NF4 存储（节省 4× 显存），前向传播时动态反量化（dequantize）为 BF16 参与计算，LoRA 分支 $A, B$ 始终以 BF16 训练。

7.3.2 适配器微调（Adapter Tuning）

在 Transformer 模型的每一层中引入小型神经网络模块（适配器）。采用瓶颈网络架构：先压缩到低维，非线性变换，再恢复到原始维度。

适配器前向计算（串行插入，位于注意力层和FFN层之后、层归一化之前）：

$$\mathbf{h} = \mathbf{h} + \sigma(\mathbf{h} \cdot \mathbf{W}_d) \cdot \mathbf{W}_u \quad \text{(7.3)}$$

其中 $\mathbf{W}_d \in \mathbb{R}^{H \times R}$（下映射），$\mathbf{W}_u \in \mathbb{R}^{R \times H}$（上映射），$R \ll H$，$\sigma$ 为激活函数。

微调时只更新适配器参数，原始模型参数冻结。

7.3.3 前缀微调（Prefix Tuning）

在语言模型的每个多头注意力层中添加一组可训练的前缀参数（连续矩阵），可视为若干虚拟词元的嵌入向量。

带前缀的注意力计算（基于原始注意力公式扩展）：

$$\text{head} = \text{Attention}(\mathbf{X}\mathbf{W}_Q,\ \mathbf{P}_K \oplus \mathbf{X}\mathbf{W}_K,\ \mathbf{P}_V \oplus \mathbf{X}\mathbf{W}_V) \quad \text{(7.4)}$$

其中 $\oplus$ 表示矩阵拼接，$\mathbf{P}_K, \mathbf{P}_V \in \mathbb{R}^{L \times H}$，$L$ 为前缀长度（通常 10~100，可按任务调整）。

重参数化技巧：引入 MLP 映射函数 $\mathbf{P} = \text{MLP}_\theta(\mathbf{P}')$，将较小矩阵映射到前缀参数，稳定训练。训练完成后丢弃 MLP，只保留最终前缀参数 $\mathbf{P}$。

整个模型中只有前缀参数会被训练，实现参数高效优化。

7.3.4 提示微调（Prompt Tuning）

与前缀微调不同，提示微调仅在输入嵌入层中加入可训练的提示向量（不在每层注意力中添加）。训练时只有提示嵌入向量根据特定任务进行监督学习。

  • P-tuning：自由形式组合输入文本和提示向量，通过双向LSTM学习软提示词元表示，适用于NLU和NLG任务
  • Prompt Tuning：以前缀形式添加提示，直接在输入前拼接连续型向量；性能高度依赖底层语言模型能力

PEFT 方法综合对比

方法 插入位置 可训练参数 推理额外开销 显存节省 适用场景

7.4.2 指令微调实验结果分析

使用 LLaMA-2 (7B/13B) 在三种指令数据集（FLAN v2、ShareGPT、Alpaca）和两种增强策略（复杂化、多样化）上进行对比实验，评测日常对话（AlpacaFarm 胜率）和 NLP 任务（MMLU、BBH 准确率）。

三大核心结论

  • 与下游任务格式匹配的指令带来更大提升：FLAN v2 在 NLP 任务（MMLU/BBH）上优于 ShareGPT 和 Alpaca，但在日常对话（AlpacaFarm）上远不如 ShareGPT；ShareGPT 真实世界对话最适合引导日常对话任务
  • 提高复杂性和多样性能促进模型性能提升：多样化策略使 LLaMA-2 (13B) 对话胜率从 48.51 提升到 58.20，接近 ShareGPT 水平
  • 更大参数规模有助于提升指令遵循能力：13B 在所有情况下均优于 7B，尤其在 NLP 任务上提升显著（ShareGPT 上 MMLU：49.66→56.81）

关键要点速记

  • LoRA 公式：$\mathbf{W}' = \mathbf{W}_0 + \mathbf{A}\mathbf{B}^\top$，A 正态初始化，B 零初始化，推理时合并无额外开销
  • QLoRA：基础权重 NF4 4-bit 量化，LoRA 分支 BF16，显存从 $2P$ 降至 $0.5P$，可单卡微调 65B
  • SFT 损失：仅对输出 token 计算损失，输入部分标签设为 -100（IGNORE_INDEX）
  • 数据质量 > 数量：1K 高质量 LIMA 可接近 52K Alpaca 效果；指令格式要与下游任务匹配
  • FLAN v2 混合比：FLAN 46%、T0 27.9%、NIV2 24.2%、CoT 1.8%
  • LLaMA (7B) LoRA 显存：$R=8$ 时从 108GB 降至 14GB，$\approx 8\times$ 节省
