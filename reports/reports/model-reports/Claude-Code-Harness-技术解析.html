Claude Code Harness 工程解析

来源：~/.claude/ 本地源码 · ~/.local/share/claude/ 二进制  |  版本：Claude Code 2.1.141–2.1.146 · Superpowers Plugin 5.1.0  |  参考仓库：github.com/obra/superpowers

概述

Claude Code 的"harness"是一套将 Claude 模型包裹在工程化 Workflow 中的运行时框架，核心目标是：在不修改模型权重的前提下，通过上下文注入、生命周期钩子、技能加载机制，稳定驱动 Claude 按照特定工程流程（TDD、系统调试、并行代理分发等）工作。本报告基于本机暴露的源码，全面解析 harness 的架构设计、关键实现机制和工程决策。

Claude Code 本体是闭源的 Mach-O 编译二进制（~/.local/bin/claude），但其 Plugin/Skill 层完全开源。核心可见层为 Superpowers 插件（MIT 开源，Jesse Vincent 主导），它承担了全部 harness 工程。

1. 整体架构

Claude Code harness 由三层组成：最底层是闭源的 Claude Code 二进制（提供 API、Tool 调用、会话管理等基础能力）；中间层是 Plugin 系统（负责扩展能力加载与生命周期管理）；最上层是 Skills 系统（基于 Markdown 文件的行为规范内容）。

3. Bootstrap 注入机制

Bootstrap 注入是 harness 最核心的机制——它让 Claude 在每个会话开始时就"知道"自己拥有超能力（Superpowers），并在 1% 相关概率时主动调用技能。这个机制有两条并行路径。

3.1 Claude Code 路径：SessionStart Hook

  Note over CLAUDE: 收到 <EXTREMELY_IMPORTANT>

session-start 是一个精心设计的 Bash/Windows cmd 聚合脚本（polyglot script），无需文件扩展名即可在 Windows（via Git Bash）和 Unix（直接 bash）两个平台上执行。JSON 转义不使用逐字符循环，而是通过 Bash 参数展开的 C 级字符串替换实现（性能大幅优于循环）：

escape_for_json() {
    local s="$1"
    s="${s//\\/\\\\}"   # 反斜杠
    s="${s//\"/\\\"}"   # 双引号
    s="${s//$'\n'/\\n}" # 换行
    s="${s//$'\r'/\\r}" # 回车
    s="${s//$'\t'/\\t}" # Tab
    printf '%s' "$s"
}

3.2 OpenCode 路径：Messages Transform Hook

OpenCode 平台使用 JS 模块加载，通过 experimental.chat.messages.transform 钩子在每个 agent step 检查并注入 bootstrap：

// superpowers.js（已截取关键部分）
'experimental.chat.messages.transform': async (_input, output) => {
  const bootstrap = getBootstrapContent(); // 使用模块级缓存
  if (!bootstrap || !output.messages.length) return;
  const firstUser = output.messages.find(m => m.info.role === 'user');
  if (!firstUser || !firstUser.parts.length) return;

  // 幂等保护：防止重复注入
  if (firstUser.parts.some(p => p.type === 'text' &&
      p.text.includes('EXTREMELY_IMPORTANT'))) return;

  // 将 bootstrap 插入用户消息的第一个 part
  const ref = firstUser.parts[0];
  firstUser.parts.unshift({ ...ref, type: 'text', text: bootstrap });
}
为什么注入到用户消息而非系统提示？
  • Token 膨胀：系统提示在每轮都会重复计入，用户消息只在首轮注入一次（Issue #750）
  • 模型兼容性：多个系统消息会破坏 Qwen 等模型的处理（Issue #894）
  • 缓存效率：前缀可缓存，减少每步推理的 token 计算

3.3 Bootstrap 内容缓存

模块级变量 _bootstrapCache（undefined=未加载，null=文件不存在）确保每个会话只做一次磁盘 I/O，后续所有 agent step 直接返回内存缓存：

let _bootstrapCache = undefined; // 模块级缓存

const getBootstrapContent = () => {
  if (_bootstrapCache !== undefined) return _bootstrapCache; // 命中缓存直接返回
  const skillPath = path.join(superpowersSkillsDir, 'using-superpowers', 'SKILL.md');
  if (!fs.existsSync(skillPath)) { _bootstrapCache = null; return null; }
  const fullContent = fs.readFileSync(skillPath, 'utf8');
  const { content } = extractAndStripFrontmatter(fullContent);
  _bootstrapCache = `<EXTREMELY_IMPORTANT>\nYou have superpowers.\n\n${content}\n...</EXTREMELY_IMPORTANT>`;
  return _bootstrapCache;
};

4. Hooks 系统

Hooks 是 harness 的生命周期管理层，允许在 Claude Code 特定事件点触发外部命令。当前 Superpowers 只使用了 SessionStart 钩子，但系统设计支持多种事件。

4.1 hooks.json 结构

{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|clear|compact",
        "hooks": [
          {
            "type": "command",
            "command": "\"${CLAUDE_PLUGIN_ROOT}/hooks/run-hook.cmd\" session-start",
            "async": false
          }
        ]
      }
    ]
  }
}
Matcher 语义
  • startup：全新会话启动
  • clear：用户执行 /clear 重置上下文
  • compact：系统自动压缩会话历史（上下文接近上限）

每次这三种事件发生，bootstrap 都会重新注入，确保 Claude 在任何新的"起点"都能感知到 Superpowers。

4.2 run-hook.cmd 跨平台设计

run-hook.cmd 是一个精妙的跨平台 Bash/cmd 聚合脚本。文件开头用 : << 'CMDBLOCK' 实现：在 Unix 下 : 是空操作，整个 CMDBLOCK 被忽略；在 Windows cmd.exe 下，@echo off 到 exit /b 之间是有效的批处理代码。

: << 'CMDBLOCK'
@echo off
REM Windows 路径：尝试 Git Bash → PATH bash → 静默退出
if exist "C:\Program Files\Git\bin\bash.exe" (
    "C:\Program Files\Git\bin\bash.exe" "%HOOK_DIR%%~1" ...
)
CMDBLOCK

# Unix 路径：直接 exec bash
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
exec bash "${SCRIPT_DIR}/${1}" "${@:2}"

不使用 .sh 扩展名是为了规避 Claude Code Windows 版的自动 bash 前缀检测（会对 .sh 文件自动加 bash，但运行器自身不需要）。

5. Skills 系统

Skills 是 harness 的"行为规范层"，用 Markdown 文件编码了一套经过实战验证的 AI 工程工作流。每个 SKILL.md 文件都遵循相同的结构：YAML frontmatter（供 Skill 工具发现）+ Markdown 正文（供模型阅读执行）。

5.3 "铁律"模式（Iron Law Pattern）

所有关键技能都采用"铁律"设计模式：用大写加粗的不可协商规则 + "Red Flags"理性化防御表来抵抗 AI 的自我说服倾向：

铁律示例（TDD）
NO PRODUCTION CODE WITHOUT
A FAILING TEST FIRST

Write code before the test?
Delete it. Start over.
Not "keep as reference."
Not "adapt while writing tests."
Delete means delete.
Red Flags 防理性化表
错误想法现实
"This is just a simple question"Questions are tasks.
"I need more context first"Skill check comes BEFORE.
"I remember this skill"Skills evolve. Read current.

7. MCP 集成

Model Context Protocol（MCP）是 Claude Code 的外部工具扩展协议，允许将任意 API 作为工具注册给 Claude 使用。配置通过 ~/.claude/mcp.json 声明：

{
  "mcpServers": {
    "tavily": {
      "command": "npx",
      "args": ["-y", "tavily-mcp@latest"],
      "env": { "TAVILY_API_KEY": "..." }
    }
  }
}

Claude Code 在启动时通过 npx 动态加载 MCP 服务器进程，通过标准输入/输出进行 JSON-RPC 通信。工具调用结果直接可用于 Claude 的上下文。

8. 持久化记忆系统

Claude Code 内置了一套基于文件的记忆系统，存储在 ~/.claude/projects/{project-path}/memory/。每条记忆是一个独立的 Markdown 文件，通过 YAML frontmatter 标注类型和描述：

---
name: user-role
description: 用户是数据科学家，专注于 LLM 推理与训练优化
metadata:
  type: user
---

用户是 ML 工程师，熟悉 Python/PyTorch，当前专注于 RL 训练相关研究。
偏好简洁回答，不喜欢过多解释性文字。

记忆分为四类：user（用户画像）、feedback（行为反馈）、project（项目上下文）、reference（外部系统引用）。通过 MEMORY.md 索引文件管理，前 200 行自动加载到会话上下文。

10. 关键工程设计决策

通过源码分析可以归纳出 harness 工程的核心设计哲学：

设计决策问题解决方案权衡
注入到用户消息而非系统提示 系统提示每轮重复计 token；Qwen 等模型多系统消息不兼容 在首条用户消息前插入 bootstrap 内容 用户消息可见，但实际使用中不影响体验
模块级缓存 bootstrap 内容 每个 agent step 都重新读盘解析 SKILL.md 代价高 _bootstrapCache 模块变量，首次加载后永久缓存 会话内 SKILL.md 修改不生效（可接受）
零外部依赖 添加 npm 依赖增加安全面和维护负担 纯 Node.js 内置模块（fs/path/os/url） 功能受限，但稳定可控
Polyglot hook 脚本 Windows/Unix 需要不同的脚本执行方式 Bash/cmd 聚合脚本 + 无扩展名文件名 脚本稍复杂，但跨平台免维护
SKILL.md frontmatter 元数据 技能发现需要结构化元数据，内容需要人类可读 YAML frontmatter + Markdown 正文混合格式 解析需要额外代码，但人机友好
SUBAGENT-STOP 守卫 子 Agent 收到 bootstrap 后会重复检查技能，浪费 token <SUBAGENT-STOP> 标签跳过 bootstrap 执行 需要所有子 Agent dispatch 时明确指定
Bash 参数展开 JSON 转义 逐字符循环转义 JSON 对长文档极慢 连续 ${s//old/new} C 级字符串替换 可读性略低，但性能数量级提升

12. 总结：Harness 的本质

Claude Code harness 工程的本质是一套轻量级的"行为契约注入系统"：通过 SessionStart 钩子在每个会话开始时将工程工作流规范注入模型上下文，再通过 Skill 工具按需加载具体流程，实现了不修改模型、不依赖微调、仅靠上下文工程就能稳定驱动 AI 按照特定工作流工作的目标。

设计哲学总结
  • 上下文即代码：SKILL.md 是可版本管理、可审查、可测试的"行为代码"
  • 铁律 + Red Flags 防御：通过显式列出理性化借口来对抗 AI 的自我说服倾向
  • 技能=懒加载模块：Bootstrap 只注入目录引导，具体技能在需要时才加载，避免 token 浪费
  • 平台无关设计：相同的 skills 通过不同的注入路径支持 5+ 个 AI 编码平台
  • 零依赖原则：插件本身无 npm 依赖，降低安全面和维护成本
  • 人工审查节点：所有关键 PR 工作流都要求人工参与，防止 AI 在高风险操作上自作主张
