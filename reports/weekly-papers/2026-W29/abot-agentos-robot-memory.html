ABot-AgentOS：面向长时序具身 agent 的通用机器人 Agent OS 与终身多模态记忆

1. 概述

标题ABot-AgentOS: A General Robotic Agent OS with Lifelong Multi-modal Memory
arXiv ID2607.10350 (v2, 2026-07-15)
核心问题VLM/VLA 提升了机器人感知与动作预测，但长时序具身 agent 仍缺一个通用运行时层（推理 / 记忆 / 工具 / 验证 / 跨体态执行）；ABot-AgentOS 在低层控制器之上提供 deliberative agent 层
机构AMAP CV Lab（高德 / Alibaba Group）
作者Jiayi Tian 等 33 位作者；Project Lead：Mingyang Yin、Zedong Chu（通讯作者）
项目主页https://amap-cvlab.github.io/ABot-AgentOS
配套基准EmbodiedWorldBench（16 场景、4 难度、200+ 任务，含导航/物体搜索/NPC 对话/动态事件/trace-grounded 评分）

ABot-AgentOS 把具身智能从“单一 VLA 控制器”推进到“带操作系统的机器人 agent”。论文的核心论点是：在 VLM/VLA 基座与低层机器人控制器之间，应当存在一个可复用的 deliberative agent 层，负责场景条件规划、上下文隔离的技能执行、多阶段验证、多模态记忆，以及端云协同。该层不替换已有控制栈，而是作为统一的认知层，横跨人形、四足机器狗、移动操作平台、机械臂等多种 embodiment。

围绕这一论点，论文给出三项主要贡献：（1）一个通用机器人 Agent OS 架构，通过结构化的 agent 组件（main LLM、上下文管理、Skill Runner、工具接口、多阶段验证）把高层认知与物理执行解耦，并以插件式技能集成适配异构形态；（2）EmbodiedWorldBench，一个可执行基准，覆盖室内/室外/混合 16 场景、4 难度、200+ 任务，强调跨场景连续性、社交动态与工程可复现；（3）Universal Multi-modal Graph Memory，一种 typed、source-grounded 的多模态记忆图，将对话、视觉观察、空间上下文、时序关系、任务轨迹转为结构化节点与边，并配套 failure-driven 自演化循环——把诊断出的记忆失败编译为 gated runtime evo-assets，只提升到后续评测 split，从而在不泄漏当前 split 的前提下实现累积式终身改进。

实验上，在 EmbodiedWorldBench 子集上，ABot-AgentOS 相对单控制器 baseline 在 Task Success Rate (TSR) 与 Goal Completion Rate (GCR) 上均有明显提升；在 LoCoMo、OpenEQA、Mem-Gallery、NExT-QA、EgoLife 五个记忆基准上，ABot-AgentOS Static 取得 87.5 / 59.9 / 88.6 / 76.5 / 65.4 的成绩，自演化进一步提升至 88.7 / 60.4 / 89.0 / 80.6 / 66.2。论文还附带了面向部署的小模型训练管线（文本沙盒 → 教师轨迹蒸馏 → SFT → 基于 GiGPO 的在线 RL → 自演化奖励引擎），但明确说明该部分不公开私有数据与生产结果。

2. 研究背景与动机

2.1 VLM/VLA 与长时序具身 agent 的鸿沟

具身智能正把 AI 从数字环境推向物理世界。VLM 与 VLA 系统让机器人获得了自然语言理解、视觉场景理解、导航与动作预测能力，但论文指出一个关键鸿沟：“理解”与“行动”之间仍有断层。具体表现为三个待解难题：（i）如何把高层语义推理翻译成可靠的多步物理执行；（ii）如何在不大量重训的前提下跨多种机器人形态泛化；（iii）如何为持续交互构建长期、持久的记忆。

更尖锐的是，具身任务往往缺乏显式的中间步完成信号。一个 agent 可能调用了导航指令却并未真正离开当前位置，或在反复碰撞旋转的同时，语言层面仍“相信”任务正在推进。这与软件 agent（如 SWE-agent 的 agent-computer interface、Toolformer 的 API 调用、ReAct 的交错推理-行动）形成鲜明对比——数字任务通常有测试、API 响应、页面状态等外部信号可校验，而具身任务必须依赖 agent 声明进度、执行轨迹与观测场景状态三者的一致性。

2.3 三大 Gap 与为何需要 OS 层

论文把现有系统的不足归纳为三个 gap，并据此论证“为何需要一个 Agent OS 而非更大模型”：

推理-执行 gap：很多基座模型系统把模型输出直接映射为动作或依赖单体 pipeline，缺乏中间 agent 层来做任务分解、工具调用、技能委派、验证、恢复与多步逻辑推理。

跨体态泛化 gap：机器人 agent 系统常与特定硬件、控制 API 或环境假设紧耦合，跨体态迁移代价高。

持久具身记忆 gap：短期 buffer、纯文本缓存或任务专用记忆模块，无法可靠地跨长期交互保存多模态、关系化、source-grounded 的经验。

这三个 gap 还暴露了一个评测需求：长时序具身 agent 需要超越孤立导航/操作/VQA 的基准，转而测试可执行的多场景场景，包含动态事件、交互与 trace-grounded 评分。这正是 EmbodiedWorldBench 的动机。

2.4 与相关 agent 框架的区别（机构定位）

ABot-AgentOS 来自 AMAP CV Lab（高德 / Alibaba Group），是一个面向真实部署的系统级工作。与 SWE-agent（面向软件工程的 agent-computer interface）、Toolformer（API 工具调用）、ReAct（交错推理-行动）这类软件 agent 相比，它的关键区别在于：把执行组织为 reasoning-execution-verification 闭环，而不是简单地让 LLM 调用更多工具。与机器人侧的 SayCan、Inner Monologue、Voyager 相比，它额外强调“完成信号的一致性校验”与“跨体态插件式技能集成”。与 MemoryBank/MemGPT/Mem0 相比，它不只是文本记忆，而是把多模态经验写成 typed graph，并在记忆之上叠加 failure-driven 的管线级自演化。

3.3 场景条件规划 / Skill Runner / 多阶段验证

场景条件规划（Scene-Conditioned Task Planning）。main LLM 不是逐条下达底层动作，而是结合当前场景、地图、机器人状态、近期历史与可用技能，判断任务需要导航、搜索、人机交互、汇报、操作还是额外观察，并形成“带显式完成条件、可修订”的高层计划。关键在于场景条件而非纯语言：同一指令在不同位置、不同可视证据、不同可达区域下需要不同执行策略。计划随新观察、工具结果、技能摘要与 verifier 反馈动态更新。

Skill Runner（过程执行）。技能不是一次性工具调用，而是由 skill-level subagent 在隔离的本地上下文中执行，该上下文包含子目标、近期观察、技能状态、失败尝试与恢复策略。main LLM 只收到压缩后的技能进展与结果，而非全部中间动作序列。这种上下文隔离对长时序任务至关重要——若每次局部碰撞、短距移动、失败尝试都追加到 main LLM 上下文，全局目标会被过程细节淹没。终止时 Skill Runner 返回紧凑的语义摘要：子目标是否达成、失败原因、发现的新场景信息、尝试的恢复策略、main LLM 应如何使用该结果。

多阶段验证（Multi-Stage Verification）。Verifier 校验语言层信念与环境层完成之间的一致性，分三阶段：Runtime verification 监控近期轨迹与技能状态是否有效推进，识别停滞、重复碰撞、局部循环或与计划不一致的行为；Skill-level verification 检查委派子任务是否真正满足语义目标，而非仅因工具/subagent 正常返回就接受成功；Finish-time verification 在 main LLM 尝试终止任务时执行，综合原始指令、当前计划、执行历史、技能摘要、观察与交互中新增的需求，决定是否允许任务结束。

3.4 Universal Multi-modal Graph Memory

记忆系统是论文的另一核心贡献。它被定位在在线运行时之下、与上下文管理互补：上下文管理决定“当前 prompt 放什么”，记忆决定“什么应跨 episode 持久化、如何把相关历史证据取回上下文”。这种分离避免长期记忆退化为非结构化的 prompt 堆积。论文把长期经验表示为 typed graph：

$$G = (V, E),$$

其中节点 $v \in V$ 表示实体或证据单元，边 $e \in E$ 表示时序、语义、空间、身份、交互或 provenance 关系。每个节点存储一个紧凑的 JSON-style 信息字段，包含 schema 版本、数据集/来源引用、时间引用、证据摘要、置信度、adapter 专属字段与 provenance（记录 source id、adapter 版本、抽取模型与抽取元数据）。provenance 使记忆项可追溯到它所源自的观察、视频片段、帧、图像或会话。

这种表示区别于传统基于文本块的 RAG：文本检索主要返回语义相似片段，而记忆图先定位相关 seed 节点，再沿 typed 边扩展为局部证据子图，从而支持对身份、时间、位置、参与、provenance、空间关系的结构化推理。

混合检索打分

给定查询 $q$，混合 seed 选择打分为：

$$s(q, v) = \lambda_{\mathrm{sem}} s_{\mathrm{sem}}(q, v) + \lambda_{\mathrm{lex}} s_{\mathrm{lex}}(q, v) + \lambda_{\mathrm{meta}} s_{\mathrm{meta}}(q, v) + \lambda_{\mathrm{type}} s_{\mathrm{type}}(q, v),$$

其中 $s_{\mathrm{sem}}$ 为 embedding 相似度，$s_{\mathrm{lex}}$ 为词法重叠，$s_{\mathrm{meta}}$ 度量时间/来源/模态/地点等元数据兼容性，$s_{\mathrm{type}}$ 偏好查询期望的节点类型。top-ranked seeds 随后在固定深度与 evidence-token 预算下沿 task-relevant typed 边扩展，产生包含语义/时序/空间/身份/provenance 上下文的局部证据子图。该子图序列化为紧凑证据上下文，配以 retrieval trace 注入 agent 推理上下文。这与 WorldMM 等动态多模态检索 agent 对独立记忆库的检索不同：ABot-AgentOS 是“seed + 图邻域扩展”，answerer 在证据项之间的关系上推理，而非在孤立片段上推理。

记忆写入与维护

记忆更新可发生在交互中与 reflection 检查点。memory-writing 服务从观察/工具结果/对话轮/执行轨迹流中选择信息，转为紧凑图记录并链接到 session、place、time、source reference、provenance。论文以一组 graph-construction adapters 实例化该 writer。其设计原则是语义压缩优先于原始存储——长期记忆应在不牺牲可追溯性的前提下提升信息密度。例如 utterance “I adopted a Maltese dog yesterday” 被表示为时间定位的语义事件，链接 utterance、解析后的时序上下文、身份假设、置信度估计与来源证据，而非原始 transcript 行；附加图像时，图像节点作为支持性多模态证据连到该事件。写入后进行轻量维护：近重复实体/事件节点在 provenance、时序、身份证据兼容时合并；频繁观察的实体保留有界代表证据集的紧凑状态摘要；陈旧状态事实通过 temporal edge 被更新观察取代（而非立即删除），使检索能区分“当前状态”与“历史证据”。

3.5 failure-driven 终身自演化循环

长期记忆不应只靠累积内容来演化，还应改进“写入-检索-选择-使用证据”的管线本身；否则系统会在记忆图增长的同时反复犯相同的抽取/检索/时序 grounding/视觉选择/答案组合错误。论文把这一过程形式化为split-wise 协议：在长期部署（或其基准近似）上维护不相交 split 的有序序列 $D_1, \ldots, D_T$。在 split $t$，系统维持两个持久状态：累积记忆图 $G_{t-1}$ 与已提升的 evo-asset 集 $A_{\lt t}$。

核心的“无泄漏”约束：split $t$ 产生的任何 evo-asset 都不用于 split $t$ 的推理；只有通过 gate 的 asset 才会被提升、且只作用于后续 split。这让自演化成为累积式终身过程，而非一次性事后修补。在线运行、asset 提议与 asset 提升的形式化如下：

$$T_t, G_t = \mathrm{Run}(D_t;\, G_{t-1},\, A_{\lt t}),$$

$$\Delta A_t = \mathrm{Gate}\left(\mathrm{Compile}\left(\mathrm{Propose}\left(\mathrm{Diagnose}(T_t)\right)\right)\right),$$

$$A_{\leq t} = A_{\lt t} \cup \Delta A_t.$$

其中 $T_t$ 为 split $t$ 上收集到的答案轨迹与失败轨迹，只有 $A_{\leq t}$ 可用于后续 split $D_{t+1}, \ldots, D_T$。gate 对每个候选 asset 在 target validation 子集与 regression 子集上评估，仅当目标分提升不少于 $\tau_{\mathrm{gain}}$ 且回归分下降不超过 $\tau_{\mathrm{reg}}$ 时才接受：

$$\mathrm{Accept}(a) = \mathbb{I}\left[\Delta S_{\mathrm{target}}(a) \geq \tau_{\mathrm{gain}} \;\wedge\; \Delta S_{\mathrm{reg}}(a) \geq -\tau_{\mathrm{reg}}\right].$$

该准则使提升保守：asset 必须在改进其目标失败模式的同时保住此前可靠的 case。被接受的 evo-asset 是生命周期管理的 JSON DSL 记录，不执行生成的 Python 代码；每个 asset 声明其目标层、触发条件、允许动作、安全约束、provenance、校验结果与版本 id。asset 可针对 memory writing、evidence selection、answer composition、visual frame selection、temporal normalization 或 adapter-level normalization。正常 QA 行为除非显式加载 accepted asset 否则不变；writer-side 与 frame-policy asset 需要重建图，而 evidence-selection 与 answerer asset 可运行时加载。下图为该循环的伪代码。

Algorithm 1: Failure-Driven Lifelong Self-Evolution（split-wise）

Input: 有序不相交 split 序列 D_1, ..., D_T；初始记忆图 G_0；初始 asset 集 A_<1 = ∅；阈值 τ_gain, τ_reg

Output: 终态记忆图 G_T 与累积 evo-asset 集 A_≤T

for t = 1 to T do

// 1) 在线运行：仅用此前 split 提升的 asset，禁止用本 split 产生的 asset

T_t, G_t = Run(D_t; G_{t-1}, A_<t) // 写记忆 / 检索证据 / 记录 retrieval+answer trace

// 2) 仅在 split t 评测完成后，用 ground-truth（或部署侧反馈）诊断失败

failures = Diagnose(T_t) // 归因到 memory-writing / retrieval / evidence / temporal / entity / answer

candidates = Propose(failures) // 候选修复（针对目标管线层）

dsl_assets = Compile(candidates) // 编译为受限 JSON DSL evo-asset（不生成可执行代码）

for each a in dsl_assets do

// 3) Gate：target 子集须提升 ≥ τ_gain，regression 子集下降 ≤ τ_reg

if Accept(a) == True then ΔA_t.add(a) // 否则回滚、不提升

A_≤t = A_<t ∪ ΔA_t // 仅此后 split 可用

return G_T, A_≤T

论文强调，这套机制与真实部署直接兼容：在部署中，正确性信号不必来自基准 ground-truth，而可来自环境结果（任务成败）、人类纠正、或低置信度的 retrieval/answering trace——benchmark 的 split-wise 协议只是对自然具身反馈的受控替代。

3.7 端云协同：路由与记忆分区

端云协同路由。并非每个任务都应交给云端大模型——常规请求可由端侧小模型 + 本地工具完成，而长时序任务需更强场景理解、规划、技能执行与验证。ABot-AgentOS 的路由层让端侧模型先观察任务与上下文，再决定本地处理或升级云端。路由策略从训练样本与执行反馈中学习（而非固定规则），捕获“哪些请求可被本地工具可靠解决、哪些需云端规划、哪些需先额外观察再路由”，在控制延迟与部署成本的同时保留云端能力。

端云协同记忆管理。具身 agent 持续获取异构记忆（地图、语义地标、障碍物、物体、人相关观察）。公共环境记忆（路障、施工区、导航地标）共享可提升多 agent 协作；而隐私敏感记忆（人脸、个人物品、与个人关联的物体）必须留在本地。为此设计了私有优先（private-by-default）的分层记忆：端侧私有记忆存储地图、语义、多模态交互历史、用户偏好与本地环境经验；云端公共记忆只含可共享知识（可复用地图表示、通用任务经验），支持跨机器人上传/下载。每条新记忆在同步前做隐私判断——含人/脸/姓名/个人物体/所有权关系的视为不可共享，而地图/交通锥/路障/静态地标等公共环境信息视为可共享。论文构建了隐私分类与上传决策测试集，系统在“记忆项是否适合云端同步”上达到超过 99% 的准确率。

3.8 部署侧小模型训练管线

除公开的系统/基准/记忆组件外，论文还描述了一个面向部署的小模型训练管线，目标是把 ABot-AgentOS 式长时序规划与工具使用能力从大教师模型迁移到更小的可部署 agent 模型。管线闭环连接四阶段：文本环境构建 → 教师轨迹蒸馏 → SFT → RL，并配自演化奖励引擎。

  • 文本环境与任务构建：每个 NL 指令转为有状态沙盒实例，由 LLM 生成 Easy/Medium/Hard 变体，含 env_state（位置/可达性/物体位置与状态）、failure_triggers（物理或语义障碍）、human_persona（NPC 角色/能力/可提供的帮助）。EnvController 校验 skill 调用并返回观察/失败，HumanAgent 处理有效求助并可更新 env_state——使障碍处理、求助、重规划、状态更新成为训练信号。
  • 教师轨迹蒸馏与 SFT：强教师模型在沙盒中控制 ABot-AgentOS 式 agent 产出 ReAct 式轨迹（含失败尝试、求助、重试、恢复），用 LLM-as-a-Judge 过滤后转为保留交互结构的 tool-call SFT 样本，训练学生模型作为 ABot-AgentOS 技能上的可执行策略。
  • RL（GiGPO + LLM-as-a-Judge 奖励）：SFT 初始化的学生在相同沙盒中在线采样、接收 EnvController/NPC 反馈并用奖励引导策略优化。使用 GiGPO 把奖励转为相对优势：对同一初始状态采多条 rollout 形成 episode 相对优势，并在对齐的可比决策步上形成 step 相对优势，使局部恢复选择在类似情境下被强化。

自演化奖励引擎

奖励引擎把每条具身轨迹转为 turn-level 与 episode-level 信号。turn-level 奖励 skill-aware 路由（导航/操作/VQA/工具用不同 rubric），并结合 LLM 语义判断与可验证规则检查（非法工具、非法命令、畸形参数、缺失时序前置），还加入对“跳过必要因果步骤的貌似合理动作”的遗漏惩罚。episode-level 奖励对整条轨迹评估效率/一致性/完整性：

$$r_{\mathrm{episode}}(\tau) = \lambda_{\mathrm{eff}} R_{\mathrm{eff}}(\tau) + \lambda_{\mathrm{cons}} R_{\mathrm{cons}}(\tau) + \lambda_{\mathrm{comp}} R_{\mathrm{comp}}(\tau),$$

合并回报为：

$$R(\tau) = \sum_{t=1}^{T} \hat{r}_t + r_{\mathrm{episode}}(\tau),$$

其中 $\hat{r}_t$ 为 skill-specific rubric 路由、LLM 语义判断、可验证规则检查与遗漏惩罚产出的有效 turn-level 奖励。Meta-Judge 不直接判断 agent 是否正确，而是校验 first-order judge 输出的可靠性，按 accuracy / logical soundness / completeness / clarity / feedback value 五维打分：

$$Q(x_t) = \sum_{k=1}^{5} w_k q_k, \qquad \mathrm{LowQualityJudgeCase}(x_t) = \mathbb{I}\left[Q(x_t) \lt \theta\right].$$

低质量 judge case 进入多 agent 自演化：Cluster 按技能与失败类型分组 → Analyzer 定位缺陷 rubric 组件并产出修订计划 → Refiner 局部编辑相关 rubric/规则/示例 → Validator 在全验证集上评估，仅在提升整体质量时接受，否则回滚。在当前验证设置下，初始 Judge 模型约 60% 人类对齐，Meta-Judge 驱动的自演化把对齐度提升到 90% 以上。

4.3 终身自演化结果

自演化变体使用与对应 static run 完全相同的记忆图 schema、base hybrid graph retriever 与 writer-answerer 配置，唯一差异是后续 split 可加载此前 split 提升的 evo-assets（writer rules、evidence-selection 偏好、answerer calibration、frame-selection、temporal-normalization 等）。每个数据集被切为有序不相交 split $D_1, \ldots, D_T$；ground-truth 仅在 split 评测完成后用于诊断失败，不进入推理、不写入记忆图、不为同一 split 生成 asset。下图与表展示 static → +Self-evo 的变化。

4.4 奖励引擎与隐私门控

奖励引擎的 Meta-Judge 自演化把 Judge 模型的人类对齐度从约 60% 提升到 90% 以上；隐私门控在“记忆项是否适合云端同步”的专用测试集上达到 >99% 准确率，在保端侧隐私的同时允许非敏感公共知识跨机器人共享。这两项支撑了“可部署、可审计”的系统定位。

5. 总结与启发

5.1 局限性

论文在 Conclusion 中坦陈若干局限：

  • 大规模真实世界验证仍缺失：尚需在噪声感知、不完美执行、网络延迟、安全约束与异构机器人 embodiment 下验证。
  • EmbodiedWorldBench 覆盖仍有限：场景多样性、社交交互深度与当前 agent 评测覆盖面有限；未来将发布完整基准评测并开放 EmbodiedWorldBench。
  • 记忆与自演化管线依赖结构化 trace 与事后反馈；隐私感知的端云记忆共享需要更强的审计、用户控制、访问管理与失败分析。
  • 小模型训练管线仍停留在文本状态语义沙盒，应纳入视觉观察、多模态反馈与更多仿真平台。
  • agent 评测仅在小子集上：论文自述为“initial system validation rather than a complete benchmark leaderboard”，避免在模型或任务类别上做细粒度声称。

5.2 核心洞见与读后评注

洞见 1：把“完成信号的一致性校验”提到一等公民。论文最 sharp 的观察是：具身任务缺的不是更强的动作预测，而是“语言层信念 ↔ 执行轨迹 ↔ 观测场景状态”三者一致性的校验机制。Verifier 在 runtime/skill/finish 三时机介入，本质是把“动作是否真的改变了世界”这一被软件 agent 视为外生信号的条件，内化为 agent harness 的内生监督信号。这解释了为何在相同 Qwen3.6-Plus 基座下，分层架构能把 TSR 从 49.97 拉到 61.96——收益来自结构而非参数。

洞见 2：记忆从“存什么”转向“检索谁 + 扩展什么关系”。Universal Multi-modal Graph Memory 的关键不在图本身，而在检索范式：先 seed 再沿 typed edge 扩展为局部证据子图，使 answerer 在“证据项之间的关系”上推理，而非在孤立文本片段上推理。这与 WorldMM 等对独立记忆库的检索形成分野。LoCoMo 逼近人类（87.5 vs 87.9）、NExT-QA 因果/时序增益最强，都印证了关系化记忆对“需要结构化证据”的问题的价值。

洞见 3：自演化的“无泄漏 split 协议”是把事后修补升级为终身学习的关键约束。很多“自改进 agent”工作容易滑入“用本 split 监督修本 split”的泄漏陷阱。论文的 split-wise 协议（$A_{\lt t}$ 只含此前 split 的 asset，$D_t$ 的失败只能生成供 $D_{t+1}$ 用的 asset）把自演化变成累积式过程。更巧妙的是 evo-asset 是受限 JSON DSL而非生成代码，且必须同时满足 target 提升 $\geq \tau_{\mathrm{gain}}$ 与 regression 下降 $\leq \tau_{\mathrm{reg}}$——这把“安全资源演化”原则落到 gate 上，使每一步改进可版本化、可审计、可回滚。

洞见 4：基准设计即方法声明。EmbodiedWorldBench 的“可执行场景 = $\langle M, S_0, O, \mathcal{N}, C\rangle$”与 trace-grounded 评分，把“agent 是否真在多场景连续推进、是否真能动态重规划”纳入可复现评测。Scene-conditioned planning 与 trace-grounded scoring 形成镜像：前者要求 agent 在场景中规划，后者要求评分能从轨迹审计——二者共同抵制“prompt collection 式基准”的陷阱。

读后评注。这篇工作在“OS 层”定位上是有说服力的——它不试图取代 VLA，而是在其上提供推理/记忆/工具/验证/跨体态的运行时，并以私有优先的端云记忆与 gated evo-asset 守住可部署底线。值得关注的张力在于：agent 评测仍只在子集上、自演化增益在部分基准上较小（Mem-Gallery +0.4、OpenEQA +0.5），且正文与摘要在 OpenEQA 增益数字上不一致——这提示“管线级自演化”的收益目前仍偏温和，其价值更多在“可审计的累积改进机制”而非单次绝对提升。若未来能展示自演化在长部署周期（数十 split）下的累积放大效应，并与 OS 层的跨体态迁移结果联合发布，将更完整地兑现“通用机器人 Agent OS + 终身多模态记忆”的承诺。
