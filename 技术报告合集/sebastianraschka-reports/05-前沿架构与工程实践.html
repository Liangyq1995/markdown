1.2 DeepSeek-V3 核心架构创新

多头潜在注意力（MLA）

MLA 是 DeepSeek 最具影响力的架构创新之一。与 GQA 通过"共享"减少 KV Cache 不同，MLA 通过"低维压缩"实现同样目的：

  • 将 K 和 V 联合投影到低维潜空间，缓存压缩后的潜向量
  • 推理时从潜向量解压恢复 K/V
  • DeepSeek-V2 消融实验证明：同等内存压缩比下，MLA 建模性能优于 GQA

专家混合（MoE）设计

DeepSeek V3 的 MoE 设计有几个独特之处：

  • 细粒度专家：256 个专家（远多于 Mixtral 的8个），每次激活 8 个
  • 共享专家：部分专家被所有 token 共享（保留通用知识），其他是路由专家
  • 负载均衡损失：专门设计确保专家被均匀使用，避免"专家坍塌"

多 Token 预测（Multi-Token Prediction）

不只预测下一个 token，同时预测接下来的 N 个 token。这提供了更密集的训练信号，同时在推理时可以用于投机解码加速（speculative decoding）。

1.4 自我验证的挑战与方案

过程奖励模型（PRM）是自我验证的经典方案，但面临两大挑战：

  • 中间步骤的正确性难以自动验证（不像最终答案那样有标准答案）
  • 可能导致奖励黑客行为（reward hacking）——模型学会操纵验证器而非真正解题

DeepSeekMath V2 的解决方案：让 LLM 自身充当验证器，对自己生成的中间步骤进行评分，结合自我精炼迭代改进答案。

3.2 两种关键会话文件

完整会话记录（Full Transcript）

存储整个会话的完整历史，以 JSON 格式保存到磁盘。功能：

  • 可恢复性——关闭 Agent 后可以从上次中断处继续
  • 完整的工具调用记录（输入+输出）
  • 所有中间推理步骤

工作记忆（Working Memory）

完整记录的精炼版本，专注于"当前任务最重要的信息"：

  • 当前任务目标
  • 已修改的关键文件
  • 重要发现和注记
  • 下一步计划
压缩记录（Compact Transcript）vs 工作记忆的区别：前者用于提示词重构（给模型看历史摘要），后者用于任务连续性（跨轮次维持任务状态）。两者都是对完整历史的压缩，但服务于不同目的。

3.3 提示词预算管理

Coding Agent 的核心工程挑战之一是如何在有限的上下文窗口内塞进足够的信息。主要策略：

策略一：内容裁剪（Clipping）

限制单个内容块的最大长度：

  • 文档片段超过阈值 → 截断并标注"[已截断]"
  • 大型工具输出（如 grep 结果）→ 只保留最相关的 N 行
  • 内存注记 → 限制最大字数

策略二：历史压缩（Summarization）

随着会话进行，旧的历史事件被压缩为摘要。关键原则：近期事件保留更多细节，远期事件压缩更激进——因为最近几步操作与当前任务最相关。

3.4 工具设计原则

# Coding Agent 工具的典型设计模式
class AgentTool:
    name: str           # 工具名称（LLM 用来调用）
    description: str    # 功能描述（影响 LLM 何时选择此工具）
    parameters: dict    # 参数 schema（JSON Schema）

    def execute(self, **kwargs) -> ToolResult:
        """
        执行工具并返回结构化结果
        - 成功时返回内容
        - 失败时返回错误信息（让 LLM 能处理错误）
        - 避免抛出异常（Agent 需要看到失败信息）
        """
        raise NotImplementedError

# 示例：文件读取工具
class ReadFileTool(AgentTool):
    name = "read_file"
    description = "读取指定路径的文件内容。大文件支持 offset 和 limit 参数分段读取。"

    def execute(self, file_path: str, offset: int = 0, limit: int = 2000):
        try:
            with open(file_path) as f:
                lines = f.readlines()[offset:offset+limit]
            return ToolResult(success=True, content="".join(lines))
        except FileNotFoundError:
            return ToolResult(success=False, error=f"文件不存在: {file_path}")

四、LLM 预训练与后训练新范式

原文：New LLM Pre-training and Post-training Paradigms

通过分析 Qwen 2 和 Apple AFM 的技术报告，本文揭示了工业级 LLM 训练的前沿实践，这些细节在论文中鲜少被详细讨论。

4.1 Qwen 2：被低估的开源强模型

Qwen 2 是阿里云的大型语言模型系列，在多个基准上与 Meta Llama 3 和 Google Gemini 竞争，但在社区知名度上相对较低。技术报告揭示了几个有趣的训练细节：

  • 高质量数据筛选：从超大语料中通过质量过滤器精心筛选，数据质量远优于数量
  • 多阶段后训练：SFT → DPO → RLVR 的完整对齐管线
  • 代码和数学专项训练：在预训练阶段就对代码和数学语料做了特殊处理

4.2 Apple AFM：意外透明的技术报告

Apple Intelligence Foundation Language Model（AFM）的技术报告是一个"意外之喜"——Apple 通常对技术细节保持沉默，这份报告的发布出人意料。

报告揭示的关键设计决策：

  • 针对设备端部署的极度优化（小模型、量化优先）
  • 使用 DPO 做指令对齐，同时维护安全约束
  • 隐私计算与模型质量的平衡策略（部分计算在设备端，部分在服务器端）
