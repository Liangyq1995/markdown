1.1 混合注意力：KDA（3/4 层）+ Gated MLA（1/4 层）

每个 Block 由 3 层 KDA + 1 层 Gated MLA 组成（3:1 比例贯穿主干），主干末端再补一层 Gated MLA 保证最后一层是全局注意力。全模型共 69 层 KDA + 24 层 MLA。

Kimi Delta Attention（KDA）——先建立直觉

一句话：Softmax 注意力像「每次翻完整本历史书找相关段落」；KDA 像「只带一本页数固定的笔记本」——读完每个 token 就先衰减、再擦掉旧笔记、再写上新笔记，然后用当前 query 从这本笔记本里读出答案。笔记本大小恒定，所以状态不随上下文长度增长。

Softmax / MLA：概率加权检索

对所有历史位置算相似度 → Softmax 成概率 → 加权求和。KV cache 随 $T$ 线性增长（MLA 每 token 约 576 维潜状态）。

适合「任意远距离精确匹配」；贵在缓存与算力都随长度涨。

KDA：定长状态上的擦写记忆

维护固定大小矩阵 $S$（单头 $128\times128$）。每步只更新 $S$，读出 $\tilde{o}=S^\top q$。状态大小与 $T$ 无关。

适合长序列里的近因感知与递推混合；贵在递归难并行——靠 chunkwise + Tensor Core 化解。

$$ S_t = \underbrace{\big(I - \beta_t k_t k_t^\top\big)}_{\text{② 擦除}}\,\underbrace{\mathrm{Diag}(\alpha_t)}_{\text{① 衰减}}\, S_{t-1} + \underbrace{\beta_t k_t v_t^\top}_{\text{③ 写入}}, \qquad \tilde{o}_t = S_t^\top q_t $$
$\alpha$ 与 $\beta$ 的分工（粒度差 128 倍）
  • $\alpha_t \in (e^{-5},1)^{128}$：逐通道保留因子，进 $\mathrm{Diag}(\alpha_t)$——决定旧状态每个 key 通道各自忘掉多少（越接近 1 记得越久）。
  • $\beta_t \in (0,1)$：每头一个标量（整层只有 96 个数）——「擦掉多少旧的，就写入多少新的」。因为 $k_t$ 已 L2 归一化，$\beta_t=1$ 时 $I-k_tk_t^\top$ 恰是把 $k_t$ 方向投影掉的正交投影（完全替换该方向记忆）；$\beta_t\to 0$ 则这一步几乎不动状态。

K3 相对 Kimi Linear 的两处改动

  1. 下界衰减（Lower-bounded decay）——换来 Tensor Core 能算对角块

Kimi Linear

$g = -e^{A}\mathrm{Softplus}(z) \in (-\infty, 0)$，无下界。

分块形式里键要除以累积衰减 $1/\Gamma$，$1/\Gamma$ 可无界增长 → 溢出风险 → 对角小块只能走逐位置对计算（Tensor Core 用不上）。

Kimi K3

$g = g_{\min}\sigma(e^{A}z) \in (g_{\min}, 0)$，固定 $g_{\min}=-5$。

16-token 小块累计对数衰减 $\in(-80,0)$，$1/\Gamma < e^{80}\approx 5.5\times10^{34}$，稳落在 BF16 动态范围 → 对角 / 非对角块全部走稠密 Tensor Core matmul。

$$ g_t^h = g_{\min}\,\sigma\big(e^{A^h} z_t^h\big) \in (g_{\min}, 0)^{d_k}, \qquad \alpha_t^h = \exp(g_t^h) \in (e^{g_{\min}}, 1)^{d_k} $$
  1. 全秩输出门。把低秩输出门换成输入相关的满秩投影：先对递归输出做 head-wise RMSNorm，再做数据依赖门控：
$$ y_t = W_o\left[\sigma(W_g x_t) \odot \mathrm{RMSNorm}(\tilde{o}_t)\right] $$

训练 / prefill 实际走 chunkwise 并行形式：$A_{[t]}=\mathrm{Tril}\big[(Q\odot\Gamma)(K\oslash\Gamma)^\top\big]$，$O_{[t]}=(\Gamma\odot Q)S_{[t]}+A_{[t]}\widetilde{V}_{[t]}$；Tril 含对角，正因为读的是更新后的状态。推理时状态 $S$ 原地递推；投机解码下用「缓存投影输入、片上重放」避免拒绝草稿后无法回滚（见 §4.4）。

三处容易记反
  1. 输入 $d{=}7168$ 不是 $96\times\mathrm{head\_dim}$；头主序扁平形只出现在上投影之后（18432 / 24576 / 12288）。
  2. $k_R$ 不是从 $c_{KV}$ 解压出来的——它是同一次下投影的另一段，且头间共享。
  3. view+transpose 发生在上投影之后；NoPE 下 Q 的 rotary split→cat 是恒等（rotary_emb = None）。
  • NoPE 的工程收益：扩上下文时无需改 RoPE 频率基或 YaRN；位置敏感与近因感知由夹在中间的 3 层 KDA 提供，MLA 只负责无限制的全局内容交互。
  • 缓存代价对照：一层 MLA ≈ 576/token；一层 KDA 常数状态 ≈ 1.57M 元素/序列——约到 $T\approx2731$ 两者持平。这也是 3:1 混排的动机：多数层用定长状态，少数层保留全局 Softmax。
  • 训练细节：注意力输出保持 FP32 以纠正 flash attention 偏置舍入；输出瓦片与 KV 暂存缓冲复用共享内存，换更深 KV 流水线。
$$ c_t^{\mathrm{KV}} = W^{\mathrm{kv}}_a x_t,\quad [K^C_t \mid V_t] = W^{\mathrm{kv}}_b\,\mathrm{RMSNorm}(c_t^{\mathrm{KV}}),\quad y_t = W_o\big[\sigma(W_g x_t)\odot \tilde{o}_t\big] $$

1.2 Attention Residuals（AttnRes）：深度维的注意力

一句话：把 Softmax 注意力从横着的序列轴转 90° 放到竖着的深度轴——每层不再只读那个一路累加下来的 $h$，而是对更浅的层做一次加权检索。K3 再每 12 层切一刀，把 93 层收成 8 条总线 + 1 个 embedding = 9 个信息源。

普通残差 = 深度上的 RNN

$h_l = h_{l-1} + f_l(h_{l-1})$——此前所有层被压进同一个向量，像 RNN 把历史压进一个隐状态。

AttnRes = 深度上的 Transformer

$h_l = \sum_{i<l} \alpha_{i\to l} v_i$——每层自己挑要读哪些更浅的层；query 是可学习常量 $w_l$，数据相关性只从 key 进来。

序列轴 $t$（普通注意力）深度轴 $l$（AttnRes）
Query 从哪来$q_t = W_q x_t$，随 token 变$q_l = w_l$，每子层一个可学习常量
因果掩码$s \le t$：不能看未来$i < l$：不能看更深的层
轴有多长$T$ 可到 $10^6$$L=93$，所以 $O(L^2 d)$ 本来就不贵
为什么还要分块FLOPs 与 KV cache不是算力——是让每层输出都活着的显存与流水线跨 stage 通信
块间传什么状态矩阵 $S\in\mathbb{R}^{d_k\times d_v}$（KDA）一个向量 $b_n\in\mathbb{R}^d$
合并算子矩阵乘累加Softmax 凸组合，至多 9 项
$$ \alpha_{i\to l} = \frac{\phi(q_l, k_i)}{\sum_{j=0}^{l-1}\phi(q_l, k_j)},\quad \phi(q,k)=\exp\big(q^\top\mathrm{RMSNorm}(k)\big),\quad h_l = \sum_{i=0}^{l-1}\alpha_{i\to l}\cdot v_i $$

1.3 Stable LatentMoE：896 专家、激活 16 的极端稀疏

一句话：共享专家走「全宽高速公路」处理通用变换；路由专家挤进「半宽小巷」$\ell=3584$，让你能养 896 个专家却只激活 16 个。代价是路径病态 + 均衡极难——于是有 RMSNorm、SiTU-GLU、Quantile Balancing 三件套。

LatentMoE 把「模型全宽」与「路由专家宽度」解耦。K3：路由专家 896、每 token 激活 16（稀疏度 56），潜空间 $\ell=3584$（$=0.5d$），共享专家固定 $N_s=2$：

$$ u = \sum_{i \in \mathcal{T}_k(x)} p_i\, E_i^{\mathrm{routed}}(W_{\downarrow} x), \qquad y = \sum_{j=1}^{N_s} E_j^{\mathrm{shared}}(x) + W_{\uparrow}\,\mathrm{RMSNorm}(u) $$

极端稀疏放大两个失效模式，Stable LatentMoE 用三个组件应对：

① 归一化 LatentMoE（RMSNorm）

路由路径是「$W_\downarrow$ → 多分支专家 FFN → $W_\uparrow$」近四连矩阵乘的病态链式结构，叠加 2.8T 规模会在路由分支产生激活爆炸。在专家聚合与上投影之间插入 RMSNorm，降低路由分支对尺度变化的敏感度；除稳定训练外，验证 loss 与下游基准也一致变好。

② SiTU-GLU（Sigmoid Tanh Unit）

SwiGLU 两个乘性因子都无界，大坐标叠加会产生激活离群值；原始 GLU 的 sigmoid 门有界但丢失 Swish 的正侧近似线性区。SiTU-GLU 对两端分别施加平滑封顶 $\mathrm{softcap}(x,\beta)=\beta\tanh(x/\beta)$：

$$ \mathrm{SiTU\text{-}GLU}(x) = \left[\beta_1 \tanh\left(\frac{W_g x}{\beta_1}\right) \odot \sigma(W_g x)\right] \odot \left[\beta_2 \tanh\left(\frac{W_u x}{\beta_2}\right)\right] $$
  • K3 取 $\beta_1=4$（门）、$\beta_2=25$（上），输出严格有界：$\|\cdot\|_\infty\le\beta_1\beta_2=100$。
  • 原点附近与 SwiGLU 一阶吻合；$\beta\to\infty$ 时逐点还原 SwiGLU；相对硬截断，平滑 cap 在饱和区外保留非零梯度。

③ Quantile Balancing（QB）——先建立直觉

一句话：不要用「负载偏了就 ±γ」这种拧旋钮的方式调专家偏置。先算出每个 token 的入选门槛，再看每个专家「差多少才挤得进去」（margin），然后按列切一刀分位数——一步定位下一步偏置，无需辅助损失、也无需学习率式超参。

沿用 aux-loss-free 路由：$T_i=\mathrm{argtopk}(s_i+b)$，但 $b$ 只进选择、不进混合权重 $p_{i,j}$（也不进梯度）。DeepSeek-V3 式 $b_j\leftarrow b_j+\gamma\,\mathrm{sign}(\bar{\ell}-\ell_j)$ 在 896 专家时几乎没有可用的 $\gamma$ 区间；QB 改用分数完整分布，一步定位。

小例（论文 Fig.5 / wdkns 复算）：$m{=}8$ token、$n{=}4$ 专家、$k{=}1$、$q{=}mk/n{=}2$。K3 实际是 $n{=}896$、$k{=}16$，分位点 $1-k/n\approx0.982$。

a · Top-(k+1)

前 k 个是真正路由；第 k+1 个的值就是门槛 $\alpha_i$

α ∈ ℝᵐ —— 每 token 一条门槛

为什么多取一个：Top-k 只告诉「谁进来了」，QB 还要「差多少才进得来」

b · Margin

$M = S - \alpha\mathbf{1}^\top$：$M_{ij}=s_{ij}-\alpha_i$

专家 j 距离挤进 token i 还差多少

换候选偏置后，负载 = $\sum_i 1[M_{ij}>-\hat{b}_j]$，关于阈值单调递减 → 可求逆

c · 逐列切刀

每列降序，在第 $(q{+}1)$ 行切一刀

$\hat{b}_j = -\mathrm{quantile}_{1-k/n}(M_{:,j})$

要恰好 q 个留在线上，阈值只能落在第 (q+1) 大那一格

d · 去均值

减均值不改任何 Top-k，只把 $b$ 钉在零均值

下一步再用；本批不用自己算出的 bias

推理时偏置冻结

$$ \hat{b}_j^{(t+1)} \leftarrow -\mathrm{quantile}_{1-k/n}\big(s_{:,j}-\alpha^{(t)}\big),\qquad b^{(t+1)}\leftarrow\hat{b}^{(t+1)}-\mathrm{mean}\big(\hat{b}^{(t+1)}\big) $$
三处「取自哪个分数」必须分清：路由与门槛取自有偏分数 $s+b$；margin 与混合权重 $p_{i,j}$ 取自原始分数 $s$。旧偏置只通过 $\alpha$ 进入更新，也不会污染 $p$ 的梯度。
  • 直方图估计：全局 batch 边际达数百万、跨 rank 分片，精确分位不可行。每专家 $B{=}1000$ 桶直方图，步末一次整数 all-reduce（每层 $nB$ 个值），线性插值读分位数；误差几个 $10^{-3}$，通信量不到交换原始边际方案的 1%。
  • 注意：「重新路由后恰好均分」不是定理——定理只保证门槛固定时每列恰好 $q$ 个；真正路由时门槛随新偏置一起动，实际负载是近似均衡。

二、预训练：数据、缩放律与训练配方

2.1 数据

  • 文本四域：Web Text、Code、Mathematics、Knowledge；规则启发式 + 分类器质量打分 + 去重，域采样率由小模型消融定。知识与数学语料沿用 K2 的 rephrase 配方（风格/视角多样化改写、分块自回归生成、对照原文保真校验）。
  • 视觉语料：captions、图文交错文档、OCR、感知、视频、视觉编码；坐标监督同时给绝对与归一化（[0,1]）两种格式。大幅扩充程序化多模态数据：代码片段与其渲染结果配对（SVG、3D 资产、Webpage、Game、CAD 图纸）。

2.2 缩放律：2.5× 效率提升与 cosine 之争

  • 架构/数据/训练改动改变了最优训练区间，重新做缩放律研究重调 batch size、学习率、TPP 与模型形状。拟合曲线显示整体缩放效率较 K2 提升约 2.5×（同等 FLOPs 下 OOD 验证 loss 显著更低）。
  • cosine vs WSD：两者最优超参（峰值 LR、batch size）差异巨大，共用一套超参对比会系统性偏袒一方；各自独立搜参后，cosine 衰减的最终 loss 一致低于 WSD，故采用 cosine 为默认调度。

2.3 训练配方

  • 原生多模态联合训练：语言与视觉从第一步起在同一 next-token 目标下联合优化，视觉与文本 token 交错于同一序列，而非「先训 LLM 再接视觉塔」。
  • 优化器 Per-Head Muon + K2 式 weight clipping；MoE 负载均衡用 QB；cosine LR + 1% 线性 warmup；weight decay 全程 0.1。
  • 上下文先从 8K 起步，后续阶段扩到 64K。

2.4 长上下文扩展：8K → 64K → 256K → 1M 四阶段课程

  • 位置编码：NoPE——位置信息完全由 KDA 的递归门控与衰减机制隐式编码，直接外推到 1M，无需 RoPE 重缩放/插值。
  • 长上下文数据：自然长文档/视频含大量近重复、二进制块、截断文件、无效机器日志，需精确+模糊去重、视频帧感知哈希、启发式+分类器过滤、结构校验；真正长而连贯的样本稀缺，需上采样防止被短序列淹没。
  • 长度 ≠ 长程能力：合成长上下文数据——精心置换拼接多模态文档与子任务，使任务只有注意到散布于整个 1M 上下文的信息才能解，防止注意力退化为局部模式。
  • 渐进扩展：预训练期 8K→64K，cooldown 期 256K→1M。把昂贵的长序列计算集中在训练预算的一小部分，经济且让模型渐进适应；百万 token 训练的可行性由 KDA 上下文并行（§四）支撑。

3.1 SFT 冷启动

在既有 Kimi SFT 管线基础上大幅扩充复杂 agentic 任务覆盖：用前代 Kimi 领域专家模型合成轨迹，经多阶段验证 + 人工在环标注；所有数据用 XTML（自研 chat template，见 §3.8）统一序列化。从 SFT 阶段起即施加 QAT（MXFP4 权重 / MXFP8 激活，见 §3.6）。

3.2 RL：三领域 × 三档 effort，partial rollout 抗长尾

不为单任务训练专用 RL 模型，而是跨三大领域、每领域在 {low, high, max} 三档推理强度各训一个专家，共 9 个专家模型：(i) 通用任务（通用体验、视觉、推理、忠实性、搜索、知识工作）；(ii) 通用 Agent（长程助理、深度研究、段落级写作）；(iii) 编码 Agent（SWE、编码体验、kernel、Web 开发）。随 RL FLOPs 增加，工具调用步数与各领域分数同步持续上升。

  • Partial rollout：每迭代对 N 个 prompt 各采样 K 条轨迹（N×K 活跃），完成比例达 λ 即暂停生成进入策略优化，不等长尾；暂停的 rollout 入队、下一迭代优先恢复（依赖沙箱基础设施）。同一 prompt 的 K 条一旦齐了就立即送训。
  • 抗陈旧：长程轨迹天然跨多个迭代，引入数据陈旧。策略优化用逐 token 正则把更新约束在局部邻域，在极端 off-policy 下仍保持稳定。

3.3 Reasoning Effort RL：按题预算控制

每题关联初始 token 预算 $b_0(x)$（由冷启动模型估计），超出缩放阈值即覆盖奖励：

$$ R(y) = -1 \quad \text{若 } T(y) \gt \tau \cdot b_0(x) $$

通用任务 $T(y)$ 计 thinking tokens；agentic 任务计累计输出 tokens（推理轨迹 + 工具调用参数）。课程式退火：先以大 $\tau$ 训 max 档（仍封顶抑制过度思考），再退火到小 $\tau$ 得 high / low 档；$\tau$ 按领域在人工在环指导下调整。

3.4 Agentic GRM：不可验证任务的奖励模型

不可验证通用任务沿用 K2.5 的锦标赛式组奖励（二元比较），评审 agent 必须遵守协议：① 读产出 → ② 生成 rubric → ③ 按 rubric 逐项打分 → ④ 记录到 scorepad。为抑制「输出越来越长」的 reward hacking，加预算式冗长控制：输出长度超过 $\sigma \cdot \ell_0$ 的候选在二元比较中自动判负。

3.5 MOPD：多教师在环蒸馏

给定领域 $d$ 与采样 effort 档 $e$，用对应教师 $\pi_{\mathrm{teacher}}^{(d,e)}$ 对学生 $\pi_\theta$ 给出逐 token 在环蒸馏奖励：

$$ r_{\mathrm{opd}}^d(y_t \mid e, x, y_{\lt t}) = \mathrm{clip}\left(\mathrm{sg}\left[\log \frac{\pi_{\mathrm{teacher}}^{(d,e)}(y_t \mid x, y_{\lt t})}{\pi_\theta(y_t \mid e, x, y_{\lt t})}\right],\ -R_{\max},\ R_{\max}\right) $$

稠密奖励无缝接入 RL 框架（partial rollout 等基建直接复用），clip 抑制极端优势信号。试过更细粒度 top-k 蒸馏目标，收敛与终性能均无明确优势。

3.6 部署感知后训练：MXFP4 QAT 与 EAGLE-3 草稿模型

  • MXFP4 QAT：占参数大头的 MoE 专家权重量化到 MXFP4、激活 MXFP8；非专家组件（注意力投影、LatentMoE 投影、共享专家、路由器）保持高精度。QAT 贯穿 SFT 与 RL 全程，RL 的 rollout 与训练共享同一量化方案，消除训推不一致。
  • 草稿模型微调：预训练自带 MTP 层（结构与主干 block 相同），将其微调成 EAGLE-3 式单解码层草稿模型——目标模型冻结，只更新草稿层与特征融合投影。训练展开 7 步；输入融合目标模型第 1、4 及最后一个 AttnRes 块的低/中/高层特征，经无偏置矩阵 $W_{E3}$ 投影，初始化为 $[\,0\ 0\ I\,]$（初始等价于只用高层特征 $h_h$，即 MTP 预训练时的输入），微调中逐步学会利用低中层特征。
  • LK loss：投机解码加速由逐 token 接受率 $\sum_x \min(p(x), q(x))$ 决定，最小化 KL 代理目标不保证最大化接受率，故直接优化接受率本身的负对数：
$$ \mathcal{L}_{\mathrm{LK}} = -\log \sum_{x \in \mathcal{V}} \min\big(p(x), q(x)\big) $$

$p, q$ 在温度 1 下取值，无额外真值交叉熵项；草稿微调沿用 QAT 配置（专家 MXFP4 / 激活 MXFP8）。

3.8 XTML：K3 的聊天模板

围绕三个目标重新设计：可扩展（新能力靠后向兼容的消息格式而非模板改版）、低对齐税（少量 SFT 即可学，轻调基座可直接进 RL）、解码友好（简单编码器/流式解析/语法约束）。用三个保留特殊 token [open] [sep] [close] 替代 XML 尖括号，另设 [end_of_msg] 作生成停止符——每个结构边界都是显式特殊 token，消除 tokenization 歧义。

  • 消息分区：全局 option 消息（tool-declare、thinking-effort）置于输入消息之前（改动本就使 KV cache 失效）；一次性 option（tool_choice、response_format）置于输入消息之后（不破坏历史 KV cache）；会话中动态加载的工具通过插入新的 tool-declare 消息扩容，无需重建上下文。
  • 通道：assistant 消息体分 think / response / tools 三通道（借鉴 Harmony）。思考模式与 instruct 模式仅由生成前缀区分。K3 只支持 preserved thinking——think 通道始终保留在历史中（即使为空）。这也是官方「局限性」中要求 harness 回传完整思考历史的原因。
  • 工具调用：每个 call 带 tool 与 index 属性（编号并行调用），tool-result 重复同样的 tool/index 对；参数带类型（字符串原文、其余 JSON 类型紧凑序列化），代码等自由文本是一等公民而非转义 JSON 字符串；纯 JSON fallback 块只出现在输入 token，训练时 mask 掉 loss。
  • reasoning effort：作为 thinking-effort 全局 option 消息，用自然语言声明档位（schema 预留 low/medium/high/max 四级，K3 支持子集），充当生成约束指令——新 option 几乎零训练即可引入。

四、基础设施：3T 训练 × 1M RL × 生产服务

K3 罕见地叠加三个系统难题：混合 KDA 注意力、3T 级稀疏多模态训推、百万 token agentic 负载。基础设施沿模型生命周期与之协同设计。

4.1 KDA 的算法-系统协同设计

FlashKDA：chunkwise 训练/prefill 内核

KDA 的 chunkwise 形式 chunk 内并行、chunk 间串行，朴素执行会让 SM 在串行传播期闲置。基于 CUTLASS 的 FlashKDA 把 token 并行阶段与 head 并行递归各自独立调度调优，重叠 chunk 内计算与跨 chunk 状态传播，显著优于 Triton 参考实现；同时服务训练与推理 prefill，作为 flash-linear-attention 的后端自动分发。另有设备内 CP 规划器：状态转移可独立于入状态评估再精确复合，把序列切到单 rank 的多个 SM 上并行求段转移再合并，解决超长 prefill 下「每 rank 只有几个头、SM 大量闲置」的问题，无跨设备通信。

KDA Context Parallelism（KCP）

softmax 注意力的 CP 要交换随序列增长的 KV 块；线性注意力只需传固定大小状态 $S$，但朴素线性注意力「各 rank 从 S=0 算局部状态再求和」的做法对 KDA 不成立——delta rule 在写入前先用 token 相关矩阵 $M_t = (I - \beta_t k_t k_t^\top)\mathrm{Diag}(\alpha_t)$ 作用于入状态，局部段的效果依赖进入该段的状态。KCP 把每段效果分解为两个本地可算量：累积转移 $M_{t\leftarrow 1}$（作用于入状态）与从零生成的局部状态 $\widetilde{S}_t$：

$$ S_t[i{+}1] = \widetilde{S}_t[i{+}1] + M_{t\leftarrow 1}[i{+}1]\, S_{T_i}[i] $$

两个量在 $S_{T_i}[i]$ 可用之前就能用本地 token 算出，正是各 rank 交换的片段；rank 级更新满足结合律，可用前缀扫描恢复每个 rank 的入状态：各 rank 本地算两个张量 → 一次 all-gather → 按序复合。KCP 只需固定大小的 all-gather 即完成递归状态同步，算力随序列线性扩展（构建于 DeltaNet CP 之上，实现见 FLA PR #691）。

4.2 3T 级预训练基建

MoonEP：完美均衡的专家并行

  • 目标：每个 rank 恰好收到 $S \times K$ 个 token，所有 rank 计算量完全一致。已证明：每 rank 预留 E/R 个冗余专家槽即可保证均衡规划恒有可行解（上界基本紧，最坏构造需 $\lceil E(R-1)/R^2 \rceil \approx E/R$）；对比 ECHO/UltraEP 的预设上限或 token cap（无解即训练中断、需手调且留残余不均衡），MoonEP 训练永不因规划失败中断。
  • 在线规划：精确最优解用 ILP 离线算参考，线上用近最优 GPU 规划内核，开销可忽略且始终遵守 E/R 上界；前向用当前 micro-batch 的 router 输出规划并预取冗余专家，反向把梯度暂存本地 reduce buffer 后归约回原属 rank。
  • 零拷贝通信：融合 permute/unpermute 算子，规划内核预算每个 token 的目的地直发远端、通信缓冲视图直接给计算；最坏不均衡下 DeepEP 需 $S \times K \times R$ 缓冲，MoonEP 只需固定 $S \times K$。
  • 静态形状免同步：每层每 rank 恒收 $S \times K$ token ⇒ 所有层计算形状静态已知，消除逐层 MoE host 同步；rank 内专家 token 数仍偏斜，用 workload-aware 调度器在 launch 前按当前分布自适应 GEMM 参数；共享专家 GEMM 放到独立流上与其他内核重叠。

显存高效训练

  • 统一激活管理器：重计算/量化/offload/远程 offload 都是张量级可插拔存储策略，注解式声明、与模型代码解耦；单一显存池 + 层粒度预取回取；K3 大部分激活用 block-wise FP8 量化 + offload/远程 offload，逐元素算子配重计算。
  • MoE 梯度重写（受 SonicMoE 启发）：permuted probs 的梯度经数学变换只依赖中间激活与上游梯度，消除对前向输出的反向依赖；group GEMM 前向只存 dispatch 输入，反向重算 dispatch（通信可与部分反向计算重叠）。
  • AttnRes 伴随优化：块表示在边界层生成一次、供后续所有层共享并常驻 GPU；AttnRes 计算整体包 checkpoint；流水线并行用缓存式流水线通信，只增量传输新块、micro-batch 结束即释放，达显存理论下界。
  • PP rank 间激活均衡：interleaved 1F1B 下各 PP rank 驻留激活不均，用 Mooncake Transfer Engine 把激活远程 offload 到其他 PP rank 的显存。
  • Pipeline ZeRO-2 梯度分片：梯度跨 DP rank 分片并存放 CPU 内存（GPU 上保留 double grad buffer）。
  • P2P 式 Muon 正交化：分布式优化器把参数分片到 DP rank，而 Newton–Schulz 需要完整矩阵——不做全参数 all-gather，各 rank 只通过 P2P 向属主 rank 取回自己持有参数的分片，通信与计算按 model-chunk 粒度流水重叠。

多模态编码器优化

  • 动态 CP：大图沿 patch 维切到多设备、gather-KV 算注意力；CP 组再分子组负载均衡地分发多张大图，降低大视觉样本延迟与跨设备负载不均。
  • 藏进流水线气泡：interleaved 1F1B 下，首批 micro-batch 的文本前向集中在开头、末批的文本反向集中在结尾；据此分解 ViT 计算——首批前向同步先跑，其余前向排进气泡，反向同理。大部分 ViT 计算被藏进流水线气泡，视觉编码器有效开销基本消除（K2.5 DEP 的进一步演进）。

4.3 百万 token Agentic RL 基建

  • 共置 RL + 外部 KV cache 池：co-located 训练让每个 1M-context RL 实验只需几百张 GPU；写回式设计——活跃解码块留 GPU，被逐出的可复用空闲前缀才写回 CPU DRAM 外部池、复用前预取；KDA 状态与对应 MLA KV 块一起 offload/预取，生命周期对齐。训练迭代结束后把训练状态（权重+优化器）卸到 NVMe 腾 DRAM，rollout 后释放池避免争用。
  • 自动节流调度：轨迹推进时上下文逐渐变长，固定并发不是保守就是爆 KV。用活跃请求数、排队数、KV 利用率等运行时信号动态控制发往推理引擎的请求数，无需手调即避免欠饱和与过载。
  • 梯度缓冲复用：参考模型等 forward-only 非策略模型权重驻留 CPU，需要时用策略模型的 FP32 梯度缓冲（每 GPU 仅存 2 个 VPP chunk 槽）来实体化——一个槽算当前 chunk、另一个槽预取下一 chunk，不新增显存。

4.4 推理与在线服务

KDA 感知前缀缓存

混合架构下 KDA 递归状态（每请求一份定长）与 MLA KV（随序列增长、按 token 分页）大小与生命周期完全不同，但缓存前缀只有在同一边界两者都能恢复时才可复用：

  • 统一布局：把 KDA 状态打包进与 MLA KV 相同的分页块池（页字节数对齐，共享分配/引用计数/逐出实现）；页内按头连续存储，头是跨节点传输最小单元；PD 分离两侧 TP 度不同时重排布放在传输路径上做，GPU 侧零改洗。
  • 粒度解耦：状态快照只在稀疏边界可承受 ⇒ 物理块被迫大到 1024–6144 token，若哈希粒度随之变粗，缓存几乎无用（短于一块的请求永不命中）。解法：前缀哈希跑在 MLA 页内的细粒度哈希块（512 token）上，物理块仍是粗分配单元；KDA 只在（稀疏子集的）哈希端点存 checkpoint。查找两阶段：MLA 侧先整块匹配、落空则回退到块内哈希端点；KDA 侧要求候选边界在每个 KDA 缓存组都有 checkpoint；命中取两阶段都满足的最长边界。例：前 2800 token 匹配的请求在 $B = 2560 = 5 \times 512$ 处命中（深在 6144-token 物理块内部），从 B 续 prefill，$[0,B)$ 零重算。
  • 并发一致性：命中块先全组 pin 再分配；当前调度步内分配/注册的块在拷贝落地前不参与匹配；任一 KDA 组逐出 checkpoint 即原子失效其全部兄弟。

高性能内核

  • KDA 解码：MTP 投机解码下验证拒绝部分草稿时，原地更新的状态无法回滚；存每草稿位快照又会倍增状态流量。改为只缓存草稿 token 的投影输入（远小于状态），在片上重建被接受 token 的状态（与 ReplaySSM 独立同思路）；重放、bonus token、下一草稿窗口共享一个融合内核（短卷积/归一化/门控/递归/输出归一化），验证延迟随验证 token 数亚线性增长。
  • Block AttnRes：prefill 用序列并行（TP all-reduce 拆成 reduce-scatter + all-gather，块内内核插中间）使每 token 块表示只在一个 rank 实体化；解码时块间内核放旁流与主流重叠，块内合并 + RMSNorm 融进前序 TP all-reduce。
  • Stable LatentMoE：latent 下投影与路由器融为单 GEMM；latent 权重跨 rank 分片、输出 all-gather 用 multimem store 融进 GEMM 尾声；小 batch 下路由专家 group GEMM 退化为访存受限的权重流——改用 WarpDecode 式 token 中心内核（每 warp 负责一个输出神经元直读权重），warp 内再分 lane team 处理不相交专家子集 + warp 级归约；权重布局离线预置换降低运行时反量化开销。

集群级调度

  • 缓存感知亲和调度：1M 下典型编码输入带 400K 前缀、prefill 增量仅 4K，命中比重算便宜数个量级 ⇒ 会话路由到持有其前缀缓存的集群；一致性哈希把每会话钉在主集群 + 预备份集群，主挂时备集群重新 prefill，且备分配均匀散布全 fleet，单集群故障影响有界。
  • 预算制准入控制：生产流量单请求成本横跨约 3 个数量级（<2K 到 1M token），按「平均请求」做的容量规划/限流失效；给不同请求类别分配独立资源预算，长上下文突发最多耗尽自己份额，不拖累全局 TTFT SLO。
部署建议（官方）：专家并行规模越大越需要大高带宽通信域，推荐 64+ 加速卡的超节点（supernode）配置部署 K3；KDA 前缀缓存实现已贡献给 vLLM 社区，随模型一同发布。官方 API 基于 Mooncake 分离式推理架构，编码负载下缓存命中率超 90%。

  • Tier 2 端到端漏洞利用：36 题（16 用户态 + 20 内核，全部人类专家验证可解，全套约 540 专家时）——K3 解出 14/36（38.9%），GLM-5.2 为 8/36；14 题中 10 题来自用户态轨道。失败模式四类：拿到原语后完不成利用链末段；缓解措施下策略选择差（该用 data-only 时死磕控制流劫持）；陷入长时间无效调试循环；提交前验证不足。
  • 第三方印证：UK AISI 与 NIST CAISI 联合评估结论一致——K3 优于 GLM-5.2（ExploitBench 32% vs 24%；32 步模拟企业网 17 vs 11 步），但端到端利用完成度仍落后前沿网络能力模型（41 题任意代码执行 0 通过）。

七、局限、定价与使用建议

7.1 官方明示的三条局限

  1. 对思考历史敏感：K3 以 preserved thinking 模式训练，harness 若未按要求回传全部历史 thinking、或会话中途从别的模型切到 K3，生成质量可能极不稳定。建议用兼容性已验证的 harness（如 Kimi Code），且不要中途切模型。
  2. 过度主动：训练偏重长程困难任务，遇到小问题或意图模糊时可能替用户做意料之外的决定。需要严格边界的应用，应在系统提示或 AGENTS.md 中施加显式行为约束。
  3. 体验差距：整体竞争力强，但与 Fable 5、GPT-5.6 Sol 相比用户体验仍有可见差距。
