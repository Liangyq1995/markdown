一、框架三大问题

问题问什么失败症状
Execution如何在 GPU/CPU 上跑算子？GPU 0% 利用率
Differentiation如何自动求 $\partial L/\partial W$？手写梯度错维度
Abstraction如何组合层而不写 CUDA？重复 boilerplate

二、抽象阶梯

flowchart BT
  L0["CUDA / Triton 内核"]
  L1["ATen / cuDNN 算子"]
  L2["nn.Module / Keras Layer"]
  L3["Trainer / Lightning"]
  L0 --> L1 --> L2 --> L3

越往上开发越快；越往下控制 $\eta_{\text{hw}}$。生产路径：默认 L2–L3，热点用 L0 custom kernel（第 11 章）。

三、Execution：Kernel Launch Tax

每个 GPU kernel 启动固定开销约 5–50 μs（驱动+调度）。1000 个 tiny op → 50 ms 纯 overhead，零有用 FLOPs。对策：torch.compile / XLA / CUDA Graph 融合算子，把 1000 次 launch 并成 1–10 次。

铁律 $L_{\text{lat}}$ 在框架层的表现：小 batch 推理时 launch 占比可超 30%。

四、Differentiation：Autograd

x = torch.tensor([2.0], requires_grad=True)
y = x ** 2 + 3 * x
y.backward()
print(x.grad)  # tensor([7.])  因 dy/dx = 2x+3 |_{x=2} = 7

计算图 tape：前向存中间值 → 反向按链式法则。内存代价：训练需存激活 ≈ 参数量 2–3×（与第 5 章一致）。

五、nn.Module 与训练一步

optimizer.zero_grad()
logits = model(batch_x)           # forward
loss = F.cross_entropy(logits, y) # loss
loss.backward()                   # backward
optimizer.step()                  # W -= lr * grad

单步时间分解（典型 ResNet A100）：forward ~40%，backward ~40%，optimizer ~10%，DataLoader ~10%（饥饿时 DataLoader→50%+）。
