概述

音频天然具有交互属性——人类在日常生活中时刻处于声音环境之中，随时感知、随时响应。然而，当前的大型音频语言模型（Large Audio Language Models，LALMs）普遍采用离线批处理范式：先收集完整音频，再统一推理，无法在音频流入时实时决策。这一局限使得实时语音助手、主动音频干预等场景无从实现。

本文提出 Audio-Interaction——一个统一的流式音频大模型，通过 SoundFlow 端到端框架（含流式数据构建、感知感知训练、异步低延迟推理三阶段），配合 StreamAudio-2M（260万条、302k小时的流式音频语料库）和新基准 Proactive-Sound-Bench，在保持主流离线任务竞争力的同时，首次实现了"always-on perceive-decide-respond"的在线音频交互循环。

在8个基准测试上的实验表明，Audio-Interaction（3B参数）在 MMAU 指令理解评测中以 58.15分 超越 Qwen2.5-Omni-7B（49.58分），同时在主动音频干预基准上以 62.8% 的多事件准确率领先所有对比模型，验证了流式统一架构的有效性。

研究背景

理解本文的动机，需要从三个维度审视当前音频AI的局限性：离线模型的结构性缺陷、实时交互的现实需求，以及流式音频建模面临的技术挑战。

离线 LALMs 的局限

现有 LALMs（如 Qwen2-Audio、SALMONN、Qwen2.5-Omni）采用的是经典的"输入-推理-输出"静态范式，可形式化为：

$$y = f(x, \mathcal{A})$$

其中 $x$ 是完整音频输入，$\mathcal{A}$ 是任务指令，$y$ 是模型输出。这一范式存在三个根本性缺陷：

  • 无法处理连续流：音频必须先收集完毕才能处理，无法在音频持续流入时实时推理；
  • 被动响应：模型只能等待用户显式指令，无法主动感知环境音频事件（如烟雾报警、婴儿哭声）并主动介入；
  • 任务碎片化：ASR、音频理解、对话等任务分散在不同模型中，缺乏统一的在线处理框架。

实时交互的现实需求

随着智能耳机、车载助手、智能家居等场景的普及，用户对音频AI的期望已从"问答工具"升级为"始终在线的智能伴侣"。这要求模型能够：

  • 在用户说话的同时实时转录（实时ASR）；
  • 在连续音频流中跟随多轮指令（流式指令跟随）；
  • 在检测到特定环境音事件时主动提醒用户（主动音频干预）。

这三类能力在离线范式下均无法原生支持，需要从架构层面重新设计。

流式音频建模的技术挑战

将音频处理从离线迁移到流式并非简单的工程适配，而是面临深层的技术挑战：

  • 跨块连续性：音频被切分为固定长度的块（chunk）后，块间语义连续性会被打断。实验发现，原始编码器输出的块间余弦相似度仅为 0.25，直接影响理解质量；
  • 决策时机：模型需要在每个时间步判断"保持静默"还是"生成响应"，这一二元决策的精度直接决定交互体验；
  • 推理延迟：流式场景对首块响应延迟（First Chunk Latency，FCL）极为敏感，传统自回归推理的串行特性会导致显著的卡顿；
  • 数据缺乏：现有音频数据集几乎全部为离线格式，缺少带时间戳标注的流式交互数据。

核心框架：Always-On Perceive-Decide-Respond Loop

Audio-Interaction 的核心设计哲学是将音频交互形式化为一个持续运行的感知-决策-响应循环，使模型在每个音频块到达时均执行一次完整的决策过程，而非等待完整输入。

形式化定义

与离线范式的静态映射不同，Audio-Interaction 在每个时间步 $t$ 同时输出决策令牌 $d_t$ 和响应 $r_t$：

$$(d_t, r_t) = f(a_{\leq t},\ d_{<t},\ r_{<t})$$

其中 $a_{\leq t}$ 是截至当前时刻的音频流，$d_{<t}$ 和 $r_{<t}$ 是历史决策和响应上下文。决策令牌 $d_t$ 取值为：

$$d_t \in \{\texttt{<silent>},\ \texttt{<response>}\}$$

响应生成规则为：

$$r_t = \begin{cases} \varnothing, & d_t = \texttt{<silent>} \\ f_{\mathrm{resp}}(a_t, C_t), & d_t = \texttt{<response>} \end{cases}$$

其中 $C_t$ 是包含历史决策和响应的上下文。这一设计将"何时响应"和"响应什么"解耦为两个子问题，前者由轻量决策头处理，后者仅在触发时激活完整生成路径，从而在保证响应质量的同时控制计算开销。

关键设计：决策令牌机制

决策令牌 <silent> 和 <response> 是整个框架的核心创新。与传统的 VAD（语音活动检测）不同，这两个令牌是语义级别的决策，而非纯粹的能量/频谱检测：

  • <silent>：不仅代表"无人说话"，还包括"有声音但无需响应"（如背景音乐、环境噪声）；
  • <response>：不仅响应用户明确指令，还能主动识别需要干预的环境事件（如报警声、婴儿哭声）。

实验发现，模型中存在一个特定注意力头（L35H14，第35层第14号头）在流式控制令牌的生成决策中起主导作用，单独消融该头会导致语音翻译令牌匹配率下降 0.88，揭示了流式控制的神经机制具有高度局部化的特征。

SoundFlow 系统：端到端流式处理框架

SoundFlow 是支撑 Audio-Interaction 的完整工程框架，覆盖从原始数据到实时推理的全链路。它由三个紧密耦合的阶段组成：流式原生数据构建、感知感知训练、异步低延迟推理。

阶段一：流式原生数据构建

离线音频数据集不能直接用于流式训练——它们缺少连续性、时间戳标注和噪声背景。SoundFlow 的数据构建管线通过以下步骤将离线数据转化为流式格式：

  1. TFJP 预处理（Time-Frequency Joint Processing）：对每条音频执行静音切割（$\tau=300$ms）、噪声分析（最低能量5%帧）、谱减法去噪（$\gamma=1.0$）、边界归一化和谱平滑（$\omega=20$ms Hann窗），最多迭代 $K=3$ 次直至稳定，对齐步长 $\delta=200$ms；
  2. 分层事件筛选：按音频类型（语音/音乐/环境音/噪声）分层采样，确保各类事件在训练集中的覆盖均衡；
  3. 序列拼接与噪声混合：将多条短音频拼接为 3–15 轮的连续对话序列，同时叠加双轨噪声（前景0dB、背景-6dB、环境-12dB），噪声池 $\mathcal{N} = \textsc{MUSAN} \cup \textsc{WHAM!} \cup \textsc{DNS-Challenge}$，SNR 均匀采样 $\mathcal{U}(5, 20)$dB；
  4. Token级标注：为每个位置生成 $\langle\text{input ids}, \text{labels}\rangle$ 对，包含决策令牌和响应内容的对齐标注。

阶段二：感知感知训练（四阶段课程）

训练采用由浅入深的四阶段课程策略，每阶段递进地解锁更多模块：

阶段描述可训练模块核心目标
Stage 1格式训练LM Head + 新Token嵌入学习 <silent>/<response> 令牌用法
Stage 2适配器训练Adapter only将块级声学特征对齐到LM语义空间
Stage 3大规模流式SFTAdapter + LMASR/翻译/对话/音频理解多任务联合
Stage 4指令跟随微调全模型多轮对话、主动干预、历史回顾能力

训练目标采用双损失函数，同时优化语言建模损失和流式控制损失：

$$\mathcal{L} = \frac{1}{N}\sum_{j=1}^{N}\left(\underbrace{-\log P_\theta(t_j \mid \mathcal{H}_j)}_{\mathcal{L}_{\mathrm{LM}}} + \lambda \underbrace{-\log P_\theta(s_j \mid \mathcal{H}_j)}_{\mathcal{L}_{\mathrm{stream}}}\right)$$

其中 $t_j$ 是目标文本令牌，$s_j$ 是流式控制令牌（silent/response），$\mathcal{H}_j$ 是历史上下文，$\lambda$ 为平衡系数（最优值 $\lambda=1.0$）。双损失设计确保模型在提升语言理解质量的同时，精准学习流式决策时机。

此外，训练中还引入了两项关键技术：

  • 历史回顾（History Review）：在训练序列中随机插入对历史片段的回顾问答，防止模型在长序列中遗忘早期内容；
  • 静音训练（Silence Training）：专门构造含大量静音段的训练样本，强化模型在无声环境下的"保持静默"决策。

StreamAudio-2M 数据集

StreamAudio-2M 是本文构建的大规模流式音频语料库，也是目前已知规模最大、任务覆盖最广的流式音频交互数据集。它包含 260万条 训练样本、302k小时 音频、749万轮 对话交互，覆盖 7个核心能力 和 28个子任务。

数据构建管线

从原始数据到最终语料库经历四步处理：

  1. 数据收集：汇聚约164万条基础样本（约8900小时），来源覆盖多语言ASR、音频理解、对话等开源数据集；
  2. 预处理：使用 CosyVoice TTS 合成语音，LLM 改写文本以增加多样性，ASR 质量过滤（WER阈值 $\tau_{\text{wer}}=0.10$，最多重试 $R=2$ 次）；
  3. 序列拼接：TFJP 预处理 + 双轨噪声混合，生成3–15轮连续对话序列；
  4. Token级标注：为每个位置生成决策令牌和响应内容的精确对齐标注。

异步低延迟推理：FIFO 调度机制

流式推理的核心挑战在于：音频块持续到来，而语言模型的自回归生成需要时间。若处理不当，会出现两类问题：首块响应延迟过高（FCL过大），或因处理速度跟不上输入速度而产生卡顿（Stall）。SoundFlow 通过 FIFO（First-In-First-Out）异步调度 机制解决这一问题。

FIFO 调度原理

传统同步推理中，音频块的处理与LM生成串行执行，导致每个块的等待时间累积。FIFO 调度将两者解耦为独立的异步流：

  • 输入队列：音频块以固定间隔（400ms）入队，编码器持续处理；
  • 决策队列：决策头以FIFO顺序消费编码结果，输出 silent/response 令牌；
  • 生成队列：仅当决策为 response 时，触发LM生成并将结果异步推送到输出流；
  • 背压控制：当生成队列积压超过阈值时，自动降低采样率或跳帧，防止内存溢出。

FIFO 效果验证

实验数据显示，FIFO 调度将首块延迟从 831ms 降至 392ms（降低 4.5×），并将卡顿率从 5.2% 降至 0%，实现了稳定的实时交互体验。

跨块连续性：神经机制分析

一个重要的发现是，模型能够在内部自动重建跨块的语义连续性。实验测量了不同模块输出的块间余弦相似度：

  • 原始编码器输出：余弦相似度 0.25（连续性极低）；
  • GPT Layer 0 输出：余弦相似度提升至 0.80（仅经过一层即大幅恢复）。

这说明语言模型的最底层就已具备跨块语义融合能力，连续性重建是一个涌现性质，无需专门的跨块注意力机制。

实验结果

Audio-Interaction 在 8 个基准测试上与主流离线和在线模型进行了全面对比。核心发现是：一个3B参数的流式模型可以在多个维度超越7B参数的离线模型，打破了"流式=性能妥协"的固有认知。

MMAU 音频指令理解基准

MMAU（Massive Multitask Audio Understanding）是综合评测声音理解、音乐理解和语音理解的主流基准。Audio-Interaction（3B）以 58.15 分成为所有参测模型中的最高分，超越 Qwen2.5-Omni-7B（49.58）达 8.57 分。

消融实验揭示了各组件的贡献：

  • 流式SFT（V1→V2）：触发准确率从无到有（92.42%），MMAU 提升 +0.75；
  • TFJP预处理（V2 vs V3）：触发准确率提升 +7.07pp（92.42%→85.35%的对比说明去除TFJP后下降）；
  • 事件筛选（V2 vs V4）：MMAU 提升 +3.45（55.11→58.56），是质量提升最显著的单一组件；
  • 完整模型（V5）：触发准确率达 96.77%，各项指标综合最优。

Proactive-Sound-Bench：主动音频干预基准

Proactive-Sound-Bench 是本文提出的新基准，专门评估模型在无显式指令情况下主动识别并响应环境音频事件的能力——这是现有所有音频基准均未覆盖的能力维度。

基准设计

Proactive-Sound-Bench 包含 644个 人工设计的声学事件场景，按难度分为两个层级：

  • Single 层级：单一事件决策——在干净或低噪声背景下，判断是否需要对特定声学事件（如烟雾报警、婴儿哭声、门铃）进行响应；
  • Multiple 层级：多事件干扰——在持续的干扰音（背景音乐、人群噪声）中，准确识别目标事件并维持干预决策。

事件类别覆盖 6个顶级类别、17个子类别，包括：

  • 安全警报（烟雾报警、CO报警、火警）；
  • 家庭事件（婴儿哭声、宠物叫声、门铃）；
  • 交通场景（汽车喇叭、紧急车辆警报）；
  • 自然灾害（雷声、地震警报）；
  • 医疗场景（心脏监护仪、呼叫铃）；
  • 工作场景（会议提醒、电话铃声）。

评测指标为各类别的平均准确率，Single 和 Multiple 分别统计。

评测结果

Audio-Interaction 在 Single 层级（61.2%）和 Multiple 层级（62.8%）均取得最高分。尤其在更具挑战性的 Multiple 层级，相比 Qwen2.5-Omni-7B（32.1%）提升 +30.7pp，体现了流式训练在主动感知方面的显著优势。值得注意的是，MiniCPM-o-4.5 在 Multiple 层级也表现出色（58.9%），说明部分离线模型通过特殊设计也能具备一定的主动响应能力，但 Audio-Interaction 仍以 3.9pp 领先。

总结与启发

Audio Interaction Model 是音频AI领域从"工具型"向"交互型"演进的重要里程碑。它不仅提供了一套完整的技术方案，更揭示了若干值得深思的研究洞见。

核心贡献总结

1. 范式转换：将音频AI从"输入-推理-输出"的静态范式升级为"always-on perceive-decide-respond"的动态循环，从根本上扩展了LALMs的能力边界。

2. 统一框架：SoundFlow 首次在单一模型中统一了实时ASR、流式指令跟随、主动音频干预三类在线能力，避免了多模型切换的工程复杂性。

3. 数据驱动：StreamAudio-2M 的构建方法论（TFJP预处理 + 分层事件筛选 + 双轨噪声混合）为流式音频数据的规模化生产提供了可复现的范本。

4. 效率突破：3B参数的流式模型在MMAU上超越7B参数的离线模型，证明流式训练不仅不损害理解能力，反而通过更丰富的上下文学习提升了整体性能。

关键技术洞见

  • 连续性涌现：跨块语义连续性在 GPT Layer 0 即自动重建（0.25→0.80），说明LM底层具备强大的上下文融合能力，无需专门的跨块注意力机制；
  • 注意力头专化：单个注意力头（L35H14）主导流式控制决策，揭示了流式能力在模型内部的高度局部化表征；
  • 双损失平衡：$\lambda=1.0$ 是语言质量与流式决策精度的最优平衡点，过大的 $\lambda$ 会损害语言理解能力；
  • 块大小甜点：400ms 块大小在延迟（392ms）与质量（MMAU 58.15）之间取得最优平衡，与人类语音感知的自然分组粒度高度吻合。

局限性与未来方向

  • ASR 精度：流式模式下 WER 略高于专用 ASR 模型（3.17% vs 1.48%），在高精度转录场景仍有提升空间；
  • 多语言扩展：当前主要支持中英双语，多语言流式交互能力有待验证；
  • 端到端语音输出：当前输出仍为文本，与 Moshi 等端到端语音系统相比缺少直接语音响应能力；
  • 个性化适应：always-on 系统需要根据用户偏好动态调整触发阈值，个性化流式交互是重要的未来方向；
  • 隐私与安全：持续监听模式带来的隐私保护问题需要在部署层面重点关注。

对行业的启发

Audio-Interaction 的成功表明，流式与离线不是对立关系——通过精心设计的数据构建（TFJP）、训练策略（双损失+课程学习）和推理机制（FIFO调度），流式模型可以在保持离线任务竞争力的同时获得全新的在线能力。这一思路对视频、多模态等其他流式场景同样具有参考价值。

对于工程实践者而言，400ms 块大小、FIFO 调度、$\lambda=1.0$ 双损失权重等具体超参数选择提供了可直接参考的工程基线。对于研究者而言，L35H14 注意力头的发现为理解流式能力的神经机制开辟了新的探索方向。
