第10章 模型压缩

《Introduction to Machine Learning Systems》Vijay Janapa Reddi · MIT Press · Vol.1 · 生成日期：2026-07-04

核心主线优化栈三层（结构→数值→执行）→ 剪枝/蒸馏/NAS → 量化 PTQ/QAT → 架构效率与算子融合 → 技术选型
学习目标理解压缩作为 Algorithm-Machine 协同设计，能在精度约束下选择并组合剪枝、量化、蒸馏与架构优化

一、开篇：为何需要模型压缩

赢得基准测试的模型，很少能直接上生产。Cloud / Edge / Mobile / TinyML 各自施加内存、延迟、功耗硬约束——7B 参数 FP16 模型需 14 GB，而智能手机共享 RAM 仅 8 GB。压缩不是"把模型做小"，而是在部署物理环境中重新谈判硅片契约（Silicon Contract）：训练时向上谈判算力与精度，部署时向下谈判内存、带宽与延迟。

定义：模型压缩（Model Compression）

通过消除冗余参数（剪枝 Pruning）、降低数值精度（量化 Quantization）或将行为迁移到小架构（蒸馏 Distillation），在尽可能保留预测精度的前提下，降低计算成本与内存占用。

  • 与 NAS 区别：NAS 在训练前搜索高效架构；剪枝/量化是训练后压缩
  • 常见陷阱：多种技术叠加可能相互干扰——剪枝后再量化可能放大近零权重区域的量化误差

部署鸿沟（Deployment Gap）

MobileNetV2 INT8 约 3.5 MB，仍超出 TinyML ~524 KB 信封约 6.7×；而专用 DS-CNN 关键词识别约 500 KB 可适配。压缩在 TinyML 上是生存问题，而非可选优化。

1.2 DR 案例：compress-validate-adjust 循环

第 3 章 512 MB / 灵敏度 ≥90% 约束在此落地为迭代管道：

  1. FP32 MobileNetV2 ~14 MB → INT8 ~3.5 MB（量化）
  2. 验证农村子群灵敏度：0.923 → 0.891（低于 0.90 门槛）
  3. QAT 2 epoch + 校准集 500 张农村图 → 0.904（通过）
  4. Jetson 实测 p99 180 ms（< 2 s SLA）

每步只接受可测指标晋升；FLOPs 降 4× 但灵敏度 0.88 则回滚上一 artifact。

1.3 Pareto 前沿与停止准则

横轴延迟/体积，纵轴精度。膝点（knee）后：INT4 再省 2× 内存但灵敏度 −3 pt → 不采纳。工程在膝点停，而非追极限压缩比。

二、结构优化：剪枝

现代网络过度参数化（Overparameterization）是训练所需，但部署时每个多余参数都浪费内存与算力。剪枝目标：在参数预算 $k$ 内最小化精度损失。

$$\min_{\hat{W}} \mathcal{L}(\hat{W}) \quad \text{subject to} \quad \|\hat{W}\|_0 \leq k$$

$\|\hat{W}\|_0$ 为 L0 范数（非零参数计数），NP-hard，实践中用幅度剪枝（Magnitude-based Pruning）等启发式替代。

类型移除对象内存计算加速硬件兼容
非结构化单个权重高压缩比需稀疏内核需专用支持
结构化通道/滤波器/层中等直接减少 FLOPs通用加速器友好
动态运行时按输入可变自适应实现复杂

N:M 结构化稀疏（A100 2:4 模式）

每 4 个权重中保留 2 个非零——硬件约束而非数学最优。A100 Sparse Tensor Core 在满足 2:4 布局时可获约 2× 数学吞吐，非结构化 90% 稀疏若无匹配内核则可能比稠密更慢。

2.1 剪枝策略与彩票假设

迭代剪枝：多轮"剪枝→微调"，27% 通道移除后精度仅降 0.4%。一次性剪枝：同时移除 27% 通道，精度从 0.995 跌至 0.943（5% 退化）。

彩票假设（Lottery Ticket Hypothesis, LTH）：大网络中存在"中奖子网络"，重置到初始权重后单独训练可达与全网络相当精度——暗示部分训练开销是可发现的冗余。

2.2 三区域框架（Region 1/2/3）

区域技术精度代价系统收益

工程顺序：先 Region 1（免费），再 Region 2（DR QAT 在此），Region 3 仅在约束仍不满足时进入。

2.3 NAS 与硬件感知搜索

神经架构搜索（NAS）在训练前搜索 depth/width/operator 组合，目标函数含 latency/FLOPs 惩罚项。MnasNet 在 Pixel 手机上 latency-aware 搜索，比 MobileNetV2 同精度快 1.5×。与剪枝区别：NAS 产出新拓扑，剪枝从已有拓扑删除——TinyML 524 KB 信封常需 NAS 级 redesign（DS-CNN）而非 post-hoc 压缩。

三、知识蒸馏

剪枝从现有架构"雕刻"；蒸馏则训练全新学生模型模仿教师模型行为。教师软标签（如 $[0.85, 0.10, 0.05]$）携带类间相似性"暗知识"（Dark Knowledge），比硬标签 $[1,0,0]$ 信息更丰富。

$$p_i^{(T)} = \frac{\exp(z_i/T)}{\sum_j \exp(z_j/T)}$$
$$\mathcal{L}_{\text{distill}} = (1-\gamma_{\text{KD}})\mathcal{L}_{\text{CE}}(\mathbf{p}_{\text{student}}, y) + \gamma_{\text{KD}} T^2 \mathcal{D}_{\text{KL}}(\mathbf{p}_{\text{teacher}}^{(T)} \Vert \mathbf{p}_{\text{student}}^{(T)})$$

DistilBERT 案例

保留 BERT 约 97% 性能，参数减 40%（110M→66M），推理快 60%，内存 1.35 GB→0.81 GB，延迟 85 ms→34 ms——跨越移动端实时 NLP 门槛。

四、量化与精度

结构优化 alone 难超 50–70% 参数削减；量化将每个参数/激活的 bit 宽度从 FP32 降至 INT8/INT4，直接攻击铁律的数据移动项 $D_{\text{vol}}/\text{BW}$。

量化物理：能量层级

Horowitz 数据：32-bit DRAM 读相对 8-bit 整数加法的能量比约 21,333×。FP32→INT8 不仅 4× 缩小数据，算术能量约降 30×——"4× 价格换 30× 回报"的能量红利（Energy Dividend）。

4.1 均匀量化公式

$$q = \text{round}\left(\frac{x}{s}\right), \quad \hat{x} = q \cdot s$$

$s$ 为缩放因子，$q$ 为离散整数值。三种策略复杂度递增：

  • PTQ（Post-Training Quantization）：训练后转换，需校准集估计激活范围
  • QAT（Quantization-Aware Training）：训练循环中插入假量化节点
  • 极端量化：INT4、二值/三值网络，TinyML 必需但精度风险高
格式位宽存储缩减典型场景
FP3232-bit基准通用训练/推理
FP16/BF1616-bit2×Tensor Core 训练
INT88-bit4×边缘/移动推理
INT44-bit8×LLM 端侧部署

LLM 量化速算：Llama 3 8B

FP16：$8 \times 10^9 \times 2$ = 16 GB，需 24 GB GPU。
INT4：$8 \times 10^9 \times 0.5$ = 4 GB，可上 8 GB 消费级 GPU。
自回归 decode：读 4 GB 权重 @ 50 GB/s → 80 ms/token 理论下限；INT4 @ 3.35 TB/s（H100）→ ~1.2 ms 理论下限（第 13 章 TPOT）。

4.2 GPTQ / AWQ

GPTQ：逐层 Hessian 感知量化，将 $W$ 压到 4-bit，8B 模型 ~4.1 GB。校准集 ~128 条文本即可估计激活尺度。

AWQ（Activation-aware Weight Quantization）：保护激活幅度大的「salient」通道用更高精度，4-bit 下 perplexity 损失小于 naive PTQ。Llama3-8B AWQ 可在 H100 80 GB 上 batch≈1700 并发（配合 PagedAttention，见第 13 章）。

4.3 QAT 假量化节点

# 训练图插入 fake quant，反向用 straight-through estimator
x_q = round(x / s) * s   # s 为 per-channel scale
# 导出 INT8 引擎时 s  baked into conv weight

PTQ 用 512–1024 张生产分布图像估 $s$；用 ImageNet 校准 wildlife 相机可掉 3.2 pt。对称量化 $s=\max(|x|)/127$ 实现简单、Tensor Core 友好；ReLU 后全正激活可用非对称 zero-point $z$。

五、架构效率

压缩在纸面上变小，profiler 仍可能显示稠密内核、精度转换开销——架构效率决定剩余计算如何映射到机器。

5.1 硬件感知设计

观测瓶颈架构响应代表网络
冗余卷积计算深度可分离卷积MobileNet
内存压力特征复用、参数缩减DenseNet, SqueezeNet
全局超预算复合缩放 depth/width/resolutionEfficientNet
平台不匹配硬件感知 NASMobileNetV3, MnasNet

标准卷积复杂度 $\mathcal{O}(hw C_{\text{in}} C_{\text{out}} k^2)$；深度可分离卷积分解为 $\mathcal{O}(hw C_{\text{in}} k^2) + \mathcal{O}(hw C_{\text{in}} C_{\text{out}})$，常获 5–10× FLOP 削减（MobileNetV2 相对 ResNet-50 约 13.7× 运算量，接受约 4 点 ImageNet 精度损失）。

5.2 算子融合

$$D_{\text{vol,unfused}} = 2NM \quad \Rightarrow \quad D_{\text{vol,fused}} = 2M$$

Conv-BN-ReLU 三算子未融合：3 次 kernel launch、6 次内存传输；融合后 1 次 launch、2 次传输。ResNet-50 单层 256 通道 $28\times28$ 可消除约 3.2 MB 中间流量。FlashAttention 通过 SRAM 分块将注意力 HBM 流量从 $\mathcal{O}(S^2)$ 降至 $\mathcal{O}(S)$。

5.3 自适应计算

早退（Early Exit）：中间层置信度足够则终止，简单输入省算力。条件计算：SkipNet 跳过简单输入的层；MoE 每 token 仅激活少数专家（Switch Transformer 1.6T 参数但每 token 仅 0.13% 激活）。

六、技术选型与组合

验收指标：FLOP/MAC 计数不等于 wall-clock；稀疏无硬件支持时可能更慢；DR 案例以 Jetson 上 batch=1 的 p99 延迟为唯一 SLA 指标，工具链 PyTorch → ONNX → TensorRT，须在部署芯片上测。

推荐流水线（MobileNet 部署示例）

  1. 结构化剪枝 50% 滤波器（表示层）
  2. INT8 量化剩余权重（数值层）
  3. BN 融合进卷积（执行层）

三层作用于不同栈级，增益复合而非重叠。验证必须在目标硬件上测量延迟、能耗与精度——FLOP 计数不能替代实测。

七、章节总结

核心要点

  1. 压缩是 Algorithm-Machine 协同设计，重新谈判硅片契约
  2. 优化栈三层（结构→数值→执行）应组合使用，在 Pareto 前沿"膝点"停止
  3. 非结构化稀疏需硬件匹配；结构化剪枝与 N:M 模式才能转化为真实加速
  4. 蒸馏产生稠密小模型，适合架构根本不同的部署目标
  5. 量化攻击数据移动与算术能量；LLM 自回归生成尤其受益于 INT4
  6. 架构效率（MobileNet、融合、早退）将 profiler 瓶颈前移到设计阶段
压缩的守恒定律：复杂度很少消失，只是从参数/精度迁移到运行时稀疏格式、蒸馏训练预算或路由开销。工程师的任务是把代价移到部署约束下最便宜的轴上。
