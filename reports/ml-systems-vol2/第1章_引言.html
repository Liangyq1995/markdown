一、规模时刻：从单卡到舰队

Vol.1 优化单节点上的数据、算法与机器；Vol.2 处理当模型与流量超出单机物理 envelope 时出现的全新 physics。训练 GPT-3 约 $3.14 \times 10^{23}$ FLOPs、1024 V100、至少 29 天；PaLM 6144 TPU v4、约 $10^{24}$ FLOPs——这些数字说明：前沿能力已是分布式系统问题，而非更大 batch 的单机实验。

三、缩放定律与 Chinchilla

$$\mathcal{L}(X) \propto X^{-\alpha_{\text{scale}}}$$

损失随参数量 $P$、token 数 $D$、算力 $C$ 呈幂律下降——但等比例损失改善需要超线性资源。Chinchilla（Hoffmann 2022）修正早期「大模型、少 token」偏见：compute-optimal 约 20 token / 参数。

算例：$10^{24}$ FLOPs 预算

IsoFLOP 谷底约 63B 参数 + ~1.4T token（教材 extrapolation）。GPT-3（175B / ~300B token）相对 Chinchilla 前沿欠训练——同算力下更小模型+更多数据可能更优。

500 A100·月 + 仅 5B token 医疗语料：算力过剩、数据稀缺 → 应缩小模型、避免重复 epoch 记忆化，而非堆参数。

四、规模约束：可靠性、CI、CAP

4.1 可靠性鸿沟

$$R_{\text{fleet}}(t) = (R_{\text{node}}(t))^N$$

单节点 99.9% 可用 → 1000 节点同时健康仅 $(0.999)^{1000} \approx 36.8\%$。10,000 节点 @ 99.99% 仍约 36.8%——故障是常态，容错（第 7 章）是架构前提。

4.2 通信强度 CI

$$\text{CI} = \frac{\text{网络传输字节}}{\text{本地 FLOPs}}$$

Workload Alpha：10 MB / $10^{14}$ FLOPs → CI = $10^{-7}$（易扩展）。Beta：1 GB / $10^{13}$ FLOPs → CI = $10^{-4}$（高 1000×，加 GPU 可能变慢）。LLM 全参数 DP 属 Beta 类。

4.3 CAP 与同步训练

网络分区时：同步训练选 Consistency（一节点失联全体 stall）；异步选 Availability（继续但 stale gradient）。无免费午餐——Fleet 须在 SLA 与收敛间显式选型。

五、C³ 分类与 Fleet Law

Vol.1 D·A·M 描述 workload；C³ 描述舰队 wall-clock 去向：

  • $C_1$ Compute：本地矩阵乘，目标 $\eta_{\text{hw}}$ 高
  • $C_2$ Communication：AllReduce、AllToAll，受 bisection 限制
  • $C_3$ Coordination：barrier、调度、checkpoint、容错
$$T_{\text{step}}(N) = \frac{T_{\text{compute}}}{N} + T_{\text{comm}}(N) + T_{\text{sync}}(N) - T_{\text{overlap}}$$
$$f_{\text{compute}} = \frac{T_{\text{compute}}/N}{T_{\text{step}}(N)}$$

当 $f_{\text{compute}} < 0.5$，半数硅片空转。Google Goodput 实例化：$\eta_{\text{program}} \times \eta_{\text{runtime}} \times \eta_{\text{scheduling}}$——分别对应 $C_1$/$C_2$/$C_3$ 损失。

能量侧：$\rho_{\text{energy}} = O_{\text{useful}} / (E_{\text{compute}} + E_{\text{cooling}} + E_{\text{network}})$

GPT-3 训练碳排约 552 t CO₂（Patterson 2021 量级）。跨 Pod 传 TB 级 checkpoint 时 $E_{\text{network}}$ 不可忽略——第 15 章展开。

七、章节总结

  1. 规模使 ML 成为舰队工程：协调成本与故障率与算法同等重要
  2. Chinchilla 20:1 token/param 是资源分配锚点；单边放大触发 breakdown
  3. $R_{\text{fleet}} = R_{\text{node}}^N$ 与 CI 比值决定扩展是否值得
  4. Fleet Law + $f_{\text{compute}}$ 是 step 级诊断；Goodput 是生产度量
  5. 治理（安全、审计、公平）在十亿用户规模下是控制面硬约束
Vol.1 问「单机上如何跑快」；Vol.2 问「如何让 N 台机器像一个计算机——并在故障、分区与监管下仍交付能力」。
