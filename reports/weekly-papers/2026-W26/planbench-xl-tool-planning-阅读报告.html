1. 概述

随着 LLM 智能体在真实世界中的部署规模不断扩大，如何在大规模工具生态中完成需要多步骤、多工具协作的复杂任务，成为衡量智能体能力的关键维度。然而，现有基准测试大多局限于工具数量有限、任务步骤较短的简化场景，难以反映真实部署中工具检索受限、工具可能失效或误导的复杂情况。

本文提出 PlanBench-XL，一个面向长程规划的交互式基准，覆盖 327 个零售领域任务，工具库规模达 1,665 个工具。智能体必须通过迭代检索工具、调用工具以获取中间证据、并基于证据链推进后续调用，最终完成任务。更重要的是，PlanBench-XL 引入了阻断机制（Blocking Mechanism），通过在检索时替换关键工具为缺失、失效或语义误导性工具，强制智能体在运行时检测失效路径并动态重规划。

实验对 10 个主流 LLM 的评测揭示：即使是最强的前沿模型（GPT-5.4），在无阻断设置下准确率仅为 51.90%，而在最严苛阻断条件下急剧跌落至 11.36%。这一结果表明，当前 LLM 智能体在大规模、部分可观测、不可靠工具环境中的自适应规划能力仍然严重不足。

2. 研究背景与动机

本节梳理 PlanBench-XL 所要解决的核心问题：现有工具使用基准的局限性，以及真实世界工具智能体所面临的三重挑战。

2.1 现有基准的局限

当前主流的工具使用评测基准（如 ToolBench、APIBench、ToolAlpaca 等）普遍存在以下问题：

  • 工具规模偏小：大多数基准仅包含数十到数百个工具，远低于真实生产环境中成千上万的工具规模；
  • 任务步骤过短：多数任务仅需单步或两步工具调用即可完成，缺乏对多步骤、跨工具依赖链的考察；
  • 工具可靠性假设过强：现有基准默认工具总是可用且返回正确结果，忽视了真实环境中工具失效、API 超时、返回错误值等常见情况；
  • 忽略检索约束：大多数基准将完整工具列表直接提供给模型，而非模拟真实场景中通过语义检索逐步发现工具的过程。

原始 PlanBench（Kokel et al., 2024）关注积木世界（Blocksworld）等抽象规划任务，验证了 LLM 在符号规划上的局限，但未涉及工具生态中的检索约束与不可靠性问题。

2.2 真实世界智能体的三重核心挑战

挑战一：部分工具可见性（Partial Tool Visibility）

智能体无法一次性获取所有工具，必须通过语义检索逐步发现相关工具，并在有限的检索预算内完成任务。这要求智能体具备主动探索与信息管理能力。

挑战二：长程推理与证据链（Long-Horizon Evidence Chaining）

任务通常需要多步工具调用，每步的输出作为下一步的输入参数（即"中间证据"）。智能体需要正确推断隐含的子目标，并在整个轨迹中维护状态追踪。

挑战三：不可靠工具访问（Unreliable Tool Access）

关键工具可能在检索时被替换为失效版本，包括：显式报错、隐式错误返回值、语义相似但功能不同的工具。智能体需要检测失效信号并动态重规划，而非盲目继续执行。

2.3 研究动机总结

PlanBench-XL 的核心动机是：在大规模、检索受限、工具不可靠的真实场景下，系统评测 LLM 智能体的长程自适应规划能力。这不仅是学术研究的需要，更是工具智能体走向生产部署的必要条件。

3.2 零售工具生态系统

PlanBench-XL 选择零售领域作为测试场景，原因在于零售业务天然涉及订单管理、退款处理、库存查询、物流追踪等多个功能模块，工具间存在复杂的数据依赖关系，非常适合测试多步骤证据链推理。

工具库共包含 1,665 个工具，每个工具定义包含：

  • 工具名称与功能描述：用于语义检索的自然语言描述；
  • 输入参数规范：包括参数名称、类型、是否必填；
  • 输出类型定义：明确工具返回的数据类型，使工具的"能力边界"可被显式推理；
  • 领域数据类型系统：工具基于统一的领域数据类型（如 order_id、refund_status、tracking_number）定义接口，使工具的可组合性可以被形式化推导。

3.3 任务构建流程

PlanBench-XL 包含 327 个任务实例，每个任务通过以下流程构建：

  1. 目标工具路径设计：首先人工设计目标工具调用链（Ground-Truth Tool Path），确保每个任务都有明确的正确解；
  2. 中间证据注入：在工具调用链中，前步工具的输出作为后步工具的输入参数，形成证据依赖图；
  3. 任务自然语言化：将工具调用链转化为自然语言任务描述，任务中隐含对中间子目标的推断需求；
  4. 多路径保留：对于阻断实验，确保每个任务实例在阻断部分工具后仍保留至少一条可行的替代路径。

3.4 阻断机制（Blocking Mechanism）

阻断机制是 PlanBench-XL 最核心的创新之一，旨在模拟真实世界中工具不可靠的情况。在检索阶段，原本应返回的正确工具被替换为以下三类"阻断替代工具"：

阻断类型 英文名称 行为描述 示例 难度
显式失效 Explicit Failure Block 工具返回明确的错误信息，如 "error: endpoint unavailable" get_refund_status 返回 error: service down 较易识别
隐式失效 Implicit Failure Block 工具返回看似合法但实际错误的值，静默违反其文档行为 get_refund_status 返回 refund_status=tuna 最难识别
语义误导 Semantically Misleading Block 返回功能相关但不同的工具，表面上可用作替代 get_refund_status 被替换为 get_order_status 中等

阻断机制的设计保证了两个关键属性：

  • 评测公平性：同一设置下，所有模型面对相同的阻断工具集，确保横向比较的可靠性；
  • 实例独立性：不同任务实例的阻断工具独立采样，避免系统性偏差；
  • 可解性保证：每个阻断实例都保留至少一条可行的替代工具路径，即问题本身仍然有解。

3.5 阻断强度变体

实验中设计了多种阻断强度，通过阻断比率（Block Ratio）控制被阻断的关键工具比例：

  • 无阻断（No Block）：基线设置，工具全部可用；
  • 部分阻断（Block Ratio 0.2 ~ 0.8）：逐步增加被阻断的关键工具比例；
  • 严苛阻断（仅保留最长恢复路径）：阻断所有短路径，智能体必须找到最长的替代工具链才能完成任务，对应 GPT-5.4 准确率崩溃至 11.36% 的场景。

3.6 评测指标体系

PlanBench-XL 设计了三类指标，全面衡量智能体在大规模工具环境中的表现：

指标类别 指标名称 含义 方向
任务完成 Accuracy (%) 最终答案正确的任务比例（基于 Grounded Accuracy 标准） ↑
探索行为 EGT Precision (%) 执行过程中选择正确数据类型的比例，衡量探索精度 ↑
Avg. Turns 平均交互轮数，反映探索效率 —
Mean EDT 平均有效深度，衡量有效推进的步骤数 ↑
执行质量 S/C Ratio 检索调用与工具调用的比率，理想值接近 1 —
ITCR (%) 无效工具调用率（Invalid Tool Call Rate） ↓
UIRR (%) 无效信息重用率（Useless Info Reuse Rate） ↓

3.7 交互协议

智能体通过以下多轮循环与 PlanBench-XL 交互：

  1. 接收任务描述，在可见步骤预算内开始规划；
  2. 构造检索查询，调用语义检索器获取候选工具列表；
  3. 从候选列表中选择工具，执行结构化工具调用；
  4. 解析工具返回结果，更新内部状态与证据；
  5. 重复步骤 2-4，直到积累足够证据；
  6. 输出最终答案。

单步验证实验表明，在仅需单次工具调用的 185 个简单查询上，Qwen3-8B 达到 85.95% 的准确率，检索器将正确工具纳入候选列表的比例高达 92.43%。这说明检索器本身性能可靠，多步任务上的大幅性能下降主要源于多步规划、状态追踪和执行决策的困难，而非检索器失效。

4. 实验结果与分析

本节呈现 10 个 LLM 在 PlanBench-XL 上的全面评测结果，重点分析无阻断基线性能、不同阻断类型的影响、以及失败模式的深层原因。

4.2 阻断实验结果

下图展示了 4 个代表性模型在不同阻断类型和阻断强度下的准确率变化，揭示了阻断机制对智能体性能的深远影响。

关键发现：GPT-5.4 在无阻断设置下准确率为 51.90%，当仅保留一条可行路径时跌至约 30%，而在最严苛阻断（仅保留最长恢复路径）下崩溃至 11.36%。这意味着阻断使其准确率下降超过 40 个百分点。

4.3 不同阻断类型的差异化影响

显式失效：能阻止错误值传播，但无法阻止无效搜索

当工具返回明确错误信息（如 error: endpoint unavailable）时，智能体通常不会将该错误值作为后续工具调用的参数，这说明显式错误信号能有效阻止错误数据的直接传播。然而，智能体往往会基于失败工具的名称或功能继续发起新的搜索，导致在错误方向上浪费大量检索轮次。

隐式失效：最致命的失败模式

当工具静默返回错误值（如 refund_status=tuna）时，智能体无法识别返回值的异常性，往往将其作为合法证据继续传播，导致整个推理链被"污染"。隐式失效是导致性能下降最严重的阻断类型，因为它剥夺了智能体检测失效的机会。

语义误导：模型有一定抵抗力

语义误导工具（如将 get_refund_status 替换为 get_order_status）在所有被调用的阻断替代工具中占比不超过 3%，GPT-5.4 和 Llama-3.3-70B 甚至从未调用此类工具。这表明当前模型能够利用工具名称和描述，识别并拒绝功能仅在表面相关的替代工具。

4.4 失败模式深度分析

通过对失败轨迹的系统分析，研究者识别出以下主要失败模式：

失败模式 描述 严重程度
不可恢复漂移
(Irrecoverable Drift)		 智能体初期有所进展，但在某步骤采取错误工具行动后，完全无法回到正确轨道。这是最主要的失败模式。 极高
目标遗忘
(Goal Forgetting)		 在长轨迹中，智能体逐渐偏离原始任务目标，开始追求错误的子目标。 高
证据丢失
(Evidence Loss)		 早期工具调用获得的关键中间证据未被正确保留，导致后续步骤无法利用已发现的有效信息。 中
无效搜索循环
(Futile Search Loop)		 智能体在失效工具周围反复发起检索，无法跳出局部最优，浪费大量交互轮次。 中
错误值传播
(Error Value Propagation)		 将隐式失效工具的错误返回值作为合法参数传入后续工具，导致整条推理链污染。 极高

值得注意的是，研究发现在发生漂移后，有用工具在最近的检索上下文中重新出现的比例在默认设置下为 42.5%，在阻断设置下为 53.4%。这说明失败的根源不是记忆丢失（工具确实出现在上下文中），而是智能体无法正确识别和利用已发现的有效工具。

4.5 延长交互的有限收益

实验还测试了通过重复"继续提示（continuation prompts）"给予智能体更多交互轮次的效果。结果令人失望：大多数模型的准确率提升不超过 5 个百分点，仍远低于无阻断设置下的准确率。

这一发现揭示了一个重要结论：性能瓶颈不在于可用的交互步骤数量，而在于智能体诊断失效路径、放弃无效计划、并构建新恢复计划的能力。阻断实验评测的是部分可观测环境下的自适应重规划能力，而非对已知状态空间的简单搜索。

5. 总结与启发

5.1 主要贡献

  • 规模化工具生态基准：PlanBench-XL 是首个在 1,665 工具规模上评测 LLM 长程规划的交互式基准，填补了现有评测在工具规模和任务复杂度上的空白；
  • 阻断机制创新：三类阻断类型（显式失效、隐式失效、语义误导）提供了模拟真实工具不可靠性的系统化方法，为后续研究提供了重要工具；
  • 多维度评测框架：任务完成、探索行为、执行质量三类指标的组合，为全面诊断智能体规划失败提供了细粒度视角；
  • 关键发现揭示：明确指出当前 LLM 智能体在自适应重规划方面的核心缺陷，为未来研究指明方向。

5.3 研究启示

PlanBench-XL 的研究结果对 LLM 智能体的研究与工程实践具有以下重要启示：

1. 需要显式的失效检测机制

当前模型对隐式失效几乎没有抵抗力。未来研究应探索工具输出合理性验证机制，让智能体在将工具返回值纳入推理链之前，先验证其是否符合预期的数据类型和取值范围。

2. 中间证据的主动管理

证据丢失问题表明，智能体需要显式的工作记忆管理策略，而非依赖 LLM 上下文窗口的隐式记忆。结构化的证据存储和检索机制（如外部记忆库）可能是解决方案之一。

3. 自适应重规划能力的专项训练

延长交互无法显著提升性能，说明重规划能力需要专项培养，而非仅靠更多的推理步骤。包含工具失效场景的针对性训练数据、以及强化学习中的恢复奖励信号，可能是提升这一能力的有效途径。

4. 规模与能力的双重门槛

结果显示，模型规模（8B vs 70B+）和模型家族（开源 vs 闭源前沿）都对长程规划性能有显著影响。长程工具规划可能存在一个能力涌现的规模门槛，小模型在这一任务上几乎无法发挥作用。

5. 工具生态设计的重要性

零售领域的类型化工具系统（基于统一数据类型定义接口）使工具的可组合性可被形式化推理，这一设计思路对实际工具生态的构建具有参考价值：清晰的工具接口规范和数据类型系统，有助于智能体更准确地推断工具间的依赖关系。

5.4 未来研究方向

  • 开发专门针对工具失效检测的训练方法和数据集；
  • 探索结构化工作记忆在长程工具规划中的应用；
  • 研究多智能体协作在大规模工具生态中的潜力；
  • 将 PlanBench-XL 扩展至零售领域之外的其他行业场景；
  • 开发能够从失败轨迹中学习的在线自适应规划算法。
