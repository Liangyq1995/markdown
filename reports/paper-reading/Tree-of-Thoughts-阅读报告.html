1. 核心问题与动机

1.1 自回归解码的根本局限

LLM 推理的本质是对下一个 token 的自回归预测，形式化为：

$$p_\theta(x) = \prod_{i=1}^{n} p_\theta(x[i] \mid x[1\ldots i-1])$$

这种机制在大多数任务上有效，但在以下场景根本失败：

flowchart LR
    AUTO["自回归解码\ntoken 级 · 从左到右\n每步无法回头"]
    S1["❌ 需要战略前瞻\nGame of 24：前几步决策影响全局"]
    S2["❌ 需要探索回溯\n填字游戏：局部死路需要撤销"]
    S3["❌ 需要全局评估\n写作计划：整体连贯性 > 局部流畅性"]
    AUTO --> S1 & S2 & S3
认知科学依据（Kahneman 双过程理论）：人类有"System 1"（快速、自动、直觉）和"System 2"（慢速、深思熟虑、有意识）两种思维模式。LLM 的 token 级生成类似 System 1——ToT 的目标是为 LLM 赋予 System 2 的规划能力。这与 Newell、Shaw、Simon 1950 年代的问题空间搜索理论直接呼应。

1.2 现有方法的局限性对比

2. 背景：推理方法形式化

论文对四种方法给出了统一的数学形式化（以 $p_\theta$ 表示预训练 LM，$x$ 为输入，$y$ 为输出，$z_i$ 为中间思维步骤）：

$$\text{IO: } y \sim p_\theta^{\text{IO}}(y \mid x)$$ $$\text{CoT: } z_i \sim p_\theta^{\text{CoT}}(z_i \mid x, z_{1\ldots i-1}),\quad y \sim p_\theta^{\text{CoT}}(y \mid x, z_{1\ldots n})$$ $$\text{CoT-SC: } \arg\max_y \#\{i \mid y^{(i)} = y\},\quad [z_{1\ldots n}^{(i)}, y^{(i)}] \sim p_\theta^{\text{CoT}}(z_{1\ldots n}, y \mid x)$$ $$\text{ToT: 在状态树 } s = [x, z_{1\ldots i}] \text{ 上搜索，用 } G(p_\theta, s, k) \text{ 生成，} V(p_\theta, S) \text{ 评估}$$

CoT-SC 的核心限制：链内无局部探索，且"最频繁输出"启发式仅适用于输出空间有限的情况（如多选题），不适用于需要连续决策的任务。

3. ToT 框架：四个核心设计

flowchart TD
    DECOMP["1. 思维分解\n将问题拆分为有意义的中间步骤\n粒度由任务决定：词/等式/段落"]
    GEN["2. 思维生成器 G(pθ, s, k)\n策略A：独立采样 k 个思维（丰富空间）\n策略B：顺序提出 k 个候选（约束空间）"]
    EVAL["3. 状态评估器 V(pθ, S)\n策略A：独立评分（1-10 / sure/maybe/impossible）\n策略B：跨状态投票选出最优候选"]
    SEARCH["4. 搜索算法\nBFS：按层保留 top-b 状态，适合有限步骤\nDFS：深度优先+剪枝回溯，适合约束明确任务"]
    DECOMP --> GEN --> EVAL --> SEARCH

3.1 思维生成策略

给定树状态 $s = [x, z_{1\ldots i}]$，生成 $k$ 个候选下一步思维 $z_{i+1}^{(j)}$（$j=1\ldots k$）：

$$\text{策略A（独立采样）：} z^{(j)} \sim p_\theta^{\text{CoT}}(z_{i+1} \mid s), \quad j = 1\ldots k$$ $$\text{策略B（顺序提出）：} [z^{(1)}, \ldots, z^{(k)}] \sim p_\theta^{\text{propose}}(z_{i+1}^{(1\ldots k)} \mid s)$$

策略 A 适合思维空间丰富（如段落写作）时保证多样性；策略 B 适合约束空间（如一行等式）时避免重复。

3.2 状态评估策略

$$\text{策略A（独立评分）：} V(p_\theta, S)(s) \sim p_\theta^{\text{value}}(v \mid s), \quad \forall s \in S$$ $$\text{策略B（跨状态投票）：} V(p_\theta, S)(s) = \mathbf{1}[s = s^*], \quad s^* \sim p_\theta^{\text{vote}}(s^* \mid S)$$
LM 自评估的创新性：传统搜索启发式要么是人工编程（如 DeepBlue），要么是从数据中学习（如 AlphaGo）。ToT 提出第三种方式——用 LM 自身的推理能力进行评估，既比编程规则灵活，又比学习启发式样本效率高。

4. 算法伪代码（原文 Algorithm 1 & 2）

Algorithm 1: ToT-BFS

Input: x, pθ, G, V, step limit T, breadth b, candidates k

S₀ ← {x}

for t = 1, …, T do

S'ₜ ← {[s, z] | s ∈ Sₜ₋₁, z ∈ G(pθ, s, k)}

Vₜ ← V(pθ, S'ₜ) // 评估所有候选

Sₜ ← top-b states in S'ₜ by Vₜ

end for

return G(pθ, argmaxs∈Sₜ Vₜ(s), 1)

Algorithm 2: ToT-DFS

Input: state s, step t, pθ, G, V, limit T, threshold v_th

if t > T then record output G(pθ, s, 1)

end if

for s' ∈ G(pθ, s, k) do

if V(pθ, {s'})(s) > v_th then

DFS(s', t+1) // 递归深入

end if

// 否则剪枝，回溯到父状态

end for

5.2 Game of 24：主要实验结果

CoT 失败分析（关键洞察）：约 60% 的 CoT 样本在第一步就失败（前三个 token 就产生了错误的中间等式）。这表明 left-to-right 解码在需要前瞻的任务上根本无法应对——一步错，步步错，没有任何纠错机制。

6. 消融实验与关键发现

6.1 BFS 宽度的影响（Game of 24）

ToT 宽度 b成功率LM 调用次数
b = 145%~100
b = 574%~500
IO + Refine（k=10）27%10（用了真实反馈信号）
CoT best-of-10049%100

即使 b=1（只保留1个最优路径），ToT 已达到 45%，显著超过 CoT-SC（9%）。宽度 b=5 将成功率提升到 74%，代价是约 500 次 LM 调用。

6.2 评估策略消融

评估策略对结果至关重要：在 Game of 24 中，将"sure/maybe/impossible"三分类评估换成随机选择，成功率从 74% 降至约 10%，接近于盲目 BFS。这证明 LM 的自评估能力是 ToT 成功的核心，而非仅仅是搜索结构本身。

7. 局限性与适用边界

  • 计算成本高：每步需要多次 LM 调用（生成 + 评估），比 CoT 贵数倍到数十倍。b=5 的 Game of 24 需要约 500 次调用 vs CoT 的 100 次
  • 任务适用性受限：对于不需要搜索的任务（如直接问答），ToT 无优势。论文实验任务都是精心选择的难题
  • 思维分解依赖人工设计：不同任务的思维粒度（词/句/段）、评估方式（评分/投票）、搜索算法都需要人工指定
  • 外部影响风险：若在交互式环境中部署，多步搜索可能受到环境扰动（prompt injection 等）影响
  • 评估主观性：创意写作任务的"连贯性"评分由 GPT-4 完成，存在 self-serving bias 风险

8. 核心洞见与读后评注

本质贡献：把 LLM 推理建模为搜索问题
ToT 最深刻的贡献不是某个具体算法，而是提供了一个框架——将 LLM 推理从"生成问题"转化为"搜索问题"。IO/CoT/CoT-SC 都是 ToT 在特殊约束下的特例（深度1/宽度1的树）。这个统一视角为后续工作（LATS、AlphaCode、MCTS for LLM）奠定了概念基础。
LM 自评估：一个可扩展的启发式
传统搜索需要外部启发式函数（棋类游戏中的位置评估）。ToT 发现 LLM 自身可以作为启发式函数——用 prompt 让模型评估"当前状态离目标有多近"。这个技术在其他领域（代码调试、数学证明）同样适用，且随 LLM 能力提升而自动改善。
60% 第一步失败的深层含义
Game of 24 中 CoT 60% 在第一步失败，揭示了一个深层事实：LLM 的 token 预测能力和"问题求解"能力之间存在根本鸿沟。预测"下一个最可能的 token"和"下一个最有利于达成目标的 token"是两个不同的问题。ToT 用搜索+评估弥合了这一鸿沟。
对后续工作的影响
ToT 直接启发了：LATS（Language Agent Tree Search，结合 MCTS）、AlphaProof（数学证明的树搜索）、Reasoning with Search（OpenAI o1 系列的内核思路）、RAP（Reasoning via Planning，用世界模型做前向模拟）。"让 LLM 在推理时做搜索"已成为 2024-2026 年推理模型的核心设计哲学之一。
