概述

近年来，AI 系统在各类基准测试上屡创佳绩：AlphaGo 击败世界冠军、Gemini 在国际数学奥林匹克竞赛中摘得金牌、大模型在编程竞赛中名列前茅。然而，这些令人瞩目的基准成就并未转化为经济上可衡量的专业部署——金融、法律、工程、医疗等核心行业的实际 AI 渗透率依然有限。这种"基准成功与 GDP 影响之间的鸿沟"，正是 Agents' Last Exam (ALE) 所要直接回应的核心问题。

ALE 是由 UC Berkeley RDI 主导、联合 250+ 行业专家共同开发的大规模 Agent 评估基准。其核心设计哲学是：以真实专业工作流作为评估单元，而非人工构造的合成场景或简化问答。基准覆盖依据美国联邦职业分类体系 O*NET/SOC 2018 定义的非物理行业，形成 13 个行业集群 × 55 个子领域 的二级分类，现有 1,490 个可运行任务实例。

ALE 的评估对象是 通用计算机使用 Agent（GCUA, Generalist Computer-Use Agent），即能够同时处理 GUI 交互（桌面应用、浏览器、专业软件）与 CLI 操作（Shell 脚本、代码执行、文件操作）的 Agent，如 Claude Code、OpenAI Codex 等。这一设计有意超越了仅测试 GUI 或仅测试 CLI 能力的现有基准，要求 Agent 在单一任务流程中综合运用视觉感知、代码执行、工具调用与长期规划。

当前实验结果令人警醒：在最难的 Last-Exam 层级（38 个任务），几乎所有主流 Agent 配置的完整通过率均为 0%，最强配置（Codex + GPT-5.5）的整体通过率也仅约 24%。这与同一系统在 Terminal-Bench 上高达 82% 的通过率形成鲜明对比，说明当前 AI 系统在处理真实专业工作流时，距离实际部署仍有巨大差距。

ALE 被设计为"活体基准"（Living Benchmark）：任务池持续扩充，私有任务定期轮换至公开集，以防止基准污染。其更宏大的目标，是成为推动 AI 从"能通过考试"到"能完成真实经济价值工作"这一跨越的量化工具——当 AI 系统能够通过这场"最后的考试"，意味着其已具备在真实工业场景中持续工作的能力。

研究背景与动机

AI 评估鸿沟问题

AI 研究的进展在很大程度上由基准测试所塑造。基准不仅记录能力，更聚焦研究注意力、定义工程目标、决定哪些领域能够快速改进。ImageNet 在计算机视觉领域扮演了这一角色，推动了深度学习的爆发式发展。然而，对于经济上至关重要的金融、法律、工程、制造等行业，可比较的评估体系至今仍不完善。

"benchmark victories have accumulated faster than measurable transformation in core industries" — ALE 论文

这一"效用问题"（utility problem）的根源在于：现有基准在以下三个维度上存在系统性缺陷：

  • 任务时间跨度短：多数基准测试单步或短序列任务，而真实专业工作往往需要数小时乃至数天的持续工作
  • 行业覆盖窄：现有基准大多聚焦软件工程、通用助手或少数几个领域，无法代表整个劳动力市场
  • 验证依赖人工：真实工作流的输出高度异质（文件、电子表格、3D 模型、视频等），难以自动验证，导致评估成本高昂

ALE 基准设计

三大设计原则

ALE 的任务准入由三条高层原则决定：

  • 代表性（Representativeness）：工作流必须与真实专业实践相符，使用领域专家实际使用的软件（如建筑设计用 SolidWorks/Rhino，而非简化替代品）
  • 复杂性（Complexity）：任务必须是端到端的可交付成果，需要专家花费大量时间完成，而非仅几步 UI 操作。关键区别在于"工作流"与"单一动作"之间的差异
  • 可验证性（Verifiability）：输出必须支持确定性检查或与可观测制品绑定的明确评分标准。最强情形是可直接与参考输出对比的确定性可交付成果

行业分类体系（13 × 55）

ALE 以 SOC 2018 为职业骨架，以 O*NET 解释职业内容，通过以下步骤构建分类体系：

  1. 对 O*NET 30.2 中 1,016 个职业条目进行数字工作流筛查（GPT-4o mini，temperature=0）
  2. 合并 SOC 变体后保留 117 个唯一 SOC 基础代码
  3. 将相似工作流的 SOC 代码聚合为 51 个 SOC 锚定子领域
  4. 补充 4 个前沿子领域（量子计算等）+ 7 个扩展，最终形成 55 个子领域

每个任务实例须完整指定五个核心组件：自然语言描述、输入文件、目标软件、预期可交付成果、评估规格。在 960 个外部提交中，最终通过各阶段审核的分布如下：

  • Strong Accept：428 个（44.6%）
  • Accept：344 个（35.8%）
  • Borderline Accept：35 个（3.6%）
  • Minor Revision：49 个（5.1%）
  • Major Revision：148 个（15.4%，退回修改）

此外，还有 530 个内部委托构建的任务实例。最终形成 150 个公开实例 + 1,017 个私有实例 + 323 个待 QC 实例。

Agent 能力五层分解

论文将 Agent 的操作能力分解为五个功能层，明确区分不同 Agent 家族的能力边界：

能力层 功能描述 CLI Agent (SWE-agent) GUI Agent (AutoGLM) GCUA (Claude Code)
Brain（大脑） LLM 推理与规划 ✓ 完整 ✓ 完整 ✓ 完整
Eyes（视觉） GUI 截图感知 ✗ 缺失 ✓ 完整 ✓ 完整
Body（躯体） 编排与控制流 ✓ 完整 △ 有限 ✓ 完整
Hands（双手） 结构化工具调用 ✓ 完整 △ 主要为鼠标键盘 ✓ 完整
Feet（双脚） 运行时基础设施 ✓ 完整 △ 受限 ✓ 完整

ALE 的评估对象是 GCUA（Generalist Computer-Use Agent），即在所有五层均具备完整能力的 Agent。GUI 能力的集成通过两种模式实现：

  • GUI-as-Tool：将 GUI 操作作为普通工具暴露在主循环中（主要评估模式）
  • GUI-as-SubAgent：将 GUI 交互委托给专用视觉语言子 Agent（用于无原生视觉输入的模型，如 DeepSeek V4）

评估模式分类

由于真实工作流的可交付成果高度异质（CAM 刀具路径、财务工作簿、3D 网格、游戏世界状态等），ALE 沿两个正交轴组合评估：

  • 比较形式：精确/哈希值、结构化数值/表格字段（带容差）、几何表面/点云距离、视觉外观（视觉 LLM 评判）、固定输入轨迹下的行为世界状态、自由文本评分标准
  • 组合方式：门控评分（gate-and-score）或二元检查列表平均
门控评分（最常见模式）：二元前置条件（如"无刀具路径碰撞"、"文件解析无误"）必须通过，才会评估连续质量指标；前置条件失败则强制任务得分为 0，无论其他标准的部分进展如何。

ALE 刻意避免将 LLM 作为评判者，凡是仅能通过"询问模型结果是否正确"来评分的任务工作流，在 QC 阶段即被拒绝并重新工程化。少数确实需要 LLM 评判的任务（视频片段、游戏截图等），使用的是基于证据的窄范围是/否探针，而非通用整体性提示。

"活体基准"机制

ALE 采取公私分离策略以防止基准污染：

  • 仅公开 1,490 个实例中的约 10%（150 个）
  • 私有任务池周期性轮换至公开集，同时退役的公开任务被替换
  • 任务池持续增长，随着新工作流和行业的加入而扩充
  • 公开子集的代表性已通过实证验证（附录 D.1）

ALE 的任务来自专家实际完成的项目，通常需要专家花费数天至数周才能完成。当前最强 Agent 配置（Codex + GPT-5.5）在整体通过率上约为 24%，而在 Last-Exam 层级仅约 23%（部分任务得分），完整通过率接近 0%。这意味着：

当前最先进的 AI Agent 系统，在完成真实专业工作流方面，仍远未达到可替代人类专家的水平。

关键发现与分析

失败模式分类

对 Claude Code + Opus 4.7 失败任务的分类分析揭示了两级失败分类体系：

理解失败（31%）

Agent 无法正确理解任务要求，主要由领域知识缺失（25%）和幻觉（6%）导致。缺乏专业领域知识的 Agent 会默认使用临时脚本，而非预期的专业软件。

方法失败（47%）

Agent 理解了任务但选择了错误的解决策略，包括错误策略（30%）和实现不完整（17%）。这是最主要的失败类别，反映了专业工作流中规划能力的不足。

执行失败（22%）

策略正确但执行出错，包括实现 Bug（8%）、格式错误（10%）和GUI 失败（4%）。GUI 失败率相对较低，但考虑到 34% 的任务以图形软件为主要工具，实际 GUI 能力利用率严重不足。

GUI 能力利用不足

34% 的公开任务实例将图形软件作为主要工具，但在大多数配置中，GUI 使用占比仍然偏小——Agent 倾向于通过 Bash/CLI 替代方式执行 GUI 任务，导致专业软件功能无法充分利用。

模型 vs. Harness 效应

附录 D.4 的分析发现：在工程化良好的系统中，基础模型的选择对性能差异的影响约为 Agent Harness 选择的 3 倍。这意味着提升基础模型能力比优化 Harness 架构更为关键。

资源消耗与性能关系

成本、时间和 Token 效率分析（附录 D.5）显示：更高的资源消耗并不可靠地转化为更好的性能。例如，Claude Code + Opus 4.7 在 Full-Spectrum 层级的成本高达 $496，但整体通过率仅为 13.2%，而 ALE-Claw + GPT-5.5 以 $148 的成本实现了 23.0% 的整体通过率。

Agent 找到了匹配的 Dorico 项目并导出了 transcription.mid，但未确认 transcription.pdf 和 overview.png。由于评分硬门控要求完整的乐谱/MIDI/截图包，在音乐准确性评估之前即触发零分。失败根因：部分工具使用未能可靠地交付多制品，创意生产任务需要完整的制品包。

视觉特效DaVinci Resolve

Agent 使用了 Resolve 并导出了 MP4，但输出未满足基于参考的色度键变换要求——将一个看似合理的"鸟在天空上"片段作为目标，而非保留参考材料中预期的前景/背景关系。失败根因：错误在于视觉任务理解，而非软件操作本身。

局限性

  • 非物理行业偏向：ALE 明确排除了核心工作无法数字化的行业（如体力劳动、现场操作），这在设计上是合理的，但限制了对整个经济体的覆盖
  • 任务实例规模：尽管 1,490 个实例在规模上已属大型基准，但每个子领域的覆盖密度仍然有限（平均约 27 个），可能无法代表各子领域的全部工作流多样性
  • 评估成本高昂：单次 Agent 运行平均成本 $3-10，耗时数十分钟至数小时，全量评估成本极高，限制了快速迭代
  • Windows 任务支持有限：当前可运行任务实例以 Linux 为主，Windows 环境支持仍在扩展中
  • 基准污染风险：尽管采取了公私分离策略，但随着基准影响力增大，未来仍可能面临针对性优化的风险
  • 验证边界：部分创意性任务（视频、渲染场景等）仍需依赖 LLM 评判，尽管已尽量采用窄范围探针，但这仍引入了一定的主观性
  • 专家偏差：任务来自特定专家群体（主要为学术界和部分工业界），可能无法完整代表所有行业的工作实践
  • 时效性：作为"活体基准"，任务池持续变化，不同时期的评估结果可能难以直接比较

总结与启发

核心贡献总结

ALE 在 AI 评估领域做出了三项核心贡献：

  1. 首次全覆盖的职业锚定分类体系：以 SOC 2018/O*NET 为骨架，构建了覆盖全部 55 个非物理行业子领域的任务分类，填补了现有 16 个主流基准联合仍留下的 13 个子领域空白
  2. 真实专业工作流 + 自动化验证的结合：首次在大规模基准中同时实现"任务来自专家真实项目"和"无需人工评判的自动化验证"，解决了此前经济价值导向基准（GDPval、RLI）依赖昂贵人工评判的瓶颈
  3. 清醒的能力边界揭示：在当前最强配置（Codex + GPT-5.5）已能在 Terminal-Bench 达到 82% 的情况下，ALE Last-Exam 层级的 0% 通过率提供了一个客观、可量化的能力边界标尺

对 AI 研究的深层启示

1. 基准选择塑造研究方向——需要更审慎地选择"下一个 ImageNet"

ALE 的核心洞见之一是：AI 进步在很大程度上由基准所塑造。ImageNet 推动了计算机视觉的爆发；SWE-bench 推动了代码修复能力的快速提升。ALE 试图为专业工作流领域扮演类似角色。然而，这也意味着一旦 ALE 被广泛采用，研究资源将集中流向其覆盖的特定任务类型，可能在无意中忽视其未覆盖的能力维度。

2. 领域知识是当前最大瓶颈，而非执行能力

失败分析显示，理解+方法失败合计占约 78%，而执行失败仅占 22%。这意味着当前 AI 系统的核心短板不是"如何操作软件"，而是"是否具备足够的专业领域知识来制定正确策略"。这对训练数据的构成、领域专家知识的注入方式提出了新的挑战——仅靠扩大通用预训练数据规模，可能难以解决这一问题。

3. GUI 能力的系统性低估与低利用

尽管 34% 的任务以图形软件为主要工具，但 Agent 在实际执行中大量绕过 GUI，转而使用 CLI/脚本替代。这一现象揭示了当前 Agent 设计的一个深层问题：GUI 能力虽已集成，但 Agent 尚未学会"何时应该使用 GUI"。专业软件的核心价值往往体现在其 GUI 工作流的精密设计中，绕过 GUI 意味着绕过了专业工具的核心功能。

4. 模型能力 vs. Harness 设计的权重

基础模型的选择对性能差异的影响约为 Harness 设计的 3 倍，这为研究资源分配提供了重要参考：在当前阶段，提升基础模型的专业领域能力比精心设计 Agent Harness 架构更具杠杆效应。但这并不意味着 Harness 不重要——在相同模型下，不同 Harness 之间仍有显著差异。

5. "活体基准"理念的重要性与挑战

ALE 的滚动评估设计是对抗基准饱和与污染的重要机制。随着 AI 能力的快速提升，静态基准往往在发布后数月内即被饱和（如 HumanEval、MMLU）。ALE 的持续扩充机制试图保持评估的长期有效性，但这也带来了可比性挑战：如何确保不同时期的评估结果具有可比性，需要更精细的版本控制与统计方法。

6. 经济影响导向评估的范式转变意义

ALE 最深层的贡献，是将 AI 评估的终极目标从"在测试上表现优秀"重新锚定到"能否产生实际经济价值"。这一范式转变要求研究社区重新思考：什么样的能力提升真正重要？如何设计能够指导实际部署决策的评估体系？如果 AI 系统真的能够通过这场"最后的考试"，那将不仅仅是一个基准上的成就，而是 AI 大规模进入专业劳动力市场的真实信号。

一句话核心洞见

ALE 用数据告诉我们：当前最强的 AI Agent，在真实专业工作中距离"可用"还有相当距离——不是因为它不会操作软件，而是因为它不具备足够的专业判断力来制定正确的工作策略。这是基础模型能力的问题，也是训练数据分布的问题，更是整个 AI 研究社区需要正视的"最后一公里"挑战。
