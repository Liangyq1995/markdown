EnterpriseClawBench: Benchmarking Agents from Real Workplace Sessions

Jincheng Zhong, Weizhi Wang, Che Jiang, Kai Tian, Zhenzhao Yuan, Junlin Yang, Dianqiao Lei, Kaiyan Zhang  ·  Frontis AI
TL;DR：EnterpriseClawBench 是首个从真实企业工作会话中提取的 Agent 基准，包含 852 个可复现任务，覆盖异构文件读取、工具调用与业务产物交付三大能力维度，填补了学术基准与真实企业工作流之间的鸿沟。

01 概述

随着大语言模型（LLM）驱动的 Agent 系统在企业中的广泛应用，如何客观评估其在真实工作场景下的能力成为关键挑战。现有基准大多基于合成任务或公开数据集，难以反映企业工作流的真实复杂性。

EnterpriseClawBench 由 Frontis AI 团队提出，是一个从真实专有职场会话中派生的 Agent 评估基准。其核心创新在于：通过系统化的数据恢复与任务重写流程，将原本不可复现的企业工作记录转化为标准化、可执行的评测任务。

02 研究背景与动机

现有基准的不足

当前 Agent 评估领域面临一个根本性矛盾：学术基准追求可控性与可复现性，而企业场景则充满非结构化、多模态、高度领域专属的复杂任务。

基准类型 代表性工作 主要局限
合成任务基准 ALFWorld, WebArena 任务分布与真实工作流偏差大
公开数据集基准 GAIA, SWE-bench 缺乏企业私有文件与工具调用场景
人工设计任务 AgentBench 专家偏见，无法反映真实用户需求分布
EnterpriseClawBench 本文 从真实会话提取，覆盖真实企业工作流

企业场景的特殊性

企业工作场景对 Agent 提出了学术基准未能充分覆盖的三类核心挑战：

1
异构文件处理能力

企业日常涉及 PDF 报告、Excel 财务表格、PowerPoint 演示、数据库查询结果等多种格式，Agent 需具备跨格式理解与提取能力。

2
工具链式调用能力

真实工作流往往需要串联调用多个内部/外部工具（API、数据库、代码执行环境），并处理工具返回的中间结果。

3
业务产物交付能力

最终输出不仅需要内容正确，还需符合企业规范（格式、视觉质量、专业表达），这是现有基准普遍忽视的维度。

研究动机
作者团队在为企业客户部署 Agent 系统时发现，在公开基准上表现优异的模型，在真实企业任务上往往出现显著的性能下滑。这一"基准-现实"鸿沟促使他们构建了 EnterpriseClawBench。

03 核心方法：Benchmark 构建

数据收集与转化流程

EnterpriseClawBench 的核心贡献在于设计了一套将私有职场会话转化为可复现评测任务的系统化流程。整个流程分为六个阶段，确保数据的可用性、安全性与评估有效性。

任务结构设计

每个评测任务由五个核心要素构成，形成完整的可复现评测单元：

要素 说明 作用
Recovered Fixtures 恢复的任务所需文件与环境 确保任务可独立复现
Rewritten Prompts 经脱敏与标准化处理的任务描述 消除敏感信息，保持任务语义
Role/Skill Classification 按职场角色与技能类型分类 支持细粒度能力分析
Hard Rules 客观、可自动验证的评分规则 提供确定性评估信号
Semantic Rubrics 基于语义的主观评分标准 捕捉输出质量的细微差异

角色与技能分类体系

基准按照职场角色（如数据分析师、项目经理、内容创作者等）和技能类型（如文件处理、数据分析、报告生成等）对任务进行双维度分类，使得评估结果能够映射到具体的企业岗位需求。

技能迁移测试
基准专门设计了技能迁移（Skill-Transfer）测试场景：将某类技能在一个角色上学到的能力，测试其在另一个角色场景下的泛化表现，评估 Agent 的跨领域适应能力。

双轨评估机制

  • Hard Rules（硬规则）：自动化、确定性验证，如文件是否生成、格式是否符合要求、关键数值是否正确。
  • Semantic Rubrics（语义评分标准）：由 LLM Judge 进行语义层面的质量评估，捕捉内容完整性、专业性、逻辑连贯性等软性指标。

多维评估指标

  • 产物交付（Artifact Delivery）：Agent 是否成功生成符合要求的业务产物
  • 视觉质量（Visual Quality）：输出文档、图表的视觉呈现是否达到专业标准
  • 成本与运行时（Cost & Runtime）：完成任务的 Token 消耗与时间开销
  • Harness-Model 组合效果：不同 Agent 框架与底层模型的协同表现

04 实验结果与分析

模型性能对比

作者在多个主流 Harness 框架与 LLM 模型的组合上进行了系统评测。以下为各主要组合的综合得分（满分 1.0）：

排名 Harness 底层模型 综合得分 备注
1 Codex GPT-5.5 0.663 当前最佳组合
2 Codex Claude 3.7 Sonnet 0.621 -

关键发现
即使是最佳组合（Codex + GPT-5.5）得分也仅为 0.663，表明企业级任务对当前 Agent 系统仍具有显著挑战性，存在较大的提升空间。

技能迁移分析

基准通过技能迁移测试揭示了 Agent 跨角色泛化能力的关键规律：

技能迁移能力：源角色 → 目标角色得分变化
  • 技能专属性强：在特定角色场景下训练/优化的能力，在迁移到其他角色时往往出现 10-25% 的性能下降。
  • 文件处理能力迁移性最强：基础文件读写能力在不同角色间迁移损失最小（约 5-8%）。
  • 业务产物交付能力迁移性最弱：特定格式的报告生成、演示文稿制作等能力高度依赖角色上下文，迁移后性能下降最显著（可达 30% 以上）。
  • 工具调用能力居中：API 调用、数据库查询等工具使用能力的迁移性适中，取决于工具本身的通用性。

成本与效率分析

评估框架同时记录了各组合完成任务的 Token 消耗与时间开销，揭示了性能与成本之间的权衡关系：

成本警示
高性能组合（如 Codex + GPT-5.5）在取得最佳得分的同时，其 Token 消耗约为轻量级基线的 4-6 倍，运行时间约为 2-3 倍。企业部署时需在性能与成本间做出权衡。
性能区间 代表组合 相对 Token 消耗 平均任务时长

对研究社区的启发

1
基准构建方法论的突破

从真实用户会话中提取基准任务的方法，为后续构建领域专属评测集提供了可复用的方法论框架。构建协议的开源使得其他机构可以用相同方法构建自己的企业基准。

2
Harness 框架的重要性被低估

实验结果表明，Agent Harness 框架的选择对最终性能的影响不亚于底层 LLM 的选择。这提示研究者应将 Harness 设计作为独立研究变量加以重视。

3
视觉质量评估的必要性

企业场景中，业务产物的视觉呈现质量是重要的评估维度。现有基准普遍忽视这一点，而 EnterpriseClawBench 将其纳入评估体系，更贴近真实业务需求。

4
技能迁移能力是企业部署的关键

企业不可能为每个岗位单独训练/优化 Agent。技能迁移能力的强弱直接决定了 Agent 系统的部署成本与适用范围，应成为未来研究的重要方向。

5
0.663 的天花板意味着巨大提升空间

当前最佳性能距离完美解决企业任务仍有 33.7% 的差距，这为模型能力提升、Agent 架构优化、以及专业化微调提供了明确的努力方向。

局限性与未来工作

主要局限
  • 数据不公开：核心数据集因企业机密性质无法公开，限制了社区直接复现与对比实验。
  • 行业覆盖范围：当前数据主要来自特定行业的企业会话，可能存在行业偏差。
  • 动态工具生态：企业工具链快速迭代，基准可能随时间出现老化问题。
  • 评估主观性：语义评分标准的设计仍存在一定主观性，不同评估者可能得出不同结论。
个人评价
EnterpriseClawBench 的最大价值在于方法论层面的贡献：它证明了从真实企业会话中系统化构建高质量基准的可行性，并提供了可复用的构建协议。即使数据集本身不公开，这套方法论也为各行各业构建领域专属评测集指明了方向。对于关注企业 AI 落地的研究者和从业者而言，这是一篇值得深入研读的重要工作。
