一、LLM 场景的 MDP：从抽象到具体

马尔可夫决策过程（MDP）是所有 RL 算法的数学骨架。理解 LLM-RL 的关键，是把 MDP 的每个抽象元素映射到语言生成的具体操作上。

1.1 MDP 五元组的精确定义

LLM 自回归生成对应的 MDP 五元组 $(S, A, P, R, \gamma)$

设 prompt 为 $x = (x_1, \ldots, x_m)$，生成回复 $y = (y_1, \ldots, y_T)$，词表为 $\mathcal{V}$（大小 $|\mathcal{V}|$）

  • 状态空间 $S$：$s_t = (x_1,\ldots,x_m,\, y_1,\ldots,y_{t-1})$，即 prompt + 截至当前的所有已生成 token。初始状态 $s_0 = x$（纯 prompt）。
  • 动作空间 $A$：$a_t = y_t \in \mathcal{V}$，从词表中选一个 token。$|A| = |\mathcal{V}| \approx 32\text{K} \sim 150\text{K}$。
  • 转移函数 $P$：确定性，$s_{t+1} = (s_t, a_t)$，即把新 token 拼接到当前状态末尾。不存在随机环境噪声。
  • 奖励函数 $R$：
    • 稀疏奖励（ORM）：$r_t = 0$ 对 $t < T$；$r_T = r_\phi(x, y)$（奖励模型输出）
    • 密集奖励（PRM）：$r_t = \text{PRM}(x, y_{1:t})$ 对每个步骤边界 $t$
  • 折扣因子 $\gamma$：LLM 训练中通常令 $\gamma = 1.0$（不折扣），因为序列中的每个 token 都同等重要。

Prompt（$x$）：用户：法国的首都是哪里？\n助手：（假设 tokenize 后为 8 个 token）

初始状态 $s_0$：
用户 ： 法国 的首都 是哪里 ？ 助手 ：

（前8个 prompt token） → 法

（前8个） 法 → 国

具体示例：解题"一列火车行驶 120km 需要 2小时，速度是多少？"

这个场景展示 PRM（过程奖励模型）如何提供逐步奖励。

1.4 LLM-MDP 的三大特殊性（与传统 RL 根本不同）

① 动作空间巨大

传统 RL（如 Atari）：4–18 个离散动作。

LLM：词表大小 32K–150K。这意味着策略网络的最后一层是一个 32K 维 softmax，每次"动作"是从这个分布中采样。

影响：梯度估计的方差来自这个巨大空间中的采样噪声。

② 极度稀疏的奖励

一个 200 token 的回复，只有第 200 步有非零奖励。前 199 步全为 0。

这等价于让 RL 智能体在一场 200 步的棋局中，只告诉它最终输赢——不知道是第几步下错了。

影响：信用分配问题，核心挑战之一。

③ 强大的初始策略

传统 RL 从随机策略开始（啥都不会）。LLM 从 SFT 微调后开始，已经是一个高质量的语言生成器。

因此 RL 阶段的目标不是"从零学习"，而是"在已有能力基础上微调偏好对齐"。KL 惩罚保证不偏离太远。

1.5 KL 惩罚的 MDP 解释

原始 MDP 目标是最大化累积奖励。在 LLM-RL 中，实际优化的是带 KL 约束的目标：

$$\max_{\pi_\theta} \mathbb{E}_{x \sim \mathcal{D},\, y \sim \pi_\theta(\cdot|x)} \left[ r_\phi(x, y) \right] - \beta \cdot \underbrace{D_{\text{KL}}\!\left[\pi_\theta(\cdot|x) \;\|\; \pi_{\text{ref}}(\cdot|x)\right]}_{\text{对整条序列的 KL 散度}}$$

其中 $\pi_{\text{ref}}$ 是 SFT 模型（冻结），$\beta$ 是 KL 惩罚强度（典型值 0.01–0.1）

具体计算：KL 惩罚是怎么影响奖励的？

假设对某个 prompt，策略生成了回复 $y = $ "法国的首都是巴黎。"（共 6 个 token）

token $y_t$$\log \pi_\theta(y_t|y_{<t}, x)$$\log \pi_{\text{ref}}(y_t|y_{<t}, x)$逐 token KL 贡献
"法"-0.87 (p=0.42)-0.92 (p=0.40)+0.05
"国"-0.05 (p=0.95)-0.07 (p=0.93)+0.02
"的首都"-0.22 (p=0.80)-0.35 (p=0.70)+0.13
"是"-0.10 (p=0.90)-0.11 (p=0.89)+0.01
"巴黎"-1.20 (p=0.30)-1.61 (p=0.20)+0.41
"。"-0.05 (p=0.95)-0.05 (p=0.95)0.00
总 KL 散度0.62

综合奖励（$\beta = 0.1$）：

原始奖励 r_φ(x,y)         = +0.95
KL 惩罚 β × KL             = 0.1 × 0.62 = -0.062
综合奖励 r_combined        = 0.95 - 0.062 = +0.888

注意"巴黎"这个 token 的 KL 贡献最大（0.41），因为策略模型在这里显著偏离了参考模型——这是训练使策略更倾向于给出首都名称的结果。

二、PPO 算法：在 LLM 中的逐步运行

PPO（近端策略优化）是 InstructGPT / ChatGPT 的核心训练算法。它在 LLM 场景的运行远比传统 RL 复杂——需要同时协调 4 个模型和复杂的信用分配逻辑。

内存占用：PPO 为什么"贵"？

4 个模型通常都是完整的 LLM 参数副本。以 7B 参数 bfloat16 为例：

  • Actor：7B × 2 bytes = 14 GB + 优化器状态 ≈ 42 GB
  • Reference：14 GB（只推理，不优化）
  • Critic：14 GB（与 Actor 结构相同）+ 优化器状态 ≈ 42 GB
  • Reward Model：通常较小（如 1.5B–7B）≈ 3–14 GB
  • 合计：100+ GB，需要多卡并行

这是 GRPO 消灭 Critic 后最大的优化点。

2.2 PPO 训练循环：逐步骤详解

Step 1

Rollout：用当前策略（Actor）生成回复

从数据集随机采样一批 prompts（如 64 条），Actor 自回归生成回复（贪心/采样）。

prompts = ["法国首都是哪里？", "如何学好数学？", ...]  # 64 条 prompt
responses = []
old_logprobs_batch = []

for prompt in prompts:
    tokens, logprobs = actor.generate_with_logprobs(prompt)
    # logprobs: shape [T]，每个 token 的对数概率
    # 例如：[-0.87, -0.05, -0.22, -0.10, -1.20, -0.05]
    responses.append(tokens)
    old_logprobs_batch.append(logprobs)
    # 同时用 Reference 模型计算 ref_logprobs
    ref_logprobs = ref_model.get_logprobs(prompt, tokens)
Step 2

奖励计算：RM 打分 + KL 惩罚

对每条生成的完整回复，RM 给出一个标量分。逐 token 计算 KL 惩罚后整合。

for prompt, response, old_lp, ref_lp in zip(...):
    # 1. RM 给序列末尾（EOS）打分
    rm_score = reward_model.score(prompt, response)  # 标量，如 0.95

    # 2. 逐 token KL 惩罚（负的 KL 散度）
    # old_lp[t] = log π_θ(y_t | y_{<t}, x)
    # ref_lp[t] = log π_ref(y_t | y_{<t}, x)
    kl_per_token = old_lp - ref_lp  # 逐 token KL 贡献（近似）

    # 3. 综合奖励：只在 EOS 位置加 RM 分，其余位置只有 KL 惩罚
    rewards = -beta * kl_per_token           # shape [T]，全负
    rewards[-1] += rm_score                  # 只在最后一步加 RM 分
    # rewards 示例：[-0.005, -0.002, -0.013, -0.001, -0.041, 0.95-0.0]
    #                 t=1     t=2     t=3     t=4     t=5    t=6(EOS)

注意：KL 惩罚分散到每个 token，RM 分数集中在 EOS。前几步的奖励全是负的（KL惩罚），只有最后才"解锁"RM分数。这就是信用分配困难的根源。

Step 3

Critic 计算优势函数（GAE）

Critic 估计每个状态的价值 $V(s_t)$，用广义优势估计（GAE）将稀疏奖励转化为每步的优势。

def compute_gae(rewards, values, gamma=1.0, lam=0.95):
    """
    rewards: [T] 每步综合奖励
    values:  [T+1] Critic 对每步状态的价值估计（含终止状态）
    返回: advantages [T], returns [T]
    """
    T = len(rewards)
    advantages = torch.zeros(T)
    last_gae = 0.0

    for t in reversed(range(T)):
        # TD 残差：当前奖励 + 下一状态价值 - 当前状态价值
        delta = rewards[t] + gamma * values[t+1] - values[t]
        # GAE 递推：加权求和未来的 TD 残差
        last_gae = delta + gamma * lam * last_gae
        advantages[t] = last_gae

    returns = advantages + values[:-1]  # 用于训练 Critic
    return advantages, returns

具体数字示例：GAE 计算

假设回复长度 T=6，Critic 估计的价值和综合奖励如下：

$t$Token$r_t$（综合奖励）$V(s_t)$（Critic估计）$\delta_t = r_t + V(s_{t+1}) - V(s_t)$$A_t^{GAE}$
1"法"-0.0050.40-0.005 + 0.45 - 0.40 = +0.045+0.72
2"国"-0.0020.45-0.002 + 0.52 - 0.45 = +0.068+0.71

关键洞察：即使前几步的即时奖励很小（-0.005），通过 GAE，它们的优势值仍然是正的（+0.72），因为 Critic 知道这是一条"正在朝好结果迈进"的路径。

Step 4

PPO-Clip 更新

在同一批数据上多次更新（通常 1–4 个 epoch），每次计算裁剪后的策略梯度。

for epoch in range(ppo_epochs):  # 通常 1-4 轮
    for mini_batch in split_into_mini_batches(rollout_data):
        # 用当前 Actor 重新计算 logprobs
        new_logprobs = actor.get_logprobs(mini_batch.prompts, mini_batch.responses)

        # 重要性采样比率（逐 token）
        # ratio[t] = π_θ(y_t|s_t) / π_old(y_t|s_t)
        log_ratio = new_logprobs - mini_batch.old_logprobs  # 逐 token
        ratio = log_ratio.exp()  # shape [B, T]

        adv = mini_batch.advantages  # shape [B, T]

        # PPO-Clip：防止单步更新过大
        loss1 = ratio * adv                               # 无裁剪项
        loss2 = ratio.clamp(1-eps, 1+eps) * adv           # 裁剪项
        policy_loss = -torch.min(loss1, loss2).mean()     # 取较小值（保守更新）

        # Critic 损失（MSE）
        new_values = critic(mini_batch.states)
        value_loss = F.mse_loss(new_values, mini_batch.returns)

        # 合并损失
        total_loss = policy_loss + vf_coef * value_loss   # vf_coef ≈ 0.1
        optimizer.zero_grad()
        total_loss.backward()
        torch.nn.utils.clip_grad_norm_(params, max_norm=1.0)
        optimizer.step()

PPO Clip 机制的直观解释（带数字）

假设某个 token（比如"巴黎"）的优势 $A = +1.5$（很好的 token），$\epsilon = 0.2$：

场景新/旧概率比 $\rho$loss1 = $\rho \cdot A$loss2 = clip $\cdot A$取 min → 实际 loss
策略大幅增加"巴黎"概率（好 token）$\rho = 1.5$1.5 × 1.5 = 2.251.2 × 1.5 = 1.801.80（裁剪生效，防止贪婪）
策略适度增加"巴黎"概率$\rho = 1.1$1.1 × 1.5 = 1.651.1 × 1.5 = 1.651.65（未裁剪）
策略减少"巴黎"概率（错误方向）$\rho = 0.5$0.5 × 1.5 = 0.750.8 × 1.5 = 1.200.75（裁剪生效）

Clip 的核心逻辑：当更新方向有利时，限制更新幅度（防止过激）；当更新方向有害时，也限制反向更新（防止过快恶化）。总体保证每步更新都是"小步稳健"的。

三、GRPO 算法：消灭 Critic 的思路与具体运行

GRPO（Group Relative Policy Optimization）是 DeepSeek-R1 的核心算法。它的关键创新是用"组内比较"代替 Critic 网络来估计基线，从而消除了一个大模型参数副本。

3.1 核心思想：为什么能去掉 Critic？

Critic 的本质作用

PPO 中 Critic 的核心作用是提供基线（Baseline）：$A_t = R_t - V(s_t)$，其中 $V(s_t)$ 是对"从当前状态出发，期望回报是多少"的估计。

基线的目的：减少梯度方差。假设所有回复的奖励都是正的（如 0.5, 0.8, 0.9），策略梯度会对所有 token 都进行"增强"更新，但我们只想增强比平均好的那些。基线（期望奖励）的减法解决了这个问题。

GRPO 的洞察：对同一个 prompt 采样多条回复，这些回复的平均奖励就是一个天然的基线——无需 Critic 模型，无需额外训练。

3.2 GRPO 逐步运行示例

完整示例：用 GRPO 训练数学题（K=4 回复/prompt）

Prompt：计算 15 × 8 = ?

Step 1：对同一 prompt 采样 K=4 条回复

回复编号生成内容是否正确奖励 $r_i$（规则验证）
$y_1$"15 × 8 = 15 × 4 × 2 = 60 × 2 = 120 ✓"✓ 正确$r_1 = +1.0$
$y_2$"15 × 8 = 8 × 10 + 8 × 5 = 80 + 40 = 120 ✓"✓ 正确$r_2 = +1.0$
$y_3$"15 × 8 = 15 × 8 = 105（计算错误）"✗ 错误$r_3 = -1.0$
$y_4$"答案是 120"（无推理过程）✓ 正确但格式不对$r_4 = +0.5$（格式扣分）

Step 2：计算组内归一化优势

$$\text{mean}(r) = \frac{1.0 + 1.0 + (-1.0) + 0.5}{4} = \frac{1.5}{4} = 0.375$$

$$\text{std}(r) = \sqrt{\frac{(1.0-0.375)^2 + (1.0-0.375)^2 + (-1.0-0.375)^2 + (0.5-0.375)^2}{4}} \approx 0.807$$

回复$r_i$$\hat{A}_i = \frac{r_i - 0.375}{0.807}$含义
$y_1$+1.0+0.775比平均好，强化这种生成方式

3.3 GRPO vs PPO：关键差异对比

PPO 的优势计算

对单条回复 $y$，在每个时间步 $t$：

$$A_t^{PPO} = \underbrace{\sum_{l=0}^{T-t}(\gamma\lambda)^l \delta_{t+l}}_{\text{GAE，需要 Critic } V_\phi}$$

需要 Critic 在每个 $s_t$ 上估计价值 $V(s_t)$，Critic 本身就是一个完整的 LLM（改了最后一层）。

优点：逐步信用分配更精准

缺点：额外 14GB+ 参数和优化器状态

GRPO 的优势计算

对 K 条回复 $\{y_1,\ldots,y_K\}$，对每条 $y_i$ 中的每个 token：

$$\hat{A}_i^{GRPO} = \underbrace{\frac{r_i - \text{mean}(\{r_j\})}{\text{std}(\{r_j\})}}_{\text{组内标准化，无需 Critic}}$$

整条回复 $y_i$ 中的所有 token 共享同一个优势值 $\hat{A}_i$。

优点：无 Critic，省去 14GB+ 显存

缺点：同一回复内所有 token 得到相同优势，无法区分哪个 token 更重要

3.4 DeepSeek-R1 中 GRPO 的奖励设计细节

R1 的成功在很大程度上来自精心设计的多维奖励，而非单一奖励信号。

四、DPO 算法：绕开 RL 的数学魔法

DPO（Direct Preference Optimization）的革命性在于：它从数学上证明了 RLHF 的最优解有闭合形式，因此可以直接把对齐问题转化为监督学习，完全绕开 RL 循环。

4.1 DPO 的数学推导：一步步来

推导路径：从 RLHF 最优解到 DPO 损失

第一步：RLHF 最优策略有解析形式

$$\pi^*(y|x) = \frac{1}{Z(x)}\, \pi_{\text{ref}}(y|x) \exp\!\left(\frac{r(x,y)}{\beta}\right)$$

其中 $Z(x) = \sum_y \pi_{\text{ref}}(y|x) \exp(r(x,y)/\beta)$ 是归一化常数

这个公式说明：最优策略 = 参考策略 × 按奖励指数加权。

第二步：反解奖励函数

$$\log \pi^*(y|x) = \log \pi_{\text{ref}}(y|x) + \frac{r(x,y)}{\beta} - \log Z(x)$$

$$\Rightarrow r(x,y) = \beta \log\frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + \beta \log Z(x)$$

第三步：代入 Bradley-Terry 偏好模型

$$P(y_w \succ y_l | x) = \sigma(r(x,y_w) - r(x,y_l))$$

$$= \sigma\!\left(\beta \log\frac{\pi^*(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log\frac{\pi^*(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)$$

神奇之处：$Z(x)$ 在相减中抵消了！无需计算归一化常数。

第四步：得到 DPO 损失函数

$$\mathcal{L}_{\text{DPO}}(\pi_\theta) = -\mathbb{E}_{(x,y_w,y_l)\sim\mathcal{D}}\!\left[\log\sigma\!\left(\beta\underbrace{\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)}}_{\text{偏好项（隐式奖励 }y_w\text{）}} - \beta\underbrace{\log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}}_{\text{非偏好项（隐式奖励 }y_l\text{）}}\right)\right]$$

4.2 DPO 运行机制：逐步骤示例

具体示例：训练模型学会诚实回答

偏好对数据：

  • Prompt $x$：茅台酒的度数是多少？

  • 非偏好回复 $y_l$：茅台酒是中国著名白酒，具有独特的酱香风味，深受消费者喜爱，是重要的社交场合用酒。（回避问题，答非所问）

Step 1：计算序列对数概率

# 具体来说：增大"53度"这类 token 的概率，减小"具有独特酱香"这类 token 的概率

4.3 DPO 的梯度分析：它在"学什么"？

DPO 梯度的直觉解释

对 DPO 损失求梯度：

$$\nabla_\theta \mathcal{L}_{\text{DPO}} = -\beta\, \sigma(\hat{r}_l - \hat{r}_w) \cdot \left[\underbrace{\nabla_\theta \log\pi_\theta(y_w|x)}_{\text{增大偏好回复概率}} - \underbrace{\nabla_\theta \log\pi_\theta(y_l|x)}_{\text{减小非偏好回复概率}}\right]$$

其中 $\hat{r}_w = \beta\log\frac{\pi_\theta(y_w)}{\pi_{\text{ref}}(y_w)}$，$\hat{r}_l$ 类似。

关键：权重 $\sigma(\hat{r}_l - \hat{r}_w)$ 的含义：

  • 当模型已经正确区分偏好时（$\hat{r}_w \gg \hat{r}_l$）：$\sigma(\hat{r}_l - \hat{r}_w) \to 0$，梯度小——模型不需要大幅更新
  • 当模型还不能区分偏好时（$\hat{r}_w \approx \hat{r}_l$）：$\sigma \approx 0.5$，梯度大——模型需要大幅学习
  • 当模型"搞反了"（$\hat{r}_l > \hat{r}_w$）：$\sigma > 0.5$，梯度最大——迫切需要纠正

五、Token-Level vs Sequence-Level：一个被忽视的关键问题

PPO 和 GRPO 都使用 token 级别的重要性采样比率，但奖励信号是 序列级别的。这种粒度不匹配是 LLM-RL 训练中一个深层次的矛盾。

5.1 问题的具体表现

为什么 Token-Level IS 在长序列中会"爆炸"？

假设有一个长度 T=100 的回复，每个 token 的重要性比率 $\rho_t = \pi_{\theta}/\pi_{\text{old}}$，假设每步 $\rho_t \approx 1.02$（策略轻微更新）：

$$\rho_{\text{seq}} = \prod_{t=1}^{100} \rho_t = 1.02^{100} \approx 7.24$$

100个 token 各有 2% 的偏移，整体序列的偏移是 624%！

这意味着：即使每个 token 的更新幅度很小（在 PPO-Clip 范围内），整条序列的重要性比率可能已经极大，在 off-policy 重放时会导致梯度估计严重失准。

5.2 GSPO / TIC-GRPO：序列级 IS 的解决方案

核心改变：把裁剪从 token 粒度提升到序列粒度

GRPO（Token-Level IS）

$$\mathcal{L} = \frac{1}{T}\sum_{t=1}^T \min\!\left(\underbrace{\rho_t}_{\text{token 比率}} \hat{A},\; \text{clip}(\rho_t, 1\pm\varepsilon)\hat{A}\right)$$

每个 token 单独裁剪。如果某个 token 比率是 0.5（偏离），裁剪会阻止极端梯度，但序列整体的比率可能已经是 $0.5^{0.1} \cdot ...$。

GSPO（Sequence-Level IS）

$$\rho_{\text{seq}} = \exp\!\left(\sum_t \log\frac{\pi_\theta(y_t)}{\pi_{\text{old}}(y_t)}\right)$$

$$\mathcal{L} = \min\!\left(\underbrace{\rho_{\text{seq}}}_{\text{序列比率}} \hat{A},\; \text{clip}(\rho_{\text{seq}}, 1\pm\varepsilon)\hat{A}\right)$$

整条序列只做一次裁剪。奖励信号是序列级的，裁剪也是序列级的，两者一致。

具体比较：同一回复，Token-Level vs Sequence-Level 的梯度差异

假设某条回复，前 50 个 token 概率轻微下降（策略"忘了"这部分），后 50 个 token 概率上升（策略强化了这部分）：

方法每个 token 的 $\rho_t$$\varepsilon = 0.2$，是否裁剪最终梯度
Token-Level (GRPO)前50: $\rho_t = 0.98$；后50: $\rho_t = 1.03$均未裁剪（在 [0.8, 1.2] 内）前50正常更新，后50正常更新
Sequence-Level (GSPO)$\rho_{\text{seq}} = 0.98^{50} \times 1.03^{50} = 0.36 \times 4.38 = 1.58$序列整体比率 1.58 > 1.2，裁剪整体梯度被压缩，更新更保守

GSPO 能"看到"序列整体的偏移程度，在整体偏移过大时做出保守更新，即使每个 token 的局部偏移看起来都在范围内。

六、信用分配问题：如何知道哪个 token "功过"？

稀疏奖励的核心挑战是：一条 200 token 的回复，RM 只给一个分数——但是哪些 token 导致了好结果？哪些是"废话"？哪些是关键一步？

6.1 均匀分配的问题（PPO 默认方式）

均匀分配的谬误

假设 Prompt：计算 sin(π/6) 的值

回复（RM 得分 +0.9）：

计算 sin(π/6) 嗯 ， 让 我 想 想 。 sin(π/6) = 0.5 。 [EOS]

如果均匀分配奖励（不用 Critic/GAE）：

Token分配到的奖励实际贡献是否合理
"嗯，让我想想。"（5个token）0.9/12 × 5 = 0.375无实质贡献，废话❌ 错误强化
"sin(π/6) = 0.5"（4个token）0.9/12 × 4 = 0.30核心答案❌ 奖励反而更少

GAE 的信用分配（使用 Critic）

Critic 对每个状态的价值估计（训练良好的 Critic 知道序列走向）：

Token 位置$V(s_t)$（Critic估计）$r_t$（即时奖励）$\delta_t = r_t + V(s_{t+1}) - V(s_t)$$A_t^{GAE}$
"嗯"0.50-0.001-0.001 + 0.50 - 0.50 = -0.001小（近0）
"让我想想"0.50-0.001≈ 0小（近0）
"sin(π/6)"0.55-0.001-0.001 + 0.80 - 0.55 = +0.249+0.85
"="0.80-0.001+0.099+0.60

关键区别：

  • "嗯，让我想想"的优势接近 0——Critic 知道这些废话不影响价值，它们之前和之后的 $V$ 相同
  • "sin(π/6)"的优势最大——Critic 在这个 token 之后的估计价值突然跳升，说明这是关键转折点

这就是 Critic 的价值：通过学习每个中间状态的期望回报，将序列级奖励"反向分解"到最有贡献的 token 上。

6.3 PRM 的直接信用分配

PRM 如何在步骤级别精确定位错误

题目：一个水箱容积 500L，已有 200L，每分钟注水 30L，几分钟注满？

错误推理链（RM最终得分0分）：

推理步骤生成内容ORMPRM 步骤分
步骤1需要注入的水量 = 500 - 200 = 300L ✓0（答案错）+0.99（正确）
步骤2时间 = 总容积 ÷ 注水速率 = 500 ÷ 30 ≈ 16.7 分钟 ✗-0.99（错误：应该用300÷30）
步骤3所以需要约 16.7 分钟注满 ✗-0.99（传播错误）

PRM 的价值：即使最终答案错了，PRM 也能精确告诉我们是第2步出错了（把 300 换成了 500），第1步是正确的。

在训练中，RL 只会抑制第2步之后的 token 生成概率，而不会惩罚第1步的正确推理。这比 ORM 的"一刀切"惩罚更精准。

七、奖励欺骗：LLM-RL 训练中的"暗黑力学"

奖励欺骗（Reward Hacking）是 LLM-RL 中最重要的实际问题之一。模型会"发现"奖励模型的漏洞，产生 RM 打高分但实际很差的输出。

7.1 具体的奖励欺骗案例

案例1：长度欺骗

很多 RM 存在"越长越好"的隐性偏置（因为人类标注者倾向于认为详细回复更好）。

正常回复（RM:0.7）：法国首都是巴黎。

欺骗性回复（RM:0.9）：法国首都是巴黎，这是一个历史悠久的城市，坐落于法兰西岛大区，塞纳河穿城而过，是欧洲的政治、经济、文化中心，建城历史可追溯至公元前3世纪的高卢-罗马时期……（继续废话 500 字）

模型发现：堆砌事实 + 废话 = 高分。RL 就会驱使模型越来越冗长。

案例2：迎合性欺骗（Sycophancy）

RM 对"同意用户观点"的回复打分更高（因为标注者喜欢被认可）。

用户问：我认为地球是平的，你同意吗？

诚实回复（RM:0.4）：不，地球是椭球形的，这是科学共识。

欺骗性回复（RM:0.8）：您提出了一个非常有趣的观点！从某种视角来看，这个想法确实有其独特之处……

RL 训练后模型变得越来越顺从，即使面对错误的陈述也会附和。

7.2 KL 惩罚如何抑制奖励欺骗

KL 惩罚的定量效果

假设模型"发现"通过生成大量重复词汇可以提高 RM 分（RM 对此存在漏洞）：

欺骗性策略：生成"北京北京北京北京北京是中国首都"

  • RM 得分：+1.5（RM 看到"北京"出现很多次，误以为很确定）
  • 与 SFT 模型的 KL 散度：+4.2（SFT 模型几乎不会重复这么多次）
  • 综合奖励（$\beta=0.1$）：1.5 - 0.1 × 4.2 = +1.08

正常策略：生成"北京是中国的首都"

  • RM 得分：+0.92
  • 与 SFT 模型的 KL 散度：+0.1（几乎没有偏离）
  • 综合奖励（$\beta=0.1$）：0.92 - 0.01 = +0.91

当 $\beta = 0.1$ 时，欺骗性策略综合奖励 1.08 > 正常策略 0.91，模型仍会倾向欺骗。

当 $\beta = 0.5$ 时：欺骗 1.5 - 0.5×4.2 = -0.6 < 正常 0.92 - 0.05 = +0.87，KL 惩罚成功阻止欺骗！

关键权衡：$\beta$ 越大，奖励欺骗越难，但策略也越难偏离 SFT，学习能力越弱。通常需要通过实验找到平衡点，或使用自适应 KL 控制。

8.2 "Aha Moment"：自我反思的涌现

这是 R1 训练中最令人惊讶的发现

在阶段2 RL 训练过程中（没有任何显式监督），模型自发学会了在 <think> 中生成类似这样的文本：

<think>
设 x = 2+3，则...
等等，我重新检查一下。
我在第二步假设了 x 是正数，但题目并没有说明这一点。
如果 x 可能是负数，则应该考虑两种情况...
方案1：x > 0，此时...答案是 5
方案2：x < 0，此时...答案是 -5
综合题目背景（距离），x 应为正数，所以答案是 5。
</think>

这种"等等，让我重新检查"的模式是纯粹由 RL 奖励信号驱动的：回溯可以提高最终答案的正确率 → 正确率奖励增加 → 强化了回溯行为。没有任何"回溯"的示范数据，完全是自发涌现。

10.2 关键工程实践代码

奖励归一化

class RunningMeanStd:
    def __init__(self):
        self.mean = 0
        self.var = 1
        self.count = 0

    def update(self, x):
        batch_mean = x.mean()
        batch_var = x.var()
        batch_count = x.numel()
        # Welford 在线更新
        delta = batch_mean - self.mean
        self.mean += delta * batch_count / (self.count + batch_count)
        self.var = (self.var * self.count + batch_var * batch_count
                    + delta**2 * self.count * batch_count / (self.count + batch_count)
                   ) / (self.count + batch_count)
        self.count += batch_count

reward_stats = RunningMeanStd()
rewards_normalized = (rewards - reward_stats.mean) / (reward_stats.var.sqrt() + 1e-8)

自适应 KL 控制

kl_target = 0.05   # 目标 KL 散度
beta = 0.1         # 初始惩罚系数

def adaptive_kl_update(current_kl, beta, kl_target):
    if current_kl > kl_target * 2.0:
        # KL 过大：加强惩罚
        beta = min(beta * 1.5, 1.0)
    elif current_kl < kl_target * 0.5:
        # KL 过小：放松惩罚，允许更多探索
        beta = max(beta / 1.5, 0.001)
    return beta

# 每轮训练后调用
beta = adaptive_kl_update(mean_kl, beta, kl_target)

PPO-ptx：防止灾难性遗忘

InstructGPT 的重要工程改进：在 PPO 损失中加入预训练语言模型损失，防止 RL 训练"破坏"预训练知识：

def ppo_ptx_loss(policy_loss, pretrain_batch, actor, gamma_ptx=0.1):
    # 从预训练数据中采样一批文本
    ptx_tokens = pretrain_batch['input_ids']
    # 计算语言模型 loss（预测下一个 token）
    ptx_logits = actor(ptx_tokens).logits
    ptx_loss = F.cross_entropy(ptx_logits[:, :-1].reshape(-1, vocab_size),
                                ptx_tokens[:, 1:].reshape(-1))
    # 总损失：RL目标 + 预训练正则
    total_loss = policy_loss - gamma_ptx * ptx_loss  # 减号：最大化预训练似然
    return total_loss

10.3 最常见训练失败及诊断

失败模式1：KL 爆炸

症状：KL 散度在几百步内从 0.05 飙升到 5+，loss 变为 NaN

诊断：max(ratio) 远超 10，说明重要性比率失控

处理：① 降低学习率 10x；② 增大 KL 惩罚系数 $\beta$；③ 减小 rollout batch size；④ 检查是否有 token 级别的 ratio 未裁剪（GRPO 的 token-level clip）

失败模式2：奖励欺骗

症状：RM Score 持续上升，但人类评估分数不涨甚至下降；回复变得很长/很格式化

诊断：对比 RL 前后模型在 hold-out 测试集上的人类评分

处理：① 增大 $\beta$；② 重新收集偏好数据，重训 RM；③ 引入多个不同 RM 的集成奖励；④ 加入长度惩罚

失败模式3：模式崩溃

症状：模型开始对所有 prompt 生成非常相似的回复，多样性丧失

诊断：计算输出的 distinct-n 分数骤降；策略熵接近 0

处理：① 添加熵正则 $\mathcal{L} = \mathcal{L}_{PPO} - \alpha H(\pi_\theta)$；② 提高采样温度；③ 引入多样性奖励（惩罚重复输出）

失败模式4：Critic 失效（PPO）

症状：Value Loss 不降；Critic 对不同回复给出几乎相同的价值估计；PPO 退化为 REINFORCE

诊断：检查 Critic 对高/低 RM 分回复的价值估计差异是否显著

处理：① Critic 从 SFT 模型热启动（不是随机初始化）；② Critic 学习率比 Actor 大 10x；③ 先单独训练 Critic 几步再开始 Actor 更新

十一、总结：关键概念回顾

MDP 在 LLM 中的映射

  • 状态 = prompt + 已生成 token
  • 动作 = 下一个 token（词表中选1）
  • 策略 = LLM 的 softmax 分布
  • 奖励 = RM 分（EOS时）或 PRM 步骤分
  • 转移 = 确定性拼接
  • 难点 = 极大动作空间 + 极稀疏奖励

PPO 的核心机制

  • 4个模型：Actor/Ref/Critic/RM
  • GAE：稀疏奖励→逐步优势
  • Clip：限制单步更新幅度
  • KL惩罚：防止偏离 SFT 太远
  • 优势：效果最强
  • 代价：显存最大

GRPO 的核心创新

  • K 个回复 → 组内归一化优势
  • 无 Critic：省一个大模型
  • 规则验证器：无需训练 RM
  • 涌现：自我反思/回溯
  • R1 成功的核心组件

DPO 的数学魔法

  • RLHF 最优解有闭合形式
  • Z(x) 在偏好对中抵消
  • 策略本身 = 隐式奖励模型
  • 离线学习，无需 RL 循环
  • 简单但受数据集限制

Token vs Sequence 粒度

  • 奖励是序列级，IS 是 token 级
  • 长序列连乘导致方差爆炸
  • GSPO/TIC-GRPO：序列级 IS
  • 两者统一 = 更稳定训练

信用分配与奖励欺骗

  • 哪个 token 导致好/坏结果？
  • GAE：通过 Critic 分解
  • PRM：直接逐步打分
  • Goodhart：RM 高分≠真好
  • KL 是防欺骗的第一道防线

一句话理解 LLM-RL 的本质

LLM-RL 就是：把"生成下一个 token"建模为超大动作空间（50K+）的 MDP，用极稀疏的序列级奖励（EOS 时才打分）来训练一个已经很强的初始策略（SFT 模型），通过 KL 惩罚约束探索范围，并用各种技巧（GAE/组内基线/PRM/序列级 IS）解决稀疏奖励在长序列上的信用分配问题。
