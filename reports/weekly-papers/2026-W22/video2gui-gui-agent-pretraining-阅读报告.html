2. 核心问题与动机

2.1 现有 GUI Agent 数据的瓶颈

构建能在真实界面上自主操作的 GUI 智能体，长期受制于高质量交互轨迹数据的稀缺性。 主要原因有三：

  • 标注成本极高：人工录制屏幕操作并逐步标注动作类型、坐标、语义意图，每条轨迹耗时数分钟甚至更长。
  • 平台覆盖受限：现有数据集（AITW、Mind2Web 等）多聚焦于特定应用或特定操作系统，泛化能力差。
  • 应用多样性不足：公开数据集通常覆盖不超过数十种应用，而真实用户工作流涉及数以千计的软件。

2.2 互联网视频：被忽视的大规模数据源

核心洞察：YouTube 等平台上存在海量的屏幕录制教程视频（软件演示、操作指南、游戏攻略等），这些视频天然包含真实的 GUI 操作序列，是挖掘交互轨迹的理想原始数据源。

本文的核心思路是：无需任何人工标注，直接从互联网视频中自动化地抽取 GUI 交互轨迹，并将其转化为结构化的训练数据，从而在数量和多样性上突破现有瓶颈。

2.3 挑战

  1. 海量噪声：500M 条视频元数据中，只有极少部分是高质量的 GUI 操作教程视频。
  2. 内容异质性：视频分辨率、录制质量、界面风格差异极大。
  3. 动作语义歧义：从视频帧序列恢复「点击」「输入」「滚动」等操作类型及精确坐标，需要多模态信号的联合建模。
  4. 时序对齐难度：将视频帧、语音旁白（ASR）与界面元素三者精确对齐，是轨迹质量的关键。

近期工作（GPT-4V、Qwen2.5-VL、Mimo-VL、SeeClick、UGround、ShowUI）直接将屏幕截图输入视觉语言模型，让模型预测下一步动作。 这一范式的性能高度依赖预训练数据的质量与多样性，因此大规模轨迹数据集至关重要。

3.3 从视频学习交互

少数工作（如 VideoAgent、EgoTV）尝试从视频中学习操作流程，但主要聚焦于具身智能（Embodied AI）场景，未能解决屏幕 GUI 的细粒度元素识别与精确坐标对齐问题。 Video2GUI 首次将此思路系统化地应用于通用 GUI 预训练。

5. 关键技术详解

5.1 粗细粒度视频过滤（Coarse-to-Fine Filtering）

5.1.1 粗粒度过滤

面对 5 亿条视频元数据，首先采用轻量级启发式规则进行高效筛选：

  • 关键词匹配：标题/描述含 "tutorial"、"how to"、"guide"、"step by step" 等词汇。
  • 时长约束：保留 $2 \leq T \leq 30$ 分钟的视频，过短无法构成完整操作流程，过长信息密度低。
  • 语言筛选：优先英语和中文，确保 ASR 质量可靠。

5.1.2 细粒度过滤

对通过粗粒度筛选的视频，利用三路信号进一步评分：

$$S_{\text{quality}}(v) = \alpha \cdot S_{\text{ASR}}(v) + \beta \cdot S_{\text{OCR}}(v) + \gamma \cdot S_{\text{visual}}(v)$$

其中：

  • $S_{\text{ASR}}(v)$：基于语言模型对转录文本的连贯性与操作描述密度评分；
  • $S_{\text{OCR}}(v)$：对关键帧中检测到的 UI 文字元素数量与布局规整度进行量化；
  • $S_{\text{visual}}(v)$：识别光标轨迹、点击涟漪动效等屏幕操作视觉特征；
  • $\alpha, \beta, \gamma$ 为可调权重，满足 $\alpha + \beta + \gamma = 1$。
最终仅保留 $S_{\text{quality}}(v) \geq \tau_{\text{quality}}$ 的视频，其中阈值 $\tau_{\text{quality}}$ 通过在小规模人工标注集上验证精度-召回率曲线确定。

5.2 GUI 轨迹抽取（Trajectory Extraction）

通过四个串行子模块将过滤后的视频转换为结构化轨迹：

步骤 1：关键帧提取（Keyframe Extraction）

采用基于画面变化率的自适应采样策略，避免冗余帧。令第 $t$ 帧与第 $t-1$ 帧之间的视觉差异为：

$$\Delta_t = 1 - \frac{\langle f_t, f_{t-1} \rangle}{\|f_t\| \cdot \|f_{t-1}\|}$$

其中 $f_t$ 为帧的视觉特征向量。当 $\Delta_t \gt \tau_{\text{frame}}$ 时，将第 $t$ 帧标记为关键帧候选，再通过非极大值抑制（NMS）去除连续短时段内的重复关键帧。

步骤 2：UI 元素检测（Element Detection）

对每个关键帧，利用专门训练的 GUI 元素检测模型识别： 按钮 输入框 下拉菜单 图标 链接 等交互元素，输出元素类型 $c_i$、边界框 $b_i = (x, y, w, h)$ 及文字内容 $t_i$（如有）。

步骤 3：动作接地（Action Grounding）

将 ASR 文本片段与视觉关键帧对齐，推断每个操作步骤的：

  • 动作类型：$a \in \{\text{click}, \text{type}, \text{scroll}, \text{drag}, \text{hotkey}\}$
  • 目标元素：$e^{*} = \arg\max_{i} \text{Align}(q_{\text{ASR}}, e_i)$，其中 $q_{\text{ASR}}$ 为操作描述的文本嵌入
  • 精确坐标：$(x^{*}, y^{*})$ 取自 $b_{e^{*}}$ 的中心点
$$\text{Align}(q, e_i) = \text{sim}(q, \phi(c_i, t_i, b_i))$$

其中 $\phi(\cdot)$ 将元素属性编码为语义向量，$\text{sim}(\cdot, \cdot)$ 为余弦相似度。

步骤 4：轨迹生成（Trajectory Generation）

将连续的（帧, 动作, 目标）三元组组织为完整轨迹：

$$\tau = \bigl[(o_1, a_1, g_1),\ (o_2, a_2, g_2),\ \ldots,\ (o_n, a_n, g_n)\bigr]$$

其中 $o_i$ 为屏幕状态观测（关键帧），$a_i$ 为动作类型，$g_i$ 为操作目标描述（自然语言）。最终以 JSON 格式序列化，并附加元数据（应用名称、平台类型、任务描述）。

Algorithm 1   Video2GUI Trajectory Extraction
Input: filtered video $v$, ASR transcript $\mathcal{T}$ Output: trajectory $\tau$
1. $\mathcal{F} \leftarrow$ KeyframeExtract$(v, \tau_{\text{frame}})$  // adaptive sampling 2. for each $f_t \in \mathcal{F}$ do 3. $\mathcal{E}_t \leftarrow$ DetectUIElements$(f_t)$  // bbox + class + text 4. end for 5. $\mathcal{S} \leftarrow$ AlignASRToFrames$(\mathcal{T}, \mathcal{F})$  // temporal alignment 6. $\tau \leftarrow [\ ]$ 7. for each segment $s_i \in \mathcal{S}$ do 8. $a_i \leftarrow$ ClassifyAction$(s_i.\text{text})$ 9. $e^{*}_i \leftarrow \arg\max_j$ Align$(s_i.\text{query},\ \mathcal{E}_{t_i}[j])$ 10. $(x^{*}, y^{*}) \leftarrow$ Center$(e^{*}_i.\text{bbox})$ 11. $\tau$.append$\bigl((f_{t_i},\ a_i,\ g_i,\ x^{*},\ y^{*})\bigr)$ 12. end for 13. return $\tau$

5.4 两阶段预训练（Two-stage Pretraining）

阶段一：GUI Grounding 预训练

以元素定位任务为核心，让模型学会在给定屏幕截图和元素描述时，输出精确的归一化坐标 $(\hat{x}, \hat{y})$。训练目标为：

$$\mathcal{L}_{\text{grounding}} = \mathbb{E}_{(o, e, x^{*}, y^{*}) \sim \mathcal{D}} \left[ \left\| (\hat{x}, \hat{y}) - (x^{*}, y^{*}) \right\|^2 \right]$$

其中 $o$ 为屏幕截图，$e$ 为元素描述（文字 + 类型），$(x^{*}, y^{*})$ 为标注的归一化目标坐标。

阶段二：指令跟随微调

在完整轨迹数据上进行指令跟随训练，模型输入为任务描述与当前屏幕状态的历史序列，输出为下一步动作：

$$\mathcal{L}_{\text{follow}} = -\sum_{t=1}^{n} \log P_\theta\bigl(a_t, g_t \mid o_{\leq t}, a_{\lt t}, \text{task}\bigr)$$

联合优化动作类型分类损失与坐标回归损失，权重可通过超参调节。

训练细节：以 Qwen2.5-VL-7B 和 Mimo-VL-7B 为基础模型，阶段一在 WildGUI 的 grounding 子集上训练约 2 个 epoch，阶段二在完整轨迹数据上训练，并加入少量高质量人工标注数据（如 AITW）进行混合以防止灾难性遗忘。

7. 消融实验

7.1 过滤策略的影响

不同过滤策略组合对 ScreenSpot 准确率的影响

消融结论：

  • 仅使用粗粒度过滤时，模型性能仅比无过滤提升约 2–3%，噪声数据严重干扰预训练。
  • 加入 ASR 质量过滤后，提升增加至 6–8%，说明语音旁白对动作语义建模至关重要。
  • 三路信号（ASR + OCR + Visual）联合过滤效果最优，达到完整 Video2GUI 的性能水平。

8. 局限性

8.1 视频来源偏差

WildGUI 主要来源于 YouTube 英文教程视频，导致数据分布偏向英语界面、Windows/Web 平台，对小语种软件（如日文、阿拉伯文界面）及移动端原生应用的覆盖仍然不足。

8.2 动作类型覆盖不均

「点击」操作在视频中有明显的视觉特征（点击动效），易于识别，占数据集 70% 以上； 而「拖拽」、「手势」等复杂操作在视频中往往无明显标记，识别准确率较低，导致复杂操作训练数据稀少。

8.3 轨迹完整性依赖于 ASR 质量

当视频旁白质量差（背景噪声、口音、无旁白）时，动作接地模块的对齐准确率显著下降。约 15–20% 的视频因 ASR 质量不足而被过滤或产生低质量轨迹。

8.4 精确坐标的像素偏差

受视频压缩与分辨率限制，关键帧的像素质量低于原生截图，导致小尺寸 UI 元素（图标、滚动条）的边界框预测存在 $\pm 5$ 像素量级的误差，影响高精度定位任务。

8.5 缺乏长程规划能力的直接评估

现有实验主要评估单步动作的准确性，对于需要 30+ 步的复杂任务（如完整的表单填写工作流），Video2GUI 预训练带来的增益尚未得到充分验证。

9. 核心洞见与读后评注

9.1 方法论层面的核心贡献

洞见 1：「无标注视频」是 GUI 数据扩展的天然飞轮。 互联网上存在数亿条屏幕录制教程，这些视频天然包含有序的操作序列和语音说明，是现有人工标注数据集规模的数百倍。Video2GUI 的最大价值在于提供了一套可靠的「视频 → 结构化轨迹」的自动化流水线，使 GUI 数据的合成成本接近于零。
洞见 2：粗细粒度过滤设计具有普适价值。 三路信号（ASR、OCR、Visual）融合打分的思路，不仅适用于 GUI 数据筛选，也可推广至其他需要从噪声网络视频中挖掘结构化数据的场景（如手术操作视频、CAD 建模视频等）。
洞见 3：两阶段预训练的解耦设计值得借鉴。 将「低层感知能力（元素定位）」与「高层规划能力（任务完成）」分开训练，避免了两个目标之间的梯度干扰，是一种在工程实践中被反复验证的有效范式（参考 RLHF 中 Reward Model 与 Policy Model 的解耦）。

9.2 数据视角的深层思考

Video2GUI 揭示了 GUI Agent 研究的一个重要趋势：数据工程的价值已不亚于模型架构的创新。 在基础模型能力已经较强的今天，「如何高效获取高质量、高覆盖的领域数据」往往是决定下游任务性能的关键瓶颈。 WildGUI 的 1500+ 应用覆盖和 12M 规模，使模型真正见识到了现实世界 GUI 操作的多样性。

9.3 与相关工作的比较评析

  • vs. SeeClick / UGround：同为 GUI grounding 导向的预训练，但 Video2GUI 数据来自真实操作视频而非合成截图，分布更贴近实际使用场景，泛化性更强。
  • vs. GPT-4V + 提示工程：Video2GUI 路线通过大规模预训练将 GUI 知识内化至模型参数，推理阶段无需复杂提示设计，延迟和成本更低。
  • vs. 强化学习 GUI Agent（如 WebAgent）：RL 方法在线探索成本高昂，Video2GUI 提供的离线预训练数据可作为 RL 的初始化策略，两者互补而非竞争。

9.4 未来研究方向

  1. 多语言 GUI 数据扩展：系统性地挖掘非英语地区的本地化应用操作视频，提升模型对多语言界面的理解能力。
  2. 动态 GUI 状态建模：当前框架将轨迹表示为静态帧序列，未来可引入视频特征的时序建模（如 Video Transformer），捕捉 UI 的动态变化。
  3. 与在线 RL 的结合：以 Video2GUI 预训练模型作为 RL 智能体的初始策略，在真实环境中通过奖励信号进一步优化复杂任务完成能力。
  4. 轨迹质量评估的自动化：当前依赖人工抽样验证过滤效果，可训练专门的「轨迹质量判别器」实现端到端的自动化质量控制。
  5. 跨平台迁移学习：探索 WildGUI 中各平台数据的相互迁移规律，研究「Web 操作预训练」对「Android 操作」的正迁移机制。

9.5 总体评价

Video2GUI 是 GUI Agent 预训练领域近期最重要的工作之一。其核心贡献是方法论层面的：证明了「互联网视频是 GUI 数据的可扩展来源」，并提供了一套从原始视频到结构化训练数据的完整工程方案。WildGUI 数据集的开源将极大降低社区进入 GUI Agent 研究的门槛。值得注意的是，论文在数据工程细节（过滤阈值选取、ASR 模型选择、元素检测器训练细节）的描述略显简略，可复现性有待进一步验证。总体评分：8/10，强烈推荐阅读。
