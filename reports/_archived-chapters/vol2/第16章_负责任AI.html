一、从伦理到工程：部署闸门

高风险监管场景下，无法解释、记录、支持审计的模型——无论 accuracy 多高——都可能被挡在部署门外。Responsible AI 不是「锦上添花」，而是 Fleet Stack 治理层（Governance Layer）：下层提供 compute、数据移动、安全、鲁棒、可持续预算；治理层决定机器为何运行、服务于谁。

定义：负责任 AI（Responsible AI）

设计、审计、运营 ML 系统以满足可测的 fairness、safety、privacy、accountability 标准——将伦理原则转为可验证系统属性。

  • 与 AI Ethics 区别：伦理定义规范；负责任 AI 实现机制——bias 检测、差分隐私、audit trail、架构 guardrail
  • 常见陷阱：成品模型上做 compliance review；偏见若在表示层编码，后验阈值无法修复，须从数据采集重训

案例：Amazon 招聘算法（2018）

历史简历训练 → 系统性惩罚女性候选人。系统可构建、评估、集成——但统计最优 ≠ 伦理可接受。技术卓越与社会伤害可并存。

C³ 视角：责任是全 fleet 的 coordination 约束——fairness/safety 保证须在 compute 运行前建立。反馈环不稳定性：有毒输出侵蚀信任；歧视 degrades 未来训练数据；隐私泄露招致监管 shutdown。

二、治理层作为 Control Plane

公平性在控制论中像稳定性约束：误差分布在人口子群间应不变（或 bounded）。Explainability 是 control plane 的可观测性——无解释则 open-loop 黑箱，无法 debug 或验证安全约束。CI/CD 须像拦截内存泄漏一样拦截「老年用户群 accuracy 降 15%」的部署。

三、公平性指标与 Fairness Tax

定义：算法公平（Algorithmic Fairness）

模型误差分布或 outcomes 在受保护人口子群间不变（或有界差异）——多目标优化，非单一「公平解」。

3.1 形式化指标

二分类 $h(x)$，敏感属性 $A$：

准则公式（直觉）信贷算例
Demographic Parity$P(\hat{Y}=1|A=a)$ 跨群相等A 批准率 80%，B 须同样 80%
Equalized OddsTPR 与 FPR 跨群相等合格申请人 TPR 对齐
Equality of Opportunity仅 TPR 跨群相等「机会均等」变体
Calibration within groups$P(Y=1|\hat{p},A=a)$ 准确预测 70% 风险者中真 70% 违约
$$\text{Demographic Parity: } P(\hat{Y}=1 \mid A=0) = P(\hat{Y}=1 \mid A=1)$$

Napkin Math：Fairness Tax

信贷模型 baseline accuracy 85%。多数群 A 违约率 20%，少数群 B 40%。

  • 无约束：A 批准 80%，B 批准 60%
  • 强制 parity（B 也 80%）：B 阈值从 default prob <30% 放宽到 <50%
  • 新 accuracy 81% → 代价 4 percentage points（相对 −4.7%）

这是显式政策选择的成本，非 implementation bug。

3.2 Impossibility 与交集子群

Kleinberg–Chouldechova：基率不同时，calibration + error-rate balance 不可同时满足——工程师须选择优先准则并监控所选准则。Buolamwini：按 Race/Gender 分别看 99% accuracy，但深肤色女性仅 65%——Fairness Gerrymandering，须 intersectional 审计。

Healthcare 算法（Obermeyer 2019）

Optum 算法影响约 2 亿美国人/年。用医疗支出代理健康需求 → 低估黑人严重程度，高危护理项目黑人入组降 50%。修正 proxy 后黑人识别率 17.7% → 46.5%——单一 proxy 选择的人口级代价。

四、EU AI Act 与可审计性

EU AI Act（2024）风险分级：禁止实践、高风险系统（conformity、documentation、logging）、透明度义务、minimal risk。高风险部署须：

  • 技术文档与 conformity assessment
  • 自动决策 logging——输入、模型版本、阈值
  • 人类监督与 override 机制
  • 上市后 monitoring

GDPR Art. 22 + Art. 15： solely automated legal/significant decisions 须 meaningful logic 信息——架构上需要 explanation + recourse，非 opaque serving-only API。

Contestability Stack（生产模式，非政策词）

  1. Decision provenance：输出 ↔ 模型 binary + 输入向量密码学链接
  2. Explanation generation：Shapley/反事实高延迟 → 异步队列，保 serving SLA
  3. Appeal routing： contested 决策 → 领域专家人工队列
  4. Outcome tracking：申诉是否 overturn 机器决定

EU AI Act 高风险系统的 immutable audit trail 须预算存储、provenance、监督容量——作为 inference fleet 成本，非独立 policy artifact。

COMPAS：黑人被告假阳性 45% vs 白人 23%（ProPublica 2016）； proprietary 黑箱 + 有限解释工具 → 审计/debug 双重失败。

五、隐私、反馈环与机构嵌入

公平监控需要 demographic 数据 → 与 privacy 张力。设计选项：consent 直采、aggregate-only 审计、受限服务 escrow、DP 群统计、离线抽样标签——各改变 evidence 与 privacy risk。

预测性警务反馈环：部署 → 巡逻增加 → 逮捕记录增加 → 重训数据偏斜 → 初始小 skew 放大为系统性 disparity——静态 test set 检测不到。

Automation bias：放射系统 accuracy 99% → 人工 override 15%→2% → 剩余 1% 错误几乎不被捕获。对策：mandatory friction、随机 audit sample、confidence 强制展示。

机构层：model registry、model card、ethics board、red team（37）——review queue 与 security review 同为部署瓶颈。Google Flu Trends 多年未校正 → 机构 misalignment，非单点算法 bug。

六、章节总结

核心要点

  1. Responsible AI = Fleet Stack 治理层；失败 = 无法部署，非 reputational alone
  2. 治理是 control plane：fairness/explain/audit 与 scheduler 同级预算
  3. 公平准则数学不兼容；须 policy 选准则 + intersectional 监控
  4. Fairness tax 可量化（例：85%→81%）；Obermeyer proxy 影响 2 亿人
  5. EU AI Act / GDPR 要求 logging、explain、contestability 写入架构
  6. 反馈环、automation bias、normative pluralism 需机构流程，非 metrics alone
责任的位移定律：post-hoc 审计 trail 比设计期嵌入贵一个数量级——与 carbon、security 相同，治理债在 scale 上不可逆。
