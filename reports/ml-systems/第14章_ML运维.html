第 3 章 workflow 的「监控→重训」在 production 落地：四维监控、告警分级、自动化重训、ML CI/CD。

一、四维监控

层指标示例告警
基础设施GPU util、p99 <200 msQPS=0 5 min
模型AUC 滑动 7d降 >3 pt
数据PSI>0.2548h 内重训工单
业务DR 转诊率周环比 ±20%

二、重训触发

if psi(feature_x) > 0.25 for 3 consecutive days:
    trigger_retrain(pipeline_id="dr_v7", data_version="latest")

非日历重训：freshness debt（第 4 章）>90 天 warning，>365 天 critical。

三、ML CI/CD

  • CI：数据 GX 断言 + 单元测试 + 小 subset 训练 smoke（<10 min）
  • CD：Registry Staging → Canary 95/5（第 3 章）→ 晋升 Production
  • 回滚：保留 v{N-1} artifact + kubectl rollout undo

四、与第 3–4 章衔接

Lineage：PSI 告警 → data.dvc_rev → mlflow.run_id → 根因。Sculley CACE：改学习率可能改数据采样——变更须过接口契约审查。

五、总结

MLOps = 让 workflow 闭环可自动化、可审计。下一章：公平/隐私/合规（第 15 章）。
