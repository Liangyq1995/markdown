两个阶段命令

阶段一 启动 Ray 集群（AFO）

在 starship_job_submitter/ 目录下执行：

# 在 starship_job_submitter/ 目录下 python3 submit_rl_job_sh_v2.py \ --num_gpu=32 \ --workdir ./jobs/verl \ --command sh your_train.sh \ --debug > err

--debug：不提交实际命令，仅拉起集群 + Jupyter，方便调试
--num_gpu：总 GPU 数，除以 8 得到 worker 节点数

阶段二 提交训练 Job（Ray）

等集群就绪后，从 /log/service.txt 获取 Ray 地址，再执行：

# 在 /workfiles/sankuai/man/ 目录下 cd /Users/liangyongqi03/workfiles/sankuai/man sh submit/auto_submit_30b.sh \ --ray-address http://33.32.42.19:44390 \ > err

auto_submit_30b.sh → 调用 submit_script_30b.py，自动生成时间戳、更新 TensorBoard 路径，最终执行 ray job submit

阶段一内部执行流程（submit_rl_job_sh_v2.py）
1

解析参数 & 生成 Job 名称

从 --jobname、--command、当前时间戳生成唯一的 MODEL_DT，作为 AFO 任务名和 Ray submission-id。

2

构造 worker_script

拼接各节点启动命令：python3 afo_start/start_ray.py --workdir <basename> --command <cmd> ...，每个 AFO worker 节点都会执行此脚本。

3

写入 params.xml

通过 Configurator 加载 ray.yml，覆写 AFO 参数（GPU 数量、队列、镜像、节点黑名单等），输出到 params.xml。

4

conf.submit_job() 上传并提交

执行 hope run --files=<workdir>,./ray_submit/afo_start,mt_tools,runtime_env.yaml，每个路径的内容（非路径本身）被平铺上传到容器 /workdir/ 下。注意 ./ray_submit/afo_start 上传后变为 /workdir/afo_start/，而非 /workdir/ray_submit/afo_start/。

5

各节点执行 start_ray.py

节点 0（master）：启动 Ray head、Grafana、Prometheus、TensorBoard；等所有节点 join 后执行 ray job submit。
其他节点：执行 ray start --address=master:44391 加入集群，并监控 job 失败节点。

阶段二内部执行流程（auto_submit_30b.sh）
1

生成时间戳

submit_script_30b.py 生成格式为 MMDDHHMM 的时间戳，用于区分不同训练运行。

2

更新 TensorBoard 路径

修改 submit/test_runtime.yaml 中的 TENSORBOARD_DIR 为 .../tensorboard_log/{timestamp}，自动备份原文件。

3

执行 ray job submit

以 /workfiles/sankuai/man/ 为 working-dir，使用 submit/test_runtime.yaml 作为 runtime-env，执行 verl 训练 shell 脚本：
verl/experimental/fully_async_policy/shell/rlfactory_35b_16-16_sh_reward_server_http.sh

容器内目录结构（/workdir/）
核心规则： hope run --files=A,B,C 上传的是每个路径的内容，不是路径名本身。目录名会保留，但其父路径会被丢弃。例如 ./ray_submit/afo_start → 容器内变成 /workdir/afo_start/。 
/workdir/                               # AFO 容器内挂载点，SSD 存储
├── <basename of --workdir>/            # start_ray.py 的 os.chdir 落脚点，可以是空目录
│                                        训练代码不在这里！由阶段二 ray job submit --working-dir 上传
│                                        示例：--workdir ./jobs/verl → /workdir/verl/
│                                        示例：--workdir ./jobs/my_exp → /workdir/my_exp/
├── afo_start/                          # 来自 ./ray_submit/afo_start（父路径 ray_submit 被丢弃）
│   ├── start_ray.py                    # 各节点启动脚本，AFO worker_script 直接调用
│   └── start_ray_extern_head.py
├── mt_tools/                           # 来自 ./mt_tools/
├── runtime_env.yaml                    # 来自 ./runtime_env.yaml，start_ray.py 默认读 /workdir/runtime_env.yaml
└── tmp/                                # start_ray.py 运行时创建，Ray 临时文件存储（/tmp/ray 软链至此）
    └── ray/
        └── session_latest/
            ├── logs/               # Ray job driver 日志，定期 rsync 到 /log/ray_logs/
            ├── metrics/            # Grafana / Prometheus 配置
            └── runtime_resources/
                └── working_dir_files/ # ray job submit --working-dir 上传的文件（阶段二）
阶段二 ray job submit 的 working-dir
submit_script_30b.py 以 man/ 为 working-dir 执行 ray job submit --working-dir .，Ray 会将整个 man/ 目录打包上传到集群，解压到 /workdir/tmp/ray/session_latest/runtime_resources/working_dir_files/，训练脚本在此目录内执行。
常见问题
FileNotFoundError: /workdir/test
原因：start_ray.py 执行 os.chdir("/workdir/" + workdir_basename)，但上传的是完整路径（如 ./jobs/test），导致容器内实际路径是 /workdir/jobs/test 而非 /workdir/test。
解决： worker_script 中改为传 --workdir {p.workdir}（完整相对路径）而不是 workdir_base（basename）。
获取 Ray 地址
集群启动后，从容器日志或 AFO 页面查看 master 节点 IP，Ray dashboard 固定端口为 44390，即 http://<master_ip>:44390。
