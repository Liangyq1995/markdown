概述

Domino 是一个针对大语言模型（LLM）推理加速的投机解码（Speculative Decoding）新框架，其核心洞察在于：因果依赖建模（causal dependency modeling）与自回归执行（autoregressive execution）是两个可分离的关注点。传统自回归 draft 模型为了捕获 token 间的依赖关系，不得不串行逐步生成每个候选 token，导致 draft 阶段成为推理瓶颈；而并行 draft 方案虽然速度快，却因为忽略了 draft 块内部的 token 依赖，导致 draft 质量下降，最终接受长度（acceptance length）较低。

Domino 通过引入一个轻量级 Domino Head（由 GRU 因果编码器 + 低秩修正头组成），在并行 backbone 完成一次前向传播之后，以极低的额外开销将前缀因果信息"注入"到每个 draft 位置的 logit 分布中。配合专门设计的基础锚定训练课程（Base-Anchored Training Curriculum），Domino 在 Qwen3 系列模型上实现了迄今最高的 draft 接受长度与端到端加速比，最高单任务加速比达 8.02×，平均端到端加速比达 5.49×。

研究背景

要理解 Domino 的贡献，首先需要掌握投机解码的基本原理，以及自回归与并行两类 draft 策略各自的优劣。

投机解码原理

投机解码的核心思路是：用一个轻量级的 draft 模型（drafter）快速生成若干候选 token，再由目标大模型（verifier）并行验证这些候选 token 是否可接受。由于验证阶段可以将所有候选 token 打包为一次前向传播，与逐步自回归生成相比，每个验证步骤的计算开销几乎不变，但却能一次确认多个 token。

设 $\gamma$ 为 draft 块大小，$\tau$ 为平均接受长度（$1 \leq \tau \leq \gamma$），则投机解码的每步延迟为：

$$L_{\mathrm{spec}} = \frac{T_{\mathrm{draft}} + T_{\mathrm{verify}}}{\tau}$$

相对于目标模型自回归解码的延迟 $L_{\mathrm{target}}$，加速比为：

$$\eta = \frac{L_{\mathrm{target}}}{L_{\mathrm{spec}}} = \frac{\tau \cdot L_{\mathrm{target}}}{T_{\mathrm{draft}} + T_{\mathrm{verify}}}$$

从公式可以看出，提升加速比有两条路径：提高接受长度 $\tau$（提升 draft 质量），或降低 draft 延迟 $T_{\mathrm{draft}}$（提升 draft 速度）。这两者之间存在根本性张力。

自回归 Drafting 的优劣

自回归 draft 模型（如 EAGLE 系列）在生成第 $i$ 个 draft token 时，会将已生成的 $i-1$ 个 draft token 作为条件输入，从而精确建模 draft 块内部的因果依赖：

$$q_{\mathrm{AR}}(x_{t+1:t+\gamma} \mid x_{\leq t}) = \prod_{i=1}^{\gamma} q(x_{t+i} \mid x_{\lt t+i})$$

这使得自回归 drafter 的 draft 质量较高，接受长度较长。然而，其代价是串行执行：每生成一个 token 都需要一次完整的网络前向传播，draft 延迟随块大小线性增长：

$$T_{\mathrm{draft}}^{\mathrm{AR}} \approx \gamma \cdot (t_{\mathrm{net}} + t_{\mathrm{head}})$$

当 draft 块大小 $\gamma$ 增大时，draft 延迟显著上升，抵消了接受长度提升带来的收益。

并行 Drafting 的优劣

并行 draft 方案（如 Medusa、DFlash）在一次前向传播中同时预测整个 draft 块的所有 token，将 draft 延迟降低到近似常数：

$$T_{\mathrm{draft}}^{\mathrm{PAR}} \approx t_{\mathrm{net}}^{\mathrm{block}} + t_{\mathrm{head}}^{\mathrm{block}}$$

速度优势显著，但由于各位置的预测相互独立，忽略了 draft 块内部的 token 依赖，导致 draft 分布与真实自回归分布之间存在系统性偏差，接受长度较低。

核心方法 — Domino 框架

Domino 的方法论核心是：将因果依赖建模（causal modeling）从自回归执行（autoregressive execution）中解耦出来。具体而言，Domino 保留并行 backbone 的高速并行执行特性，同时通过一个轻量级的 Domino Head 在 logit 空间施加因果修正，以极低的额外延迟换取显著的 draft 质量提升。

并行 Draft Backbone

Domino 的并行 backbone 采用 DFlash 架构（Block Diffusion for Flash Speculative Decoding），包含 5 个 Transformer 层。给定已验证的前缀 $x_{\leq t}$，backbone 首先从目标模型中提取上下文特征 $C_t$，然后构造一个掩码输入块：

$$\tilde{x}_{t:t+B-1} = [x_t, \texttt{[MASK]}, \ldots, \texttt{[MASK]}]$$

以 $x_t$ 作为锚点 token，其余 $B-1$ 个位置填充 [MASK]。随后一次前向传播得到整个块的隐状态：

$$H_{t:t+B-1} = \mathrm{Backbone}(C_t,\; \mathrm{Embed}(\tilde{x}_{t:t+B-1}))$$

再通过冻结的目标模型 LM Head 并行计算每个位置的基础 logit：

$$L_i^{\mathrm{base}} = \mathrm{LMHead}(H_i), \quad i = t+1, \ldots, t+B-1$$

这一步完全并行，时间复杂度为 $O(1)$（相对于块大小 $B$）。

因果解耦的核心思路

并行 backbone 的问题在于：各位置的基础 logit $L_i^{\mathrm{base}}$ 是在 [MASK] 条件下计算的，完全不依赖于已采样的 draft token $x_{t+1}, \ldots, x_{t+i-1}$，因此无法捕获 draft 块内部的因果依赖。

Domino 的关键洞察是：因果依赖信息可以在 logit 空间以残差方式叠加，而无需重新执行昂贵的并行 backbone 前向传播。具体地，Domino Head 在得到 $L_i^{\mathrm{base}}$ 之后，利用前缀 draft token 的嵌入序列计算一个低秩修正量 $\Delta L_i$，将其叠加到基础 logit 上：

$$L_i = L_i^{\mathrm{base}} + \Delta L_i$$

这样，最终的 draft 分布既保留了并行 backbone 的语义信息，又融入了前缀 token 的因果依赖，实现了"解耦"。

为什么选择 logit 空间而非 hidden 空间进行修正？若在 hidden 空间修正，则每次修正后都需要重新运行完整的 LM Head（词表大小通常超过 10 万），重新引入串行瓶颈。在 logit 空间直接施加低秩残差，LM Head 只需运行一次（在基础 logit 计算时），后续的因果修正仅涉及一个维度远小于词表的低秩变换，计算代价极低。

数学推导

本节对 Domino 的核心数学形式进行完整推导，涵盖 draft 分布的建模目标、因果修正的形式化定义，以及训练目标的数学表达。

自回归 Draft 分布的目标

理想的 draft 分布应当尽可能逼近目标模型的真实分布。在自回归框架下，对于 draft 块 $x_{t+1:t+\gamma}$，联合 draft 分布为：

$$q_{\mathrm{AR}}(x_{t+1:t+\gamma} \mid x_{\leq t}) = \prod_{i=1}^{\gamma} q(x_{t+i} \mid x_{\lt t+i})$$

其中 $x_{\lt t+i} = (x_1, \ldots, x_{t+i-1})$ 包含所有已验证的前缀 token 以及 draft 块中位置 $i$ 之前的 draft token。这一分布完整建模了 draft 块内部的因果依赖，但串行执行代价为 $T_{\mathrm{draft}}^{\mathrm{AR}} \approx \gamma \cdot (t_{\mathrm{net}} + t_{\mathrm{head}})$。

并行 Draft 分布及其局限

并行 draft 方案将联合分布近似为各位置独立预测的乘积：

$$q_{\mathrm{PAR}}(x_{t+1:t+\gamma} \mid x_{\leq t}) \approx \prod_{i=1}^{\gamma} q_{\mathrm{PAR}}(x_{t+i} \mid x_{\leq t}, \texttt{[MASK]}_{t+1:t+i-1})$$

每个位置的条件分布仅以已验证前缀 $x_{\leq t}$ 为条件，忽略了 $x_{t+1}, \ldots, x_{t+i-1}$ 的影响。这导致并行 draft 分布与真实自回归分布之间存在系统性偏差，表现为较低的接受长度 $\tau$。

因果修正公式

Domino 的目标是在并行 backbone 输出的基础上，以最小的计算代价引入因果修正。设第 $i$ 个 draft 位置的 backbone 隐状态为 $H_i \in \mathbb{R}^d$，前缀 draft token 的嵌入序列为 $E_{\leq i-1} = (e_{t+1}, \ldots, e_{t+i-1})$，则：

步骤 1：GRU 因果编码

$$S_{i-1} = \mathrm{GRU}(E_{\leq i-1}), \quad S_{i-1} \in \mathbb{R}^{d_s},\; d_s = 1024$$

GRU 顺序处理前缀 draft token 的嵌入，将整个前缀的因果信息压缩为固定维度的状态向量 $S_{i-1}$。

步骤 2：低秩修正头

$$\Delta L_i = W_2\; \sigma\!\left(W_1 [H_i;\; S_{i-1}]\right)$$

其中 $[\cdot;\cdot]$ 表示向量拼接，$W_1 \in \mathbb{R}^{r \times (d + d_s)}$，$W_2 \in \mathbb{R}^{|\mathcal{V}| \times r}$，$r = 256$ 为低秩瓶颈维度，$\sigma$ 为 SiLU 激活函数，$|\mathcal{V}|$ 为词表大小。

步骤 3：最终 Draft Logit

$$L_i = L_i^{\mathrm{base}} + \Delta L_i$$

最终从 $L_i$ 的 softmax 分布中采样得到第 $i$ 个 draft token $\hat{x}_{t+i}$，并将其嵌入 $e_{t+i}$ 送入 GRU 更新状态，为下一个位置的修正提供输入。

训练目标

Domino 的训练目标结合了基础 logit 监督和最终 logit 监督，采用时变权重 $\lambda_t$ 进行加权：

$$\mathcal{L} = (1 - \lambda_t)\,\mathcal{L}_{\mathrm{final}} + \lambda_t\,\mathcal{L}_{\mathrm{base}}$$

其中 $\mathcal{L}_{\mathrm{final}}$ 为最终 logit（含因果修正）的交叉熵损失，$\mathcal{L}_{\mathrm{base}}$ 为基础 logit（无因果修正）的交叉熵损失。两个损失均采用位置指数衰减权重：

$$w_k = \exp(-k/\gamma)$$

对 draft 块中第 $k$ 个位置施加权重 $w_k$，使靠前的位置（对接受长度贡献更大）获得更高的训练权重。$\lambda_t$ 从 1 线性退火至 0，实现从"基础锚定"到"因果修正主导"的渐进式训练。

Domino Head 设计

Domino Head 是整个框架中最关键的创新模块，负责将并行 backbone 产生的"无因果"基础 logit 转化为融入前缀依赖的高质量 draft 分布。它由两个子模块串联组成：GRU 因果编码器和低秩修正头。

GRU 因果编码器

是什么：一个标准的门控循环单元（GRU，Gated Recurrent Unit），隐状态维度为 1024。

为什么用 GRU：GRU 是一种轻量级的序列建模结构，能够以 $O(i)$ 的时间复杂度将长度为 $i$ 的前缀序列压缩为固定维度的状态向量，且计算开销远低于 Transformer。相比 LSTM，GRU 参数更少，推理速度更快。在 draft 块大小为 16 的设置下，GRU 的顺序展开仅需约 16 次矩阵乘法，而并行 backbone 的一次前向传播涉及数百次矩阵乘法，因此 GRU 的额外开销可以忽略不计。

输入与输出：GRU 的输入为已采样的 draft token 嵌入序列 $E_{\leq i-1} = (e_{t+1}, \ldots, e_{t+i-1})$，输出为因果状态向量 $S_{i-1} \in \mathbb{R}^{1024}$，编码了"到目前为止已生成了什么"的语义信息。

关键设计选择：GRU 处理的是 token 嵌入（embedding），而非 token ID 或 one-hot 向量。这使得语义相近的 token 在 GRU 状态空间中产生相似的因果状态，增强了泛化能力。

低秩修正头

是什么：一个两层 MLP，中间维度为 256（低秩瓶颈），输出维度为词表大小 $|\mathcal{V}|$，激活函数为 SiLU。

为什么是低秩：词表大小通常超过 10 万，直接将 $(d + d_s)$ 维向量映射到词表空间的参数量为 $(d + d_s) \times |\mathcal{V}|$，计算代价极高。通过引入低秩瓶颈 $r = 256$，参数量降低为 $(d + d_s) \times r + r \times |\mathcal{V}|$，计算代价显著降低，同时也起到正则化作用，防止修正头过拟合。

为什么在 logit 空间而非 hidden 空间修正：若在 hidden 空间修正，修正后的 hidden state 需要重新经过 LM Head 才能得到 logit，而 LM Head 本身的计算代价很高（维度为 $d \times |\mathcal{V}|$）。在 logit 空间直接施加残差，LM Head 只需对 backbone hidden state 运行一次，因果修正仅需运行低秩修正头，避免了重复的 LM Head 计算。

参数规模：Domino 相对于 DFlash 仅增加了 56M 参数（+5.3%），但带来了平均接受长度 +16.6% 的提升，参数效率极高。

高效运行时实现

Domino Head 的顺序展开（GRU 逐步处理每个 draft token）在朴素实现下会引入约 2.64 ms 的额外延迟。论文通过以下工程优化将其降低至 1.20 ms：

  • Triton 融合内核（Fused Triton Kernels）：将 GRU 展开、低秩投影、logit 加法等操作融合为单一 GPU 内核，减少内存带宽消耗和内核启动开销。
  • CUDA Graphs：将 Domino Head 的计算图静态编译，消除每步的 CPU-GPU 同步开销和内核调度延迟。

最终，Domino 相对于 DFlash 仅增加了 2.8% 的总延迟（draft + verify），但接受长度提升了 16.6%，净加速比提升了 12.3%。

训练课程 — Base-Anchored Curriculum

Domino 的训练设计面临一个独特挑战：如何稳定地训练一个同时包含并行 backbone 和顺序 Domino Head 的混合架构，使两个模块协同而非相互干扰。论文提出了基础锚定训练课程（Base-Anchored Training Curriculum），分两阶段解决这一问题。

Teacher-Forced 因果编码

问题背景：在训练 Domino Head 时，GRU 需要以 draft token 嵌入为输入。有两种策略：

  • TTT（Training-Time Testing）：使用模型自身在训练时采样的 draft token 作为 GRU 输入，模拟推理时的真实条件。
  • TF（Teacher Forcing）：使用真实标签 token（ground truth）作为 GRU 输入。

为什么选择 Teacher Forcing：论文给出了两个关键论据：

  1. 训练早期模型生成的 draft token 质量很差，TTT 策略会让 GRU 学习从噪声前缀预测正确 token，造成训练-推理分布不匹配（exposure bias）。
  2. 投机解码的接受机制天然对齐 Teacher Forcing：位置 $i$ 的 draft token 被接受的前提是位置 $1, \ldots, i-1$ 的 draft token 全部被接受（即全部正确），这正好对应于 GRU 输入为真实前缀的情形。因此 Teacher Forcing 并不会造成训练-推理分布不匹配，反而更准确地建模了推理时的条件分布。

实验验证（见图4右侧）：TF 策略的接受长度（3.96）明显优于 TTT（3.80），且训练更稳定。

基础 Logit 坍塌问题

问题发现：单独使用 Teacher Forcing 训练时，出现了一个意外的失败模式：Domino Head 的修正能力过强，导致并行 backbone 的基础 logit 质量下降（坍塌）。直觉上，当 Teacher Forcing 提供了高质量的前缀信息时，Domino Head 可以仅凭前缀信息就预测出正确 token，backbone 则退化为仅提供低信息量的隐状态，失去独立预测能力。

这一问题在图4左侧有直接体现：未使用课程训练时，backbone 的基础 loss 在训练过程中出现了明显的上升（坍塌），说明 backbone 的独立预测能力被 Domino Head "短路"了。

课程解决方案

Base-Anchored Curriculum 的核心思路是：先强制 backbone 学好独立预测，再让 Domino Head 在此基础上进行修正。通过时变权重 $\lambda_t$ 实现渐进式过渡：

$$\mathcal{L} = (1 - \lambda_t)\,\mathcal{L}_{\mathrm{final}} + \lambda_t\,\mathcal{L}_{\mathrm{base}}$$ 

graph LR
    A["训练开始\nλ_t = 1"] -->|"线性退火"| B["训练中期\nλ_t = 0.5"] -->|"继续退火"| C["训练结束\nλ_t = 0"]

    A --> A1["损失 = L_base\n强制 backbone 学习\n独立预测能力"]
    B --> B1["损失 = 0.5·L_final\n+ 0.5·L_base\n两者协同优化"]
    C --> C1["损失 = L_final\nDomino Head 主导\n因果修正"]

阶段一（$\lambda_t \approx 1$）：损失主要由 $\mathcal{L}_{\mathrm{base}}$ 驱动，强制并行 backbone 在没有因果修正帮助的情况下独立学好基础预测分布。这确保了 backbone 不会退化。

阶段二（$\lambda_t \to 0$）：损失逐渐转移到 $\mathcal{L}_{\mathrm{final}}$，Domino Head 在已经稳定的 backbone 基础上学习残差修正，专注于捕获 backbone 无法建模的因果依赖信息。

实验结果（图4右侧）显示，TF + Curriculum 的接受长度（4.19）显著优于单独 TF（3.96）和 TTT（3.80），验证了课程训练的必要性。

实验结果

论文在 Qwen3-4B 和 Qwen3-8B 两个模型上进行了全面评测，涵盖 8 个基准任务（GSM8K、MATH-500、AIME25、HumanEval、MBPP、LiveCodeBench、MT-Bench、Alpaca），以及 Transformers 单卡推理和 SGLang 高并发服务两种后端。

Transformers 后端端到端加速比

在 Transformers 后端（单卡、温度=0）的评测中，Domino 在 Qwen3-8B 上取得了 平均 5.49× 的端到端加速比，平均接受长度达 7.17 个 token，显著超越所有对比方法。

SGLang 高并发吞吐量对比

在 SGLang 服务后端的高并发测试中，Domino 在低并发（C=2）下实现了最高 5.1× 的吞吐量加速比（Qwen3-8B，GSM8K），峰值吞吐量加速比达 5.8×。随着并发数增大，加速比下降，这是所有投机解码方法的共性（高并发时 batch 已足够大，推理变为 compute-bound，draft 的收益下降）。

消融实验：Domino Head 的贡献

论文通过消融实验验证了 Domino Head 的独立贡献。在 Qwen3-8B 上，移除 Domino Head 后（退化为纯并行 backbone），各基准任务的平均接受长度从 4.19 降至 3.49，平均加速比从 3.31× 降至 2.84×，提升幅度约 20%。

总结与启发

核心贡献总结

Domino 的核心贡献在于提出了一个优雅的解耦思路：因果依赖建模不必与自回归执行绑定在一起。这一洞察打破了长期以来"要么速度（并行），要么质量（自回归）"的二元对立，通过以下三个组件的协同实现了两全其美：

  • 并行 Draft Backbone：以 $O(1)$ 时间代价完成 draft 块的语义特征提取，提供高质量的基础 logit。
  • Domino Head（GRU + 低秩修正头）：以极低的额外开销（+2.8% 延迟，+5.3% 参数）将前缀因果信息注入 draft 分布，提升接受长度 16.6%。
  • Base-Anchored Training Curriculum：通过渐进式训练防止 backbone 坍塌，确保两个模块协同而非相互干扰。

研究启发

1. 解耦思维的普适性：Domino 的成功揭示了一个更广泛的设计原则——在神经网络设计中，将"建模什么"（causal dependency）与"如何执行"（sequential vs. parallel）解耦，往往能在两个维度上同时取得进展。这一思路可能在其他序列生成任务（如代码补全、结构化预测）中同样适用。

2. Logit 空间残差修正的潜力：在 logit 空间而非 hidden 空间施加修正，避免了重复运行 LM Head 的计算代价。这一技巧在其他需要对语言模型输出进行后处理修正的场景（如 RAG 的知识注入、安全对齐的约束修正）中值得借鉴。

3. Teacher Forcing 与投机解码的天然契合：论文指出，投机解码的接受机制（位置 $i$ 被接受的前提是前 $i-1$ 个位置全部正确）天然对应 Teacher Forcing 的训练条件。这一观察为投机解码 draft 模型的训练策略设计提供了新的理论基础。

4. 课程训练防止模块间干扰：Base-Anchored Curriculum 揭示了一个重要的训练动态：当一个"强"模块（Domino Head 有 Teacher Forcing 加持）与一个"弱"模块（backbone 需要自力更生）共同训练时，强模块可能会"短路"弱模块，导致弱模块退化。通过课程训练逐步引入强模块的监督信号，可以有效防止这一问题。这对于其他混合架构（如 MoE、adapter 微调）的训练设计有参考价值。

5. 局限性：Domino 目前仅在 Qwen3-4B/8B 上验证，对更大规模模型（如 70B+）的效果尚未报告。此外，Domino Head 的顺序 GRU 展开在 draft 块大小极大时可能成为瓶颈，需要进一步的工程优化。论文也指出，在高并发场景下（C≥16），Domino 的加速优势相对于 DFlash 有所收窄，这是所有 draft-based 方法面临的共性问题。
